## Why

后端错误日志目前仅写入文件，平台管理员查看需要登录服务器翻阅日志文件，效率低且无法追踪处理状态。需要将 Error 级别错误持久化到数据库并提供管理后台界面，方便管理员集中查看、复制和标记处理状态。

## What Changes

- 新增数据库表 `log_error`，记录 Error 级别错误的完整信息（时间、模块、错误消息、堆栈等）
- 在管理后台新增"错误日志"菜单项，平台管理员可查看错误列表
- 默认按时间倒序展示，支持复制完整错误信息
- 每条错误记录有处理状态：未处理（默认）、已处理、忽略
- 管理员可修改错误记录的处理状态
- 仅记录 Error 级别，Warning、Info 不记录
- 原有文件日志不受影响，继续保留
- 提供"清理旧日志（30天）"按钮，一键删除 30 天前的数据库错误记录和文件日志。其中文件日志删除时，无需区分级别，按文件删除即可。

## Capabilities

### New Capabilities
- `error-log-storage`: Error 级别日志自动写入数据库表 `log_error`，包含完整错误信息和处理状态
- `error-log-management-ui`: 管理后台"错误日志"页面，平台管理员可按时间倒序查看、复制错误详情、修改处理状态、清理旧日志

### Modified Capabilities
<!-- None -->

## Impact

- 新增数据库表 `log_error`（系统表）
- 修改 `src/core/agent.py` 或全局错误处理中间件，增加 Error 级别日志的数据库写入
- 新增后端 API 路由：查询错误列表、更新处理状态
- 新增前端页面组件：错误日志管理页面
- 不影响现有文件日志功能

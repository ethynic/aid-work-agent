# 私有云服务器建议配置

> 本文档适用于私有化部署本系统的服务器选型参考，可整体提供给客户作为交付方案的一部分。
> 按项目实际情况（LLM 走外部 API、PostgreSQL 16 + pgvector 向量检索、Redis 跨 Worker 状态共享、NFS 文件存储）编制。
> 价格部分为市场参考区间，实际以腾讯云 / 阿里云官网实时报价为准。

---

## 1. 部署架构概览

系统由以下组件构成，全部可部署在 Linux 服务器上：

```
Nginx（反向代理 + SSL + 静态文件 + 限流）
  └→ FastAPI 应用（Gunicorn + uvicorn，多 Worker）
        ├→ 外部大模型 API（Qwen / ZhipuAI / DeepSeek，无需本地 GPU）
        ├→ PostgreSQL 16 + pgvector（关系数据 + 向量检索）
        ├→ Redis（跨 Worker 共享状态、缓存、图片注册）
        └→ 本地文件存储（租户附件、知识库、导出文件、记忆）
```

**关键事实（影响选型）**：

| 事实 | 对选型的影响 |
|------|-------------|
| 大模型调用走外部 API | 服务器**无需 GPU**，普通 CPU 实例即可 |
| 前端为 Vite 构建的静态文件 | 运行时仅需 Nginx 托管静态资源，无需 Node.js |
| PostgreSQL 需 pgvector 向量扩展 | 数据库镜像需含 pgvector（本项目用 `timescale/timescaledb:latest-pg16`），版本不低于 14 |
| Redis 承担跨 Worker 状态共享 | 生产环境 Redis 为**必需**，不可省略；多实例部署时不得依赖进程内存共享状态 |
| 浏览器自动化（Playwright）随应用部署 | 应用服务器需额外内存承载 Chromium 进程 |
| 渠道接入（企业微信 / 钉钉 / 飞书） | 需公网可回调的域名 + HTTPS，注意回调链路带宽占用 |

## 2. 部署方案与服务器配置

提供两种方案：**方案 A（单机一体化）** 用于试点 / 小规模验证；**方案 B（分离式）** 用于生产规模化（500 并发目标）。

### 2.1 方案 A：单机一体化（最低配置，试点 / 验证）

所有组件部署在同一台服务器上，适合 ≤50 并发、功能验证、POC 交付。**本项目现网生产即为此规格（4 核 8G）稳定运行**，可作为最低底线参考。

| 项目 | 最低配置 | 建议配置 | 说明 |
|------|---------|---------|------|
| 单台服务器 | 4 核 8G，5M 带宽，100G SSD 系统盘 + 300G SSD 数据盘 | 8 核 16G，20M 带宽，100G SSD 系统盘 + 1TB SSD 数据盘 | Nginx + 应用 + PostgreSQL + Redis + 文件存储全部在一台 |
| 操作系统 | Ubuntu Server 22.04 LTS | Ubuntu Server 22.04 LTS | 容器化部署，宿主机版本可更高 |
| 数据库存储 | 数据盘建议 SSD | 数据盘建议 SSD | 向量检索 + 高频写入，机械盘会成瓶颈 |

### 2.2 方案 B：分离式（建议配置，生产 / 500 并发目标）

组件按角色拆分，独立扩容，互不争抢资源，**推荐生产环境采用**。

| 名称 | 最低配置 | 建议配置（500 并发） | 说明 | 数量 |
|------|---------|---------------------|------|------|
| 应用服务器 | 4 核 8G，10M 带宽，100G 系统盘 + 200G 数据盘 | 8 核 16G，**50M 及以上带宽**，200G SSD 系统盘 + 500G SSD 数据盘 | 承载 Nginx + FastAPI 多 Worker + Playwright 浏览器进程；SSE 流式输出与图片传输对带宽敏感 | 1 台 |
| 数据库服务器 | 4 核 8G，200G SSD | 8 核 16G，500G SSD（按数据量可扩容） | PostgreSQL 16 + pgvector；承载业务数据、向量、计费记录，为整体性能关键 | 1 台 |
| 缓存服务器 | 2 核 4G | 4 核 8G | Redis 7.x；承载跨 Worker 状态、会话缓存、图片注册，需持久化（AOF/RDB） | 1 台 |
| 文件存储服务器 | 2 核 4G，1TB | 2 核 4G，2TB+（NFS 按需扩容） | NFS 共享，存放租户附件、知识库文件、导出文件、记忆文件 | 1 台 |
| 备份 | 2TB 存储 | 5TB 以上存储（或对象存储） | 备份数据库 + 文件存储，建议异地 / 跨可用区 | 1 份 |

> **带宽说明**：500 并发下 SSE 流式 + 富文本 + 图片附件会快速消耗带宽，建议按实际峰值流量评估。5M 仅够几十人规模；20M 适合中等规模；50M 及以上适合 500 并发目标。带宽不足会直接表现为"回复卡顿、图片加载慢"。

> **容灾提示**：数据库与文件存储建议开启云厂商层面的快照 / 备份策略，或采购跨可用区高可用实例。

## 3. 软件环境要求

| 软件 | 版本要求 | 说明 |
|------|---------|------|
| 操作系统 | Ubuntu Server 22.04 LTS 及以上 | 本项目现网为 18.04，新部署建议 22.04+ |
| Docker / Docker Compose | 最新稳定版 | 应用、PostgreSQL 均以容器方式部署 |
| Nginx | 1.20+ | 反向代理、SSL 终结、静态资源、限流 |
| PostgreSQL | **14 及以上，16 更佳** | 必须包含 **pgvector** 向量扩展（知识库检索依赖） |
| Redis | 5.0+（建议 7.x） | 跨 Worker 状态共享、缓存 |
| Python | 3.10+ | 运行于应用容器内，无需宿主机安装 |
| Node.js | 无需（仅构建期需要） | 前端为构建产物，运行时不需要 |

**无需 GPU**：所有大模型 / Embedding / ASR 能力均通过外部云 API 调用，本地不运行大模型推理。

## 4. 网络与安全要求

| 项 | 要求 | 说明 |
|----|------|------|
| 域名 | 1 个自有域名 + SSL 证书 | 渠道回调、Web 访问均需 HTTPS（本项目使用泛域名证书） |
| 公网端口 | 443（HTTPS）、80（跳转） | 内部组件间可用内网 / 专线通信 |
| 安全组 | 仅开放 22、80、443 对外 | 数据库、Redis 端口仅内网可达，禁止公网暴露 |
| 限流 | Nginx 层单 IP 并发 / 频率限制 | 已内置限流与上传限速策略，防资源被独占 |
| 证书 | 建议通配符证书 | 便于多环境（生产 / 测试 / 开发）共用 |

> **采购建议**：
> - 优先**包年包月**，比按量计费省 40%~60%；新用户常有首年优惠，实际支出显著低于参考价。

> - 预算紧张时，可用**方案 A 单机一体化**起步（1 台 8 核 16G 即可承载中等规模），后续按需拆分扩展，平滑演进到方案 B。

## 7. 数据备份建议

| 数据 | 备份方式 | 频率 |
|------|---------|------|
| PostgreSQL 数据库 | pg_dump 全量 + 云快照 | 每日全量，云快照按天保留 |
| 文件存储（租户附件 / 知识库 / 导出） | NFS 快照 + 同步至对象存储 | 每日增量，每周全量 |
| 配置与脚本 | 纳入代码仓库版本管理 | 随代码提交 |

> 备份需与生产数据**异地 / 跨可用区**存放，防止单点故障导致数据不可恢复。

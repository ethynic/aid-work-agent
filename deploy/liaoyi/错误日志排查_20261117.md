## 2. 错误 1：DeepSeek 400（占比 99.9%）

### 现象

`log_error` 从 16:12 起每分钟固定 1 组 4 条（deepseek provider → failover → gateway → health assessment），16:48 前后另混入 1 条空态摘要失败。报错原文：

```
[Failover] Provider [deepseek] 不可重试错误: DeepSeek API请求失败:
{"error":{"message":"The supported API model names are deepseek-flash, deepseek-v4-pro,
but you passed qwen-flash. ...","type":"invalid_request_error"}}
```

请求实际打到 `api.deepseek.com`（DeepSeek 官方 API），但携带的模型名是 `qwen-flash`。

### 根因（用户已确认并修复）

`.env` 配置错误：`LLM_PROVIDER` 当时配了含 deepseek 的 provider 链，而 `LITE_MODEL_CODE=qwen-flash`（纯模型名走当前主 provider，见 `configs/config.yaml` llm.lite_model 注释）→ qwen 系模型名被发往 DeepSeek API，必 400。

健康研判（`system_health.assessment`，每 60s 一次 `chat_lite`）是唯一分钟级常驻 lite 调用方，因此按分钟稳定刷屏；16:48:53 平台管理员登录后打开数字员工空态（sales-assistant）触发了同一 lite 链路的空态摘要，同因失败。

修复后 `.env`（17:04 mtime）：`LLM_PROVIDER=qwen`（单 provider，无 failover）+ `QWEN_MODEL_CODE=deepseek-v4.1-flash` / `LITE_MODEL_CODE=deepseek-v4.1-flash`（百炼兼容端点，该模型名在百炼平台就叫这个名字，见 master 提交 e7600110）。

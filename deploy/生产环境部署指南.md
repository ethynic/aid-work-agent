## 1. 部署前准备：摸底与决策

### 1.1 机器信息收集表

| 项 | 内容 |
|----|------|
| 公网 / 内网 IP、云厂商、可用区 | |
| 机型 / 核数 / 内存 / 系统盘 / 带宽 | 参考：4C16G + 100~200G 盘 |
| 操作系统 | Ubuntu（apt）/ Alibaba Cloud Linux（dnf）命令有差异 |
| SSH 用户名 / 认证方式 | 密钥优先；密码登录建议关闭 |
| 是否空机 / 已有业务 | 决定独占还是混部 |

### 1.2 环境摸底清单（混部机必做）

```bash
ss -tlnp                      # 端口占用全表（对外端口规划须避开）
free -m                       # 内存水位（已有 MySQL/Java 应用各占多少）
df -h                         # 磁盘余量
docker ps 2>/dev/null         # 是否已有 Docker 与容器
systemctl is-active nginx     # nginx 是否已存在（宝塔管理的占 80/443）
```

### 1.3 部署决策（与客户对齐后落档）

| 决策项 | 独占机（243 模式） | 混部机（诺度模式） |
|--------|-------------------|-------------------|
| 已有应用 | 无 | 全部保留；无人使用的可压缩内存（Java 加 `-Xmx` 前先列清单确认） |
| nginx | 宿主机自装 nginx，直接占 80/443 | **复用宝塔 nginx**，本项目容器不对外暴露，由宝塔站点反代到本机容器端口 |
| 对外端口 | 常规 | 避开已占端口清单（先 `ss -tlnp` 摸底） |
| 内存预算 | 见 §1.4 独占参数 | 见 §1.4 混部参数；上线后核对宿主机可用内存 |
| 域名 / 证书 | 泛域名商业证书或 acme.sh | 域名解析先验证；证书用 acme.sh HTTP-01 自动续期 |
| LLM/ASR/SMS 账号 | 沿用公司配置，量大后评估独立账号 | 同左（向客户明确费用归属；**客户自购 key 时积分系数统一设 1**，见 §5） |

### 1.4 资源参数参考（两套模板）

| 参数 | 独占（243） | 混部（诺度） |
|------|------------|-------------|
| WORKERS | 6 | 2 |
| aid-agent-api 内存上限 | 8G | 2.5G |
| aid-agent-background | 4G | 1.5G |
| aid-redis | 1G | 512M |
| aid-runner-api / worker | 1G / 6G（shm 128M/512M、tmpfs 128m/2g） | 1G / 3G（overlay 压缩：runner 内存 6g→3g、tmpfs 2g→1g） |
| PG shared_buffers / work_mem | 1GB / 16MB | 512MB / 8MB |
| PG 容器上限 / max_connections | 6G / 80 | 3G / 40 |
| 宿主机 swap | 4G + `vm.swappiness=10` | 按余量配置 |

> 独占参数含 2026-10-19 调优（shm 512M + TMPDIR tmpfs + PG `/pg_temp`），**新版 compose 文件已内置**，新部署直接生效；参数核对与验证命令见 §8.1。

## 2. 基础环境安装

### 2.1 sudo 免密（部署账号）

```bash
sudo sh -c 'echo "<user> ALL=(ALL) NOPASSWD: ALL" > /etc/sudoers.d/<user> && chmod 440 /etc/sudoers.d/<user>'
```

### 2.2 Docker 安装

- **Ubuntu**：`apt install docker-ce docker-ce-cli containerd.io docker-compose-plugin`（DEPLOYMENT.md 第一步）
- **Alibaba Cloud Linux 3**：默认 dnf 源无 docker-ce，先加阿里云 Docker CE 源（按 CentOS 8 路径），再 `dnf install`（完整命令见 [济南诺度私有云部署.md](济南诺度私有云部署.md) §3.2）
- 验证 `docker compose version`（v2 插件，**无中划线**），`systemctl enable --now docker`

### 2.3 Docker Hub 加速 + 日志轮转（国内服务器必需）

`/etc/docker/daemon.json`：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://dockerproxy.net"
  ],
  "log-driver": "json-file",
  "log-opts": {"max-size": "50m", "max-file": "3"}
}
```

> 腾讯云机器可改用内网镜像 `mirror.ccs.tencentyun.com`（243 同款）。日志轮转（log-opts）必须在**拉镜像/建容器之前**配好，后配不溯及既有容器。

### 2.4 git

服务器无 git 时安装（诺度：`dnf install git` → 2.43.7）。

## 3. 代码上线

### 3.1 目录规划

- 独占机：`/var/www/agent/`（compose 与代码同目录，243 惯例）
- 混部机：`/var/www/agent/app/`（代码在 app 子目录，compose 材料放兄弟目录，诺度模式）；**目录名一次定准**，后改名要同步 `.env`、compose、nginx、acme.sh 四处引用（诺度已踩过一次 `/var/www/aid` → `/var/www/agent`）

### 3.2 codeup 仓库访问（三种方式，按可用性选择）

| 方式 | 适用 | 要点 |
|------|------|------|
| **SSH 只读部署密钥（推荐）** | 服务器 git 拉取的长期方案 | 私钥取仓库工作区 `deploy/codex_readonly`（已 gitignore 不入库，从开发机携带上传），放到服务器 `<user>` 家目录并 `chmod 600`；对应公钥部署到 codeup；origin 用 SSH 地址；仓库级 `git config core.sshCommand "ssh -i <key> -o BatchMode=yes -o StrictHostKeyChecking=accept-new"`（`git reset` 不影响） |
| HTTPS 令牌 + `.git-credentials` | 独占机自用 | ⚠️ codeup 个人令牌可能配了 **IP 白名单**（办公网/指定服务器可用、客户机房被拒），跨网部署前先验证 |
| `git bundle` 首装 | 令牌被白名单挡住时的一次性通道 | 本机 `git bundle create aid-master.bundle master` → 推到服务器 → `git fetch /tmp/aid-master.bundle`；后续改走 SSH 密钥 |

> ⚠️ **凭据纪律**：令牌/密码只进服务器的 `.git-credentials`（600），不进对话、不进文档；曾发生令牌在排错报错中带出的事故，涉事令牌应轮换。

### 3.3 sparse-checkout（服务器瘦身，必配）

```bash
cd <项目目录>
git config core.sparseCheckout true
printf '/*\n!/.agents/\n!/.claude/\n!/.codebuddy/\n!/.pytest_cache/\n!/.zcode/\n!/docs/\n!/ext/\n!/openspec/\n!/plans/\n!/test_uploads/\n!/tests/\n' > .git/info/sparse-checkout
git read-tree -mu HEAD
```

- ⚠️ `deploy/` **必须保留**（容器 ENTRYPOINT 读 `deploy/gunicorn.conf.py`、更新脚本与备份 cron 依赖）
- ⚠️ `plans/` 被排除后是运行时可写目录，须**预创建**并对齐运行身份属主（`mkdir -p plans && chown <uid>`），否则 worker 启动 `PermissionError` crash 循环（agent3 事故）
- ⚠️ **远程执行 sparse-checkout 命令严禁接管道截断输出**（`| head` 的 SIGPIPE 会把 git 杀在 apply 中途，按空规则删工作区）；恢复用 `git checkout -f HEAD`
- 运行时可写目录一并预创建：`log/`、`storage/`、`plans/`，属主 = 容器运行用户

## 4. PostgreSQL 部署

- 位置：独立目录（如 `/var/www/agent/postgres/`，compose + init 脚本 + `.env`），`.env` 中 `POSTGRES_PASSWORD` **随机生成、600 权限**（仓库默认值仅兜底，禁止沿用）
- 镜像：`timescale/timescaledb:latest-pg16`（含 pgvector + timescaledb）；**迁移/恢复场景必须与源库版本一致**（2.27.2 vs 2.30.0 跨版本 restore 会丢 hypertables）
- 双库：`aid_work_agent`（init-postgres.sql 首启自动建，当前约 168 表）/ `aid_work_logs`（**手工建库**后执行 init-postgres-logs.sql）
- 注意 `POSTGRES_USER=aid_user` 时 **aid_user 即超级用户**（影响后续禁连/权限操作语义）
- 参数按 §1.4 模板；混部机务必设容器内存上限
- **端口绑定**：
  - 独占机：对外映射（如 `10864`）依赖**云安全组拦截公网入站**，宿主机 ufw 建议加第二层
  - 混部机：绑**内网 IP**（如 `172.29.49.136:15432`）——同机容器可访问、公网不可达；⚠️ 绑 `127.0.0.1` 时**容器经 DNAT 反而不可达**，勿用
- 迁移/恢复工具（backup/restore/update_postgres.sh）从仓库 `deploy/` 复制，改脚本内库/用户/密码常量

## 5. .env 配置

模板取自 243 生产（**流式拷贝，密钥不落对话**），服务器端改写项：

| 键 | 处理 |
|----|------|
| `DATABASE_URL` / `LOGS_DATABASE_URL` | 指向本机 PG 地址（独占：宿主 IP:映射端口；混部：内网 IP:端口） |
| `REDIS_PASSWORD` | **随机新生成**（自建 `aid-redis` 容器，仅容器网络可达，不发布宿主机端口） |
| `REDIS_HOST` | `aid-redis` |
| `PUBLIC_BASE_URL` | 客户域名，如 `https://agent.xxx.com` |
| `CORS_ORIGINS` | `https://<域名>,aidagent://app` |
| `AGENT_RUNNER_API_URL` | `http://runner-api:8091` |
| `AGENT_RUNNER_NETWORK` | 容器网络名（如 `aid-network`） |
| `AGENT_RUNNER_UPLOADS_HOST_DIR` / `STORAGE_HOST_DIR` | 宿主机附件目录（按 §3.1 目录规划） |
| `AGENT_RUNNER_WEB_SERVICE_TOKEN` / `RPA_SECRET_KEY` | **随机新生成**（全新库无存量密文，直接换新值即可；存量库迁移则必须沿用原值，否则密文全部解密失败） |
| `WORKERS` | 按 §1.4 |
| `USAGE_FACTOR` / `VIDEO_GEN_USAGE_FACTOR` / `EMBEDDING_USAGE_FACTOR` / `ASR_USAGE_FACTOR` | 积分用量系数（代码默认 100/33/100/100，按我方承担 API 成本、售积分盈利的口径设定）。**客户自购充值 LLM/ASR key 的私有云，四项统一设 1**（平台不加价，积分 ≈ 元成本价）；模板沿自 243 时注意其中 `USAGE_FACTOR=50`、`VIDEO_GEN_USAGE_FACTOR=33` 需逐项改。诺度 2026-10-22 已落地（四项全 1，容器内 `create_settings().billing` 验证生效，备份 `.env.bak_20261022_usagefactor`） |
| `LLM_PROVIDER` / `API_KEYS`、ASR/SMS 配置 | 沿用公司账号（客户侧费用归属提前对齐） |

> ⚠️ 改 `.env` 后必须 `docker compose up -d --force-recreate`，`docker compose restart` **不重新读取 env_file**（高频坑）。

## 6. 容器编排与启动

1. compose 主文件（独占：`docker-compose.prod.yml`；混部：`docker-compose.main.yml`）+ Runner overlay（独占：根级 `docker-compose.agent-runner.yml`；混部：`deploy/nuodu/docker-compose.agent-runner.yml` 压缩版），存储于代码库随 git 分发
2. 前端构建：`node:22-alpine` 容器内 `npm install && npm run build`（npm 缓存挂命名卷加速）
3. 启动并验证：

```bash
docker compose -f <主compose> -f <runner overlay> up -d --wait
docker ps   # 全部 healthy
curl -s http://localhost:<api端口>/health     # 含 db_pool 状态
curl -s http://localhost:<api端口>/health/db
```

已知的启动期噪音（可忽略）：多 worker 并发 `CREATE TABLE IF NOT EXISTS` 触发 `pg_class_relname_nsp_index` duplicate key WARNING（表已由 init-postgres.sql 建好）。

排障速查：

| 症状 | 处理 |
|------|------|
| Worker `PermissionError: log/agent` | 可写目录缺失或属主不对 → 宿主机预创建 + chown |
| Playwright/Chromium 启动失败 `/tmp` 权限 | compose 已挂 tmpfs `/tmp mode=1777` + entrypoint `fix_tmp.sh` 兜底 |
| 容器反复重启连不上库 | `.env` 改后未 force-recreate；或 PG 绑了 127.0.0.1（见 §4） |

## 7. nginx / TLS

- **独占机**：宿主机 nginx，conf 模板 [agent.aidingyi.cn.conf](agent.aidingyi.cn.conf)，关键项：SSE `proxy_buffering off`、知识库上传限速、**下载接口限速正则**（新增下载点必须同步，见 backend_dev.md 下载接口规范）、渠道回调路径
- **混部机（宝塔）**：
  - conf 源文件入库 `deploy/nuodu/`，安装到 `/www/server/panel/vhost/nginx/<域名>.conf`
  - 限流 zone 用独立前缀（如 `nd_`），避开宝塔内置 `perip`/`perserver` 冲突
  - ⚠️ 宝塔把 `/www/server/panel/vhost/` 锁为 root 600，部署用户写不了证书 → **证书自管**在 `/var/www/agent/cert/`（宝塔面板看不到该站点证书，属预期）
- **证书**：acme.sh（Let's Encrypt HTTP-01，ECC）→ `--install-cert` 到项目目录，reloadcmd 对应独占（`sudo nginx -s reload`）或宝塔环境；80 端口保留 ACME webroot + 301
- 外部回调端点在渠道配置页录入后，逐个做外网连通性验证

## 8. 发布后必做（通用标准动作）

> 每批次发布可能附**专项事项**（特殊数据迁移脚本、一次性补录、临时调参等），以当批次的发布说明（deploy/生产发布备忘.md，随批次更新）为准；本节为**每次发布/新部署都要做的通用动作**。

### 8.1 容器内存 / 临时目录 / PostgreSQL 调优验证

新版 compose 已内置：应用容器 shm 512M（runner-api 128M）+ TMPDIR tmpfs（按容器 1g/1g/2g/128m）；PG `shared_buffers=1GB`、`work_mem=16MB`、`effective_cache_size=8GB`、`temp_tablespaces=/pg_temp`（2G tmpfs）。逐项验证：

```bash
sudo docker inspect aid-agent-api aid-agent-background aid-runner-worker aid-runner-api \
  --format '{{.Name}} mem={{.HostConfig.Memory}} shm={{.HostConfig.ShmSize}}'
sudo docker exec aid-agent-api sh -c 'echo TMPDIR=$TMPDIR; df -h /home/appuser/tmp /dev/shm'
sudo docker exec aid-runner-worker sh -c 'df -h /home/appuser/tmp /dev/shm'
sudo docker exec aid-postgres psql -U aid_user -d postgres -Atc \
  "SHOW shared_buffers; SHOW work_mem; SHOW effective_cache_size; SHOW temp_tablespaces;"
sudo docker exec aid-postgres sh -c 'df -h /pg_temp; du -sh /pg_temp'
sudo docker inspect aid-postgres --format 'mem={{.HostConfig.Memory}} shm={{.HostConfig.ShmSize}}'
```

预期（独占机）：api/background/runner-worker `shm=536870912`（512M）、runner-api `shm=134217728`（128M）；`/home/appuser/tmp` 为 tmpfs；PG 参数 `1GB / 16MB / 8192MB / /pg_temp`；PG 容器 `mem=6442450944`（6G，混部按 §1.4 压缩）。若 Compose 未施加 PG 内存上限，补 `sudo docker update --memory 6G --memory-swap 12G aid-postgres`。

⚠️ **PG compose 独立副本陷阱**：若生产 PG 实际使用的 compose 是代码库目录之外的独立副本（243 曾是 root 属主的非 git 副本），git pull **不会更新它**——升级参数必须手工同步（同步前先备份 `.bak_<日期>`），并用 `docker compose config` 核对 `.env` 变量解析值后再重建。

### 8.2 宿主机 Swap / swappiness

```bash
sudo fallocate -l 2G /swap2.img
sudo chmod 600 /swap2.img
sudo mkswap /swap2.img
sudo swapon /swap2.img
echo '/swap2.img none swap sw 0 0' | sudo tee -a /etc/fstab

sudo sysctl -w vm.swappiness=10
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-aid-swappiness.conf
free -m && swapon --show
```

### 8.5 发布后验证

```bash
sudo docker stats --no-stream          # 各容器内存基线
sudo docker exec aid-runner-worker sh -c 'df -h /home/appuser/tmp && du -sh /home/appuser/tmp'
sudo dmesg -T | grep -iE 'oom|killed process' | tail -20   # 无输出为佳
```

功能抽检：导出一份 PPT（走 Chromium）、做一次 Word/PDF 转换、知识库检索一次；同时观察 runner-worker/api 内存峰值与 `/home/appuser/tmp` 用量。

### 8.6 风险提示

- tmpfs 属于内存：**上限达到时任务报 ENOSPC（不会拖垮宿主机）**，但大视频/超大 PPT 转换可能失败；观察 `/home/appuser/tmp` 用量后再决定是否调 `size`。
- 容器重启会清空 TMPDIR 中的临时文件，属预期行为；不要在 tmpfs 放任何需要跨重启保留的数据。
- `mem_limit` 是上限而非预留，各容器 limit 之和超过物理内存属正常；真正的风险是同时突发导致宿主机 OOM，发布后观察一周。
- `work_mem` 按每个排序/哈希节点分配，不要随手调大（80 连接下会成倍放大）。

### 8.7 回滚要点

| 范围 | 回滚方式 |
|------|---------|
| 应用（api/background/runner） | 更新脚本指定上一版本 commit（如 `bash agent_update.sh <commit>`） |
| PostgreSQL 参数 | 恢复 compose 备份件后 `docker compose -f docker-compose.postgres.yml up -d --force-recreate postgres` |
| 仅临时目录异常 | 下调 tmpfs `size` 后重建对应容器；内存压力过大时同步下调 runner-worker `mem_limit` |
| Swap | `sudo swapoff /swap2.img`，删除 fstab 对应行；删除 `/etc/sysctl.d/99-aid-swappiness.conf` 后 `sysctl --system` |

## 11. 踩坑速查表（两例部署汇总）

| 坑 | 根因 | 处理 |
|----|------|------|
| `docker compose restart` 后新 `.env` 不生效 | env_file 仅在容器创建时注入 | 一律 `up -d --force-recreate` |
| alinux3 装不上 docker-ce | 默认源无该包 | 加阿里云 Docker CE 源（CentOS 8 路径） |
| Docker Hub 拉不动 | 直连超时 | daemon.json 配镜像加速（建容器前配好 log-opts） |
| codeup 拉取 403 | 个人令牌 IP 白名单挡住客户机房 | 改 SSH 只读部署密钥（长期）/ git bundle（首装一次性） |
| worker 启动 `PermissionError` | sparse-checkout 排除后运行时目录消失、属主不对 | 预创建 `plans/` `log/` `storage/` 并 chown |
| sparse-checkout 把工作区删成空 | 远程命令接 `| head`，SIGPIPE 杀在 apply 中途 | 严禁管道截断；恢复 `git checkout -f HEAD` |
| PG 绑 127.0.0.1 后容器连不上 | DNAT 不匹配源地址 | 绑内网 IP 或依赖安全组隔离 |
| TimescaleDB restore 后 hypertables 全丢 | 镜像版本与源库不一致 | 用同版本镜像（如 2.27.2-pg16），空库 DROP+CREATE 再导 |
| `docker cp` 静默失败 | Docker 29 已知问题 | `cat file \| docker exec -i <容器> sh -c "cat > file"` |
| 宝塔环境证书写不进 vhost 目录 | `/www/server/panel/vhost/` root 600 | 证书自管项目目录，acme.sh `--install-cert` + reloadcmd |
| nginx `limit_conn_zone already bound` | 多份 conf 重复定义全局 zone | 仅保留一份；宝塔环境用独立前缀 |
| 更新脚本用 sudo/root 跑 | root 保留 HOME 改写 git 凭据属主 → 后续 fetch 全挂 | 以部署用户直接运行；凭据自愈备份件 `/root/.git-credentials.bak` 机制见 agent_update.sh 变更记录 7 |
| PG 容器重建打挂 sim worker | 10 秒中断 + sim 容器 `restart: no` | 维护窗口后手动 `docker start`；混部无 sim 不受影响 |

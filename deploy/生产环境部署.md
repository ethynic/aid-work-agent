### 2.3 踩坑记录（后续迁移/重建必读）

| 坑 | 根因 | 处理 |
|------|------|------|
| TimescaleDB 跨版本 restore 失败（hypertables 全丢） | 新拉镜像 2.30.0 vs 旧机 2.27.2，catalog 不兼容 | 拉取 2.27.2-pg16 并本地 tag 为 `latest-pg16`，重初始化卷后再 restore；日志库需按 `timescaledb_pre_restore()` → pg_restore → `timescaledb_post_restore()` 流程 |
| 部分表迁移后行数为 0 | 新机 `init-postgres.sql` 过旧（缺列），dump 的 CREATE TABLE 失败连带 COPY 跳过 | 补齐 SQL 后 DROP 表重导 / `ALTER TABLE ADD COLUMN` ×6 + `pg_restore --data-only` |
| `docker cp` 静默失败 | 新机 Docker 29 的已知问题 | 改用 `docker exec -i sh -c "cat > file"` stdin 流式写入 |
| Docker Hub 拉不动 | 公网受限 | `/etc/docker/daemon.json` 配腾讯云内网镜像 `mirror.ccs.tencentyun.com` |
| rsync `-e "ssh -i ..."` 报 `Failed to exec` | rsync 3.4.1 不接受带空格的 -e | 改 `/root/.ssh/config` Host 别名（`oldprod`） |
| nginx 启动报 `limit_conn_zone already bound` | 多份 conf 重复定义全局 zone | 仅保留一份定义，agent1 conf 中的 zone 行删除 |
| Worker 启动 `PermissionError: log/agent` | log 目录被 rsync 排除，docker 以 root 重建 | 宿主机 `chown`/`chmod`（log、storage 等可写目录对齐旧机权限） |
| 改 `.env` 端口后 api 崩溃循环（连 5433 被拒） | **`docker compose restart` 不重新读取 env_file**，容器创建时注入的旧变量仍在 | 必须 `docker compose up -d --force-recreate`；grep 确认 configs/src 无残留 5433 |

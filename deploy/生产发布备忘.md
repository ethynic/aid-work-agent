## 1. send_advisor_qr 工具启用（存量数字员工补工具配置）

**对应提交**：`334b629e`（留资口径调整，新增 `send_advisor_qr` 工具并加入 `pre-sales-api` 技能的 `requires_tools`）

**Why**：技能 `requires_tools` 自动补全（`SubagentDefinitionService.apply_skill_requirements`）只在**保存数字员工时**触发；存量定义的工具列表已固化在 DB 中，代码部署不会自动改写。存量数字员工（`inherit=false` 固定工具列表）部署后拿不到新工具，发码请求会因工具不存在而失败。副本/直用实例运行时继承父定义，修正定义行即覆盖全部实例。

**操作**：对使用 `pre-sales-api` 技能且 `tools.inherit=false` 的存量定义，补 `send_advisor_qr` 到 `tools.additional`（幂等，只补缺不覆盖；`updated_at` 刷新会触发 Runner 签名自动重建 registry，无需重启）。可后台重新保存，或直接执行：

```sql
UPDATE subagent_definitions
SET tools = jsonb_set(tools, '{additional}',
                      (tools->'additional') || '["send_advisor_qr"]'::jsonb),
    updated_at = NOW()
WHERE status = 'active'
  AND (skills->'allowed')::text LIKE '%pre-sales-api%'
  AND tools->'inherit' = 'false'
  AND NOT (tools->'additional') @> '["send_advisor_qr"]'::jsonb;
```

注意：`inherit=true` 的定义运行时继承全量目录工具，无需处理。

**验证**：任选一个已补全的数字员工，对话中让客户索要顾问二维码，确认 `send_advisor_qr` 可被调用（未配置 `employee_qr_file_id` 时应返回降级引导留联系方式，而非「工具不存在」）。前置条件：目标环境代码已包含 `334b629e`。

## 待执行：2026-10-19 容器内存 / 临时目录 / PostgreSQL 调优

生产 243 实测：16G 物理内存仅用约 5G，各容器 `/dev/shm` 仍是 Docker 默认 64M，应用 TMPDIR 落在 overlay 磁盘，PG 的 `/pg_temp` tmpfs 因未配置 `temp_tablespaces` 一直闲置。本次调整不改业务逻辑，只改部署参数。

### 1. 变更内容

| 文件 | 变更 |
|------|------|
| `docker-compose.prod.yml` | api：`shm_size: 512m` + TMPDIR tmpfs 1g；background：`shm_size: 512m` + `/tmp` 200m + TMPDIR tmpfs 1g |
| `docker-compose.agent-runner.yml` | runner-api：shm 128m + TMPDIR 128m；runner-worker：内存 4g→6g、shm 512m、TMPDIR tmpfs 2g |
| `deploy/docker-compose.sim.yml` | 仿真 api1：shm 512m + TMPDIR tmpfs 1g |
| `deploy/docker-compose.agent-runner.sim.yml` | 仿真 runner-api1：shm 128m + TMPDIR 128m；runner-worker1：shm 512m + TMPDIR tmpfs 2g |
| `deploy/docker-compose.postgres.yml` | shared_buffers 1GB、effective_cache_size 8GB、work_mem 16MB、maintenance_work_mem 512MB、启用 `temp_tablespaces=/pg_temp`、`/pg_temp` 1G→2G、内存 4G→6G |
| `src/tools/ppt/html_exporter.py` | Chromium 启动补 `--disable-dev-shm-usage` |

**要点**：TMPDIR 原本就指向 `/home/appuser/tmp`，只是落在 overlay 磁盘；现在在该路径挂 tmpfs，业务代码零改动。tmpfs 用量计入容器 `mem_limit`。

#### 4.3 PostgreSQL（低峰执行，约 10 秒数据库中断）

```bash
# 先完成 §2 的文件同步
cd /var/www/agent2/deploy
sudo docker compose -f docker-compose.postgres.yml up -d --force-recreate postgres
sudo docker inspect aid-postgres --format 'mem={{.HostConfig.Memory}} shm={{.HostConfig.ShmSize}}'
```

预期 `mem=6442450944`（6G）。若 Compose 未施加内存上限，补执行：

```bash
sudo docker update --memory 6G --memory-swap 12G aid-postgres
```

验证参数与 tmpfs 生效：

```bash
sudo docker exec aid-postgres psql -U aid_user -d postgres -Atc \
  "SHOW shared_buffers; SHOW work_mem; SHOW effective_cache_size; SHOW temp_tablespaces;"
# 预期：1GB / 16MB / 8192MB / /pg_temp
sudo docker exec aid-postgres sh -c 'df -h /pg_temp; du -sh /pg_temp'
```

#### 4.4 宿主机 Swap / swappiness（建议，需 sudo）

```bash
# 新增 2G swap 文件（现有 /swap.img 2G，合计 4G）
sudo fallocate -l 2G /swap2.img
sudo chmod 600 /swap2.img
sudo mkswap /swap2.img
sudo swapon /swap2.img
echo '/swap2.img none swap sw 0 0' | sudo tee -a /etc/fstab

# 降低积极换出倾向
sudo sysctl -w vm.swappiness=10
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-aid-swappiness.conf
free -m && swapon --show
```

### 7. 风险提示

- tmpfs 属于内存：**上限达到时任务报 ENOSPC（不会拖垮宿主机）**，但大视频/超大 PPT 转换可能失败；观察 `/home/appuser/tmp` 用量后再决定是否调整 `size`。
- 容器重启会清空 TMPDIR 中的临时文件，属预期行为；不要在 tmpfs 放任何需要跨重启保留的数据。
- `mem_limit` 是上限而非预留，各容器 limit 之和超过物理内存属正常；真正的风险是同时突发导致宿主机 OOM，发布后观察一周。
- `work_mem` 按每个排序/哈希节点分配，不要随手继续调大（80 连接下会成倍放大）。

## 1. file_assets 历史文件名补录脚本（随 8825d880 发布）

**背景**：file_assets 表（commit 8825d880）上线前，文件原始名只存 Redis（24h TTL），过期后磁盘自愈重建退化为存储名 `file_xxx.ext`。新表只覆盖增量，**存量历史文件名需要跑一次补录脚本恢复**。

**脚本**：`scripts/backfill_file_assets.py`（幂等，可重复执行；dry-run 默认，`--execute` 才写库）

**执行步骤**（在生产 API 容器内）：

```bash
# 1. dry-run 核对待补录数量与样例（不写库）
docker exec aid-agent-api python3 scripts/backfill_file_assets.py

# 2. 确认无误后写库
docker exec aid-agent-api python3 scripts/backfill_file_assets.py --execute
```

**数据源与优先级**：
1. 磁盘扫描 `storage/tenants/{tid}/{scene}/`（name=磁盘名，含 path/size/mime）
2. 消息表原始名（chat_messages attachments/images/downloadableFiles + channel_messages attachments），**在磁盘之后写入、优先级最高**；只覆盖"空名/存储名形态"，不冲已有用户可见名

**验证**：

```sql
-- 按来源统计
SELECT source, count(*) FROM file_assets GROUP BY source ORDER BY 2 DESC;
-- 抽查此前报障文件
SELECT file_id, tenant_id, name, size, source FROM file_assets WHERE file_id = 'file_2ef39b21b91f';
```

agent-tool-runtime 0.2.13（内含 boss-cli 0.2.13）
构建日期：2026-09-11

0.2.13 相对 0.2.12 的变化（「大部分卡片点不开」的修复：打开简历改用真实鼠标点击）

- **打开简历详情从 CDP 合成点击改为 Win32 真实鼠标点击**：客户机实证 BOSS 反作弊
  SDK 会选择性拦截 CDP 合成点击——被拦时点击静默失效、页面毫无反应（同一账号里
  打招呼的 Win32 点击一直正常）。真实鼠标输入与人工操作无法区分，不受此拦截影响。
  点击位置不变：候选人姓名文字的中心（坐标来自页面 DOM，任何分辨率/缩放/窗口
  尺寸都点在卡片行内）
- 读取阶段与点击阶段的坐标全部与视口求交：小屏笔记本上弹层画布底部出屏时，不再
  报「像素级同画面比对失败」，滚轮落点也恒在可见区内
- 简历画布识别门槛改为随视口自适应（宽/高 ≥ 视口对应边 ×25%，下限 200px）：
  弹层画布尺寸随窗口大小变化，写死像素在不同分辨率/缩放的电脑上会误判
  「详情未打开」（历史上固定 600 误杀过 572 高的真实画布）
- 日志增强保留（0.2.12 引入）：[boss-batch] 逐卡点击序列/画布尺寸现场、批量汇总，
  [boss-op] 失败原因，[boss-ocr] 引擎决策——诊断包采集方式不变
- 批量全部未打开时，返回消息会提示排查方向
- 使用建议：批量读取期间请勿移动鼠标（真实鼠标滚动/点击借用中）；如遇大面积
  失败，先人工确认页面可正常打开简历，再重试
- 升级方式不变：先停止本机 Runtime，再 npm install -g 新 tgz 覆盖安装，最后重启

agent-tool-runtime 0.2.12（内含 boss-cli 0.2.12）
构建日期：2026-09-10

0.2.12 相对 0.2.11 的变化（客户机「简历打开失败/不保存」事故整改，复盘见
agent 仓库 docs/incidents/boss-resume-batch-empty-incident.md）

- **修复批量读简历点击错位**（重要）：点击点从绝对像素（主体列 x=600/按钮 y+70，按
  开发机窗口校准）改为**点击候选人姓名文字的中心**——坐标直接来自页面 DOM，任何分辨率/
  缩放/窗口尺寸都点在卡片行内。旧版在部分电脑上点击无反应或开错人的详情（把 A 的简历
  存成 B 的名字）即此原因。姓名配不出的卡片不再盲点，直接跳过并记录原因
- 修复「点开了简历却没存进后台」的误判：0.2.11 的姓名交叉校验拦下的正是错位点开
  （点开的人与卡片姓名不符），属正确防护；配合本版点击修复，正常打开的简历会照常入库
- 日志大幅增强，诊断包采集方式不变（桌面双击 collect_logs 即可），runtime.log 新增：
  · [boss-batch] 逐卡现场：点了哪里（点击序列）、页面画布尺寸、每份简历 OCR 字数/引擎、
    批量汇总（尝试 N 张成功 M 份失败 K 个）
  · [boss-op] 每个操作的失败原因（此前只有云端能看到）
  · [boss-ocr] OCR 引擎决策（RapidOCR/系统 WinRT，回退不再无声）
  · [runtime] 任务领取/开始/终态回传行（此前服务化启动时这些行不落文件）+ 回传数据大小
  · 云端对应记录回传数据大小与入库结果，两侧可比对定位丢数据环节
- 升级方式不变：先停止本机 Runtime，再 npm install -g 新 tgz 覆盖安装，最后重启

agent-tool-runtime 0.2.11（内含 boss-cli 0.2.11）
构建日期：2026-09-03

0.2.11 相对 0.2.10 的变化（识别引擎内置化——客户机零 Python 依赖，装机一条命令）
- **识别引擎（RapidOCR + GPU 加速）已内置在安装包中**：无需安装 Python、无需 pip 装
  任何包，装完 Runtime 即获得高质量 OCR（此前需手动装 Python + pip 包才能启用）
- 内置环境自带 DirectML GPU 加速（普通办公机核显即可），OCR 约 3 倍于 CPU 模式；
  驱动异常自动回退 CPU 重跑，`AID_BOSS_OCR_DML=0` 可强制关闭
- 安装包体积从 3MB 增至约 148MB（内置识别引擎与模型的一次性代价，离线可用）
- doctor 的 OCR 检查项会标注「包内置环境」+ 加速后端 + 单次推理实测耗时
- 升级方式不变：先停止本机 Runtime，再 npm install -g 新 tgz 覆盖安装，最后重启

agent-tool-runtime 0.2.10（内含 boss-cli 0.2.10）
构建日期：2026-09-03

0.2.10 相对 0.2.9 的变化（简历读取质量攻坚——姓名/完整性/识别精度三修复 + GPU 加速）
- 简历读取姓名铁律：候选人姓名绝不由 OCR 猜测——批量读取只认卡片 DOM 配对（配对失败
  跳过不入库），单份读取必须显式传姓名；新增姓名×简历文本交叉校验（防点开的人与卡片
  不符）。服务端对新旧客户端均向后兼容（旧 CLI 照常可用，服务端只记观测日志）
- 拼接长图完整性：到底判定三层加固（滚动被吞自动恢复重试，不再误判到底截断半份简历）；
  逐段 OCR 替代整图识别（不再受长图尺寸限制）；接缝错位自动检测并在结果中警告人工核对；
  每段滚动步长真机校准（修复接缝内容丢失/重复）
- 识别精度大幅提升：OCR 引擎切换为 RapidOCR（此前系统自带 OCR 错字率约 20%，如
  「问题→河题」「Linux→Linuw」，且输出满篇空格）——识别近乎全对、天然无字符间空格；
  系统会自动清理残留空格
- GPU 加速默认启用（可选安装）：pip install onnxruntime-directml 后自动走核显/显卡
  加速，OCR 约 3 倍提速；不装也能用（自动走 CPU）；驱动异常自动回退 CPU 重跑
- doctor 新增「OCR 引擎」检查项：显示当前引擎（RapidOCR/WinRT 兜底）、加速后端
  （DirectML/CPU）与单次推理实测耗时，装机验收一眼判断机器算力是否够用
- 升级方式：先停止本机 Runtime（stop_runtime 或 Stop-ScheduledTask），再
  npm install -g 新 tgz 覆盖安装，配置与配对自动保留，最后重新启动 Runtime

agent-tool-runtime 0.2.9（内含 boss-cli 0.2.9）
构建日期：2026-09-01

本目录文件
- agent-tool-runtime-0.2.9.tgz   安装包（BOSS 直聘操作能力已内含，只需装这一个）
- start_runtime.bat / register_runtime_task.ps1   后台运行与开机自启
- collect_logs.bat / collect_logs.ps1   诊断包采集
- 安装手册.md   按手册从上到下执行即可

环境要求
- Windows 10/11 x64、Node ≥ 20、本机 Chrome（无需管理员权限）

0.2.9 相对 0.2.8 的变化（客户端可观测性补强——任何启动方式都有日志/诊断证据）
- runtime 进程内直接写日志文件（logs/runtime.log，超 5MB 自动轮转 runtime.old.log）：
  此前只有经 start_runtime.bat 启动才有文件，手动控制台跑 aid-runtime 时日志随窗口
  关闭全丢，排障只能靠服务端反推；boss CLI（[boss-mcp] 工具调用行）的输出也一并落盘
- start_runtime.bat 不再重定向输出（避免与进程内写文件双写），日志行改英文消除乱码
- doctor 新增「姓名配对自检」：直接报告当前页 N 个打招呼按钮配对成功几个、姓名清单；
  配对为 0（页面布局与锚定规则失配）时明确报错并提示发诊断包
- collect_logs 诊断包增强：新增 node 进程清单 processes.txt（排查旧 runtime 未停、双
  runtime 并存）；修复版本号读取为空的问题（PowerShell 对无 BOM UTF-8 按 GBK 误读，
  导致 JSON 解析失败）；zip 内文件名 ASCII 化（env_info.txt 等，解压不再乱码）
- 升级方式：先停止本机 Runtime（stop_runtime 或 Stop-ScheduledTask），再
  npm install -g 新 tgz 覆盖安装，配置与配对自动保留，最后重新启动 Runtime

0.2.8 相对 0.2.7 的变化（真机事故修复：定向打招呼“一直往下滑找不到人”+ CDP 断连误报）
- 姓名配对锚定去绝对像素（任意窗口宽度可用）；侧栏菜单与沟通页列表/面板分界同步相对化
- 定向查找滚动上限 30 屏 + 实时进度上报（“正在查找「姓名」…已滚动 N 屏”）
- CDP 断连错误改为可重试的“Chrome 调试端口不可用”（不再报未预期错误）
- collect_logs.bat：在压缩包里直接双击时提示先解压

# AID Work Runtime UI + BOSS CLI 试用验收包

构建日期：2026-10-12。Windows 10/11 x64。Runtime UI **0.0.3**、Host **0.2.15**、BOSS CLI 0.3.1（保留物理点击依赖及最新续筛、坐标与大图回传修复）。

本次修订 **r6** 修复Host启动健壮性：打开管理连接不再重写旧操作记录，兼容标准UTF-8 BOM配置/记录，系统保护、旧进程检查和执行进程监督固定调用Windows系统PowerShell。仅本机资料异常时保留只读管理连接、显示具体原因，仍可正常退出或卸载。保留r5跨版本续装轮换及此前恢复/BOSS冷启动修复；未打开Chrome或未登录时，已验签且已启用的BOSS仍可接收正常云端调用，业务仍按原登录、桌面和授权检查执行。

只读管理不表示设备身份或旧任务已修复。原配对配置/凭据正常时可以继续连接；如果原身份资料确实不可读取且存在旧配对/启动历史，不自动生成新身份、不重建管理密钥、不重放旧业务。不会要求客户提交日志来例行升级。

**退出与卸载**：r4 区分当前执行与历史记录。只有历史“待核对”、当前没有执行任务时，可以正常退出或卸载，配对和旧任务记录保留。当前有任务时先正常收尾；不把旧记录强行标为已完成，也不重跑旧任务。

**升级自动收尾**：r3 起，运行安装器会让旧 Runtime 停止领取新任务、等待在途任务和结果交付，再安全退出后覆盖安装；安装后恢复此前运行状态，已手动停止的状态保留。网络不通或任务长时间未收尾时会暂停安装，恢复网络后重新运行即可；不强杀、不重跑旧业务。

**r1/r2 已卡在“待核对”的用户**：运行 r6 安装器；出现「恢复已登记」后正常重启 Windows。重新登录后继续安装并核对旧进程已停止；原配对配置/凭据有效时继续使用原设备，不需要卸载、重新配对或提交日志。配对、插件、历史任务与未确认结果保留；不确定的业务结果不会自动重跑。旧版正常运行时可先托盘退出后安装。未知历史仍限制更换身份和破坏性插件管理，但可安装包内更高版本0.3.1，旧插件文件保留。本包保留r1/r2公钥，其他来源旧包需管理员确认兼容性。

**r3/r4/r5 卡住退出、卸载或覆盖安装**：运行r6安装器；「恢复已登记」才表示续装登记成功，随后正常重启Windows。此前旧安装器绑定的续装文件不会继续挡住新版，旧控制材料归档保留。若只想卸载旧版，可在Windows「设置 → 应用 → 启动」禁用本产品自启并正常重启，登录后不要打开Runtime，直接卸载。正常卸载保留设备配置。登记失败时安装器立即停止并显示错误码，不应继续等待。

**这是未签 Windows 证书的试用验收版，不是正式发行版。** BOSS 插件有本批隔离发布者签名，安装器已内嵌匹配的公钥。自动更新暂未启用。Windows 可能提示未识别发布者；先核对管理员提供的 SHA256 和来源，再按本单位试用策略安装。

## 一、旧命令行用户先迁移

1. 在原设备仍在线时结束已有任务，确认没有执行中任务、待核对效果或未回传结果。出现 unknown、待核对或结果未确认时先联系管理员；不能换设备后从头重跑可能已经写入的任务。
2. 打开 Windows「任务计划程序」，找到并**禁用** `AidWorkToolRuntime`、`AidWorkToolRuntimeWatchdog`（如果存在），防止旧版登录自启/自愈再次拉起。其他名称的旧启动项、Startup 快捷方式、NSSM 服务需由原安装管理员确认并停用。
3. 正常停止原 `aid-runtime start` 和自愈运行脚本，等待退出；隐藏黑窗口、关闭观察页面不等于后台进程已经停止。不要批量结束所有 Node 进程。UI 报旧实例冲突时继续检查旧任务和原进程。
4. **保留** `%APPDATA%\aidwork-tool-runtime`，包括旧 `config.json`、`credentials.bin`、日志、journal/outbox/session-tasks 等已有记录。不要删记录清障、不要把 DPAPI 凭证搬到另一 Windows 用户。旧 Chrome 数据目录 `C:\chrome-debug` 也保留。
5. 本验收版使用独立目录 `%APPDATA%\aidwork-tool-runtime-acceptance`，不自动导入旧设备身份。找管理员重新生成一次性配对码；新设备验证后，在云端选择/绑定新的设备，原设备按管理员流程停用。旧执行中的任务不会迁移到新设备。

本包支持原 r1/r2 UI 验收版的原目录覆盖升级，并保留其插件签名根。其他来源的 UI 验收版可能使用不同签名根，需管理员先确认兼容性；不能删除 pending 记录或手改信任文件绕过校验。

## 二、安装和配对

1. 将 **r6 ZIP 解压到一个新文件夹**，双击其 `安装文件` 中 **0.0.3** EXE；不要重复运行旧的0.0.2安装器。同一Windows用户安装，不用SYSTEM服务。覆盖已有UI版无需先卸载；旧版续装出现「恢复已登记」后正常重启Windows，再等待登录后续装。
2. 从桌面/开始菜单打开 **AID Work Runtime 验收版**。首次打开有图形界面，并默认启用「登录 Windows 后自动启动」。
3. 在配对区域填写管理员提供的**服务地址**、设备名称、一次性配对码。地址是原系统的完整 `https://企业服务域名`（或管理员明确提供的测试 HTTP 地址），不是 BOSS 网站、前端子页面或含 token 的 URL。设备名例如「招聘电脑-试用」。不要把旧 config 整份覆盖到验收目录。
4. 点击配对；一次性码过期需重新生成。凭证由 Runtime 通过 Windows 用户保护机制保管，不需要粘贴 token 或编辑凭证文件。
5. 配对成功后点击「启动执行」，确认运行状态和在线连接。暂未安装业务插件也可以连接；安装成功与业务就绪是不同状态。

## 三、安装最新 BOSS CLI

1. 在 Runtime 管理页点击「安装 / 升级第一方插件」，通过文件选择器选择 `插件包/boss-0.3.1-dev.aidplugin.zip`。不要选外层组合包，也不要把插件 ZIP 解开。
2. 等待安装操作完成，确认插件显示版本 **0.3.1** 且已启用。安装器与插件必须来自同一 ZIP；混用旧包可能验签失败。
3. 启动 Chrome 调试实例，沿用旧用户 `C:\chrome-debug` 登录数据。例如快捷方式目标（Chrome 在其他位置则由管理员调整）：

   ```text
   "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="C:\chrome-debug"
   ```

   打开 BOSS 直聘并扫码登录招聘账号，切到目标职位/推荐或沟通页面。旧普通 Chrome 窗口可能忽略新调试参数；使用专用实例，管理员检查 9222 端口。首次无调试实例时原 CLI 可按既有逻辑启动专用 Chrome，但登录必须本人完成。
4. 回到 Runtime 刷新状态。未打开 Chrome、未登录或桌面不满足条件时可显示「已安装 / 未就绪」及原因；按诊断准备环境，不要反复重装。
5. 云端选定此试用设备，先做已授权的只读检查。发消息、打招呼等真实招聘动作按原业务授权操作，本安装过程不会自动执行。

## 四、登录自启、托盘与退出

- 自启发生在**开机后当前用户登录 Windows 时**。未登录、休眠或锁屏不保证 BOSS 可执行；这不是 SYSTEM 后台服务。
- 第一次启动默认登记自启。右下角托盘图标右键 →「登录 Windows 后自动启动」可勾选/取消；任务管理器「启动应用」也能禁用。后续打开不会强行恢复已被用户禁用的项。
- 自动登录启动隐藏窗口并驻留托盘；已配对且安全处于「已停止」时恢复执行。首次未配对时需手动打开界面完成上述配置。已启动、收尾中不会再启动；启动前待核对、已阻断、授权撤回或启动失败时显示窗口，保留记录等管理员处理。运行后发生授权变更可在管理页查看；失败或超时不会反复提交启动。
- 双击托盘图标或右键「打开执行节点」显示界面。关闭窗口仅隐藏；要退出时选择托盘「退出」，等待已有任务安全收尾。托盘退出只停止本次会话，下次登录仍按自启设置执行；若要长期停用，先取消自启再退出。
- 重启验收：正常重启并登录后确认托盘出现、云端设备在线；保持 Chrome/BOSS 登录和桌面可交互。新版异常退出会先核验自有进程树停止，再恢复连接；旧版没有监督记录时按界面提示重启一次。由 Runtime 本次启动的 Chrome 可能随停止收尾关闭，登录数据保留；原先已打开的外部 Chrome 不会被回收。
- 卸载保留设备执行数据；正常卸载清除本产品自启项，覆盖更新保留用户选择。卸载不能替代执行中任务的安全退出。

## 五、常见问题与回退

| 现象 | 处理 |
|------|------|
| 实例冲突 | 检查旧计划任务、自愈脚本和 Runtime 进程，正常停止；不强抢实例 |
| 签名 / 摘要错误 | 核对同一 ZIP、SHA256；完整重取组合包，不改 envelope、manifest 或信任根 |
| 未配对 / 授权撤回 | 联系管理员确认设备授权，再按界面配对；不要复制旧 token |
| 已安装但未就绪 | 依据诊断检查 Chrome、9222 调试端口、BOSS 登录及交互桌面 |
| 旧版待核对 | 运行r6安装器，确认「恢复已登记」后重启一次；业务unknown保留，不重放 |
| r3/r4 安装结束提示自启尚未恢复 | 安装文件已经写入；后续使用r6，保留旧材料并重新登记续装；真实恢复失败保留记录并显示错误码 |
| Host启动资料异常 | r6保持只读管理连接并显示具体原因；原文件保留，可退出/卸载。身份缺失不自动新配对，不能用清记录冒充恢复 |
| 没有托盘 / 没有自启 | 手动打开应用，检查托盘自启复选项及 Windows 启动应用是否禁用 |

回退时先结束试用任务并正常退出 UI，取消其自启。确认试用设备无 pending/unknown 后，管理员将云端选择恢复为原设备，再重新启用原计划任务。不能同时启用两套执行节点处理同一旧任务。

日常升级与重启恢复不要求用户提交日志。业务结果 unknown 由管理员在原任务中核对实际效果。**不要发送 credentials.bin、management-secret.bin、一次性码、token 或整份含敏感内容的数据目录。**

## 六、本批验证范围

构建、固定Node资源、插件签名与完整清单、隔离Host管理、自启及安装器内容由开发验证。r6在本机自主复现旧包23个启动场景，并独立验证新版37个场景，包括正常配对配置、坏密钥/记录/配对事务、只读记录、BOM、隔离home、H1严格消费和私有退出；本机假云端完整启动/心跳/模拟任务/Job回收通过，未接触真实BOSS账号。r5安装器十组结果在相同脚本下复用。真实客户身份或历史业务没有被这些测试恢复；真实UAC、MUI交互、Windows重启续装及客户完整安装卸载尚未实测，不要求客户额外运行诊断。

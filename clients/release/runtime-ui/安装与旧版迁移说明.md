# Runtime UI + BOSS CLI r8 试用验收包

Windows 10/11 x64；Runtime UI 0.0.5、Host 0.2.17 / Core 0.2.16、BOSS CLI 0.3.1、内置 Node 22.23.3。

**本包 Windows 安装器未签名，只用于试用验收。** 插件采用本批隔离发布者签名。请使用管理员提供的完整 r8 ZIP，并核对 SHA256；不要混用旧 r1～r7 安装文件或插件。

## 安装与连接

1. 把整个 ZIP 解压到新目录，运行 `安装文件/AID-Work-Runtime-0.0.5-win-x64-acceptance-unsigned.exe`。建议选择“仅为我安装”，使用原 Windows 用户与原安装目录。
2. 同产品覆盖升级保留原配对、插件和历史任务。正常旧实例会先收尾退出；旧版拒绝退出时，安装器等待有界，并登记重启续装，临时关闭本产品旧版登录自启。看到“续装已登记”后正常重启 Windows，登录后等待续装。登记失败时按提示修复目录权限、Windows 凭据保护或安装文件后重试。
3. 打开 **AID Work Runtime 验收版**。原配置有效时，不必再次配对，点击“检查连接并给出处理方式”。收到真实服务器心跳响应后才显示验证成功。
4. 未配对时填写企业服务根地址、设备名称、网页“本地工具”生成的新配对码。地址例如 `https://agent2.aidingyi.cn`，不要填 BOSS 地址、网页子页面或带密码、token 的 URL。
5. 配对后检查连接并给出处理方式，在网页“本地工具”中选定正确设备；需要接任务时点击“启动执行”。检查连接只发心跳，不启动任务，也不覆盖服务器记录的插件能力。

验收版的配置目录是 `%APPDATA%\aidwork-tool-runtime-acceptance`。卸载保留配置和执行事实，重装不会自动删除。配置保留不等于配置损坏会自动消失，应使用下面的恢复入口。

## 遇到离线、报错或无法重新配对

报错时，**“连接检查与恢复”面板直接显示在错误下方**。绿色“查看连接处理步骤”只负责跳到并聚焦该面板，检查等待期间也可点击。不会打开客户端就自动进行长检查。

打开客户端的 **“连接检查与恢复”**，点击 **“检查连接并给出处理方式”**，按显示的类别和步骤处理。管理连接不可用或普通配对按钮被禁用时，这个检查入口仍可使用。无需提交日志或截图来完成例行恢复。

看到“管理密钥缺失”或“代码11”时，不要根据“设备信息暂不可读”判断配对已丢失：先检查。原凭据能验证时使用“保留原配对，修复管理连接”；原配置/凭据确实无法恢复时，使用“重新配置连接”。检查本身只验证配置、凭据和服务器，旧执行资源在您确认恢复时核对。需要重启时按当前结果先登记，再正常重启。

检查未完成时面板保留步骤并显示进度，不能重复提交恢复；步骤链接始终可用。若提示检查结果尚未确认，不反复配对；等待当前检查完成后按提示处理。历史执行资源较多时，确认恢复的检查可能较长；未确认停止时不会归档或覆盖。

| 页面情况 / 类别 | 处理步骤 | 处理完成后 |
|---|---|---|
| 原凭据验证成功，但管理密钥 / 操作记录异常 | 选择“保留原配对，修复管理连接”，阅读说明并确认 | 原配置和凭据保留，管理记录归档；再次实际验证服务器心跳 |
| DEVICE_NOT_SELECTED | 心跳已通过，但网页未选定本次配对设备；到网页“本地工具”选定正确编号 | 不用重装或重配；选择正确设备后再启动执行 |
| CONFIG_MISSING / CONFIG_INVALID | 选择“重新配置连接”，输入正确服务地址、设备名称、新配对码 | 原资料完整归档，生成新设备编号；在网页选定新设备并安装 BOSS 插件 |
| CREDENTIALS_MISSING / CREDENTIALS_UNREADABLE | 先使用原配对的 Windows 用户；确实无法恢复时重新配置 | 不复制其他用户凭据；新码配对后验证心跳 |
| CREDENTIALS_REVOKED | 管理员确认使用授权，再重新配置并使用新配对码 | 新凭据通过服务器验证后继续；反复重装不能恢复服务器已撤销的授权 |
| PAIRING_CODE_INVALID | 在网页重新生成配对码，用新码提交 | 不重复使用过期或已经消费的码 |
| PAIRING_TRANSACTION / PAIRING_INCOMPLETE | 重新打开客户端，让已登记的本机事务继续，再检查连接 | 配对响应未确认时不自动重复请求；仍未配对则生成新码，在普通配对区域提交 |
| DNS_FAILED / NETWORK_FAILED | 检查网络、VPN / 代理和服务地址；地址错误时重新配置 | 网络恢复后再检查，原地址正确时不需要重配 |
| TLS_FAILED | 管理员检查 HTTPS 证书链和电脑日期，修复证书后检查 | 不关闭证书验证、不清凭据 |
| SERVER_FORBIDDEN / SERVER_API_MISSING / SERVER_UNAVAILABLE | 管理员修复网关权限、正确接口地址或服务器异常 | 服务恢复后重新检查；客户端不会把服务不可用显示成已连接 |
| LOCAL_STORAGE / WINDOWS_PROTECTION | 使用原 Windows 用户，请管理员修复本产品目录权限、系统 PowerShell、用户凭据保护；空间不足时释放空间 | 修复后检查连接，再继续恢复，不删除设备或任务文件 |
| INSTANCE_CONFLICT / MANAGEMENT_UNAVAILABLE | 正常退出另一个 Runtime 或旧 CLI；只关闭窗口不会退出后台 | 旧版拒退出时正常重启，运行新版安装包；安装文件缺失时用本包修复安装 |
| EXECUTION_ACTIVE / LOCAL_CHECK_UNAVAILABLE / 旧资源需核验 | 先停止执行；仍无法收尾时选择“登记重启恢复”，登记成功后正常重启 Windows | 重开客户端检查连接，再继续原配对修复或重新配置 |
| CONNECTION_RESOURCE_EVIDENCE_CHANGED | 原资源记录在登记后发生变化，重新登记重启恢复 | 登记成功后再正常重启，按新检查结果继续 |
| LOCAL_RUNTIME_STATE / 旧任务仍阻断正常启动 | 服务器连接与旧任务核对分开处理；如需新设备工作，明确选择重新配置 | 旧任务留在原设备，新编号不继承或重放旧任务 |
| RECOVERY_INTERRUPTED | 重新打开客户端，继续同一次已登记事务，然后检查当前配置 | 已配对时不要再次重新配置；未确认配对时生成新码，按提示处理 |

**保留原配对**只修管理控制资料，旧业务、会话、插件和核对标记仍在原位置，未确认任务不会被标为完成。心跳接口只证明凭据被服务器接受，不返回设备编号；编号以原配对记录为准。

**重新配置**会先确认旧执行资源已停止，再归档整个旧目录并创建新配置。设备名称可以沿用，但名称相同不会恢复原设备编号。新设备需要在网页选定，BOSS 插件需要重新安装；原任务、未确认结果与旧插件文件保留在归档中，不迁移、不重放。

“登记重启恢复”只记录资源核验和停止接收新执行，不会立即关闭任务、清空记录或重启 Windows。安装器的“重启续装登记”只保证续装控制，不能替代未知执行资源的核验；遇到缺失或损坏的旧资源资料，装好后页面可能还需指导一次登记重启。只有显示登记成功才按该流程继续。

## 服务端状态与客户端重装的关系

当前服务端按设备 token 对应的 active 记录验证心跳；设备被撤销或 token 失效会返回 401，重新安装程序不会恢复旧 token。使用新的有效配对码会创建新 active 设备，不按旧设备名称或机器指纹永久禁用新配对。

服务端选定标记 selected=false 不拒绝心跳，但网页不会把业务发给该设备；新配对后必须选定新编号。配对码五分钟有效、只能使用一次，生成新码会作废同用户未使用的旧码。

旧任务的 unknown、会话 blocked、业务 binding 的 automation_blocked 限制对应业务，并不阻断设备心跳。管理员应处理该业务原因，不能靠重装客户端或删除本机文件绕过。新设备不会自动继承原设备的业务 binding 或旧任务。

## 安装 BOSS 插件

1. 在“第一方插件”点击“安装 / 升级离线包”，选择 ZIP 内 `插件包/boss-0.3.1-dev.aidplugin.zip`。插件 ZIP 不解压，不选择外层组合 ZIP。
2. 等待显示安装完成、版本 0.3.1、已启用。安装成功与软件已就绪分开显示，未就绪按页面具体原因处理。
3. 启动专用 Chrome 调试实例并登录 BOSS。旧用户可继续使用 `C:\chrome-debug` 登录资料，例如 Chrome 快捷方式目标：

   ```text
   "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="C:\chrome-debug"
   ```

4. 刷新插件状态，确认网页选定此设备、Runtime 已启动并在线，再进行已授权业务。登录、锁屏和页面状态由本人处理；本安装过程不发送招聘消息。

## 登录自启、关闭窗口与卸载

- 默认登记当前用户登录 Windows 后自动启动。托盘菜单可勾选 / 取消，后续打开不会强行覆盖用户已禁用的选择。
- 右上角 X **隐藏到托盘**；托盘“退出”才会退出客户端。仅历史记录待核对、当前没有执行时，可以正常退出或卸载。
- 当前有任务时先停止；网络导致无法收尾时，按“连接检查与恢复”登记正常重启。不要批量结束所有 Node 进程。
- 旧版本卸载拒退出时，使用 r8 安装器登记续装；不要在旧版错误弹窗中反复覆盖或卸载。只需卸载时可在 Windows“设置 → 应用 → 启动”禁用本产品，正常重启后不开客户端直接卸载。
- 安装器登记 / 恢复登录自启失败时会显示错误码和处理提示；启动客户端后可在托盘重新启用自启。

## 旧命令行组合包迁移

由原安装管理员停用旧 `AidWorkToolRuntime` / `AidWorkToolRuntimeWatchdog` 任务、自愈脚本或其他旧服务，正常退出旧 CLI。保留原 `%APPDATA%\aidwork-tool-runtime` 和 Chrome 登录资料。验收版使用独立目录，需要新配对码；旧任务不自动迁移，不能换设备后重跑可能已发生效果的任务。

## 包内文件与验证范围

包内含 UI 安装器、BOSS 离线插件、HTML / Markdown 配置说明、VERSION、SHA256 清单及验证记录。客户机不需要 Node、npm、Git 或 Python。自动在线更新未启用。

验证记录区分隔离 Windows / 真实本机组件验证与客户环境。服务器故障、账户授权、客户机器系统损坏需要对应管理员修复；只有真实心跳通过才显示连接验证成功。真实管理员提权、客户实际重启和 BOSS 登录属于现场验收，不把模拟 boot 变更或隔离测试冒充现场成功。

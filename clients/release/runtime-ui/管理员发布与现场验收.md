# r9 管理员发布与现场验收

## 服务端先确认

- Runtime 新注册和设备替换配套代码已提交、推送：`4192da65`。本批 BOSS 0.3.5 固定源提交：`b8124834`。
- agent2 由管理员手动部署；部署应包含数据库迁移、API 与网页。部署后确认启动健康、迁移完成，网页“本地工具”出现“更换此设备”。本次助手没有部署服务器。
- 尚未更新服务器时，客户端仍可使用普通配对码新注册；指定旧设备替换与自动注销不能记为验收通过。
- 使用内部测试账号：生成普通码→客户端提交→凭据保存→完成配置→真实心跳验证→网页选定新设备。再使用替换码重复流程，确认只撤销指定旧设备，其他设备、原任务和审计记录保留。不要以设备名称相同判断编号相同。
- 服务端 401 表示当前凭据不被接受，不代表电脑永久禁用；新的有效普通配对码可建立新设备。网关、服务器、证书、目录权限或 Windows 凭据保护异常应修复对应原因，不要求客户删除资料或寻找密钥。

## 本次自愿现场试用

用户已安排原故障客户自愿协助试装。内部真实安装、UAC 和 Windows 重启验收暂缓；本机源码、独立临时目录和模拟 boot 的结果不能替代现场结果。

1. 同一 Windows 用户、原目录覆盖安装，确认安装结束，客户端能打开，错误提示与处理入口可点击。
2. 配置有效时保留原连接；失效时使用“重新配置连接”，明确提交新码。服务器应看到实际 pair 请求和消费结果。
3. 新凭据保存后继续完成配置；资源未确认停止时先登记重启，正常重启后继续。已经保存的凭据不应丢失或再次要求旧配对码；处理完后以真实心跳成功确认连接。
4. 安装本包 BOSS 0.3.5，登录、刷新，确认已启用且就绪；启动执行后服务器应看到招聘能力。内部验证优先打开和读取，不额外发送招聘消息。
5. 托盘启用登录自启，明确停止执行后正常退出并重启 Windows；登录后确认托盘自动出现、连接配置保留、显式停止仍被保留。再取消自启重启，确认不会自行重新启用。只关闭窗口后应保留后台，托盘退出应结束客户端。
6. 卸载与重装应保留设备资料及历史执行事实；配置损坏的处理按页面引导，不把保留资料误当安装失败。

若某项未完成，按页面的类别和明确步骤继续处理，并在验收记录标记未通过。服务器未部署、真实重启或业务未测不能写成通过；签名仍为 Windows `NotSigned`，本包不能当正式签名发行包。

## 客户 ZIP

包内应有未签名安装器、签名试用 BOSS 离线插件、客户简明步骤、完整 HTML/Markdown 配置故障说明、VERSION、SHA256 清单以及分项验证记录。客户机不需要 Node/npm。安装器与插件应来自同一 r9 ZIP，避免混用同名旧安装器。

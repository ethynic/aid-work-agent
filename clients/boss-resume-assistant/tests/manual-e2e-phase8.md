# Phase 8 真机端到端验证步骤（需用户在场）

> 前置：`npm run build` 通过；`npm start` 能启动客户端。
> 原则：真机验证以人工观察为准，任何异常应体现为「暂停 + 界面可见原因」，而不是静默或乱点。

## 1. 登录门禁

1. 启动客户端，进入「登录」页，点击「启动浏览器」。
   - 预期：系统 Chrome 打开一个**全新窗口**（独立临时 profile，无既有登录态），地址为 BOSS 登录页；客户端状态变为「等待手动登录」。
   - 预期：此时客户端**不会**连接浏览器（可用 `netstat -ano | findstr LISTENING` 看到 Chrome 调试端口存在，但客户端日志无 CDP 活动）。
2. 在 Chrome 中用 BOSS 直聘 App 扫码登录，进入「推荐牛人」，选好岗位，关闭所有弹窗。
3. 回到客户端点击「登录完成，开始工作」。
   - 预期：状态变为「已连接，待开始」；审计日志（cdp_audit）中出现 `/json/version`、`Target.attachToTarget`、`Page.enable`、`Page.captureScreenshot`（视口实测），**无任何 Runtime.***。

## 2. 岗位配置

1. 进入「岗位配置」，创建岗位：城市、最低年限、必备技能、排除关键词、动作上限。
   - 预期：保存成功；硬规则含未知键/非法上限时保存被拒绝并显示错误。

## 3. 任务执行（小样本）

1. 进入「任务控制台」，选岗位，点「开始」。建议先用日上限=2 的岗位控制影响面。
2. 观察实时事件流：应依次出现 读取列表 → 打开详情 → 截图 → OCR → 筛选 → （执行动作|等待复核）→ 关闭详情 → 检查点。
3. 预期落库（可在「审计日志」页验证）：
   - 每个打开的详情都有一条 resume_views（先 LIST_DOM_FALLBACK 后更新为 OCR_NORMALIZED）。
   - captures 表有 long 图记录，长图文件存在于 `userData/captures/{日期}/`。
   - evaluations 有三态结论与理由。
   - 合格 → 打招呼动作 CONFIRMED（按钮文案消失确认）；不合格 → 不合适动作（原因可映射时）。
   - UNCERTAIN → 无动作，出现在「复核队列」。
4. 暂停/恢复/停止：
   - 点「暂停」：当前候选人处理完后状态变「已暂停」；点「恢复」继续。
   - 点「停止」：状态变「已停止」，会话行 STOPPED。

## 4. 恢复

1. 任务运行中直接杀掉客户端进程（模拟崩溃）。
2. 重启客户端：启动时上次 RUNNING/PAUSED 会话被标记 INTERRUPTED（可在 DB 中确认）。
3. 重新走登录门禁并开始同一岗位：
   - 已评估过的候选人**不再**打开详情（指纹去重）。
   - 结果未知（UNKNOWN）的动作**不会**重发。
   - 崩溃残留的 PLANNED 动作会重新走完整前置校验后才执行。

## 5. 复核与导出

1. 「复核队列」对 UNCERTAIN 候选人改判（必须填理由）：
   - 预期：review_overrides 记录原结论+改判结论+理由；原 evaluations 行不变。
2. 「审计日志」按岗位/日期/候选人/动作/状态筛选动作日志；按方法/状态筛选 CDP 审计。
3. 导出 CSV/JSON：选择路径后写入文件，行数与界面提示一致；CSV 用 Excel 打开中文不乱码。

## 6. 已知真机观察点

- **候选人枚举启发式**：当前用「2~4 个汉字的可见文本节点」识别候选人姓名，可能漏识别（含英文/数字的昵称）或误识别（罕见 UI 文案）。首批运行请人工核对打开的是否都是候选人卡片；误判时任务会因「无法唯一定位」暂停而非乱点。
- **详情打开确认**：点击卡片后用「详情快照中仍能找到候选人姓名」做启发式确认，若 BOSS 详情结构变化可能导致误暂停，属 fail-loud 预期行为。
- **列表滚动**：无新候选人时会向下滚动列表重试（默认 3 轮），虚拟滚动场景下候选人去重完全依赖本地指纹。
- **结构化字段**：本版本 OCR 只产出全文文本进筛选上下文，未做 OCR→结构化字段解析；城市/年限等硬规则依赖列表 DOM 字段，缺失时会进入 UNCERTAIN 复核。

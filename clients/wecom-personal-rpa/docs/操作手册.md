## 3. 视觉定位方案概览

企业微信 PC 客户端是 Direct2D 自绘 UI，UIA / MSAA / Windows.Media.Ocr 三条传统路径在真机验证中**全部失效**（dump 0 控件、子对象数 0、中文 OCR 识别率 < 10%）。本客户端改走 **Qwen3-VL 多模态视觉定位**：

```
企微主窗口截图（PowerShell 委托 + 像素自检）
    ↓
Qwen3-VL API（bbox 像素坐标，单次 ~28s / ~0.03 元）
    ↓
VisionCache（SQLite，窗口指纹不变时复用，命中 <30ms）
    ↓
InputExecutor（bbox → 屏幕坐标 → SendInput + 剪贴板粘贴）
```

降级链：Qwen3-VL 主策略 → `OcrVisionLocator`（Windows.Media.Ocr）→ 几何位置兜底。详细设计见 `docs/system/wecom-personal-rpa-vision-design.md`。

## 4. vision 配置说明

`configs/client.example.yaml` 的 `vision:` 段字段含义：

| 字段 | 含义 | 默认值 |
|---|---|---|
| `enabled` | 视觉定位总开关；未配置 `QWEN_API_KEYS` 时启动器自动置 false | `true` |
| `primary_model` | 主模型 | `qwen3-vl-plus` |
| `fallback_model` | 主模型连续失败时降级 | `qwen3-vl-max` |
| `api_endpoint` | Qwen3-VL OpenAI 兼容端点 | DashScope |
| `api_keys` | API key 池，`${QWEN_API_KEYS}` 占位符由 `VisionConfigLoader` 从环境变量注入 | — |
| `timeout_seconds` | 单次 grounding HTTP 超时 | `120` |
| `max_retries` | 5xx/超时重试次数（指数退避） | `3` |
| `cache.enabled` | 视觉缓存开关 | `true` |
| `cache.ttl_hours` | 缓存 TTL，防企微静默升级 bbox 失效 | `24` |
| `cache.sqlite_path` | 缓存 SQLite 落盘路径 | `${AppData}/WeComRpa/vision_cache.db` |
| `screenshot.pre_foreground_check` | 截图前校验企微主窗口在前台 | `true` |
| `screenshot.pixel_sanity_check` | 截图像素自检（防全白/全黑被遮挡） | `true` |
| `screenshot.max_white_ratio` | 白像素占比上限，超过判为可疑截图 | `0.5` |
| `screenshot.min_color_diversity` | 颜色种类下限，低于判为可疑截图 | `30` |

> 密钥安全：`api_keys` 禁止在 yaml 中明文长期存储，由 `Client.App/Services/VisionConfigLoader.cs` 从 `QWEN_API_KEYS` 环境变量注入。

### 6.2 视觉定位真机回归
验证 C# `QwenVisionLocator` + `VisionCache` 在真实企微截图上的端到端定位能力。

前置：
1. 目标机已登录企业微信 PC 客户端、窗口可见在前台
2. 在 `c:\repos\aid-work-agent\.env` 中配置 `QWEN_API_KEYS=<key1>,<key2>...`

跑回归：
```powershell
powershell scripts\run-vision-regression.ps1
```
两阶段执行：
- **阶段 1**：调 `capture-wecom-for-csharp.ps1` 用 PowerShell 前台化企微 + 截图 + 像素自检（白色占比 > 40% 或颜色多样性 < 50 判失败）
- **阶段 2**：C# `Client.VisionRegression.exe --image <PNG>` 跑场景 1（5 元素定位）/场景 2（缓存命中）/场景 3（指纹失效 cache miss）

读取 YAML 报告：
```powershell
# 报告路径
ls vision-regression-out\report_*.yaml
# 关键字段
#   scenarios.scene1.status: pass/fail     5 元素 bbox 命中
#   scenarios.scene2.cache_hit_ms: 7-29    缓存命中耗时
#   scenarios.scene3.status: pass          指纹变更后 cache miss
```

> **设计说明**：场景 4（截图自检）/场景 5（失败降级）在 `--image` 模式下标记为 skipped，因为它们依赖真实截图采集层，无法用外部 PNG stub 验证。这是测试工具限制，不是生产 bug——生产环境 Client.App 是常驻 GUI 进程，前台权限天然 OK。

### 6.3 本地启动 App 冒烟
```powershell
dotnet run --project src\Client.App -c Debug
# 或：
powershell scripts\run-app.ps1
```
**预期**：

- 日志写入：`%LOCALAPPDATA%\WeComPersonalRpa\Client.App\logs\client-<日期>.log`

### 6.4 服务端渠道端到端冒烟（不需客户端）
验证后端 `wecom_personal_rpa` 渠道能收 HMAC 回调、去重、落 outbox——**完全不需要客户端**，是当前最有意义的服务端验证。

前置：
1. 服务端已部署并启动（含本渠道代码）
2. 服务端已配置环境变量 `RPA_SECRET_KEY=<强随机串>`
3. 已注册一个测试客户端，拿到 `client_id` 与**明文 client_secret**

```powershell
powershell scripts\test-server-callback.ps1 `
  -ServerUrl "https://<服务端>" -TenantId "<租户ID>" -ConfigId "<渠道配置ID>" `
  -ClientId "<client_id>" -Secret "<明文client_secret>"
```
**预期**：HTTP 200，返回 `{"result":"accepted"}`；相同 event_id 再跑一次，服务端日志显示「重复事件已跳过」。

> 该脚本用与服务端 `auth.compute_signature` **字节对齐**的 HMAC-SHA256（`client_id+timestamp+nonce+raw_body`，UTF-8 拼接，hex 小写），是验证鉴权链路的标准工具。

## 7. 生产环境部署前置

部署到生产目标机前，**必须**确认以下条件：

| 项 | 要求 | 验证方法 |
|---|---|---|
| 操作系统 | Windows 10/11 x64，桌面会话常驻不锁屏 | `quser` 或组策略锁屏策略 |
| .NET 8 桌面运行时 | 装或依赖自包含发布 | `dotnet --list-runtimes` 含 `Microsoft.WindowsDesktop.App 8.x` |
| QWEN_API_KEYS 环境变量 | 系统级环境变量，逗号分隔多 key | 新开 PowerShell `echo $env:QWEN_API_KEYS` 非空 |
| 企业微信 PC 客户端 | 已安装、已登录、窗口默认可见 | 任务栏可见、进程 `WXWork.exe` 存在 |
| 桌面基线 | 1920×1080、DPI 100%、企微窗口固定尺寸 | `Get-CimInstance Win32_VideoController`；DPI 设置面板 |
| 服务端注册 | 已通过 `POST /api/saas/wecom-personal-rpa/clients` 注册并拿到 `client_id` / 明文 `client_secret` | 服务端管理端可见 |
| 服务端 RPA_SECRET_KEY | 已配置、与客户端 secret 同密钥体系 | 服务端环境变量 |

## 9. 安装部署（目标 Windows 机）

### 9.1 拷贝产物
把 `publish\` 整体拷到目标机，例如：
- App：`C:\Program Files\WeComRpa\app\Client.App.exe`
- Supervisor：`C:\Program Files\WeComRpa\supervisor\Client.Supervisor.exe`

### 9.2 配置客户端（ConfigTool 写入加密配置）

> **重要**：客户端**不读 yaml**。`configs/client.example.yaml` 仅是历史模板，对 Client.App 无效。
> 客户端只读 DPAPI 加密文件 `client_config.enc`。必须用 `Client.ConfigTool.exe` 把配置写入本机。

#### 路径约定

ConfigTool 默认输出路径 = Client.App 启动时实际读取路径，二者共用 `src/Client.Core/Config/ClientAppPaths.cs` 的常量来源：

```
%LOCALAPPDATA%\WeComPersonalRpa\Client.App\data\client_config.enc
```

不要再写到 `%LOCALAPPDATA%\WeComRpa\client_config.enc`——这是 2026-06-25 之前的老路径，**已废弃**（新 ConfigTool 不写、Client.App 不读）。

#### 推荐用法：交互模式

```powershell
.\Client.ConfigTool.exe
# → 逐项提示输入 client_id / client_secret（不回显）/ agent_base_url / tenant_id / poll_interval_seconds
# → 默认写入 %LOCALAPPDATA%\WeComPersonalRpa\Client.App\data\client_config.enc
```

参数从平台后台「RPA 绑定管理」→「新增绑定」或「轮换密钥」获取。

#### 自动化场景：参数模式

```powershell
.\Client.ConfigTool.exe `
    --client-id rpa_client_xxxxxxxxxxxxxxxx `
    --client-secret xxxxxxxxxxxxxxxxxxxxxxxxxx `
    --agent-base-url https://your-agent-host `
    --tenant-id tenant_xxxxxxxxxxxx `
    --yes
```

#### `--output` 参数用法

默认路径即 Client.App 读取路径，多数场景**无需**指定 `--output`。仅以下场景需要：

- 自定义了 Client.App 的 `DataDirectory`（目前不支持，预留场景）
- 测试 / CI：写到临时目录验证后再拷贝部署

```powershell
.\Client.ConfigTool.exe --output D:\tmp\client_config.enc ...
```

#### ⚠️ 老路径残留警告

**如果这台机器装过 2026-06-25 之前的客户端**，可能在老路径 `%LOCALAPPDATA%\WeComRpa\client_config.enc` 留过文件。这个文件**已废弃**，但留着会迷惑排查。如果客户端启动后行为异常（比如连到错的 BaseUrl），先清理：

```powershell
Test-Path "$env:LOCALAPPDATA\WeComRpa\client_config.enc"   # True 即有残留
Remove-Item "$env:LOCALAPPDATA\WeComRpa\client_config.enc" -Force
```

#### 验证写入成功

```powershell
Get-Item "$env:LOCALAPPDATA\WeComPersonalRpa\Client.App\data\client_config.enc" |
    Select-Object FullName, LastWriteTime, Length
```

期望：`FullName` 在 `WeComPersonalRpa\Client.App\data\` 下，`LastWriteTime` 是当前时间。

#### 服务端侧 `RPA_SECRET_KEY`

服务端必须配置环境变量 `RPA_SECRET_KEY`（用于加密存 `encrypted_secret`，与客户端持有的明文 secret 是**同一把**：注册时服务端用 `RPA_SECRET_KEY` 加密存库，验签时解密还原，客户端用明文算 HMAC）。两端必须用同一套密钥体系，否则签名永远不匹配。

更详细的 ConfigTool 用法见 [`src/Client.ConfigTool/README.md`](../src/Client.ConfigTool/README.md)。MSI 部署场景的对应章节见 [`docs/build-install-guide.md`](./build-install-guide.md) §4.2.1。

### 9.3 设置 QWEN_API_KEYS 环境变量
```powershell
# 系统级（推荐，所有进程可见）
setx QWEN_API_KEYS "sk-xxx,sk-yyy" /M    # /M 需管理员
```
设置后**新开** PowerShell 验证：`echo $env:QWEN_API_KEYS`。

### 9.4 安装 Supervisor 为 Windows 服务（需**管理员** PowerShell）
```powershell
powershell scripts\install-service.ps1 -Action install `
  -SupervisorPath "C:\Program Files\WeComRpa\supervisor\Client.Supervisor.exe"
```
脚本用 `sc.exe create WeComRpaSupervisor ... start= auto` 创建并启动服务。Supervisor 监督 `Client.App` 存活、崩溃自动拉起、离线上报。

其它操作：
```powershell
install-service.ps1 -Action uninstall        # 卸载服务
install-service.ps1 -Action stop|start       # 停/起
Get-Service WeComRpaSupervisor                # 查状态
```

### 9.5 App 自启
- 推荐：由 Supervisor 拉起（Supervisor 检测 App 未运行则启动）
- 或：登录后自启——`Client.App.AutostartRegistrar`（注册表 Run 键）

### 9.6 首次登录
1. App 启动 → 托盘 → 状态 `NeedLogin`
2. `LoginQrWindow` 通过视觉定位截取二维码区域
3. 手机企业微信扫码确认 → App 状态转 `Running`
4. `MessageWatcher` 开始监听，新消息经服务端 agent 生成回复，App 在企微会话发送

## 11. 诊断与排错

```powershell
powershell scripts\diagnostics.ps1 -OutPath .\wecom-rpa-diag.zip
```
导出**脱敏**诊断包（最近日志 + 配置摘要剔除 secret + 服务状态 + 状态机当前态）。

**常见错误**：

| 现象 | 原因 / 处理 |
|---|---|
| `RuntimeError: RPA 客户端密钥加解密无法初始化` | 服务端未设 `RPA_SECRET_KEY`；设置后重启 |
| 回调返回 `auth_failed` | client_secret 不一致 / 时钟漂移 >300s / client_id 拼错；用 `test-server-callback.ps1` 比对 |
| App 状态一直 `NeedLogin` | 企微未登录 / 二维码过期；用 `capture-wecom-for-csharp.ps1` 验证截图正常 |
| 视觉定位连续失败 | 检查 `QWEN_API_KEYS` 是否注入、企微是否在前台；看 vision 缓存是否过期（TTL 24h） |
| 截图像素自检失败 | 企微被其他窗口遮挡；确保企微常驻可见、目标机不锁屏 |
| 状态自动转 `PausedError` | 桌面锁屏 / 分辨率-DPI 不符基线 / 企微窗口不可见；解锁并按基线设置 |
| Supervisor 服务起不来 | 路径错 / 未以管理员安装；看 EventLog |
| 签名偶尔失败 | 客户端时钟漂移；同步系统时间（NTP） |
| 视觉缓存命中率骤降 | 企微静默升级导致窗口指纹变；等 TTL 过期自动重建或手动删 `vision_cache.db` |

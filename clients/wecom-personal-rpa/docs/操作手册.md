## 3. 编译

### 3.1 命令行（推荐）
```powershell
cd clients\wecom-personal-rpa
dotnet restore
dotnet build WeComPersonalRpaClient.sln -c Debug      # 或 -c Release
# 或用脚本：
powershell scripts\build.ps1 -Configuration Debug
```
- 输出目录：`src\<工程>\bin\<Configuration>\net8.0[-windows]\`
- 首次编译会还原 NuGet（FlaUI/OpenCvSharp/Serilog/Dapper 等），需联网。

### 3.2 IDE
VS 打开 `WeComPersonalRpaClient.sln` → `Ctrl+Shift+B` 编译，`F5` 调试 Client.App。

### 3.3 常见问题
| 报错 | 处理 |
|---|---|
| `MSB4019: 未找到 SDK` | .NET 8 SDK 未装/版本不符，重装 x64 SDK |
| `net8.0-windows` 还原失败 | 确认在 Windows 上且装了「.NET 桌面开发」工作负载 |
| `NU1xxx` 还原失败 | NuGet 源/网络问题，检查 `nuget.config` 或公司源 |
| FlaUI/OpenCvSharp 找不到 | 同上，确认联网能访问 nuget.org |

### 4.2 本地启动 App 冒烟（看骨架是否健康）★
```powershell

# 或：
powershell scripts\run-app.ps1
```
**预期（现在就能看到的）**：
- 系统托盘出现图标，右键菜单可用（状态/暂停恢复/重新登录/打开日志/退出）。
- 日志写入：`%LOCALAPPDATA%\WeComPersonalRpa\Client.App\logs\client-<日期>.log`。

> ⚠️ **不要期待它真的去操作企业微信**——当前 `Client.App` 注入的是 `Stubs/AutomationStubs.cs` 桩（`SendText/SendImage/SendFile` 全 `return false`）。托盘/日志/状态机正常 = **骨架健康**，仅此而已。真实自动化见 §4.4。

### 4.3 服务端渠道端到端冒烟（不需客户端，现在就能跑）★★ 最有价值
验证后端 `wecom_personal_rpa` 渠道**真的能收 HMAC 回调、去重、落 outbox**——这一步**完全不需要客户端**，是当前最有意义的端到端验证。

前置：
1. 服务端已部署并启动（含本渠道代码，提交 `d7b8d72`）。
2. 服务端已配置环境变量 `RPA_SECRET_KEY=<强随机串>`。
3. 已注册一个测试客户端，拿到 `client_id` 与**明文 client_secret**（注册接口仅返回一次，见 §7.2）：
   ```powershell
   # 在服务端管理员上下文调用
   $resp = Invoke-WebRequest -Method Post `
     -Uri "https://<服务端>/api/saas/wecom-personal-rpa/clients" `
     -Headers @{ Authorization="Bearer <管理员token>"; "X-Tenant-Id"="<租户ID>" } `
     -Body (@{ name="测试客户端"; min_version="1.0.0" } | ConvertTo-Json) -ContentType "application/json"
   $resp.Content   # 含 client_id 与 client_secret（明文，仅此一次，妥善保存）
   ```

跑冒烟：
```powershell
powershell scripts\test-server-callback.ps1 `
  -ServerUrl "https://<服务端>" -TenantId "<租户ID>" -ConfigId "<渠道配置ID>" `
  -ClientId "<client_id>" -Secret "<明文client_secret>"
```
**预期**：HTTP 200，返回 `{"result":"accepted"}`；再跑一次（相同 event_id）仍 accepted 但服务端日志显示「重复事件已跳过」；客户端离线时 agent 回复落入 `wecom_rpa_action_outbox`（可在服务端审计/DB 查看）。

> 该脚本用与服务端 `auth.compute_signature` **字节对字节一致**的 HMAC-SHA256 签名（`client_id+timestamp+nonce+raw_body`，UTF-8 拼接，hex 小写），是验证鉴权链路的标准工具。

### 4.4 端到端真实联调（暂不可行，需先完成 STATUS ③）
**前置（按顺序）**：
1. 计划第 0 节「编码前准入验证」：在真实 Windows+企微环境用 FlaUI/OpenCV 探测控件，回填 `assets/wecom_nodes.yaml`（AutomationId/Name、坐标、模板路径、阈值）。
2. 删除 `src/Client.App/Services/Stubs/AutomationStubs.cs`，在 `App.xaml.cs.ConfigureServices` 改注册为真实 `Client.Automation` 实现。
3. 补齐 `MessageWatcher`（入站文本/附件抓取）、`LoginStateDetector`（二维码截图）、`SendMessageService.DownloadToTempAsync`（真实下载）。
4. 目标机企微已登录（或准备扫码）。

完成后联调流程：启动 App → 托盘 → NeedLogin 弹二维码窗 → 手机扫码 → Running → MessageWatcher 上报 → 服务端 agent 回复 → App 收 action 并在企微发送 → 回执上报。

## 5. 发布（publish）

```powershell
powershell scripts\publish.ps1 -Configuration Release -Runtime win-x64
```
脚本做：
- `dotnet publish Client.App` 与 `Client.Supervisor` 为**自包含单文件**（目标机无需装 .NET），输出到：
  - `publish\app\Client.App.exe`
  - `publish\supervisor\Client.Supervisor.exe`
- 拷贝 `configs\client.example.yaml`、`assets\wecom_nodes.yaml` 到 `publish\app\` 旁。

等价手敲：
```powershell
dotnet publish src\Client.App\Client.App.csproj -c Release -r win-x64 --self-contained `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish\app

  -p:PublishSingleFile=true -o publish\supervisor
```

## 7. 安装部署（目标 Windows 机）

### 7.1 拷贝产物
把 `publish\` 整体拷到目标机，例如：
- App：`C:\Program Files\WeComRpa\app\Client.App.exe`
- Supervisor：`C:\Program Files\WeComRpa\supervisor\Client.Supervisor.exe`

### 7.2 配置 `client.yaml`
拷贝 `configs\client.example.yaml` → 与 exe 同级的 `configs\client.yaml`，填真实值：

| 字段 | 说明 | 来源 |
|---|---|---|
| `agent_base_url` | aid-work-agent 服务端地址 | 服务端运维提供 |
| `client_id` | 客户端 ID | 服务端 `POST /api/saas/wecom-personal-rpa/clients` 注册返回 |
| `client_secret` | 客户端密钥（明文） | 同上，**仅注册时返回一次**，妥善保存；客户端用它算 HMAC 签名 |
| `poll_interval_seconds` | 离线时拉取 outbox 间隔 | 默认 15 |
| `storage_path` | 本地数据/日志根 | 默认 `%LOCALAPPDATA%\WeComPersonalRpa` |
| `rate_limits` | 限速覆盖 | 默认 per_minute=5 / per_day=100 |

服务端侧必须配置环境变量 `RPA_SECRET_KEY`（用于加密存 `encrypted_secret`，与客户端持有的明文 secret 是**同一把**：注册时服务端用 `RPA_SECRET_KEY` 加密存库，验签时解密还原，客户端用明文算 HMAC）。两端必须用同一套密钥体系，否则签名永远不匹配。

### 7.3 安装 Supervisor 为 Windows 服务（需**管理员** PowerShell）
```powershell
powershell scripts\install-service.ps1 -Action install `
  -SupervisorPath "C:\Program Files\WeComRpa\supervisor\Client.Supervisor.exe"
```
脚本用 `sc.exe create WeComRpaSupervisor ... start= auto` 创建并启动服务。Supervisor 会监督 `Client.App` 存活、崩溃自动拉起、离线上报。

其它操作：
```powershell
install-service.ps1 -Action uninstall        # 卸载服务
install-service.ps1 -Action stop|start       # 停/起
Get-Service WeComRpaSupervisor                # 查状态
```

> 把 `scripts\` 也拷到目标机，或直接在目标机用 `sc.exe` 手敲：
> `sc.exe create WeComRpaSupervisor binPath= "C:\Program Files\WeComRpa\supervisor\Client.Supervisor.exe" start= auto`

### 7.4 App 自启
- 推荐：由 Supervisor 拉起（Supervisor 检测 App 未运行则启动）。
- 或：登录后自启——`Client.App.AutostartRegistrar`（注册表 Run 键，最小实现，STATUS ②，实测见 §4.2）。

### 7.5 首次登录（⚠️ 当前 STATUS ③ 未完成，流程供后续）
1. App 启动 → 托盘 → 状态 `NeedLogin`。
2. `LoginQrWindow` 弹出企业微信登录二维码（当前 `LoginStateDetector` 截图未实现）。
3. 手机企业微信扫码确认 → App 状态转 `Running`。
4. `MessageWatcher` 开始监听，新消息经服务端 agent 生成回复，App 在企微会话发送。

## 9. 诊断与排错
```powershell
powershell scripts\diagnostics.ps1 -OutPath .\wecom-rpa-diag.zip
```
导出**脱敏**诊断包（最近日志 + 配置摘要剔除 secret/路径 + 服务状态 + 状态机当前态），供排查或上报。

**常见错误**：

| 现象 | 原因 / 处理 |
|---|---|
| `RuntimeError: RPA 客户端密钥加解密无法初始化` | 服务端未设 `RPA_SECRET_KEY`；设置后重启 |
| 回调返回 `auth_failed` | client_secret 不一致 / 时钟漂移 >300s / client_id 拼错；用 `test-server-callback.ps1` 比对 |
| App 状态一直 `NeedLogin` | 企微未登录 / 二维码过期（当前 LoginStateDetector 未实现截图，见 STATUS ③） |
| 状态自动转 `PausedError` | 桌面锁屏 / 分辨率-DPI 不符基线 / 窗口不可见；解锁并按基线设置 |
| Supervisor 服务起不来 | 路径错 / exe 无执行权限 / 未以管理员安装；看 EventLog |
| 签名偶尔失败 | 客户端时钟漂移；同步系统时间（NTP） |

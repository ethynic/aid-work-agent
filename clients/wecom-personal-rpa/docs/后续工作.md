## 1. 这是什么 & 现在到哪了

**功能**：个人企业微信账号 RPA——一个独立 .NET 客户端登录企微、监听消息、上报服务端、接收服务端下发的文本/图片/文件 actions 并在企微里发送。服务端 `aid-work-agent` 把它作为一个平级渠道 `wecom_personal_rpa`（与微信客服同模型，只差「回复」是下发 actions 而非调微信 API）。

**代码位置**：
- 服务端：`src/channels/wecom_personal_rpa/`（8 模块）+ `src/saas/api/wecom_personal_rpa_{routes,admin}.py` + 对 `main.py`/`models/message.py`/`channel_factory.py`/`channel_config.py` 的注册 + `deploy/{init-postgres,db_update}.sql` 5 表

## 4. 已知陷阱与约束（避免重蹈）

1. **Stubs 桩是当前核心缺口**（P0.2）：`Client.App` 现在不会操作企微，别误以为「能编译=能用」。
2. **两份 `wecom_nodes.yaml`**：`assets/wecom_nodes.yaml`（设计完整模式，运行期**不**加载）与 `src/Client.Automation/assets/wecom_nodes.yaml`（`NodesConfigLoader` 实际加载的简化模式）。**P0.1 回填后者**。建议本会话顺手统一两份。
3. **WebSocket 多 worker 一致性**：`client_connection_registry` 是进程内单例，Gunicorn 多 worker 下跨进程隔离。首版单 worker 可用；多 worker 需 Redis pub/sub 广播或 sticky session（对齐 `.claude/rules/backend_dev.md`）。
4. **`RPA_SECRET_KEY` 必配**：服务端用它加密存 `encrypted_secret`，验签时解密；客户端持有的明文 `client_secret` 是同一把。不配→注册/验签直接 RuntimeError（fail-loud，不影响启动）。
5. **远程 PG 不可达**：集成测试 `tests/integration/test_wecom_personal_rpa_flow.py` 用路由级最小 app + mock 边界绕过 `conftest.py` 的 DB pool fixture（仅测试隔离，不进生产）。
6. **PowerShell 脚本编码**：`scripts/*.ps1` 须 UTF-8 **with BOM**、无 emoji，否则 Windows PowerShell 5.1 把中文按系统码页解码导致单引号串解析失败。
7. **`publish/` 与 `probe-report.yaml` 已 gitignore**：本地构建产物不入库。
8. **延迟 import**：`wecom_personal_rpa_routes._process_inbound_message` 内部延迟 import `src.core.*`，避免 import 期触发 `master_agent` 单例——改路由时保持。

# 产品效果图（interior-render）

把「户型图 + 产品/材质图」变成**真实感强、产品颜色质感还原到位**的室内效果图。
结构判读用 `image_read`（多模态读图），取色用 `scripts/sample_color.py`（经 skill_execute），
出图用 `image_render`（无参考图=文生图，1-3 张参考图=图生图）。

## 何时用
- 用户给出户型图（或某房间）+ 产品/材质照片，要"出效果图 / 看产品摆进去 / 铺上这款砖什么样"。
- 关键词：户型图、效果图、产品进家/进店预览、地砖墙砖/岩板/家具/灯具 上墙效果。
- 不适用：需要**度量级精确尺寸/坐标**的 2D 布局（那是几何任务，扩散模型不保证）。

## 核心思路（两层，但轻量）
1. **结构真值靠"读图"，不靠出图模型**：墙体/门窗/空间数量由 `image_read` 在**原始清晰户型图**上判读。出图模型只负责把选定空间渲染真实，**换模型不会修复结构识别错误**。
2. **产品还原靠"参考图 + 算法精确色"，不靠大模型估色**：把**真实产品图**作为 `image_render` 的参考图（材质锚点），颜色由 `sample_color.py` 像素级取均值写入提示词（大模型只负责定位取色区域，不负责估色），禁止用"暖白/米色"等模糊词让模型自由发挥。

## 关键纪律（踩过的坑，必须遵守）
- **禁止用像素阈值 / 骨架化 / Canny 自动提取来"生成结构"**。曾为做"纯净蓝图"对户型图跑阈值，把较浅/较细内墙一起滤没，产出"看似全开放、实际丢光内墙"的失真图，导致房间数与墙体全错。结构只能由 `image_read` 在原始图上判读。
- **清晰度闸门**：若户型图分辨率过低、线条发虚、或同一交界连通性反复判读不一致 → **不要糊图上下结论**，请用户提供更高清的户型图后再做。
- **喂原始带家具户型图时**，提示词必须显式声明"家具/地毯/虚线/圆弧**不是墙**，不得当成隔断或凭空加墙/吧台/柱"，否则模型会把家具线读成隔断、房型错位。
- **出图模型的 edit 只接受 1-3 张参考图**。若需同时锚定 >3 张（多产品/多角度），分批生成（每次 ≤3 张）。
- **右下角"AI生成"角标为会话界面显示标识（前端渲染，租户可在管理后台开关）**，生成图片文件本身无水印；不要靠提示词去水印，也不要向客户宣称"图片带水印去不掉"。
- **3D 是视觉近似**：交付时如实说明"尺寸/朝向以户型图为准"；不保证度量精确。
- **锁房间比例/结构只能靠"整图喂 + 以图生图"，不能靠纯文字、也不能裁剪单房间**：要还原某房间的真实长宽比，必须把**整张户型图 + 产品图一起**喂给 `image_render`，并在提示词命令模型"严格按户型图中该房间那块的真实尺寸比例生成"。**禁止**用纯文字描述去锁比例（不可能精确），**禁止**把单个房间从户型图上裁剪出来再喂（视觉定位不可靠、且丢失上下文）。若模型把采光墙旋到侧墙 / 在侧墙违规开大窗：改用**竖构图**（强制沿进深拉开纵深）+ 把"镜头站在 X 端朝 Y 拍、尽头=主采光面、左右两侧=实墙绝不许开窗"写成最高优先级硬约束。
- **取景角度按空间类型走默认最佳机位**（用户不指定即用默认，指定则从之），详见 Phase 2.5。切忌正对尽头墙的扁平"走廊式"正面机位。

## 工作流

### Phase 0 · 澄清（只在有歧义时问，能合理默认就直接做）
- **目标空间由产品品类决定，不是一律取最大厅**：
  - 地面材质（地砖/地板/岩板地铺）→ 该住宅或商铺中最该展示的主空间（客餐厅、店铺大厅…按品类）。
  - 墙面材质（墙砖/岩板上墙/涂料/壁纸）→ 产品图或用户暗示的那面墙所属空间。
  - 单体产品（家具/洁具/灯具）→ **其所属房间**：沙发/茶几→客厅，床/衣柜→卧室，马桶/浴室柜→卫生间，餐桌/吊灯→餐厅，陈列/射灯→店铺。
  - 用户点名空间则一律以用户为准，并说明所做的假设。
- 产品：单图多件时确认哪一件/哪种材质进图；产品品类已隐含摆放面（地砖→地面、壁灯→墙面）则不必再问。
- **场景类型也要判**：户型图/产品图暗示是商铺（零售店、 showroom）还是住宅，据此切换模板里的 `<住宅/商铺>`。

### Phase 1 · 读素材（`image_read`）
**固定只读 2 次**：户型图一次 + 产品图一次（每次一张图，question 按下方模板**照抄**，要求只答一行 JSON、禁止解释）。**禁止重复判读、复核或换问法再读**（仅清晰度闸门触发时例外）。

**户型图 question 模板**（照抄）：
```
这是户型图。只答一行JSON，不要任何解释：
{"room_count":<房间数>,"rooms":[{"pos":"<方位>","shape":"<形状>"}],"target":{"pos":"<目标空间方位>","shape":"<形状>","doors":"<门/门洞位置，无则空串>","windows":"<窗位置，无则空串>"},"has_dimensions":<true|false>,"has_room_names":<true|false>,"clarity":"清晰|模糊"}
```

**产品图 question 模板**（照抄）：
```
这是瓷砖/建材产品图。只答一行JSON，不要任何解释：
{"category":"<品类>","texture":"<纹理类型：木纹|石纹|纯色|几何>","gloss":"哑光|柔光|亮面","tone":"<整体色调：暖/冷/中性、浅/中/深>","grout":"<可见砖缝规格，无则填 无>","grouped":<true|false>,"crops":[{"label":"floor","crop":[x,y,w,h]},{"label":"wall","crop":[x,y,w,h]}]}
```

`crops` 字段要求模型返回产品图中**纯净材质区域**的裁剪坐标（像素，左上原点），避开接缝高光、反光、文字标注、背景杂物；地面/墙面各给一组，产品图只展示单一面时给一组即可。这是算法做不了、大模型擅长的定位任务。

**两个模板都禁止让 VL 报 HEX / 估颜色数值**：VL 的 HEX 是"看着像"的目测估算（实测与像素真值有偏差），且解释性长回答极慢（同图同模型实测：散文式回答 8~10s/348~423 token，一行 JSON 1s/19 token）。精确色一律由 Phase 2 的 `sample_color.py` 像素级取样（约 0.6s，且更准）。产出：
- 户型 JSON：深色/加粗墙围合的真实房间数与方位、目标空间形状、门窗位置、**有无尺寸标注/比例尺**、图上是否已印房间名。触发清晰度闸门。
- 产品 JSON（**只判特征，不估颜色数值**）：品类、纹理类型、表面光泽、整体色调倾向、砖缝、是否成组、**取色区域坐标 crops**。

### Phase 1.5 · 产品风格适配判断（必做，决定软装方向）
根据 Phase 1 读出的产品特征，判断该产品**最适合搭配哪种室内风格**，再据此选 Phase 3 模板中的风格描述词与负向排除词。**核心原则：效果图的软装风格必须与产品气质协调，不能"产品是产品、环境是环境"两张皮。**

**判断维度 → 风格映射表：**

| 产品特征 | 适配风格 | 典型软装元素 | 应排除的风格 |
|---|---|---|---|
| 浅色木纹砖/暖木色/哑光 | 奶油原木风、日式原木、北欧自然 | 浅橡木家具、棉麻布艺、藤编、亚麻纱帘、暖白微水泥、绿植 | 深色胡桃木、黄铜金属、冷灰色调、意式轻奢、工业风 |
| 深木色/烟熏橡木/高光 | 意式轻奢、现代极简、新中式 | 胡桃木/黑檀木饰面、真皮沙发、金属线条、大理石点缀 | 浅色原木、田园碎花、明亮日系 |
| 白色/灰色大理石纹砖/亮面 | 现代轻奢、意式极简、法式轻奢 | 岩板背景墙、金属收边、玻璃/亚克力、高级灰布艺 | 原木风、日式、乡村田园 |
| 暖色石材/米黄大理石/柔光 | 法式轻奢、新中式、暖调现代 | 奶白/米色护墙板、黄铜点缀、丝绒、弧形家具 | 工业风、极简黑白、冷调北欧 |
| 水泥灰/微水泥/哑光 | 侘寂风、工业风、极简 | 微水泥墙、原木枯枝、粗陶、铁艺、素色棉麻 | 亮面大理石、奢华水晶灯、欧式雕花 |
| 黑色/深色金属/亮面 | 现代暗黑、意式极简、工业轻奢 | 黑色金属框架、深色皮革、氛围灯带、混凝土 | 田园、日式原木、奶油风 |
| 彩色/花砖/复古 | 地中海、复古混搭、波西米亚 | 拱形元素、藤编、彩色织物、绿植、复古家具 | 极简、暗黑、冷调现代 |
| 单体产品（家具/灯具/洁具） | **以产品自身风格为锚**，其余软装衬托 | 与产品同风格+同色系的配角家具 | 与产品风格冲突的元素 |

**执行要点：**
1. 从 Phase 1 的产品 JSON 中提取：**色调倾向（tone）、光泽（gloss）、纹理类型（texture）、整体气质（自然/奢华/简约/复古）**。
2. 对照上表选定**主风格**（一个，不要混搭两个对立风格）。
3. 将主风格写入 Phase 3 模板的【软装】风格变量，将"应排除的风格"写入负向词。
4. 若用户明确指定了风格，以用户为准，但仍需提醒可能与产品气质不协调。
5. **软装必须饱满**：选定风格后，按该风格的典型元素尽量丰富地填充空间（沙发、茶几、地毯、灯具、窗帘、绿植、装饰画、摆件等），避免空旷简陋感。"高档"来自材质层次与细节丰富度，不等于堆砌金属或深色。

`image_read` 返回 `answer`（判读结论）+ `file_path`（图片本地绝对路径，Phase 2 取色要用）。

### Phase 2 · 算法精确取色（必做，颜色唯一权威来源）
**Phase 1 的大模型色调倾向不作为最终颜色依据**——颜色以本阶段算法取色为准。使用 Phase 1 返回的 `crops` 坐标调用 `sample_color.py`（按组加 `--label`）：

```bash
python3 scripts/sample_color.py --image "<产品图本地路径或URL>" --crop x,y,w,h --label floor
python3 scripts/sample_color.py --image "<产品图本地路径或URL>" --crop x,y,w,h --label wall
```

经 `skill_execute` 执行本技能脚本。**图片输入必须是本地绝对路径或 URL**：用 Phase 1 中 `image_read` 返回的 `file_path`；file_id（file_xxx）不能直接喂脚本。若 Phase 1 未返回坐标或坐标明显不合理，退化为不带 `--crop`（取中心 40%）并核对结果是否为纯净材质区。

- **表面材质类**：按 Phase 1 返回的每组 crop 坐标逐一取色 → `floor=#xxxxxx, wall=#yyyyyy`；若源图墙地同色就统一一个 HEX。
- **单体产品类**：取产品主体色块 → `<品类>=#xxxxxx`，同时记下材质（布艺/皮革/金属/木质/玻璃等）与光泽。

**优先级规则**：Phase 1 的色调倾向（如"暖米黄"）与 Phase 2 的 HEX 有出入时，**以 HEX 为准**写入提示词；Phase 1 的色调描述仅作辅助文字说明（如"暖米黄色 floor=#C8AA82"）。

**只描述源图里真实存在的颜色与材质**，不得自行加灰墙/水泥/石纹/亮面等源图没有的东西。

### Phase 2.5 · 取景角度（按空间类型取默认最佳机位）
**通则**：避免正对尽头墙的扁平"走廊式"正面；默认用**对角斜视 / 斜侧三分之四视角**——相机置于靠近一侧墙角、朝对角方向拍，同时纳入主采光面与一面侧墙，既显纵深又显宽度、更立体。**用户指定机位则一律以用户为准**；未指定按下表默认：

| 空间类型 | 默认机位 | 构图 |
|---|---|---|
| 客厅 / 起居室 | 站在与主采光面（阳台/大窗）相对那端的**某侧墙角**，朝对角看向采光面，斜侧约 **30-45°**，纳入采光面 + 一面侧墙（电视墙或沙发墙） | 横为主（狭长厅可适度竖，但仍斜侧、不做纯正面） |
| 主卧 | 门口对角，以**床头背景墙**为视觉主体，约 **30-40°** 斜视，纳入窗/飘窗 | 横 |
| 餐厅 | 以**餐桌**为主体，约 **45°** 三分之四斜视，纳入相邻客厅或窗 | 横 |
| 厨房 | L 形/一字**沿长轴**从开口端朝灶台墙，约 **30-40°** | 横 |
| 卫生间 | 门口对角约 **45°**，纳入洗手台 + 淋浴/浴缸 | 横 |
| 小空间（次卧/卫/厨） | 略广角、机位抬高、尽量**对角拉长**显宽敞 | 视情况 |

把选定的机位写进 Phase 3 模板的"取景"句；负向词固定加入 `正对尽头墙, 走廊式正面, 扁平视角, 侧墙开窗, 左右墙落地窗`。

> **输入为毛坯房实景照片时**（非户型图）：照片本身即为结构+透视锚点，提示词改为"空间几何严格以第二张实景照片为准，保持照片中的房间比例、采光面位置、墙面开口、拍摄视角与透视关系完全不变"。此时**不套用 Phase 2.5 的对角机位规则**（照片已决定机位），负向词中也**不写"正对尽头墙/走廊式正面"**（避免与照片实际视角矛盾）。照片中的临时物品（脚手架、施工杂物）在提示词中明确要求"去除"。

### Phase 3 · 生成（`image_render`，图生图）
参考图顺序：**`[产品图(材质锚点), 户型图(布局锚点)]`**（顺序即语义顺序）。调用：

```
image_render(
  prompt="<见下方模板，<…> 用 Phase 0/1/2 判读结果填入>",
  negative_prompt="<见下方模板>",
  reference_images=["<产品图>", "<户型图>"],
  size="1280*960", n=1
)
```

参考图支持本地绝对路径（含 `image_read` 返回的 `file_path`）/ file_id / URL。**户型图必须整张一起喂**（它是布局/比例锚点）。若加户型图后模型把家具读成墙、或房型/比例乱 → **不要删户型图**，而是①在提示词重申"家具/地毯/虚线/圆弧不是墙、不凭空加隔断"，②把该房间的真实长宽比写成硬约束，③按 Phase 2.5 选对角斜视机位、必要时改竖构图。只有在反复确认结构仍不可控时，才退化为"仅产品图 edit + 文字描述空间"，且须向用户说明比例不再锚定户型图。

n=1（按张计费，客户明确要多方案对比时才调大）；同一 seed+prompt 可复现，调优对比时指定 seed。

**按产品类别选模板（关键：不同品类"还原重点"不同，切勿一律用铺贴话术）：**

**A. 表面材质类**（地砖/墙砖/岩板/石材/瓷砖/涂料/壁纸——还原"铺开后的颜色与质感"）：
```
生成一张<住宅/商铺><目标空间>的写实室内效果图。空间几何以第二张户型图中<Phase1 判读的方位>那块<形状>区域为准，
严格按户型图中它的真实尺寸与长宽比例生成（如<南北向长方形、进深>面宽>），不要做成正方形或横向厅；
<哪面墙>为采光窗，其余为内墙；不要把户型图里的家具、地毯、虚线、圆弧当成墙或隔断，不要凭空增加隔墙/吧台/柱子。
【取景】<Phase 2.5 选定机位，如：相机站在与采光面相对那端的某侧墙角、朝对角斜看向采光面，约35-45°三分之四视角，
同时纳入尽头采光面与一面侧墙，不要正对尽头墙拍成扁平走廊式正面；采光面以外的侧墙必须是实墙、禁止开大窗>。
材质严格以第一张产品图为准：<地面/墙面>铺贴与产品图完全相同的<品类>——颜色 <Phase2 精确 HEX，如 floor=#xxxxxx>，
<哑光/亮面>表面，<按产品图的砖缝规格/纹理方向/是否通铺>。要求：颜色忠实还原产品图，不要偏冷/偏蓝/偏灰/过度增白；
真实<哑光>质感，表面均匀干净，绝对不要白色涂抹斑块、不规则镜面高光、水渍或噪点；墙·顶·地交界过渡自然，
不要水平色差分界线。【软装】整体风格为 <Phase 1.5 选定的主风格，如：奶油原木轻奢风>，
```

### Phase 4 · 自检（可选，默认跳过以提速）
**默认不执行此阶段**——直接交付生成图，由用户自行判断效果。仅在以下情况触发 `image_read` 对照产品图自检：
- 用户明确要求"帮我检查下效果"；
- 用户反馈图明显有问题、需要定向重跑时，此时读图定位偏差再调提示词。

自检时按产品类别判：
- **表面材质类**：颜色/质感是否贴产品、有无涂抹斑块/镜面反光/水平色差带、铺贴范围与缝规是否符合产品图。
- **单体产品类**：造型/比例/结构是否忠实、颜色与材质是否一致、是否只出现一件。
- **两类通用**：房间是否像目标空间、取景是否符合 Phase 2.5 设定、有无需去除的品牌文字/logo。

不达标就**调提示词/换 seed** 重跑（而非硬交），**最多重跑 1 次**，不无限打磨；重跑仍不达标就如实交付并说明可调项。

### Phase 5 · 交付
生成图已随 `image_render` 结果自动交付到会话（图片消息）。**最终回复不超过 3 句**：推荐点 + 一句可调项，禁止"这次是怎么落地的""说明一下"等章节化长解释与任何标题。**企业微信客服渠道（wecom_kf，系统提示词会标注）不输出解释与推荐文字，仅交付图片**：最终回复只写一句极短确认（不超过 20 字，如"效果图已发出，想调整随时说"），**不要留空**——空回复会被系统判为任务未完成而触发重试。透明说明仅在客户问及时简要回答：3D 为视觉近似，尺寸与朝向以户型图为准；产品颜色以参考图锁定；会话界面"AI生成"角标为前端显示标识（租户可开关），图片文件本身无水印。

## 验证
- 交付前确认：产品主色/材质/（单品的）造型与参考图肉眼一致；**表面材质类**无涂抹斑块/镜面反光/水平色差带，**单体产品类**无变形/比例失调/同款重复；房型与户型图方位一致；无品牌文字/logo。
- 若用了 Phase 2 取色，核对提示词里的 HEX 与样块一致。

## 不要使用本技能
- 需要度量级精确尺寸/坐标的 2D 布局图、施工图 → 几何/绘图任务，找主智能体。
- 纯图片编辑（抠图、改背景、去水印、人像处理）→ 非本技能范围。
- 不涉及户型图/空间场景的产品展示图（如白底商品图）→ 直接文生图需求，无需本技能工作流。

# 信息采集表 fields.json 格式（doc-layout-clone 技能）

## 用途

当第 3 步需要用户补充的信息**较多**（经验阈值：≥6 个字段，或需用户提供财务 / 人员 / 知识产权 / 市场等多类结构化数据），
不要在聊天里逐条追问，改为生成一份可填写的 Word 信息采集表：

- 字段有 `value`（来自知识库 / 参考资料的**真实值**）时，写入表格且**不高亮**，标注"来源已填"——这类是可直接回填的内容。
- 字段只有 `sample`（模板里的**示例值**）时，以**黄色高亮**呈现，表示"这只是结构示意，必须替换为真实内容"。
- 用户填完后，用 `--extract` 把值读回；它会额外标出 `unfilled`（没替换、仍等于示例值的字段）和 `empty`（留空字段）。
- **这两类（unfilled / empty）属于缺口，默认不得作为真实内容回填**：应留 `【待补：…】` 或向用户索取。只有用户明确说"用示例 / 模拟一版"时，才允许把示例值当答案，并在交付时显著声明为示例数据。

**红线（最高优先级）**：模板 / 样版 / 历史文件里的样例数据**只能作结构示意与定位锚点，绝不能作为成品实际内容输出**。成品内容的唯一合法来源是知识库检索结果、用户上传的参考资料、用户在对话中明确给出的数据；来源不全就留白或问人，**绝不编造**。`fields.json` 里的字段与示例值只能由本次读样版分析得出，属于**本次任务产物**，放在工作目录，**不写进技能包**。脚本 `make_intake.py` 不含任何业务常量。

## fields.json 结构

```json
{
  "title": "信息采集表",
  "note": "黄色高亮=模板示例值，仅示意结构，必须替换为真实内容；非高亮=已从来源填好的真实值。* 为必填。",
  "groups": [
    {
      "name": "一、主体信息",
      "fields": [
        {
          "key": "company_name",
          "label": "公司全称",
          "value": "（此处填来自内容来源的真实值）",
          "source": "用户上传的证照材料",
          "sample": "（模板示例值）",
          "hint": "证照登记全称",
          "sample_from": "模板样版",
          "required": true
        },
        {
          "key": "field_2",
          "label": "字段名称 2",
          "sample": "（模板示例值）",
          "hint": "数据口径说明；来源缺失，待用户提供",
          "required": false
        }
      ]
    }
  ]
}
```

### 字段含义

| 键 | 必填 | 作用 |
|----|------|------|
| `title` | 否 | 文档主标题；命令行 `--title` 可覆盖 |
| `note` | 否 | 标题下的说明；命令行 `--note` 可覆盖。应写明黄色高亮含义 |
| `groups[].name` | 是 | 分组小标题，如"一、主体信息""二、经营财务" |
| `groups[].fields[].key` | 是 | 字段唯一标识；回收时作为 values.json 的键；应与 `answers.json` 里的键一致或可映射 |
| `groups[].fields[].label` | 是 | 表中"信息项"列显示的中文名 |
| `groups[].fields[].value` | 否 | **来自知识库 / 参考资料的真实值**。非空则写入表格且**不高亮**，可直接回填。优先于 `sample` |
| `groups[].fields[].sample` | 否 | **模板里的示例值，仅作结构示意**。无 `value` 时非空即黄色高亮；**不得作为成品真实内容**，除非用户明确要求沿用示例 |
| `groups[].fields[].hint` | 否 | "口径 / 说明"列，写数据口径、佐证材料、注意事项 |
| `groups[].fields[].source` | 否 | `value` 的内容来源标注（如"知识库检索""用户上传的 XX.pdf"），拼进说明列 |
| `groups[].fields[].sample_from` | 否 | 示例来源标注（如"模板样版"），拼进说明列 |
| `groups[].fields[].required` | 否 | true 时 label 加 `*`，提示必填 |

## 生成

```
python scripts/make_intake.py <工作目录>/fields.json <工作目录>/信息采集表.docx \
    [--title "..."] [--note "..."]
```

输出 JSON：`out` / `groups` / `fields` / `highlight`（恒为 `yellow=示例数据`）。
生成后用 `cp` 工具把采集表复制为用户可见的交付文件，请用户填入真实值后发回：黄色高亮=模板示例、仅示意结构必须替换；非高亮=已从内容来源填好的真实值。**只有在用户明确说"用示例 / 模拟一版"时，才允许保留示例值回填。**

## 回收

用户填写后：

```
python scripts/make_intake.py --extract <填好的信息采集表.docx> \
    <工作目录>/fields.json --out <工作目录>/intake_values.json
```

**stdout**（供即时查看）：`count` / `values`（key -> 用户填写值）/ `unfilled`（文本仍等于示例值、未替换的 key）/ `empty`（留空 key）/ `gap_count`（缺口字段总数）。

**`--out` 落盘文件 `intake_values.json`**（结构化，缺口标记随文件持久化）：

```json
{
  "values": {"company_name": "（用户填写的真实值）", "report_no": "（用户填写的真实值）"},
  "_gaps": {
    "unfilled": ["field_a"],
    "empty": ["field_b"],
    "gap_count": 2,
    "note": "unfilled/empty 均属缺口，默认不得作为成品内容回填"
  }
}
```

- 取真实值用 `intake_values.json` 的 `values`，映射到 `answers.json` 对应字段，再走第 4 步回填。
- **必读 `intake_values.json._gaps`**：`unfilled` + `empty` 列出的 key 是缺口字段，默认不得把它们的示例值/空值当真实内容回填，应留 `【待补：…】` 或向用户索取；仅当用户明确要求"沿用示例"时才可用 `sample` 回填，且交付时须声明为示例数据。**绝不能只看 `values` 就全量回填**——那样会把未替换的示例值当真实内容，违反最高铁律。
- 回收按 `fields.json` 的分组与行序定位到表格第 3 列，**不依赖用户是否保留高亮**（高亮只作视觉提示，判定缺口以文本是否等于 `sample` 为准）。

## 判定何时启用采集表

| 情形 | 做法 |
|------|------|
| 待改字段 ≤5，且都是简单值 / 方向选择 | 按原第 3 步在对话里一次问全 |
| 待改字段 ≥6，或需用户提供财务 / 人员 / 知产 / 市场等结构化数据 | **生成信息采集表**，让用户离线填写 |
| 用户明确说"信息太多，给我个表填" | 生成信息采集表 |
| 用户**明确要求**"先用示例数据 / 模拟一版" | 才允许把 sample 当答案回填，且必须在交付说明里显著声明"含示例 / 模拟数据，非真实内容"。用户没这么要求时禁用此路 |

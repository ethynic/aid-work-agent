# 三态判定规则（权威口径）

判定基准日统一取 `--as-of`（默认运行当天）。所有日期按 `YYYY-MM-DD` 比较，**不含当天算逾期**：`due_date < as_of` 才算已过期。

## 一、定义

| 状态 | 英文值 | 定义 | 典型信号 |
|---|---|---|---|
| **正常** | `on_track` | 进度符合计划，未越过任何计划节点，且无实质性阻塞 | 里程碑按期完成；完成率 ≥ 计划完成率−5pt；沟通记录里只有常规推进 |
| **延误** | `delayed` | **尚未到期**，但进度已明显落后于计划，或存在会导致延期的实质阻塞 | 完成率落后计划 ≥ 10pt；关键路径任务停滞 > 7 天；等待客户/第三方反馈超时；资源被抽调；范围变更未评审；反复出现「阻塞/卡住/等确认/延期风险」 |
| **超时** | `overdue` | **已越过**计划截止日或某个关键里程碑日期，且对应交付物未完成/未验收 | `due_date < as_of` 且未标记完成；里程碑 `planned` 已过且 `actual` 为空；汇报里明确「未按期交付」「已逾期」 |

**超时 ≠ 延误**。前者是既成事实（时间已经越过），后者是预警（时间还没到但趋势不对）。一个项目既逾期又进度落后时，判 `overdue`（取更严重态），在 `risks[]` 里写明落后幅度。

## 二、判定优先级（从上到下，命中即停）

1. **已验收 / 已结项** → 若 `completion_date` 存在且 ≤ `due_date`，判 `on_track` 并标记 `closed: true`；若 > `due_date`，判 `overdue` 并记 `overdue_days`（历史逾期，看板单独标注）。
2. **硬时间越界** → `due_date < as_of` 且未验收 → `overdue`。
3. **里程碑越界** → 任一 `state != done` 的里程碑 `planned < as_of` → `overdue`，`status_reason` 点名该里程碑。
4. **进度落后** → `planned_progress - progress >= 10`（百分点）→ `delayed`。
5. **阻塞信号** → 最近 30 天证据里出现实质阻塞（见下表）且未解决 → `delayed`。
6. **剩余时间不足** → `days_remaining > 0` 但 `progress + (days_remaining / total_days) * 100 < 95` 的粗略外推仍无法完成 → `delayed`（低置信度，必须在 `status_reason` 说明是推算）。
7. 其余 → `on_track`。

## 三、阻塞信号词（用于沟通记录研判）

| 类别 | 信号 | 权重 |
|---|---|---|
| 外部依赖 | 等客户确认、等甲方反馈、等审批、等第三方接口、等环境 | 高 |
| 资源 | 人手不足、被抽调、离职、招聘中、并行项目抢占 | 高 |
| 范围 | 需求变更、追加范围、重新评审、方案推翻 | 高 |
| 质量 | 返工、验收不通过、缺陷积压、联调失败 | 中 |
| 时间 | 顺延、推迟、改期、来不及、赶不上 | 高 |
| 已解除 | 已解决、已恢复、已确认、已闭环、已上线 | **负权重**（命中则不判延误） |

**只用 30 天内的证据**判阻塞；更早的信号若没有后续闭环记录，降权为「历史风险」写进 `risks[]`，不直接影响状态。

### 行业化信号词（建材 / 制造 / 工程供货场景）

通用词表之外，以下表述同样按对应类别计入研判，避免把行业资料误判成「常规推进」：

| 类别 | 行业信号 |
|---|---|
| 外部依赖（高） | 等特种设备登记、等环保/排放联网批复、等检测机构排期、等甲方封样/色号确认、等收货窗口、等舱位与装船窗口、等设备厂家开放数采协议 |
| 资源（高） | 停窑窗口被占用、窑炉/产线排期冲突、班组被抽调、旺季产能被挤压、能耗台账交接不全 |
| 范围（高） | 花色/样板反复改版、核算边界变更、规格追加、样板房封样重做 |
| 质量（中） | 平整度/色差/吸水率不达标、抽检口径争议、量产验收未通过、批次返工 |
| 时间（高） | 点火投产顺延、供货批次推迟、停工令、错过装船期 |
| 已解除 | 已点火、已封样、已复验通过、已批量供货、已取得认证、已装船 |

判定示例：周报写「3# 线持续停窑，日均影响产能约 1.2 万㎡，批复仍未下发」→ 命中「外部依赖 + 资源」，即使完成率已达 82%，只要未越过截止日仍判 `delayed`；越过 `due_date` 则判 `overdue`。

## 四、完成率口径

- `progress`：AI 从汇报中读到的**实际完成率**（0~100）。多份材料冲突时取时间最新的一份，并在 `evidence_gaps` 里记录冲突。
- `planned_progress`：按 `(as_of - start_date) / (due_date - start_date)` 线性推算的计划完成率（0~100，四舍五入取整）。有明确阶段计划时以阶段计划为准。
- 材料里只有定性描述（「基本完成」「过半」）时，映射为 90 / 60 之类的估计值，`confidence` 相应下调，并在 `status_reason` 标注「估算」。

## 五、置信度

| `confidence` | 含义 |
|---|---|
| 0.85 ~ 1.00 | 有明确计划日期 + 明确完成率 + 近 14 天汇报 |
| 0.60 ~ 0.84 | 有计划日期但完成率靠定性描述，或最新证据 15~30 天前 |
| 0 ~ 0.59 | 材料陈旧（> 30 天）、缺计划日期、或只有聊天记录 |

低于 0.60 时，`status` 仍要给一个（看板需要三态），但 `status_reason` 必须以「材料不足，暂定」开头，并把缺口写入 `evidence_gaps`。

## 六、全局结论口径

- `overall_status` 取四档：`健康`（无超时，延误 ≤ 1）、`可控`（无超时，延误 ≥ 2）、`需重点关注`（有超时，或延误占比 ≥ 40%）、`高风险`（超时占比 ≥ 30% 或存在跨项目共性阻塞）。
- `executive_summary` 必须回答三件事：整体健康度如何、最该先处理哪 2~3 个项目及原因、有没有跨项目的共性风险。禁止写成各项目摘要的流水账。
- `top_risks` 按「影响项目数 × 紧急度」排序，最多 5 条。

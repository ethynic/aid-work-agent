# 知识库接入指引

用户说「资料在知识库里」「从资料库拿项目进度」时走这条支路。目标只有一个：**把知识库里的进度类文档，变成 `$PPT_ROOT/data/sources/<项目名>/` 下的本地文本证据**，之后复用完全相同的抽取与研判流水线。

## 一、可用检索通道

按可用性依次尝试，命中即可，不必全跑：

| 通道 | 工具 | 适用 |
|---|---|---|
| 知识库语义检索 | `knowledge_base_search` | 按内容语义找项目进度类文档（跨租户共享范围由工具按子智能体配置自动处理） |
| 知识库文件定位 | `knowledge_file_search` | 已知文档名/文件名特征（如「XX项目周报」）按标题定位文档 |

工具能力与参数以当前会话实际载入的 schema 为准，不硬编码未验证的字段名。检索返回摘要不足以支撑研判时，通过文档读取/下载路径获取全文再落盘。

## 二、检索关键词模板

对每个已知项目名，用三组关键词交叉检索，避免只靠一个词漏召回：

```
1. "<项目名>" 进度 | 进展 | 状态
2. "<项目名>" 周报 | 月报 | 周例会 | 阶段汇报 | 验收
3. "<项目名>" 延期 | 阻塞 | 风险 | 变更 | 待确认
```

项目名未知时，先用宽口径召回项目清单：

```
项目进度 / 项目周报 / 项目台账 / 里程碑 / 交付计划 / PMO / 项目组合
```

从召回结果标题里提取项目名，去重后作为分组依据。

## 三、落盘规范

每条检索结果通过 `stage_inputs.py --kb` 落盘（脚本自动生成下列固定三段格式，保证 `extract_sources.py` 能正确识别日期与类型）：

```bash
python scripts/stage_inputs.py --root "$PPT_ROOT" --project "<项目名>" --kb \
    --title "<文档标题>" --text-file "<检索正文文本路径>" --date "<YYYY-MM-DD，未知留空>" --origin "<原始文档链接或栏目名>"
```

生成的文件形如 `data/sources/<项目名>/kb_<YYYY-MM-DD>_<标题>.md`：

```markdown
---
source: knowledge_base
origin: <原始文档链接或栏目名>
title: <文档标题>
doc_date: <文档日期，未知留空>
retrieved_at: <检索时间>
---

# <文档标题>

<正文全文>

## 检索命中说明
命中关键词：<...>
```

沟通记录类（会议纪要、聊天导出）在 `--title` 里带 `沟通` / `会议` / `纪要` / `chat`，脚本会归为 `communication`。

## 四、去重与冲突

- 同一文档被多个关键词召回 -> 按 `origin` 去重，只落一份。
- 本地上传与知识库出现同名同日期文档 -> 保留本地上传（用户直接给的优先），在 `logs/extract_report.md` 记录跳过原因。
- 同一项目多份材料里完成率打架 -> 全部保留，证据包并列展示，由研判取最新一份并在 `evidence_gaps` 写明冲突。

## 五、检索不到时

不虚构、不硬凑。在 `data/projects.json` 对应项目的 `evidence_gaps` 里写清「知识库未检索到 <项目名> 的进度文档，已检索关键词：…」，看板详情面板会显示这条缺口。全局 `executive_summary` 里也要提一句材料覆盖度。

## 六、source_mode 标记

| 取值 | 含义 |
|---|---|
| `upload` | 只用会话上传文件 |
| `knowledge` | 只用知识库文档 |
| `mixed` | 两者合并 |
| `demo` | 演示数据（看板显示醒目标识） |

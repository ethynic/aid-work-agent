# 对照价格来源：资料库历史报价 + 互联网公开价格

比价的可信度取决于「对照组」是不是真的可比。本文件规定检索方式、留痕字段与可信度口径。
**总原则：宁可标「未见公开报价」，也不填估算价、不编 URL。**

## 1. 资料库历史报价单（source_type=library）

### 1.1 检索工具

| 通道 | 用途 |
|---|---|
| `knowledge_base_search` | 租户知识库内容语义检索，返回命中片段（text/doc_id）与文档信息（title/file_path） |
| `knowledge_file_search` | 按文件名/标题定位知识库文档，拿到 `file_path` 后可整读或交给 `extract_quotes.py` |
| `read` 类工具 | 读取文本型知识库文档片段，手工整理成 `library_prices.json` |

### 1.2 检索词构造

按「从精确到宽泛」三轮，命中即停：

1. `品名 + 关键规格 + 单价/报价`，例：`冷轧钢板 1.0mm*1250*2500 单价`
2. `品名 + 品牌/型号 + 价目表/框架价/历史报价`
3. `品名 + 报价单 / 采购价 / 中标价`（按年度、项目名再缩小）

同一品项找到多份历史价时，**全部保留**（不同 `supplier` 名，如「资料库-2025框架价」「资料库-2024项目A」），
让基准价用中位数而不是某一年的单点价；并在 `source_date` 写明报价日期，越旧的价格在摘要里提示时效。

### 1.3 取价与落库

- 命中文档为结构化报价单（xlsx/csv/docx）且 `file_path` 可访问 → 直接把 `file_path` 交给 `extract_quotes.py --source-type library --source-ref "<文档名>" --merge`。
- 只能读到文本片段 → 直接按 `data-contract.md` 第 8 节写 `library_prices.json`，字段至少包含
  `supplier / source_type=library / source_ref / source_date / name / spec / standard_uom / unit_price / currency / tax_included / unit_multiplier=1 / match_key`。
- 片段里只有「总价」没有「单价」→ 不推算，标「价格不完整」并跳过。
- 历史价与本次规格不一致 → 保留但 `note` 写明差异，并在「异常与不可比」提示；不要改规格硬配。

### 1.4 资料库未命中

`warnings` 里写「资料库未命中：<品名>」，继续走上传单之间 + 网络参考价的对比，不中断流程。

## 2. 互联网公开价格（source_type=web）

### 2.1 通道优先级

1. `web_search` / `web_fetch` 工具（默认通道）
2. `web-search-pro` 技能：用于工具不可用、需要百度系通道或批量抓取的场景
3. 仍不可达 → 写 `note="未见公开报价（检索通道不可用）"`，不猜价

### 2.2 query 模板

```
"<品名> <规格/型号> 单价 价格"
"<品牌> <型号> 官方报价 / 参考价"
"<品名> <规格> 1688 批发价 / 京东 自营 价格"
"<品名> 市场价格 行情 YYYY年MM月"
"<品名> 中标价 / 采购价 公告"（工程、大宗、设备类尤其有用）
```

中文品名走百度系，英文品名走 Google/Bing；需要国别站点时用 `site:` 限定。
每个品项尽量取 **2~3 个独立域名**的结果；单一来源要在 `note` 标注「单一来源」。

### 2.3 来源可信度顺序

| 级别 | 来源 | 说明 |
|---|---|---|
| A | 厂商官网价目表、官方旗舰店、公开招采/中标公告 | 规格与口径最清楚，优先采用 |
| B | 1688/京东自营/天猫官方店、行业价格指数、大宗商品现货行情 | 挂牌价，注意含运费/税/起订量 |
| C | 经销商报价页、资讯文章、问答/论坛里的价格 | 只作旁证，`note` 标「待核实」 |
| 排除 | 二手/拍卖/清仓价、明显不同规格、需登录询价、纯标题无金额页面 | 不写入 `unit_price` |

### 2.4 必填留痕字段

`source_ref` = 完整 URL（不要短链）；`source_date` = 采集当天；`note` 里写清：

- 价格类型：零售价 / 批发价 / 含税挂牌价 / 中标价 / 行情区间中值 / 参考价
- 口径差异：是否含税、是否含运费、最小起订量、包装单位、账期
- 规格吻合度：完全一致 / 近似（差在哪）/ 不同（不同则不要写进同一 `match_key`）
- 若页面给的是价格区间，取区间中值并在 `note` 标「区间中值 X~Y」

### 2.5 口径差异清单（对比时必须提示）

| 差异 | 为什么不能直接比 |
|---|---|
| 零售 vs 采购批量价 | 起订量、阶梯折扣不同 |
| 含税 vs 未税 | 13% 增值税即可造成两位数百分比偏差 |
| 含运费/安装 vs 出厂价 | 大宗、设备类运费占比高 |
| 单位不同（张/吨、箱/个） | 无换算系数时不能隐式换算 |
| 报价日期久远 | 原材料价格波动，需在摘要提示时效 |
| 品牌/等级/产地不同 | 同名不同档次，应标不可比 |

### 2.6 网络价在结果里的位置

- 默认 `flag=reference`，只出现在 Excel 的「网络参考」列与摘要的「网络参考价」段落，
  **不进入基准、不触发源报价单红绿标色**。
- 只有显式 `--include-web-in-baseline` 才参与基准；此时必须在摘要写明「基准含网络挂牌价，口径差异已放大」。
- 上传单和资料库都无价、只有网络价时，脚本会用网络价中位数做基准并标注「仅网络参考基准（非成交口径）」。

## 3. 禁止事项

1. 不用大模型「常识估价」冒充市场价或资料库价。
2. 不把搜索结果摘要里的数字当最终价格，尽量用 `web_fetch` 打开原文核对单位与含税口径。
3. 不编造 URL、文档名、报价日期；查不到就留空并在摘要说明。
4. 不把不同规格的低价拉进同一组制造「供应商偏贵」的结论。
5. 不因网络价更低就建议直接按网络价采购；网络价只作为议价参考线索。

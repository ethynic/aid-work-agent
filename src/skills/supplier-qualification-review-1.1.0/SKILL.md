# 供应商资质审查 · Supplier Qualification Review

## 一、技能定位

本技能对应「供应链采购」场景中的**供应商资质审查**环节。
给定供应商提交的资料，自动回答两个核心问题：

1. **资料是真的吗？**（真实性审查）——营业执照、公司名称、资质文件是否真实、一致、有效、无明显伪造痕迹。
2. **这家公司信用 / 风险如何？**（信用/风险审查）——是否存在失信、司法、行政处罚、经营异常等风险信号。

> **红线（务必遵守）**
> - 本技能**不内置任何搜索 / 联网方法**：SKILL.md 与 `scripts/` 中不得出现网络请求 / 爬虫 / 第三方数据 API 的调用或代码。
> - 需要外部数据（工商、司法、信用等）时，**必须由执行本技能的上级智能体**使用 `web_search` / `web_fetch` 工具完成（见阶段三）。
> - **绝不虚构**任何营业执照字段、资质编号、信用结论或风险事件。事实性内容缺失时标注「未提供 / 未能核验」，不可编造。

## 二、运行环境注意（必读）

- 每次 `skill_execute` 调用都在独立的临时工作目录中执行，调用间不共享 cwd。所有中间产物（字段抽取表、审查清单、报告 Markdown 草稿等）**必须用绝对路径**读写，统一放在 `$SKILL_TMP_DIR` 下的任务目录中（环境变量已注入，持久不清理）。
- 技能目录运行时为只读；`scripts/` 下的脚本通过 `skill_execute` 调用，脚本路径会被自动映射为绝对路径。
- 用户上传的文件路径来自会话上传信息（冒号后面是实际上传路径），**始终使用实际上传路径**，不要用原始文件名拼路径。

## 三、适用场景 / When to Use

- 用户上传或提供供应商的营业执照、公司名称、资质证书，要求「审查资质」「核验真伪」「供应商尽调」「准入审核」。
- 采购 / 招投标前需要判断供应商资料是否真实、是否有信用风险。
- 多份供应商资料需要横向比对、给出风险排序与准入建议。

## 四、输入资料

| 类别 | 说明 | 可接受形态 |
|---|---|---|
| 营业执照 | 供应商的营业执照（正本/副本/电子执照） | 图片 / PDF / 扫描件 / 文本 |
| 公司名称 | 供应商自报或合同中写明的公司全称 | 文本（也可从营业执照读取） |
| 资质文件 | 资质证书、安许证、行业许可证、认证体系证书、荣誉证书等 | 图片 / PDF / 扫描件 / 文本 |

> 缺少某项时**不要凭空编造**：在报告中标注「未提供」，并提示用户补充。若营业执照缺失，真实性审查阶段只能做「公司名称 + 公开信息」的有限核验。

## 五、工作流（四阶段）

### 阶段一：资料归集与字段抽取（本地，无联网）

1. **归集**：把用户提供的营业执照、公司名称、资质文件逐一列出，编号归档。
2. **视觉读取（OCR 替代）**：对营业执照图片/PDF，调用 `image_read` 工具逐份判读（不建议用纯文本 OCR，视觉模型直读可更好识别印章、排版）。判读 `question` 要求结构化输出全部字段，例如：

   ```
   image_read(image="<实际上传路径或 file_id>", question="请逐字读取这份营业执照并按以下字段结构化输出：公司名称（全称）、统一社会信用代码（18位）、类型、法定代表人、注册资本（金额+币种）、成立日期（YYYY-MM-DD）、营业期限（起止或长期）、经营范围、住所/注册地址、登记机关、发证日期（YYYY-MM-DD）。无法辨认的字段标注'无法辨认'，不要猜测。")
   ```

   | 字段 | 说明 |
   |---|---|
   | 公司名称（全称） | 与公章、正文一致 |
   | 统一社会信用代码 | 18 位 |
   | 类型 | 有限责任公司 / 股份有限公司 / 个体工商户 等 |
   | 法定代表人 | 姓名 |
   | 注册资本 | 金额 + 币种 |
   | 成立日期 | YYYY-MM-DD |
   | 营业期限 | 起止日期 / 长期 |
   | 经营范围 | 文本 |
   | 住所 / 注册地址 | 文本 |
   | 登记机关 | 文本 |
   | 发证日期 | YYYY-MM-DD |

   同样用 `image_read` 抽取每份资质文件的关键字段：证书名称、证书编号、持证单位、有效期（起止）、发证机关、资质等级/类别。字段规范与判断要点见 `references/field_specs.md`。
3. 把抽取结果填入报告「供应商基本信息」表，并标记每个字段的**来源与可信度**（图片直读 / 用户提供文本）。

### 阶段二：真实性审查（本地，纯逻辑，无联网）

逐项核查并给出 ✅/⚠️/❌：

1. **统一社会信用代码校验**：必须运行 `scripts/verify_uscc.py`（不要手算，避免人为差错）：

   ```
   skill_execute(skill="supplier-qualification-review", command="python3 scripts/verify_uscc.py <USCC>")             # 人类可读
   skill_execute(skill="supplier-qualification-review", command="python3 scripts/verify_uscc.py --json <USCC>")     # 结构化，供流程消费
   ```

   校验长度(18)、字符集(GB32100)、校验位(ISO 7064 MOD 11-3)、登记管理部门代码。
   若校验不通过 → ❌ 直接标记「代码非法/疑似伪造」。
2. **公司名称一致性**：营业执照名称 vs 用户提供的公司名称 vs 各资质文件持证单位，三者必须一致；不一致 → ⚠️ 标记并提示人工复核。
3. **资质有效期**：检查每份资质文件是否在有效期内（比对当前日期）。过期 → ⚠️/❌；未填写有效期 → ⚠️ 提示补充。
4. **编号格式合理性**：资质证书编号是否符合该类证书的常规编号规则（如建筑施工资质、安许证等），明显不合常理 → ⚠️。
5. **异常 / 伪造痕迹识别**（视觉判断）：模糊不清、关键信息被遮挡、印章缺角/模糊、字体/排版异常、PS 拼接痕迹、信息自相矛盾（如注册资本与成立时间明显不匹配）。发现任一 → ❌/⚠️ 并在报告中列出具体疑点。速查表见 `references/field_specs.md` 第四节。
6. 输出「真实性审查结论」：综合上述项给出 **真实 / 存疑 / 疑似伪造** 三档之一，并附逐条证据。可勾选清单见 `references/review_checklist.md` A 组。

### 阶段三：信用 / 风险审查（依赖上级智能体检索 —— 本技能不含任何搜索方法）

> **关键约定**：本技能**不实现任何联网/搜索逻辑**。需要外部工商、司法、信用数据时，
> **由执行本技能的上级智能体**使用 `web_search` / `web_fetch` 工具完成检索。
>
> 上级智能体按下面的「外部核查委托单」逐项检索，把**原始结果**回填到对应条目；
> 本技能只负责**消费返回数据**、做风险综合与定级，不自行发起任何网络请求。

**外部核查委托单（External Verification Brief）**——上级智能体对「公司名称 + 统一社会信用代码」执行以下检索，每条回填「检索摘要 + 来源 + 发现的风险信号」：

| 编号 | 核查项 | 建议检索关键词（模板） | 关注的风险信号 |
|---|---|---|---|
| C1 | 工商登记一致性 | `"<公司全称>" 统一社会信用代码 "<USCC>"` | 公开工商信息与公司自称是否一致；是否查无此号 |
| C2 | 失信被执行人 | `"<公司全称>" 失信被执行人 限制高消费` | 是否被列失信 / 限高 |
| C3 | 裁判文书 / 司法风险 | `"<公司全称>" 裁判文书 开庭公告 被执行人` | 作为被告的涉诉数量、标的额、案由 |
| C4 | 行政处罚 | `"<公司全称>" 行政处罚 市场监管` | 近 3 年处罚记录、处罚机关与事由 |
| C5 | 经营异常 / 严重违法 | `"<公司全称>" 经营异常名录 列入经营异常` | 是否列入经营异常 / 严重违法失信名单 |
| C6 | 股权冻结 / 出质 / 变更 | `"<公司全称>" 股权冻结 股权出质 工商变更` | 大股东股权冻结、频繁变更、注册资本抽逃线索 |
| C7 | 行业 / 舆情风险 | `"<公司全称>" 投诉 曝光 安全事故 质量` | 重大负面舆情、安全事故、质量纠纷 |
| C8 | （可选）资质公开核验 | `"<资质名称>" "<证书编号>"` | 资质编号是否在官方可查范围 / 有无冒用线索 |

> 上级智能体检索后，将每条 C1–C8 的「发现」回填；若某项检索无结果，标注「未检索到公开风险记录（不代表绝对无风险）」。委托单填报表样例见 `references/review_checklist.md` C 组。

**风险评级规则**（依据回填结果综合）：

| 等级 | 触发条件（满足任一即归入该档，取最高档） |
|---|---|
| 🔴 高风险 | C2 失信/限高命中；或 C3 重大被执行/大额诉讼；或 C5 列入严重违法失信；或阶段二判定「疑似伪造」 |
| 🟡 中风险 | C3/C4/C5/C6/C7 任一存在一般风险记录（如零星诉讼、单笔处罚、经营异常已移出、股权冻结线索） |
| 🟢 低风险 | C1–C8 均未检索到公开风险记录，且阶段二真实性审查为「真实」 |

### 阶段四：生成交付物（硬性输出要求 · 必须遵守）

本阶段产出**两份 Word（.docx）文件**，作为技能执行的唯一交付物：

| 序号 | 交付文件 | 内容来源 | 文件名约定 |
|---|---|---|---|
| 1 | `供应商资质审查报告_{公司全称}.docx` | 阶段一~三全部结论，按「六（1）审查报告内容模板」排版 | 例：`供应商资质审查报告_上海美丽华卫浴设备有限公司.docx` |
| 2 | `供应商需补交材料清单_{公司全称}.docx` | 依据审查结论列出的待补/待核材料，按「六（2）补交材料清单内容模板」排版 | 例：`供应商需补交材料清单_上海美丽华卫浴设备有限公司.docx` |

> **输出形式红线（务必遵守）**
> - **交付物是两份 Word 文件，对话里只给简短总结**：聊天回复中**只写一段简短总结**（通常 5~10 行以内）：核心结论、风险等级、最关键的几项待补材料、以及文件下载链接；**不要把报告正文、清单全文等大段文字粘贴到聊天里**。详细数据、核查表、逐条证据一律放在 Word 内。
> - **生成方式**：按第六节模板把正文写成 Markdown，调用 `word_process` 工具（传 `content` 为 Markdown 正文、`content_type` 为 markdown、`output_name` 为约定文件名）分别生成两份 docx；生成后用 `cp` 工具注册下载链接交付用户。本技能自身不实现 Office 转换逻辑，只负责定义内容与模板。
> - **补交材料清单必须生成**：无论审查结论为「准入 / 条件准入 / 否决」，都应输出第 2 份文件（条件准入/否决时列必备与建议材料；结论为直接准入时，至少列出「建议类」备查材料，不得省略）。
> - 原「Markdown 报告」不再作为交付物（可仅作为内部中间格式），对外交付形态固定为上述两份 `.docx`。

### （2）补交材料清单内容模板（Word 文档 2）

清单条目由阶段四依据审查结论逐条推导：每一个 ⚠️/❌ 疑点、每一项「未提供/未能核验」的资质都必须对应一条待补或待核材料。

```
# 供应商需补交材料清单

> 供应商：{公司全称}　|　统一社会信用代码：{USCC}　|　出具日期：{YYYY-MM-DD}

## 一、材料清单
| 序号 | 材料名称 | 用途/核对要点 | 必要性 | 备注 |
|---|---|---|---|---|
| 1 | … | … | 必备 | … |
| 2 | … | … | 建议 | … |

> 必要性分两档：**必备** = 缺失则无法完成准入判定，须在签约前提供；**建议** = 增强项，用于佐证持续履约与质量能力。

## 二、提交与复核流程
| 环节 | 责任方 | 动作 | 输出 |
|---|---|---|---|
| 提交 | 供应商 | 按清单提交材料 | 盖章材料/证明文件 |
| 受理 | 采购对接人 | 清点、核验份数与有效期 | 收件登记 |
| 复核 | 合规/风控 | 逐项比对，判定必备项是否齐备 | 复核意见 |
| 准入决定 | 决策人 | 给出准入 / 条件准入 / 否决 | 准入结论 |
```

## 七、注意事项

- **事实不可编造**：任何字段、编号、信用/风险事件缺失时标注「未提供 / 未能核验」，不得臆造。
- **外部核查是辅助而非背书**：公开检索无记录不代表绝对无风险，报告中须注明此局限。
- **数据时效**：资质有效期、工商状态以「当前日期」为基准比对；审查报告应注明生成日期。
- **隐私与合规**：仅用于合规的供应商准入与尽调，不得用于非法人肉搜索或侵犯商业秘密。
- **可复现**：阶段二的 USCC 校验务必调用 `scripts/verify_uscc.py`，不要手算，避免人为差错。
- **交付形式**：对外只交付两份 `.docx`（审查报告 + 补交材料清单）；聊天回复中给简短总结即可，不要粘贴大段正文。

## 八、配套文件

- `scripts/verify_uscc.py`：统一社会信用代码本地校验（纯算法，无联网）。
- `references/field_specs.md`：营业执照字段规范、GB32100 编码规则、常见资质文件清单与有效期判断要点、伪造痕迹速查。
- `references/review_checklist.md`：可勾选的审查清单 + 外部核查委托单填报表样例。

## 九、不要使用本技能

- 单纯「帮我看看这张图片写了什么」的通用读图需求，直接用 `image_read` 即可，无需走本技能四阶段流程。
- 已有内部供应商管理系统且只需录入/查询供应商档案（无真实性核验与风险审查诉求）的场景。

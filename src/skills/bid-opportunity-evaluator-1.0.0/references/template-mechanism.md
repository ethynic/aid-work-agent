# 模版机制（Template Mechanism）

> 评估报告的**最终产出永远是 Word 文件**，且**优先按用户/资料库指定的模版排版**。

---

## 一、模版查找优先级（三选一，按序）

| 优先级 | 来源 | 获取方式 | 判定 |
|---|---|---|---|
| **① 最高** | **会话中用户提供的模版** | 用户在对话里给出的附件/路径/正文 | 有则直接用，不检索 |
| **② 次高** | **资料库中的评估报告模版** | 上层 Agent 用 `knowledge_search` 检索 | 检索到且确为模版则下载后用 |
| **③ 兜底** | **技能自带模版** | `assets/投标可行性评估报告模板.docx` | 前两者都没有时使用 |

**关键**：优先级 ① 与 ② 由**上层 Agent** 判定与获取；本技能只负责「按给定模版填充」。

### 判定要点

- 资料库检索结果**必须确认是「模版/模板」**（含占位符、空白表格、章节骨架），而不是一份已填好的历史报告。
  检索命中但不是模版 → 继续往下走，最终用自带模版。
- 检索结果无命中 → 明确告知「资料库中未找到评估报告模版，已使用技能自带模版」，不要含糊带过。
- 资料库部分来源不可用时（`unavailable` 非空），须在输出中说明**实际检索范围**，
  不把「没搜到」说成「不存在」。

---

## 二、模版占位符协议

若模版带占位符，填充最精确。支持的写法：

| 写法 | 含义 | 填充内容 |
|---|---|---|
| `{{项目名称}}` | 纯文本 | 招标项目全称 |
| `{{报告标题}}` | 纯文本 | 报告标题（默认「投标可行性评估报告」） |
| `{{投标人名称}}` | 纯文本 | 投标人全称（来自 `company_profile.company`） |
| `{{评估日期}}` | 纯文本 | 评估日期 |
| `{{结论}}` | 纯文本 | 决策标签（GO/CAUTION/NO_GO 对应中文） |
| `{{综合评分}}` | 纯文本 | 如「75.5 / 100」 |
| `{{表格:结论摘要}}` | 表格 | 在该段落位置插入对应表格 |
| `{{表格:项目概况}}` | 表格 | 同上 |
| `{{表格:资格门槛核对}}` | 表格 | 同上 |
| `{{表格:评分卡}}` | 表格 | 同上 |
| `{{表格:财务测算}}` | 表格 | 同上 |
| `{{表格:风险清单}}` | 表格 | 同上 |
| `{{段落:结论说明}}` | 段落 | 插入该段落组 |
| `{{段落:不满足项说明}}` | 段落 | 同上 |
| `{{段落:报价建议}}` | 段落 | 同上 |
| `{{段落:竞争格局}}` | 段落 | 同上 |
| `{{段落:战略价值}}` | 段落 | 同上 |
| `{{段落:投标建议}}` | 段落 | 同上 |
| `{{段落:评估说明}}` | 段落 | 同上 |

占位符段落本身会被清空，内容插在其后 —— 不会出现重复文字。

---

## 三、无占位符的模版：章节语义匹配

用户自带的模版通常没有占位符。此时按**章节标题语义**匹配：

1. 归一化标题：去掉「一、」「（一）」「1.」「第一章」等编号前缀与空格
2. 计算每个（章节 × 内容块）的命中得分：
   - 关键词出现在归一化标题：+3
   - 出现在完整标题：+2
   - 出现在标题串中：+1
3. 得分高者优先占位；一个章节只接受一个内容块，一个内容块只进一个章节
4. 剩余内容块**就近合并**到语义最接近的已匹配章节；实在无处可去的才追加到末尾「补充说明」

### 默认关键词映射

| 内容块 | 匹配关键词（节选） |
|---|---|
| 结论摘要 | 结论、决策、研判结论、是否参与、最终意见、总体意见、意见 |
| 项目概况 | 概况、项目情况、基本信息、项目简介、项目内容、研判基本信息 |
| 资格门槛核对 | 资格、门槛、符合性、资质条件、是否符合、投标资格 |
| 评分卡 | 评分、打分、评价、权重、评分结果、得分、综合评价 |
| 财务测算 | 财务、经济、测算、成本、资金、报价、经济性 |
| 竞争格局 | 竞争、对手、市场格局、竞争对手 |
| 战略价值 | 战略、长期价值、战略意义 |
| 风险清单 | 风险、隐患、风险与对策、风险应对 |
| 投标建议 | 投标建议、行动建议、结论与建议、应对措施、建议 |
| 评估说明 | 说明、免责、声明、备注、编制说明 |
| 不满足项说明 | 不满足、不符合项、差距 |
| 报价建议 | 报价建议、价格建议 |
| 结论说明 | 结论说明、判定理由、理由 |

**自定义映射**：准备一个 `mapping.json` 传给 `--mapping`：

```json
{
  "keywords": {
    "结论摘要": ["我的结论章节标题关键词"],
    "项目概况": ["我的项目情况章节关键词"]
  }
}
```

只需写要改的键，其余沿用默认（脚本会做深合并）。

## 四、填充引擎行为保证

| 项 | 保证 |
|---|---|
| 模版样式 | **保留**。页眉页脚、页面设置、字体样式、章节编号全部沿用模版 |
| 章节结构 | **保留**。模版有 5 章就还是 5 章，不擅自增加章节 |
| 内容完整 | 所有评估内容块都会落位（13/13），不丢失 |
| 残留占位符 | 无。填充后占位符段落清空 |
| 空章节 | 模版里的占位表格若与内容表头不匹配，原样保留（供人工填），不删用户表格 |

> **注意**：模版原有表格不会被删除。若模版自带空白表格，填充表格会作为**新表**插入在其后，
> 这是刻意的 —— 不擅自删除用户模版里的结构。

---

## 五、推荐工作流

```bash
# 1) 上层 Agent 定位模版（会话附件 → 资料库 → 自带）
#    会话附件：直接拿到本地路径
#    资料库：knowledge_search → 下载到本地 → 拿到路径
#    都无：使用 assets/投标可行性评估报告模板.docx

# 2) 解析模版结构（确认章节与占位符）
python scripts/inspect_template.py <模版.docx> --out work/template/

# 3) 评估决策（先出结论）
python scripts/evaluate_bid.py --profile ... --company ... --assessment ... --out work/eval/

# 4) 按模版填充，产出最终 Word
python scripts/fill_template.py \
    --evaluation work/eval/evaluation.json \
    --template <模版.docx> \
    --out 输出目录/ \
    [--mapping work/template/mapping.json]
```

**交付物**：`输出目录/投标可行性评估报告-<项目名>.docx`
（唯一正式产出；`evaluation.json` 与 `EVALUATION.md` 为过程件，供复核）

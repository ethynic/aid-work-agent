# 投标可行性评估方法论

> 供 `bid-opportunity-evaluator` 使用。脚本负责客观计算，本文负责判断标尺与分析框架。

---

## 一、硬性资格门槛清单（逐条比对，缺一即 NO_GO）

| # | 门槛 | 常见要求形态 | 我方档案字段 | 判定 |
|---|---|---|---|---|
| 1 | 主体资格 | 境内注册、有效独立法人 | `capability.legal_entity` | 布尔 |
| 2 | 经营范围 | 含本次采购品类 | `capability.scope_covers` | 布尔 |
| 3 | 资质许可 | 生产许可证（制造商）/ 厂家唯一授权书（经销商） | `capability.has_license_or_authorization` | 布尔 |
| 4 | 财务要求 | 上年度审计报告 或 近 N 季度报表（含资产负债表、利润表） | `finance.has_audit_report` | 布尔 |
| 5 | 纳税社保 | 任意 3 个月纳税证明 + 社保记录 | `tax_social.has_records` | 布尔 |
| 6 | 类似业绩 | 近 N 年 / 数量 ≥X / 单项金额 ≥Y / 同类型 | `performance.projects` | 按条件过滤后计数 |
| 7 | 信誉 | 无失信、无严重违法、无骗取中标 | `credit.clean` | 布尔 |
| 8 | 联合体 | 接受 / 不接受 | `use_jv` | 不接受时须独立投标 |
| 9 | 保证金承受 | 保证金 ≤ 我方可承受额度 | `finance.max_bond_bearable` | 金额比较 |
| 10 | 分包/禁包 | 是否允许分包 | `use_subcontract` | 布尔 |
| 11 | 地域/注册地限制 | 是否要求本地注册或本地分公司 | `local_presence` | 布尔 |

> 判定原则：**只依据招标文件原文与我方档案的客观比对**。
> 招标文件未提及的门槛不凭空添加；我方档案未填的项标为 `[待补充]` 并提示人工确认，
> **不得默认判定为「满足」**。

## 二、规模指标提取（通用，不绑定行业）

招标文件的规模描述分散在「项目概况」「项目规模」「数量、技术规格」与采购清单表。

### 单位词典

| 类别 | 单位 |
|---|---|
| 计数 | 台 套 台套 台份 个 部 件 辆 座 栋 幢 组 副 支 面 处 项 标段 |
| 面积 | m² ㎡ m2 平方米 |
| 体积 | m³ 立方米 |
| 长度 | 延米 米 m km 公里 |
| 重量 | 吨 t kg |
| 批次 | 批 批次 |

### 提取优先级

1. **采购清单表**（权威）：定位表头含「暂估数量 / 工程量 / 数量」的表，
   取「名称列 + 数量列 + 单位列」逐行提取。
2. **正文散句**（补充）：正则匹配「数量+单位」，但必须过滤噪声上下文 ——
   章节编号（2.1）、年份（2026 年）、金额（13,438,990.93 元）、百分比、URL、栏目标题。

### 已知坑

- 招标文件清单表的**单位列常有空缺**（如某行单位缺失，下一行才有）→ 沿用同表上一行单位。
- 数量列与单位列可能错位（合并单元格）→ 数量列只取纯数字，不跨列吸收。
- 「2.1 项目名称：」这类「编号+标题」会被误判为数量 → 前文全为编号时判为噪声。
- 面积合计要与分项逐条核对，**差值必须为 0**。

## 三、财务测算口径

```
资金占用 = 投标保证金 + 履约保证金 + 招标代理服务费
资金占用率 = 资金占用 ÷ 最高投标限价
估算成本线 = 最高投标限价 × (1 − 目标毛利率)
目标毛利   = 最高投标限价 − 估算成本线
```

### 报价策略推导

评标办法给出价格扣分规则时，按下式反推最优报价区间：

```
若「高于基准价 1% 扣 A 分、低于基准价 1% 扣 B 分」且 A > B
  → 报价应略低于限价（低于基准价一侧扣分更慢）
  → 建议区间：限价 × (1 − 5%) ~ 限价 × (1 − 2%)
```

理由：基准价是有效报价的算术平均值。报价接近基准价时得分最高；
明显低于限价未必是优势（若他人报价更高，反而拉低基准价导致失分）。

**禁止**：低于成本报价。脚本按目标毛利率给出成本线，
若报价低于成本线则标记 `below_cost_floor` 并升为高风险。

## 四、六维评分标尺

每维 0~100 分，加权后满分 100。客观项由脚本算，主观项由评估人打分并写依据。

### 1. 资质与能力匹配（25%，客观）

```
得分 = 硬门槛通过率 × 70 + 产品参数满足度 × 30
```

产品参数满足度 = 满足招标技术要求的条目数 ÷ 总条目数 × 100。
**零负偏离是硬要求**（招标文件常规定「不允许负偏离」），有负偏离时该分项须大幅下调。

### 2. 业绩匹配度（15%，客观）

```
有明确数量要求：得分 = min(100, 可用业绩数 ÷ 要求数 × 100)
无数量要求：取 85（优于平均）
```

可用业绩 = 满足「年限 + 类型 + 单项金额」全部过滤条件的项。

### 3. 商务条件可接受度（15%，主观）

逐项打分并写依据：

| 项 | 打分要点 |
|---|---|
| 付款条件 | 预付款比例、账期长���、结算节点、质保金比例 |
| 结算方式 | 结算周期、结算资料要求、审核时长、迟付责任 |
| 质量保修期 | 期限与行业惯例对比、备品备件责任 |
| 违约责任 | 违约金比例、赔偿范围、滞纳金、场地租赁费等 |
| 交货方式 | 车板交货/卸货责任、运输风险划分、准时率要求 |

### 4. 经济性（20%，客观）

```
毛利率映射：10% → 0 分，30% → 100 分，线性
资金占用率 ≤3%   → +8 分
资金占用率 >15%  → −15 分
```

### 5. 竞争格局（15%，半规则）

判断要素：
- **参与者数量与层级**：预计几家投标？是否头部品牌正面竞争？
- **壁垒高低**：业绩、资质、区域服务能力是否构成实质门槛？
- **价格战概率**：品类是否同质化严重？
- **对手画像**：主要竞争者是谁？他们的短板是什么？
- **议价空间**：我方在成本、产能、账期上有无差异化优势？

#### 竞品分析（两层结构）

竞品分析分两层，**目的不同、来源不同、不可互相替代**：

| 层 | 名称 | 来源 | 输出 |
|---|---|---|---|
| 实证层 | 实证竞品 | 上层 Agent 检索 / 我方市场情报 → `competitors.json` | 逐家分析表（真实企业名） |
| 结构层 | 竞争者类型画像 | 脚本从招标文件客观特征推导 | 竞争者类型表（不含任何企业名） |

**实证竞品**：必须是**可指认的真实企业名**。
「竞品A」「某某公司」「XX企业」「待补充」等代号**一律不得进入报告**——
它们在决策上零价值，且会让报告看起来像没有做完。
`competitor_intel.py verify` 会自动识别并剔除这类代号，同时剔除重复项。

**竞争者类型画像**：在尚未取得实证竞品名单时，本层本身就是可执行的竞争分析。
它刻画「本项目会吸引哪几类对手、它们凭什么是、威胁在哪、我方怎么应对」，
**全程不出现任何企业名称**。画像类型与触发条件：

| 类型 | 触发条件 | 威胁要点 |
|---|---|---|
| 头部品牌型 | 招标文件设品牌门槛（十大品牌/知名品牌/品牌影响力评分/唯一授权书） | 品牌类评分直接领先，报价含品牌溢价 |
| 价格导向型 | 价格分权重 ≥ 30 分 | 以低价切入，压缩合理利润空间 |
| 区域深耕型 | 恒定候选（属地交付敏感） | 本地熟悉度与响应速度占优，账期谈判意愿强 |
| 工程集采型 | 招标人为总承包/地产商 | 长账期下现金流成本更低 |
| 业绩壁垒型 | 评标含类似项目业绩 | 熟悉验收与资料口径，精准踩点得分 |
| 新进入者/跨品类进入 | 恒定候选 | 低价搅局，根基浅 |
| 参与主体收敛效应 | 同时设品牌门槛且项目金额可观 | 实际参与家数少于表面预期 |

**威胁度算法（实证竞品）**：基准 50 分，按下列因素加减——
价格型/经济价格带 +(价格分权重 − 20)×0.6；品牌型 +12；区域型 +8；
新进入者 −10；重合度高 +10 / 低 −8；已知不参与本项目 −15；区间裁剪至 5~100。

**应对建议按类型自动生成**：
价格型 → 不宜正面低价跟进，以交付能力与质量稳定性差异化；
品牌型 → 以客户体系既有业绩与服务网络形成差异；
区域型 → 发挥本地化服务与响应速度优势；
新进入者 → 以履约承诺函与样板稳固客户预期；
重合度高 → 重点在方案差异化与评分点全覆盖；
有明确劣势 → 针对其弱项强化我方表述。

**数据来源要求**：每家竞品须给出可追溯来源（企业官网 / 公共资源交易平台中标公告 /
公开报道 / 我方历史投标记录），并记录在 `evidence` 字段，报告会标注来源。

**绝不虚构**：未提供竞品名单时，报告明确写「尚未取得可指认的实证竞品名单
（不以代号代替真实企业名）」，只给画像分析。

**报告呈现结构（按类型分组，组下列品牌）**：

主表「竞争者类型」：竞争者类型 / 该类型下的具体品牌 / 家数 / 最高威胁度 /
对本项目的威胁点 / 我方应对策略。
- 每种类型必占一行，**不留空**；
- 有实证品牌 → 列出「品牌名（威胁度 X）」，组内按威胁度降序；
- 无实证品牌 → 「该类型尚未识别到具体品牌 —— 应为具备〈该类型特征〉的企业」。

细表「竞争者（具体品牌）」：实证竞品逐家展开
（品牌 / 类型 / 定位 / 区域 / 价格带 / 重合度 / 威胁度 / 优势 / 劣势 / 应对）。

**竞争格局正文按类型点名品牌**，句式：
「已识别可指认的竞争者 N 家，按类型分布为 —— 类型A X 家：A、B、C；类型B Y 家：D、E」；
并追加「威胁度 ≥60 需重点应对：…」与「尚缺该类竞争者的具体品牌：…，建议补充检索后重评」。

**竞品检索的优先顺序**（决定报告里出现哪类品牌）：
1. 同区域同品类的中标公告（公共资源交易平台）—— 最能反映真实对手；
2. 当地监管抽检公示（市场监督管理局建材抽检结果，含本地经销商与在售品牌）；
3. 品牌官网与行业榜单——头部品牌型；
4. 我方历史投标记录（开标记录）。

## 五、风险分类与应对

| 等级 | 定义 | 必填内容 |
|---|---|---|
| **高** | 可能导致否决投标或重大亏损 | 描述 + 具体应对措施 + 责任人 |
| **中** | 影响得分或利润，可控 | 描述 + 应对措施 |
| **低** | 需注意的执行细节 | 描述 + 应对措施 |

常见风险清单（按招标文件逐条扫）：

1. **时限类**：截止时间、开标需到场核验的材料（法人授权书原件、担保原件）
2. **签章类**：未签字盖章即否决；骑缝章/逐页章；承诺书未填未签即否决
3. **报价类**：超最高限价；大小写不一致；分项合价不等于总价；基准价法下的低价失分
4. **清单类**：同名不同规格的条目（极易串行）；暂估数量与实际结算差异
5. **商务类**：付款条件苛刻；违约条款过重；质保期与备品备件责任
6. **信用类**：信用中国/执行信息公开网查询结果；近三年诉讼与仲裁
7. **形式类**：份数、装订、密封、封套字样、电子版格式与盖章版 PDF 一致性

## 六、结论表述规范

结论三档，对应固定话术：

| 结论 | 表述模板 |
|---|---|
| GO | 「硬性门槛全部满足（X/X），综合评分 N 分（满分 100），建议参与投标」+ 2~4 条行动建议 |
| CAUTION | 「硬性门槛满足但综合评分仅 N 分 / 或剩余时间不足」，须先列明**补偿措施**，再给条件式结论 |
| NO_GO | 「存在 X 项硬性资格门槛不满足：……」，逐条列明，并说明「若补齐则结论可能改变」 |

> **不允许**只给分数不给理由，或给出「建议积极参与」这类无依据表述。
> NO_GO 也应给出补救路径（哪一项不满足、需要什么才能满足）。

竞品名单**不放在 company_profile.json 里**，而是独立成 `competitors.json`
（由 `competitor_intel.py verify` 产出），避免公司档案与市场情报混在一起。

> `annual_output` 支持中文数量级表述（「超 2 亿平方米」「1.5 万吨」「500 万套」），
> 脚本会自动换算；千分位逗号亦可（`2,000 万`）。
> 未提供竞品清单时，报告会明确标注「尚未取得可指认的实证竞品名单」，
> 并给出竞争者类型画像，**不会虚构竞品，也不会输出代号**。

### `competitors.json` 格式

```jsonc
{
  "source": "数据来源说明（会印在报告里）",
  "competitors": [
    {
      "name": "真实企业/品牌名称",       // 必填；代号会被 verify 剔除
      "type": "品牌型|区域型|价格型|工程型|新进入者",
      "positioning": "品牌定位",
      "region": "主要经营区域",
      "price_band": "高档|中档|经济",
      "overlap": "高|中|低",
      "in_project": null,                // true/false/null=未知
      "strength": "相对我方的优势",
      "weakness": "相对我方的劣势",
      "evidence": "可追溯来源：中标公告 / 企业官网 / 我方投标记录"
    }
  ]
}
```

生成与校验：

```bash
# ① 生成检索任务书（不含任何企业名）
python scripts/competitor_intel.py probe --profile work/profile/tender_profile.json \
    --company work/company_profile.json --out work/competitor_brief.json

# ② 上层 Agent 按任务书检索真实竞品 → 填 competitors_raw.json

# ③ 校验（剔除代号与重复项）
python scripts/competitor_intel.py verify --input competitors_raw.json \
    --out work/competitors.json

# ④ 带竞品跑评估
python scripts/run_pipeline.py --tender <招标文件> \
    --company work/company_profile.json --competitors work/competitors.json \
    --out work/eval
```

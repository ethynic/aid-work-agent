# 知识库检索与规格一致性判定指南

本技能「智能」环节（检索、判定、建议价）由 agent 在对话中完成，脚本不做。本文说明怎么做。

## 1. 价格资料来源

### A. 租户知识库——默认

用本环境知识库工具检索租户已入库的产品与价格资料（文档 / 表格 / CSV 均可被检索）：

- **`knowledge_file_search`（按文件名定位，优先）**：价目表、产品目录这类「产品-规格-价格」整表资料，先按文件名关键词定位（如「价目表」「产品目录」「price list」「产品手册」），命中后按文档内容查价。整表资料按文件查比逐条语义检索更准、更快。
- **`knowledge_base_search`（语义检索）**：按条目「中文名/英文名 + 关键规格」构造检索词，如 `单人沙发 velvet W700`。返回文本片段，从中**提取产品名与单价**，并记录来源文档名。

> 两种方式可并行：先用 `knowledge_file_search` 定位整表价目（精确），未命中再走 `knowledge_base_search`（语义）。检索范围（本租户栏目授权、跨租户共享）由工具层自动收口，技能层不做任何租户过滤或拼接。

### B. 用户会话内上传的本地价目表（Excel/CSV）

若用户在会话中给出一份「产品-规格-价格」表（文件已落在会话附件目录 / `$SKILL_TMP_DIR`）：

- CSV：直接读取，或 `python -c` 解析。
- Excel：用 `openpyxl` 读取。
- 建一个内存索引 `产品名/规格关键字 -> 单价/来源`，后续按条目查表即可，速度更快、价格更准。

> 两种方式可并行：先查本地价目表（精确），未命中再查知识库（语义）。

## 2. 匹配与规格一致性判定

对每条 `in_scope` 条目，取它的 `spec_bullets`（解析自 B 列描述）作为「待匹配规格」。

| 判定 | 处理 | 字段填写 |
|---|---|---|
| 知识库有同款且**关键规格一致**（尺寸/材质/颜色/品牌/型号均对得上） | 直接采用知识库单价 | `unit_price`=库价，`source="知识库-KB"`，`kb_match`=库产品名 + 来源文档名，`spec_consistent=true` |
| 知识库有、**关键规格不一致**（任一关键项不同 → 视为替换产品） | 采用替换产品单价，并留痕；**替换汇总经用户确认后才回填** | `unit_price`=替换价，`source="知识库-KB(替换)"`，`spec_consistent=false`，`replacement_desc`=「原：… → 替换：… 差异理由」 |
| **关键规格存疑 / KB 命中多条候选无法确证** | 降级，不自动成交 | `unit_price`=空，`source="待确认"`，`note`=存疑点（如「KB 命中 A/B 两款，饰面无法确证」） |
| 知识库无 | 留待阶段 3 询问 AI 建议价 | `unit_price`=空，`source=null` |

**「关键规格」指**：尺寸/长×宽×高、材质、颜色/饰面、品牌、型号、功率/容量等影响价格与功能的要素。文字表述差异（同义不同词）不算不一致；实质参数不同才算。

**证据要求**：`kb_match` 必须记录来源文档名；文档内价格与规格无法同时确证时（如片段只有品名没有价），按「待确认」处理。

## 3. 币种

清单与知识库价目币种不一致时**不得直接填价**（不做汇率换算）：`source="待确认"`，`note` 写明「清单币种 X vs 价目币种 Y」。同一知识库内币种以价目表标注为准。

## 4. 建议参考价（缺项时）

阶段 3 用户同意由大模型给价时：

- 基于市场常识给 `unit_price`，合理估算区间或单一值均可。
- `source="AI建议参考价"`，`note="大模型建议，非成交价，需复核"`。
- 必须让用户知道这是 AI 估算，不是知识库或真实报价。

## 5. 来源标注规范（硬约束）

- 知识库直接匹配：`知识库-KB`
- 知识库替换匹配：`知识库-KB(替换)`
- AI 建议：`AI建议参考价`
- 用户明确不要、留空待询价：`未报价`
- 规格存疑 / 多候选无法确证 / 币种不一致：`待确认`

任何价格都必须能回溯到上述来源之一；不允许无来源的价格。

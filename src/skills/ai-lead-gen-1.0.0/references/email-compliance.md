# 冷邮件合规要求

第 11 步发送前必读。**先确定目标地区适用哪套法规，再开始发。**

## 一、按地区的硬性要求

### 欧盟 / 英国（GDPR + ePrivacy）

冷邮件本身不是绝对禁止，但必须满足**合法利益（Legitimate Interest）**评估：

三项测试：
1. **目的测试**：目的是否正当（获客通常正当）
2. **必要性测试**：冷邮件是否是达成目的的必要手段（是否能用更轻的手段？）
3. **利益平衡测试**：对方利益是否被不当侵害

**实际操作要点**：
- 发给**与产品对应的公司职能邮箱**（`purchasing@`、`export@`、`production@`）风险较低，且商业效果最好 —— 这类地址既可识别企业归属，又确实是对口的决策口
- 发给**公司域名下的个人企业邮箱**（`j.doe@company.com`）风险居中：可识别企业归属、便于退订，优于私人邮箱；但仍属"个人化触达"，需做利益平衡测试，并在首封明确身份与拒绝方式
- 发给**私人邮箱**（gmail/gmx/web.de/hotmail 等个人邮箱服务）风险最高，难验证企业归属，德国等地区近乎禁止；仅在确无公司邮箱且其本人公开用于商务时慎用
- ⚠️ **公开窗口（`info@` `contact@` `office@`）合规风险最低，但本技能不作为目标邮箱使用** —— 它们没有负责人，回复率极低。本技能的做法是改用官网表单，或按 `references/contact-discovery.md` 路径 2→5 去找对口负责人/部门邮箱。**发到公开窗口不算"合规所以可行"**
- ⚠️ **无关职能邮箱（招聘/财务/法务/公关）不发** —— 合规上勉强过得去，但把推销邮件递到这些信箱是明确的骚扰信号，可能被举报并损害发件域名声誉
- 首次接触需在邮件中**明确告知身份与来意**，让对方能立刻理解并拒绝
- 必须在首封就提供**便捷的拒绝方式**（回复退订，一键生效）
- 各国可能有更严的本地规则：德国 UWG（严），法国 LCEN，法国 CNIL 对 B2C 与 B2B 区别对待
- **德国尤其注意**：对个人邮箱的冷邮件在德国判定为违法，除非对方事先有"事实上的商业关系"或明确的利益相关表示。发给公司职能邮箱相对安全

**数据主体权利**（收到后必须响应）：
- 访问权：对方问"你们有什么关于我的数据" → 必须提供
- 删除权：要求删除 → 72 小时内从所有系统删除
- 反对权：要求不再联系 → 立即加入全局退订名单，永久不再发

### 美国（CAN-SPAM Act）

必须满足四项，缺一即违法：
1. 主题行**不得**误导或冒充内部邮件（禁止 `Re:`、`Fwd:` 伪装）
2. 识别为**广告**的义务（除非已有肯定同意的收件人）
3. 有效**物理寄件地址**
4. **可用的退订机制**，且 10 个工作日内生效

其他：退订后不得以任何身份再发该主题邮件。

### 加拿大（CASL）

最严格之一：
- 发给**个人邮箱**的营销邮件需**明确同意（express consent）**，或满足"商业关系（existing business relationship）"或"一致的商业行为（consistent business activities）"豁免
- 豁免情况必须**留存书面记录**，说明为何适用豁免
- 加拿大是本技能合规风险最高的目的地，**默认按需同意处理**，即不做大规模个人邮箱冷邮件

### 中国（个人信息保护法 PIPL + 反垃圾邮件）

- 处理个人信息需有合法基础，商业营销属"同意"场景
- 需提供**便捷的拒绝方式**
- 需明示收集使用目的、范围
- 商业性电子邮件发送需遵守《互联网电子邮件服务管理办法》

### 新加坡（PDPA）

- 需告知收集用途并取得同意，或适用"合理利益"豁免
- 需提供退订渠道
- 营销邮件主题不得误导

### 日本（特定商取引法 + 个人信息保护法）

- B2B 邮件营销实务上较宽松，但仍需可退订
- 日本企业高度重视**敬语与格式**，语言生硬会直接导致沟通失败
- 第一封建议日语，并附英语版

### 其他地区速查

| 地区 | 要点 |
|---|---|
| 澳大利亚（Spam Act） | 严格，需事先同意才能发商业邮件，处罚极高。**默认不发** |
| 巴西（LGPD） | 需合法基础，营销需透明告知 |
| 俄罗斯 | 需事先同意，可撤回 |
| 中东（UAE/沙特） | 需事先同意 |
| 印度 | 数据保护法 2023，需同意 |

## 二、通用安全规则（无论哪个地区）

1. **新发件域名的日限额**（按**累计已发数**分档，与 `send_emails.py` 的
   `rampup_cap()` 完全一致，跨天不清零）：

   | 累计已成功发出 | 建议日限 |
   |---|---|
   | 0 – 49 封 | 20 / 天 |
   | 50 – 149 封 | 50 / 天 |
   | 150 – 499 封 | 100 / 天 |
   | ≥ 500 封 | **200 / 天**（生产基准；稳定后按专属 IP 与声誉放量至 300-500） |

   新域名/新 IP 直接 200/天极易被 Gmail/Microsoft 拉黑，反而无法持续。
   前三档的小步预热是为了让 200/天**长期跑得通**，而非卡在垃圾箱。
2. **同一域名 24 小时内 ≤ 3 封**（防止把一家公司的多个邮箱轰炸）。
   注意这是当天实际可发量的真正瓶颈：`daily_limit=200` 需要名单里有约
   67 个不同的收件域名才发得满；被限的邮件留在队列次日续发。
3. **单次批量发送前先发 3 封测试**给自己邮箱
4. **退订名单全局生效**：任何人要求停止联系，无论哪个 campaign，立即加入永久退订名单
5. **不采集敏感个人数据**：种族、宗教、政治倾向、健康状况、金融账户、工会身份、性取向一律不碰
6. **不冒充**：不用 `Re:`/`Fwd:` 伪装，不伪造发件人，不伪造已有关系
7. **留档**：保存发送日志与同意/豁免记录，保存期限 ≥ 2 年

## 三、发送前必须完成的检查

```
[ ] 已确定目标国家适用哪套法规
[ ] 已完成合法利益评估（欧盟/英国）或豁免记录（加拿大/澳大利亚）
[ ] 每封邮件含明确身份说明与拒绝方式
[ ] 每封邮件含合规退订机制（法律要求的地区）
[ ] 物理寄件地址已配置（美国/加拿大必需）
[ ] 退订链接真实可用（点一下验证）
[ ] 已在 sends.csv 中标记合规等级
[ ] 日发送量在 ramp-up 限额内
[ ] 已发 3 封测试并确认送达
[ ] 邮件预览 + 发送计划已写入 logs/（自动执行，不再逐次征求批准）
```

## 四、用户应当知道的免责说明

在 brief 中明确告知用户：
- 冷邮件在部分国家受严格监管，违规可能面临罚款（澳大利亚最高可达数千万澳元）
- 邮箱地址的合法性由发件方负责，本技能提供的名单仅供商业联络使用
- 建议：优先使用目标国家职能邮箱；对个人邮箱冷邮件建议先取得对方同意
- 建议：单条链接的所有流量集中在邮件内打开有利于送达，但也意味着追踪能力弱于营销工具

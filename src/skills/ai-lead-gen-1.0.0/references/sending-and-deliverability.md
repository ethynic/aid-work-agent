# SMTP 配置与送达率优化

第 11 步使用。

## 一、发送前的基础检查（DNS 记录，缺一不可）

**详细配置值、可复制的记录模板、子域策略与排查流程见 `references/domain-warming.md`。**
一键体检：

```bash
python scripts/domain_check.py outreach.yourdomain.com \
    --selectors s1 --smtp-ip 1.2.3.4 --blacklist
```

在发件域名上配置：

| 记录 | 用途 | 优先级 |
|---|---|---|
| SPF | 声明哪些服务器可以代表本域发信 | 必需 |
| DKIM | 邮件签名，防篡改 | 必需 |
| DMARC | 认证失败处置策略 | 强烈建议 |
| PTR (rDNS) | 反向 DNS，与正向一致 | 必需（共享 IP 常见缺失） |
| MX | 收信记录 | 必需 |

**没有 SPF + DKIM 的域名，发出去基本进垃圾箱。** 配置检查：
```bash
nslookup -type=SPF yourdomain.com
nslookup -type=TXT yourdomain.com
```

**冷邮件务必用独立子域**（如 `outreach.yourdomain.com`），不要用主域名。
主域被拉黑会连带影响日常办公邮件与客户回信。

## 二、发送账户选择

| 方案 | 适用 | 日限额参考 | 说明 |
|---|---|---|---|
| Gmail Workspace | 起步、小规模 | 500/天（未验证域更少） | 免费，但需验证域名且额度紧 |
| Outlook 365 / Microsoft 365 | 主流企业 | 300/天（默认，不可改） | 兼容性最好 |
| SMTP 服务商（Brevo/SendGrid/Mailgun/SES） | 中大规模 | 视套餐 | 有专门 IP warmup 工具 |
| Amazon SES | 大批量、成本敏感 | 近乎无限制 | 最便宜但配置最复杂，需审核 |

**冷邮件不建议**用免费的个人 Gmail 直发。

## 三、IP 与域名预热（Warmup）

新域名/新 IP 直接大量发信 = 直接进黑名单。

**预热节奏（由 `send_emails.py` 按「累计已发数」自动给出建议日限）**

| 累计已成功发出 | 建议日限 | 说明 |
|---|---|---|
| 0 – 49 封 | **20 / 天** | 新域名起步，验证链路 |
| 50 – 149 封 | **50 / 天** | 声誉初步建立 |
| 150 – 499 封 | **100 / 天** | 稳定放量 |
| ≥ 500 封 | **200 / 天** | 生产基准（核心目标） |

> 脚本读 `logs/send_log.csv` 的**累计** `sent` 记录计算档位。**跨天不清零**——
> 第二天不会退回 20/天，这是刻意设计：域名声誉是累积的。
> 声誉稳定后，用专属 IP 可安全放量到 300-500/天（此时手动调高 `daily_limit` 即可，
> 脚本只会提示、不会拦）。

> ⚠️ 新域名/新 IP 直接每天 200 封仍可能触发黑名单。前三档的小步预热是为了让
> 200/天的目标能**持续跑下去**，而非卡在垃圾箱。

预热期发送必须是**真实的、打开并有回复的**邮件（与真实客户的往来），不能让机器互相发。

### 一次能发多少：真正的瓶颈是「每域 3 封」

`daily_limit` 不是当天能发出去的上限，**`per_domain_daily_limit`（同一收件域名 24h ≤3 封）才是**。

- 想发 200 封 → 名单里需要 **约 67 个不同的收件域名**（200 ÷ 3）
- 收件人集中在少数几家公司时，当天真正能发出的封数远低于 `daily_limit`
- 脚本会在干跑时直接算好：`sendable today` 与 `cannot send today: N`
- 被限的邮件**留在队列里**，不会丢失，第二天自动续发

### 200 封/天要跑多久

按默认间隔 `delay_seconds=90` + `random_delay_extra=60`（即 90–150 秒随机）：

| 目标量 | 预计耗时 | 建议 |
|---|---|---|
| 20 封 | ~40 分钟 | 一次跑完 |
| 100 封 | ~3.3 小时 | 一次跑完或用 `--max-minutes` 切段 |
| 200 封 | ~6.7 小时 | **用 `--max-minutes` 切段**，或调低 `delay_seconds` |

`send_emails.py` 在干跑与正式发送前都会打印预计耗时。超过 4 小时建议切段：

```bash
# 每次最多跑 2 小时，到点优雅停止；已发的会记入日志，下次自动跳过
python scripts/send_emails.py --config cfg.json --emails emails.json --max-minutes 120
```

> 调低 `delay_seconds` 能压缩总时长，但**间隔越短越容易被行为检测识别**。
> 优先用 `--max-minutes` 分段，而不是无限压缩间隔。

**配置建议**：
- 专用于冷邮件的发送子域（如 `outreach.yourdomain.com`），与公司日常邮件隔离，保护主域声誉
- 大批量时用**专用 IP**，不要与日常邮件共用

## 四、邮件正文的技术要点

- **纯文本优先**：`text/plain` 为主。复杂 HTML 编辑器生成的邮件极易判垃圾
- **图片**：尽量不带图，或极少量。带图会大幅降低送达率
- **附件**：首封绝对不带附件
- **链接**：首封尽量不带链接，或最多 1 个。过多链接是垃圾特征
- **短链接**：尽量不用，因为部分邮件服务会拉黑已知短链域名
- **签名档**：控制在 4-5 行内，不要塞社交媒体图标（HTML 图标降低送达率）
- **编码**：UTF-8

## 五、垃圾邮件触发词

**主题行与正文都会检查**。避免：

| 类别 | 示例词 |
|---|---|
| 夸大词 | 免费、100%、保证、极限、最强、唯一、顶级、无与伦比 |
| 催促词 | 立即、马上、限时、最后机会、最后一天 |
| 金钱词 | $$$、赚钱、暴利、低价清仓 |
| 促销符号 | `!!!` `***` `100%` `$$$` |
| 伪装词 | Re:、Fwd:、Fw:（用于新邮件时） |

替换为平实表达：`提供`、`支持`、`机会`、`了解`。

## 六、退信处理

| 退信类型 | 原因 | 处理 |
|---|---|---|
| 550 5.1.1 用户不存在 | 邮箱无效 | **立即退订该地址**，不要重试 |
| 552 邮箱空间满 | 暂时性 | 可重试 1-2 次 |
| 450 请求速率过高 | 被限速 | 降低发送速率，等待后重试 |
| 421 服务不可用 | 临时故障 | 退避重试 |
| 550 5.7.1 被拒绝/黑名单 | 发件方被拒 | **立即停止全部发送**，修 DNS 与声誉 |

`scripts/send_emails.py` 已内置上述分类处理逻辑。

## 七、发送节奏

- 同一公司多个联系人：**间隔 24 小时以上**，不要同一批次发
- 不在周末发送（目标国当地时间）
- 工作日发送时间：**当地时间 9:00-11:00 或 14:00-16:00**
- 避免在对方所在地区节假日发送（查目标国假日历）

## 八、追踪设置

首封邮件建议**不追踪打开链接**：
- 追踪像素/链接重写会降低送达率
- 部分国家（德国、荷兰）对追踪隐私较敏感
- GDPR 下需告知追踪行为

若需追踪：使用隐私友好的方式，并在邮件中说明。

**更好的替代**：直接在 CRM 里人工记录回复状态。冷邮件的核心指标是回复率，不是打开率。

## 九、发送配置示例

复制 `assets/smtp_config.example.json` 到 campaign 目录，**密码等凭据用环境变量**，不写进文件：

```json
{

  "smtp_port": 587,
  "smtp_secure": false,
  "smtp_user": "outreach@yourdomain.com",
  "smtp_password_env": "SMTP_PASSWORD",
  "from_name": "Your Name",
  "from_email": "outreach@yourdomain.com",

  "track_opens": false

```

## 十、发送后监控

发出后 48 小时看：
- 退信率：> 5% 需立即暂停排查
- 投诉率（spam complaint）：> 0.1% 必须停止
- 回复率：冷邮件 1-5% 属正常，> 5% 说明名单质量好
- 打开率：< 10% 说明主题行或发件域名有问题

## 十一、A/B 优化路径

**主题行是默认必做项**：每封信写 A/B 两版（写法见 `email-copybook.md` 2.4），
`ab_group` 在写草稿时交替分配，发送时按组分流，结果按 `send_log.csv`
的 `ab_group` 列分组汇总。注意公司简称不进标题，放签名。

其他变量留到后续轮次，每次只改一个：
1. 钩子类型（痛点型 vs 观点型）
2. CTA（提问 vs 建议动作）
3. 发送时间（上午 vs 下午）
4. 语言（英语 vs 本地语言）

判读纪律：
- 每次测试至少 100 封才有统计意义；不足 100 封时，两版差异基本是噪声。
- 主题行影响打开率，未开 `track_opens` 时只能用回复率做代理指标，噪声更大。
- 一次只动一个变量，否则赢了也不知道赢在哪。

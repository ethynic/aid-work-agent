# 标准投标书章节结构与版式规范（Step 6 使用）

本文件给出中文政企采购场景下投标书（标书）的通用结构骨架与各分册要点。
生成标书时，以「甲方招标书要求」的 `document_components` 为准做增删，但下列骨架覆盖绝大多数情形。

## 标准结构骨架

```
封面（项目名称 / 招标编号 / 投标人 / 日期）
投标书目录
第〇部分  投标函及附录
第一部分  法定代表人身份证明 / 授权委托书
第二部分  投标保证金凭证
第三部分  商务标
    3.1 投标人基本情况（公司简介、营业执照、组织架构）
    3.2 资格证明文件（资质等级、认证体系、荣誉）
    3.3 财务状况（审计报告、近三年财务报表）
    3.4 类似业绩（业绩一览表 + 合同/中标证明）
    3.5 项目团队（人员配置、证书、职责分工）
    3.6 商务条款响应/偏离表
第四部分  技术标
    4.1 对项目需求的理解
    4.2 总体技术方案 / 服务方案
    4.3 技术规格响应/偏离表（逐条对照招标技术参数）
    4.4 实施计划与进度安排（甘特/里程碑）
    4.5 质量保障与售后服务体系
    4.6 培训与知识转移（如适用）
第五部分  报价文件
    5.1 投标报价一览表（总价、税率、币种、报价有效期）
    5.2 分项报价明细表
    5.3 报价说明与口径
第六部分  承诺书
    诚信投标、不串通、质量、工期/交付、售后、数据安全等承诺
第七部分  附录
    7.1 资格符合性审查对照表
    7.2 技术/商务偏离表汇总
    7.3 评分项响应索引（评分维度 → 对应章节/页码）
    7.4 招标文件要求的其他特定附件
```

## 多文件拆分方案（按甲方文件组成输出）

甲方招标文件通常会明确「投标文件由以下部分组成」，技能必须**按甲方约定的分册输出多份独立文件**，
而非塞进一份文档。若甲方未明确，默认按下表五册拆分（每册一个 DOCX，可单独装订、签章、密封）。

| 分册文件 | 包含章节（对应上方骨架） | 命名建议 |
|---|---|---|
| **商务标册** | 投标函、授权委托书、投标保证金、3.1 基本情况、3.2 资格证明、3.3 财务、3.4 业绩、3.5 团队、3.6 商务偏离表 | `<甲方>-<项目>-商务标.docx` |
| **技术标册** | 4.1 需求理解、4.2 总体方案、4.3 技术偏离表、4.4 实施计划、4.5 质保售后、4.6 培训 | `<甲方>-<项目>-技术标.docx` |
| **报价文件册** | 5.1 报价一览表、5.2 分项报价、5.3 报价说明 | `<甲方>-<项目>-报价文件.docx` |
| **资格审查资料册** | 营业执照、资质证书、认证、审计报告、业绩证明、人员证书等佐证原件/复印件 | `<甲方>-<项目>-资格审查资料.docx` |
| **承诺函册** | 诚信投标、质量、售后、保密、不转包、数据安全等承诺（见 `commitment-letters.md`） | `<甲方>-<项目>-承诺函.docx`（或按函拆多份） |

拆分原则：
- **偏离表随册放置**：技术偏离表放在技术标册内、商务偏离表放在商务标册内；同时生成一份合并版 `偏离表.md/.csv` 独立归档。
- **资格证明双轨**：资格审查资料册集中放佐证原件扫描/复印件；商务标册的 3.2 仅放索引与结论，避免重复厚册。
- **承诺函独立成册/成文件**：便于甲方单独抽取核验，且每函须由法定代表人或授权人签字盖章。
- **共享响应索引**：每份文件文末均附「评分项/要求 → 章节 → 所在分册」索引，保证跨文件可追溯、不矛盾。
- **命名与密封**：文件名、份数（正/副本）、密封要求严格遵循招标 `format_requirements`，不要自创命名。

## 各章要点

- **投标函**：固定格式，须法定代表人或授权人签字并盖章；金额大写与小写一致。
- **授权书**：如非法人亲自投标，必备；附双方身份证/法人证明。
- **资格证明**：按 `qualification` 逐条提供佐证，与「资格符合性审查对照表」一一对应。
- **业绩**：突出与招标规模/类型最匹配的 3–5 个案例，附可核验证明，对齐评分项 `S*`。
- **技术方案**：先「理解需求」再「给出方案」，避免空话；关键技术点呼应 `technical_specs`。
- **偏离表**：技术标与商务标各一张，逐条列出「招标要求 → 我方响应 → 偏离」。
- **报价**：与 `scoring.price_formula` 口径一致；分项汇总 = 一览表总价。
- **承诺书**：覆盖招标 `disqualification` 与 `commercial_terms` 中的承诺类要求。

## 版式规范

**版式不在本文件规定，也不固化在技能里。** 版式必须按
`references/layout-extraction.md` 的方法，从「甲方招标格式条款 + 历史标书版式范式」
推导成 `layout.json`，再由渲染器执行。

本文件只保留**结构性**约定：
- 章节层级编号沿用历史标书体系（如 一、→（一）→ 1. → (1)），编号写在标题文字里，不由渲染器生成；
- 多个文件各自成册时，封面/目录/页眉页脚/表格样式由 `layout.json` 统一控制，保证跨册一致；
- 签字区逐行包含「投标人：（盖单位章）」「法定代表人或其委托代理人：（签字）」+ 年月日；
- 表格下方注按招标文件原表样注明（如「注：此表为表样，行数可自行添加，但表式不变。」）。

## 与 `requirements.json` 的回溯

- 生成过程中，维护 `id → 章节` 映射，最终写入附录 7.3「评分项响应索引」。
- 任一 `mandatory` 要求若无对应章节，必须在偏离表与交付说明中显式提示风险。

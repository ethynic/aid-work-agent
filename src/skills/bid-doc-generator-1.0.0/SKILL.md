# 投标书（标书）自动生成 · Bid Doc Generator

## 一、技能定位

本技能将「甲方招标书要求 + 一份历史标书 + 我方资质信息 + 我方产品及价格信息」四要素，
自动生成一组**结构完整、逐条响应招标要求、可直接用于投标的投标文档**：
不仅是一份合并标书，更会**按甲方招标文件约定的文件组成，拆分为多份独立文件**——
如技术标、商务标、报价文件、资格审查资料册、以及诚信/质量/售后/保密等各类承诺函——
并附带「要求—响应—偏离」对照矩阵，确保每一处甲方要求都被覆盖、可追溯、且落在正确的文件里。

> 术语约定（避免混淆）：
> - **招标书 / 招标文件 / RFP** = 甲方（买方）发出的采购文件，本技能将其作为输入「要求」读取。
> - **投标书 / 标书 / 投标响应文件** = 我方（卖方）提交的应答文件，本技能将其作为「产出」生成。

### 边界（不要使用本技能）

- 供应商资质证书真伪核验、供应商信用/风险审查 -> 用 `supplier-qualification-review` 技能。
- 生成合同文本 -> 用 `contract-generator` 技能。
- 把数据填入既有 Excel 模板 -> 用 `excel-to-template` 技能。
- 本技能面向「从招标文件出发生成整套投标响应文档」，上述场景即使出现在投标准备流程中，也各自走对应技能。

## 二、运行环境注意（必读）

- 每次 `skill_execute` 调用都在独立的临时工作目录中执行，调用间不共享 cwd。所有中间产物
  （`requirements.json` / `layout.json` / `content.json` / `price_input.json` / `price_result.json` /
  `matrix.json` / `checks.json` 及渲染输出）**必须用绝对路径**读写，统一放在 `$SKILL_TMP_DIR`
  下的任务目录中（环境变量已注入，持久不清理）。参考文档中出现的 `work/...` 相对路径一律
  映射为 `$SKILL_TMP_DIR/work/...`。
- 技能目录运行时为只读；`scripts/` 下的脚本通过 `skill_execute` 调用，脚本路径会被自动映射为绝对路径。
- 用户上传文件的路径来自会话上传信息（冒号后面是实际上传路径），**始终使用实际上传路径**，
  不要用原始文件名拼路径。
- 中间产物的读取使用 `read` 工具；最终多份 DOCX 交付使用 `cp` 工具批量带出（**一次批量 cp**，
  不要逐个文件多次交付）。
- **扫描版（图片型）招标 PDF**：`extract_tender.py` 只能抽取文本层，扫描件会得到空结果。
  此类输入先用 `image_read` 视觉读取关键章节，或提示用户提供文字版，不要凭空补全要求条目。

## 三、Inputs（四要素，缺一不可）

| 序号 | 输入 | 含义 | 可接受形态 |
|---|---|---|---|
| 1 | **甲方招标书要求** | 甲方发出的招标文件/招标书/RFP，含资格门槛、技术规格、评分办法、商务条款、格式要求 | PDF / DOCX / 网页 / 文本 / 粘贴段落 |
| 2 | **历史标书** | 我方此前中标的同类投标书，用作风格、结构、话术、版式的范例（RAG 参考） | DOCX / PDF |
| 3 | **我方资质信息** | 营业执照、资质等级证书、认证体系、财务审计报告、类似业绩、人员证书等 | DOCX / PDF / 表格 / 文本 |
| 4 | **我方产品信息及价格信息** | 产品/方案说明、技术参数、报价表（单价/总价/税率/分项） | DOCX / XLSX / PDF / 文本 |

缺少任一要素时，**不要凭空编造**。先向用户列出缺失项并请求补充（可说明「暂用占位符标注，待补」）。
资质与报价属于事实性内容，绝不可虚构数字或证书。

## 四、Workflow（六步法）

### Step 1 · 收集与核验输入

- 定位四个输入文件/文本。通过 `skill_execute` 运行 `scripts/check_inputs.py` 校验文件是否可读
  （参数依次为：招标书、历史标书、我方资质、我方产品及价格；退出码 2 表示有缺失并输出缺失清单）。
- 若用户以文本/粘贴方式提供，先落盘为任务目录下的 `.md`/`.txt`，便于后续解析与引用。
- 明确产出路径与文件命名（建议 `<甲方简称>-<项目简称>-投标书-初稿.docx`）。

### Step 2 · 解析甲方招标书要求（核心）

加载 `references/requirements-extraction.md`，按该文给出的**招标要求提取模型**，
从招标书中结构化抽取：

- 投标人资格门槛（注册资本、资质等级、业绩年限/金额、认证、人员）
- 投标文件组成（必须包含哪些分册/章节）
- 技术规格与 SOW（逐条技术参数）
- 评分办法（商务/技术/价格权重、基准价算法、扣分规则）
- 否决/废标条款（一票否决项）
- 商务条款（工期、付款、质保、履约担保、投标有效期）
- 格式要求（装订、签字盖章、份数、密封、页码）
- 关键时间（截标、投标有效期、质保期）

机械解析（docx/pdf/xlsx -> 章节树、采购清单表、关键表格）通过 `skill_execute` 运行
`scripts/extract_tender.py` 完成（输出 `tender_extracted.json` + `tender_text.md`，纯机械不做判断）。
在此之上由大模型按提取模型写出 `requirements.json`（结构见 references），
作为后续逐条响应的「考题清单」。

**二轮细则扫描（必做）**：首轮提取完成后，对招标文件全文再做一次专扫，逐项核对是否已入清单——
否则最容易漏的就是散落在合同条款、材料规程、参数表附注里的细则类条款：

- 投标保证金：金额、缴纳形式、到账截止、基本账户/子账号要求、凭证与证明材料
- 投标有效期：天数与起算点；报价口径：含税/不含税、大小写效力、小数位
- 质保期与起算点、备品备件、缺陷响应时限、样品封存与送审签认（如样板签名要求）
- 履约担保比例、招标代理服务费（承诺书缺失/未签章常为一票否决）
- 品牌档次要求（如「十大品牌或同等档次」）、供货清单逐项规格与数量

漏提后果：该条不会进入偏离矩阵与响应索引，评标时视为不响应。扫描后补充的条目
继续用同类 id 前缀编号，并在 note 标注「二轮扫描补充」。

### Step 3 · 分析历史标书（风格与结构范式）

- 读取历史标书，提取其**章节骨架、标准话术、资质/业绩呈现方式、报价表版式、承诺条款模板**。
- 将其作为风格与版式参考（RAG 范例），使新标书在语体、层级、表格样式上与既有中标文风一致。
- 提炼可复用的固定章节（公司简介、资质体系、服务方案框架、售后承诺、诚信承诺书等）。

### Step 3.5 · 推导版式（layout.json）★版式不固化

加载 `references/layout-extraction.md`，从**两个来源**推导本次专用的版式配置：

- **甲方招标要求**（最高权威）：字体字号、纸张、装订方式、份数、目录、签章方式、页数上限、封套；
- **历史标书范式**（甲方未规定处）：字体搭配、封面形态、表格样式、页眉页脚、标题层级、编号体系。

写出 `layout.json`（字段见 layout-extraction.md），每个字段在 `_source.notes` 中标注出处。
**冲突时以甲方为准**，并记录取舍理由。随后通过 `skill_execute` 运行 `scripts/check_layout.py` 校验
（`--layout`、`--requirements`、`--report` 三个参数）。
FAIL 必须修复；WARN 需确认并记入 `pending_items`。

**历史标书视觉范式必须从 docx 样式读取，不能靠纯文本猜**：页眉页脚文字与格式
（`python-docx` 可读 `section.header/footer` 段落与页码域）、表头底纹色（表格单元格
shading XML）、表格字号（单元格 run 的字号）、封面字体搭配，都是视觉属性，
`tender_text.md` 之类的纯文本解析完全看不到。用 `read`/`skill_execute` 解析历史标书
docx 的样式 XML 取证后再填 `layout.json`；确实取不到的字段走兜底值，
并在 `pending_items` 标注「沿用默认，建议人工复核」。实测教训：漏读视觉范式会导致
页眉缺失、表头无底纹、表格字号错用正文字号。

> **严禁**把版式写死在技能脚本或参考文档里。渲染器只执行 `layout.json`，
> 未提供时使用兜底值并打印告警 —— 兜底不等于正确，必须补齐 layout.json 后重跑。

### Step 4 · 资质与要求对齐（符合性矩阵）

加载 `references/compliance-matrix.md`，建立三张对照表：

- **资格符合性审查对照表**：招标资格门槛 -> 我方佐证 -> 是否满足（满足/不满足/部分）
- **技术规格响应/偏离表**：招标技术条目 -> 我方产品参数 -> 偏离（无偏离/正偏离/负偏离）
- **商务条款响应/偏离表**：招标商务条款 -> 我方承诺 -> 偏离情况

对不满足项**显式标注风险**，禁止隐瞒或改写为满足。

### Step 5 · 报价整合

- 将「我方产品信息及价格信息」按招标要求的报价格式归整：报价一览表（总价、税率、币种）、
  分项报价明细、报价说明。
- 价格部分须与 Step 2 的评分办法一致（如低价优先/合理低价/基准价法），并标注报价口径。
- **必须由脚本计算**：把「甲方清单数量 + 我方单价 + 税率 + 最高限价」写入 `price_input.json`，
  通过 `skill_execute` 运行 `scripts/price_quote.py`（`--input` / `--out` 两个参数）计算
  `price_result.json`（分项合价、含税合价、总价、大写金额、限价校验、分项累计校验）。
  **大模型不得自行算数或手抄金额。** 退出码 1 表示校验 FAIL（如超限价），必须调整报价后重跑。
- 报价策略应结合评分办法反推：基准价法下，每低 1% 扣 0.1 分、每高 1% 扣 0.2 分，
  通常取略低于限价（3%～5%）为最优区间；同时确保分项合价累计 = 总价，大小写一致。

### Step 6 · 生成多份投标文档 + 对照矩阵

> **本技能采用「脚本化分层」架构**：Step 1/2 的**文件读取与解析**、Step 4 的**偏离表生成**、
> Step 6 的 **Word 渲染与打包**全部由 `scripts/` 下的脚本执行；
> 大模型只负责**判断**（要求性质、偏离判定）、**内容输出**（正文、承诺函、表格填充）、
> **整合**（跨文件口径统一）。**大模型不生成 .docx、不手工操作 Word 二进制。**
> 接口契约详见 `references/content-spec.md`（**先读这份**）。

1. 依据 `requirements.json` 的 `document_components`（甲方明确要求的文件组成）与
   `references/bid-structure.md` 的**多文件拆分方案**，确定本次要产出的文件清单与各文件章节归属。
   若招标文件未明确拆分，默认按五册拆分：商务标册、技术标册、报价文件册、资格审查资料册、承诺函册。
   **若甲方招标文件第六章列明了「投标文件格式」目录，必须逐项对应生成，不得合并或遗漏。**
2. 按 `references/bid-structure.md` 的**标准章节结构**组织内容，将每个章节归入对应文件；
   逐章填充：投标函 -> 授权书 -> 资格证明 -> 商务标 -> 技术标 -> 报价文件 -> 承诺函 -> 附录（偏离表/索引）。
3. 每一章节都要能回溯到 `requirements.json` 中的对应要求条目（在文末「响应索引」中标注章节↔要求↔所属文件）。
4. 大模型写出 `content.json`（全部文件内容与结构，字段规格见 content-spec.md），再通过
   `skill_execute` 运行 `scripts/render_docs.py`（`--out` 指定输出目录，`--layout` 指定版式）
   批量渲染为专业排版 DOCX。
5. 通过 `skill_execute` 运行 `scripts/build_matrix.py`（对齐结果 JSON -> 输出目录）生成
   **偏离表 / 符合性矩阵**（Markdown + CSV）；技术偏离表并入技术标册、商务偏离表并入商务标册，
   合并版另存为独立 `偏离表` 文件供归档。
6. 依据 `references/commitment-letters.md` 生成所需的**承诺函**（诚信、质量、售后、保密、不转包等），
   每份承诺函按招标文件命名与编号（如 `（五）信誉承诺函`），落在对应文件中。
7. 通过 `skill_execute` 运行 `scripts/make_package.py`（`--content` / `--out` / `--expected` /
   `--checks` 参数）做**齐全性校验 + 跨文件一致性自检 + 生成交付清单**（PACKAGE.md），
   失败项必须修复后重跑，直至 PASS。
8. **跨文件口径统一（写法级）**：同一事实口径在所有册中不仅数值一致，**写法也必须逐字符一致**——
   投标有效期（如统一写「90日历天」）、质保期（统一写「2年」，禁止「2 年」「贰年」混用）、
   金额、税率、工期、项目名称。正文表述以 requirements.json 原文措辞为基准；
   每册正文开头应含「项目名称：…」一行（自检只读正文，页眉不算）。
   实测教训：「2 年/2年」混用会让一致性自检把同一口径判成两个值。
9. 产出交付清单（示例）：
   - `<甲方>-<项目>-投标函.docx`（及招标文件要求的其余各册）
   - `<甲方>-<项目>-技术标.docx`
   - `<甲方>-<项目>-报价文件.docx`
   - `<甲方>-<项目>-资格审查资料.docx`
   - `<甲方>-<项目>-承诺函.docx`（或按函分拆为多个文件）
   - `偏离表.md` / `偏离表.csv`（合规自检）
   - `PACKAGE.md`（交付清单 + 自检报告 + 待补项）
   - `requirements.json`（解析出的要求清单，便于复核与分册对照）

全部产物就绪后，用 `cp` 工具**一次性批量交付**所有 DOCX 及 PACKAGE.md，聊天回复只给
简短交付清单与风险提示，不粘贴正文。

## 五、Critical Rules（铁律）

1. **事实零虚构**：资质、业绩、证书编号、财务数据、报价数字，凡属我方事实性内容，只可来自输入，不可编造。
   缺失则标注「[待补充：…]」，绝不填充假数据。
2. **逐条响应、零遗漏**：以 `requirements.json` 为基准，招标列明的每一条资格/技术/商务要求都必须有对应响应，
   缺失即记入偏离表并提示。
3. **偏离如实标注**：负偏离（不满足）必须显式写出，不得隐瞒或偷换概念；正偏离（优于要求）可突出呈现。
4. **版式一致性**：以历史标书为风格范式，新标书语体、层级、表格样式与之对齐，降低被识别为「模板套用」的观感。
5. **合规优先于美观**：宁可多列风险项，不可为了「好看」删除否决项提示或伪造符合性。
6. **多文件一致性**：拆分输出时，各文件共享同一套术语、金额、工期、人员与偏离结论；
   同一要求不得在不同文件中自相矛盾；每份文件均含封面/目录/页码，并共用一份响应索引指向各册。
7. **文件操作归脚本**：读招标书、解析参数表、渲染 Word、生成偏离表、打包自检，全部交给 `scripts/`；
   大模型只输出 `content.json` / `requirements.json` / `matrix.json` / `price_input.json` /
   `layout.json` / `checks.json` 六个 JSON，**不得手工生成或修改 .docx**，不得绕过脚本直接改 Word 文件。
8. **甲方目录逐项对应**：招标文件第六章「投标文件格式」列出的一至十项（含各子项承诺函）
   必须逐项生成、逐项落位，**不得合并成"其他资料"一揽子带过**。
9. **版式不得固化**：字体、字号、行距、页边距、纸张、装订、目录、页眉页脚、表格样式
   **一律来自 `layout.json`**，而 `layout.json` 必须由「甲方招标要求 + 历史标书范式」推导。
   禁止在技能脚本、`references/` 或 `content.json` 里写死任何版式参数。
   甲方规定优先于历史范式；两者都未规定的走兜底值并记入 `pending_items` 提示人工确认。

### scripts/（均通过 skill_execute 调用）

- `check_inputs.py` — 校验四个输入文件存在且可读，输出缺失清单（退出码 0/2）。
- `extract_tender.py` — **招标书解析器**：docx/pdf/xlsx -> `tender_extracted.json` + `tender_text.md`，
  自动识别章节树、采购清单表、关键表格；纯机械，不做判断。
- `price_quote.py` — **报价计算与限价校验**：`price_input.json` -> `price_result.json`，
  计算分项/含税合价、总价、大写金额，校验是否超最高投标限价、分项累计是否等于总价（退出码 0/1）。
- `check_layout.py` — **版式合规校验**：把 requirements.json 的 format 类条款与 layout.json
  逐条比对（字体/字号/纸张/装订/份数/目录/签章/页数上限/来源标注），输出合规报告。
- `build_matrix.py` — 读取对齐结果 JSON，生成偏离表/符合性矩阵（Markdown + CSV）。
- `render_docs.py` — **DOCX 渲染引擎**：`content.json` -> 多份专业排版投标文件。
  **版式全部取自 `layout.json`**（`--layout` 指定），脚本内无任何写死的字体字号版式；
  `price_table` 读报价结果、`matrix_table` 读偏离矩阵，金额与偏离符号不经人工手抄。
- `make_package.py` — **交付打包与自检**：齐全性校验 + 跨文件一致性检查
  + 生成 `PACKAGE.md`（退出码非 0 表示存在 FAIL 项）。

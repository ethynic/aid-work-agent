# 调研：多源脏 Excel → 标准模板 ETL 能力差距分析

> 2026-08-18。输入样本：`ExcelAI测试.zip`（5 个来源报表 + 1 个标准模板）。
> **定位修正（v2）**：来源格式完全不可控、不可能要求对方规范化——**大模型的解析能力就是实现“不规范→规范”映射的核心机制**。代码不建规则映射引擎，只做三件事：① 把单元格真实语义正确渲染给 LLM；② 确定性校验 LLM 输出并回喂修复；③ 执行模板填充与交付。

## 1. 场景

用户一次上传多个供应商/客户的人员增减报表（各家格式不同、且不可要求对方改），外加一个标准模板，要求把所有来源数据统一填写到标准模板输出。

标准模板 `生成标准模板格式.xlsx`：单 Sheet，仅表头行 18 列（增员/减员、姓名、身份证、参保地、手机号码、参保年月、基本工资、公积金基数、公积金比例、劳动合同起始/终止时间、岗位、学历、备注、离职方式、用工信息结束时间、社保/公积金最后缴纳月）。模板是干净单行表头空表，填充用现有能力即可；**全部难点在“让 LLM 正确读懂脏来源并输出标准记录”**。

## 2. 来源文件实测脏点（= LLM 解析能力的验收用例）

| 来源文件 | 增/减 | 结构不规则（交给 LLM 理解） | 值格式问题（需渲染层配合，LLM 看不见数字格式） |
|---|---|---|---|
| 202608德勤派单增减人员 | 新增/减少两个 Sheet | 表头含换行复合单元格（`社保缴至月份\n（如6月继续缴纳…）`）；重复列名（`派单日期`两次）；max_row=114 仅 3 行有效 | 派单日期是 Excel 序列日期 **46239**（数字格式为日期，纯文本渲染 LLM 无从知道）；参保地 `安徽省,芜湖市,镜湖区`；公积金比例 `5%:5%` |
| 万宝盛华人员变动通知 | 增员/减员两个 Sheet | 同 Sheet 多段：表头→数据→`0806补充`分段行→重复表头→更多数据 | 日期 datetime；公积金比例拆企/个两列（`5`/`5`）；始缴年月 `2026/08` |
| 活悦安徽分增减表 | 单 Sheet 减员 | 两行表头（R1 说明 + R2 真表头） | 身份证脱敏 `XXXX`；最后缴纳月 `202608` |
| 外管离职导出（上海中企） | 单 Sheet 减员 | 标题/说明/T0 占 3 行，真表头在第 4 行；合并单元格 | 养老/失业/医疗/工伤/生育/档案/补充工伤/住房公积金 8 个停止日期列→归并出社保/公积金最后缴纳月；离职语义在 `下岗原因` |
| 上海信息数据（社保&公积金） | 增员表/减员表两个 Sheet | 表头单元格内嵌枚举说明（`性别\n1男\n2女`）；数据区后有备注页脚行 | 公积金比例 0.05；日期混排 datetime/字符串 |

跨文件共性：同义字段名（雇员姓名/员工名称/姓名）、拆分粒度不同（企/个比例）、语义需派生（Sheet 名或上岗/下岗列→增员/减员；用工开始时间→参保年月）、离职文案→离职方式枚举、跨文件同人多出现。

## 3. 现有能力盘点

已具备：
- **写入侧**：`excel_template.py`（占位符 + 结构感知填充）与 `excel_template_ai.py fill_with_sample`（#44 Phase A+B+C：样例结构 LLM 分析、行数不匹配渲染、样式/合并保留、残留校验、`_extract_json` JSON 容错解析、skill 可直接 import）。
- 读取：`read_sheet`/`read_all_sheets`（表头=第1行假设，对脏表不可用）、`to_md`（markitdown 全量文本）、`read_excel_document`。
- 多附件 `file_paths`/file_id、结构化 `data` 入参、`cp` 注册下载交付、LLM 网关 + ExcelRouter。

缺口：
1. **渲染层**：现有读取把 Excel 值裸吐（46239、datetime 对象 str()、空行填充全量灌给 LLM）。LLM 看不到数字格式，序列日期会被当数字照抄进模板。需要"按数字格式渲染"的输入预处理——这是帮 LLM 看见文件真实语义，不是要求对方改格式。
2. **LLM 抽取管线**：没有“脏表文本 + 目标 schema → 标准 JSON 记录”的通用抽取 action；长表（真实月份数百行×20+列）需分块抽取再拼接，每块都要带表头/分段上下文。
3. **目标 schema 提取**：没有“从上传模板表头自动生成目标字段清单 + 格式约定”的步骤（模板每次可能是用户临时上传的）。
4. **确定性校验 + 修复回路**：没有对 LLM 输出的校验（身份证校验位、日期/年月格式、必填、枚举、跨字段一致）和把错误行回喂 LLM 修复的循环。LLM 解析为主 ≠ 不校验；校验是让“LLM 映射”可靠落地的兜底。
5. **跨文件合并去重**：无按身份证（脱敏降级姓名+参保地）去重与冲突检测。
6. **多附件编排**：无“识别哪个附件是模板、哪些是来源”并串起 抽取→校验→合并→填充→交付 的 skill/复合 action；无校验报告输出。

## 4. 目标架构：LLM 解析为主、代码校验兜底

```
多附件 ──► [0 编排] 识别模板 vs 来源（文件名+表头特征，LLM 判断）
 来源文件 ─► [1 渲染层] 每值按数字格式渲染（日期→ISO、百分比→明文），全 Sheet 文本化，压缩空行
         ─► [2 LLM 抽取] 渲染文本 + 目标 schema(字段+格式约定) → 标准 JSON 记录（分块，敏感字段照抄）
         ─► [3 校验回路] 代码确定性校验 → 错误行回喂 LLM 修复（最多 N 轮）→ 仍错的标 warning 不静默丢
         ─► [4 合并] 跨文件按身份证去重、冲突并列
 模板 ────► [5 填充] 复用 #44 fill_with_sample / _fill_structured → 终检（18 列、行数、无残留）
         ─► [6 交付] xlsx + 校验报告（各来源行数/未映射字段/逐行 warning/去重决策）经 cp 注册
```

## 5. 优先级

1. **P0**：M1 渲染层 + M3 LLM 抽取 action（最小闭环：单文件→标准 JSON）。
2. **P0**：M4 校验回路（无校验的 LLM 抽取不可交付 HR 数据）。
3. **P1**：M2 schema 固化机制（首版可直接内置本域 18 字段 schema，指纹校验作为防模板变更的保险）+ M5 合并/编排/校验报告（端到端多文件）。
4. **P2**：抽取结果缓存复用（同指纹文件跳过 LLM）、更多来源格式沉淀验收样例。

## 6. 内置默认约定（写入 schema 字段说明，可被用户指令覆盖）

- 参保地：三级串 `安徽省,芜湖市,镜湖区` 取**市级**（`芜湖市`），与 `赣州市` 对齐；已是市级原样。
- 公积金比例：统一 `企:个` 明文格式，如 `5%:5%`；单列小数 0.05→`5%`。
- 参保年月/最后缴纳月：统一 `YYYYMM`（`2026/08`、`2026-08-01`（当月参保）→`202608`）。
- 日期类（劳动合同/用工结束/离职）：统一 `YYYY-MM-DD`；Excel 序列数按日期格式渲染后照抄。
- 离职方式：归一枚举 `主动离职/被动离职/合同到期/其他`（`个人原因离职`、`员工主动提出辞职`→`主动离职`）。
- 增员/减员：优先 Sheet 名（新增/增员→增员；减少/减员→减员），无语义时看 `上岗/下岗` 列。
- 来源缺失的列（德勤等无岗位/学历/基本工资）：留空，不造值。
- 脱敏身份证（`XXXX`）：照抄 + warning 进报告。
- 跨文件同人：**不去重合并**——同人多条全部保留，每条带出处；校验报告按人分组提示「同人多条」及字段差异；模板中同人多条的行在备注末尾追加 `【同人多条：另见 文件名】`，其余行不改备注（2026-08-19 用户拍板）。

## 7. 开发决议（消歧清单，2026-08-19 补）

开发前逐项裁决，标 ❓ 的 3 项需业务拍板，其余为技术定论（有理由，可直接开发）。

### 架构与模块归属

- **D1 管线宿主 = 领域 skill**（`src/skills/excel-to-template-1.0.0/`：SKILL.md + scripts/pipeline.py + assets/schema.json），不是 excel_process 新 action、不是子智能体。理由：excel_process 是多租户通用工具，领域 schema/约定不进通用层；skill 以子进程运行、cwd 即含上传附件的 skill_ws、文件名参数由 executor 解析（skill_executor.py 已验证），LLM 同步调用照抄 `excel_template_ai._default_llm` 模式。SKILL.md description 写明触发词（模板/标准模板/汇总/增减/社保）。
- **D2 库层与 skill 层分工**：通用能力进 `src/tools/excel/`——`excel_reader.py` 加 `render_llm_view()`（M1）、新文件 `excel_extract.py`（M3 抽取 + M4 校验修复 + M5 合并去重，纯库可单测）；skill 的 pipeline.py 只做编排（找文件→调库→cp 交付），领域 schema 在 assets/。

### 输入与识别

- **D3 模板识别（确定性，零 LLM）**：模板 = 存在某 sheet「非空行数=1 且非空单元格 ≥ 5」的 xlsx（纯表头空表特征）。恰一个 → 即模板；零个或多个 → 报错请用户指认；用户消息已指认（"X 是模板"）则优先指认。
- **D4 输入形态**：支持多个 .xlsx 附件 + .zip（脚本内解包到临时目录只取 .xlsx）；.xls 报错提示转 .xlsx。
- **D5 渲染规范（M1 契约）**：值按 number_format/is_date 渲染——datetime→`YYYY-MM-DD HH:MM:SS`、date→`YYYY-MM-DD`、百分比格式→`5%` 明文、其余 `str()` 去首尾空白；合并单元格非锚点格为空串；全空行跳过、空列保留（列对齐）；单元格超 300 字符截断标 `…(截断)`；输出 `## Sheet: 名` + markdown 表。**不**消歧表头、**不**去重列名——原样给 LLM。

### 抽取（M3）

- **D6 LLM 调用**：同步 SDK + `disable_thinking=True` + temperature 0（照抄 `_default_llm`，含 qwen/zhipu 分支）；模型跟 `settings.llm` 走（报价测算按 deepseek-v4-flash，运行时不硬编码）。
- **D7 分块**：按 sheet 顺序装填，每块 ≤ 50 非空数据行 **或** ≤ 24k 输入 tokens（先到为准）；每块 prompt 必含固化 schema 文本 + 涉及 sheet 的表头区原样文本（同 sheet 拆多块时表头随块重复）。
- **D8 输出契约**：JSON 数组，元素 = 18 字段（缺省 null）+ `_source`（`文件名#Sheet#行号`）；解析复用 `_extract_json` 容错模式。
- **D9 失败路径**：单块 JSON 解析失败→原块重试 1 次；再失败→**任务级失败**（明确报错，不输出部分结果）；网络错误指数退避重试 2 次。

### 校验修复（M4）

- **D10 校验规则分级**：error（阻断）= 身份证非 18 位/校验位错（脱敏除外）、日期字段非日期、年月非 YYYYMM、增减非枚举、姓名/身份证/增减为空；warning（不阻断）= 脱敏身份证、社保≠公积金最后缴纳月、参保年月/最后缴纳月为 null、比例格式异常。
- **D11 修复回路**：仅 error 行回喂（原行 + 已抽记录 + 错误清单），最多 2 轮；仍 error → **该行不写入模板**，进报告「人工处理清单」（附原始行）✅ 2026-08-19 用户拍板。warning 行照写 + 进报告。

### 合并（M5 前半）

- **D12 同人多条处理（2026-08-19 用户拍板，替代原"取信息更全合并"方案）**：**不自动去重、不字段合并**——同人多条全部保留写入模板；每条经 `_source` 标注出处；校验报告按业务键（完整身份证；脱敏/缺失降级为姓名+参保地+增减类型）分组列出「同人多条」明细（各条出处 + 字段级差异 diff）；模板中命中同人多条的行，备注末尾追加 `【同人多条：另见 文件名】`，其余行备注保持原样。
- **D13 输出排序**：增员在前、减员在后，组内按（来源文件名, 行号）稳定排序。

### schema 固化（M2）

- **D14 schema 资产**：skill 包 `assets/schema.json` = 18 字段定义 + 约定文本 + `template_header` 别名数组（一个字段可对应多个表头写法）。指纹 = 规范化表头（去 `\n` 合并空白）哈希 + sheet 名；匹配→直接用，不匹配→一次 LLM 重抽并写回资产（只读部署降级为会话内使用+报告提示）。多租户不同模板天然共存（指纹索引，资产全局共享，不含 PII）。
- **D15 填充（纯代码零 LLM）**：不用 fill_with_sample；克隆模板 → 规范化表头匹配 `template_header` 得列绑定 → 逐行写值 → 数据行样式复制表头行（边框/字体/居中） → 终检（行数=合并记录数、18 列表头完整、无残留）。

### 交付（M5 后半）

- **D16 校验报告**：独立 `.md`（摘要：各来源抽取/写入/跳过数；明细：逐行 warning/error+原始行；去重与冲突决策），与 xlsx 一起 cp 注册；**不加第二 sheet**（防下游机读）。
- **D17 命名**：`{模板名}_汇总_YYYYMMDD-HHMM.xlsx` / `{模板名}_校验报告_YYYYMMDD-HHMM.md`。

### 计费与运行时

- **D18 计量**：管线所有 LLM 调用接 `record_background_llm_usage(source="excel_etl", stage=extract|schema_reextract)`（与 excel_router 同模式），保证公用云按任务对账。
- **D19 不走 ExcelRouter**：skill 直调库函数，省每次 ~0.75 积分路由费。

### 测试与验收

- **D20 黄金样例**：5 个样本文件 + 人工标注黄金 JSON（14 条）入 `tests/fixtures/excel_etl/`；验收 = 字段级全等（含日期格式/枚举归一/`_source`）。单测逐脏点断言：两行表头、多段重复表头、标题前置行、备注页脚、Excel 序列日期、重复列名、8 险种日期归并、脱敏身份证、多列比例合并。

### 业务拍板记录（2026-08-19，全部已定，设计无遗留歧义）

- ✅ **Q1 error 行处置**：修复 2 轮仍失败 → 不写入模板，进报告「人工处理清单」附原始行（宁漏勿错，防错身份证影响真人参保）。
- ✅ **Q2 同人多条**：不去重、不合并——两条都保留、每条标出处、报告按人分组提示异常（用户原话口径："一个人出现了两次那就是两条，每条知道出处，提示存在多条异常"）。
- ✅ **Q3 敏感数据**：方向 = **脱敏出域 + 回写还原**——身份证/手机号在发给 LLM 前替换为占位符（如 `[ID_7]`），抽取结果回写时代码按占位符映射表还原真值；LLM 全程不见真实证件号（本场景 LLM 对证件号只需照抄位置、无需理解内容，占位符往返可行；真加密无意义——模型读不了密文）。**具体脱敏方法（简单占位符 / 格式保留加密 FPE / AES 映射表）与覆盖字段范围（是否含姓名）后定**，M1 渲染层与 M8 还原层之间预留 `mask()/unmask()` 钩子接口，先以"手机号/身份证占位符"最简实现上线。

| per-user 邮箱凭据（DB 加密存储，设置页绑定） | ✅ `EmailCredentialDB` |

### 补充决议（D21~D24）

- **D21 email_read 增强**：返回结构加 `attachments: [{filename, content_type, size}]`（walk 一遍 disposition 即得，含 RFC2231/encoded-word 中文文件名解码，复用 `_decode_header_value`）；`since` 参数走 IMAP 服务器端 `SINCE` 条件（日期是 ASCII，可服务器端，解决月度批量定位）；`body_preview` 长度可调（默认 500）。
- **D22 新增附件下载能力**：`email_read` 加 `download_attachments` 参数（uid + 附件名过滤 + 目标目录），附件字节落盘到 skill_ws，返回本地路径列表；单附件大小上限 25MB；超大跳过并进报告。实现放 email_tool.py（与读取共用 IMAP 连接逻辑）。
- **D23 附件相关性判定（两级，skill M0 扩展）**：① 确定性预筛——扩展名 ∈ {.xlsx,.xls,.zip} 且文件名命中关键词（增减/社保/公积金/人员/变动/通知/派单/模板）→ 直接下载；② 未命中但邮件主题/正文相关的 → LLM 判定（主题+正文+附件清单，一次调用批量判定多封，输出 下载/跳过+理由）。**标准模板附件不期待来自邮件**（模板由用户会话内提供或 skill 资产内置），邮件只进来源报表。
- **D24 幂等与水位**：每次任务记录已处理邮件 UID 水位（skill 会话状态/输出目录 marker 文件），重复执行不重复下载重复抽取；BODY.PEEK 不标已读，保持邮箱状态无副作用。

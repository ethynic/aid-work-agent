# 测算：多源脏 Excel → 标准模板（每百条数据点数消耗基准）

> 2026-08-18。基准模型 **deepseek-v4-flash**（单价取自 `token_cost_prices`：输入 3.0 / 输出 9.0 / 缓存命中 0.1 元/百万 token）。
> **积分两本账（勿混用）**：
> - **扣费端**：`积分 = token 成本(元) × usage_factor(100)`（`calculate_credit_cost`）→ **1 积分 = 0.01 元 API 成本**；
> - **充值端**：默认 **1 元 = 10 积分**（`tenant-credit-billing-design.md` §充值，管理员可调）→ **1 积分 = 0.1 元 售价**。
> - 两边之差即系统内含 **10 倍毛利**：1 元 API 成本扣 100 积分，客户充值面值 10 元。
> Token 实测：样本 5 文件按"LLM 视图"渲染后用 tiktoken o200k_base 计数（DeepSeek tokenizer 近似，±20~30%）。

## 0. 结论（每 100 条记录）

| 方案 | 消耗（积分） | API 成本（元，×0.01/积分） | 充值面值（元，×0.1/积分） |
|---|---|---|---|
| **skill 管线（推荐架构，缓存命中 80%）** | **≈ 25~28 积分** | ≈ 0.25~0.28 | ≈ 2.5~2.8 |
| skill 管线（无缓存，保守上界） | ≈ 39 积分 | ≈ 0.39 | ≈ 3.9 |
| 敏感性上界（输出冗长 + 修复率翻倍 + 无缓存） | ≈ 50 积分 | ≈ 0.50 | ≈ 5.0 |

**单条记录：扣费 0.25~0.5 积分 = API 成本 0.0025~0.005 元 = 充值面值 0.025~0.05 元**。按现有 1 元=10 积分充值价直接扣，系统已含 10 倍毛利，无需再加价即可盈利；若想更高毛利再上浮积分单价，见 §4。

## 2. 分阶段消耗模型（100 条，skill 管线架构）

| 阶段 | 调用量 | 输入 tokens | 输出 tokens | 积分 |
|---|---|---|---|---|
| M2 schema 抽取 | **仅首次/模板变更时 1 次**，指纹匹配（纯代码）后固化复用 | ≈ 1k | ≈ 0.5k | 摊销后 ≈ **0** |
| M3 抽取（50 行/块） | 2 次调用 | 2×(573 schema prompt + 950 表头×5Sheet + 4050 行) ≈ **11.2k** | 2×50×140 = **14k** | in 3.4 + out **12.6** = **16.0** |
| M4 修复回路（10% 记录×1 轮） | 10 条 | 10×(81 原行 + 140 记录 + 50 错误 + 150 指令) ≈ **4.2k** | **1.4k** | **2.5** |
| 填充（schema 固化后列绑定确定） | 0 次（纯代码） | 0 | 0 | **0** |
| 编排会话（约 5 轮 agent 循环） | 5 次 | 系统提示+工具 schema+历史 ≈ 40~60k（**缓存命中后按 20% 计费**） | ≈ 2k | 缓存 80%：**6**；无缓存：**19.8** |
| **合计** | | | | **缓存 24.5 / 无缓存 38.4**（四舍五入仍按 25 / 39 计） |

要点：
- **schema 固化（用户确认）**：目标模板稳定，schema 一次抽取固化为资产，按模板指纹（sheet 名+表头哈希）匹配复用，模板不变永不重抽；摊销成本 ≈ 0。注意 573 token 的字段约定文本**仍随每次抽取调用进 prompt**（模型必须看到 18 字段定义才能映射），这是刚性输入，固化省的是"生成 schema"和"填充前结构分析"两次调用。
- **输出 token 是大头**（抽取 14k 输出 = 12.6 积分，占一半）。18 字段全量 JSON 每条 140 token 不可省——null 字段也必须显式输出才能机器校验。
- **编排开销第二大且最不确定**（系统提示词 + 工具 schema 每轮重发）。DeepSeek 上下文缓存把这部分压到 ~6 积分，但缓存命中率需真机校准。
- 渲染层（M1）、合并去重（M5）、校验（M4 规则部分）、填充写入均为纯代码，**零积分**。
- 抽取调用必须**关闭 thinking**（参照 d5efc61b 教训：DeepSeek 思考耗尽输出配额），否则输出 token 翻倍以上。
- 走 excel_process 内部 ExcelRouter 每次多一次路由 LLM 调用（~1k in / 0.5k out ≈ 0.75 积分/次）——skill 直连管线可避开，全程省 5~10 积分。

## 3. 敏感性

| 变量 | 基准 | 变化 → 积分影响 |
|---|---|---|
| 单条输出 | 140 t | 200 t → +5.4 积分 |
| 修复率 | 10%×1 轮 | 20%×2 轮 → +5 积分 |
| Sheet 数 | 10 个 | 20 个（表头×2）→ +1.5 积分 |
| 缓存命中 | 80% | 0% → +14 积分 |
| 上面全叠加 | — | **≈ 50 积分/百条封顶** |

样本实测锚点：本 zip（14 条、8 Sheet）抽取+修复 ≈ 6~7 积分 + 编排 ≈ 6~20 积分，单次任务 12~27 积分。

## 4. 公用云报价建议

- 成本基准：每 100 条扣费 25~50 积分 = API 成本 0.25~0.5 元 = 充值面值 2.5~5 元（1 元=10 积分）。
- **按现有充值价（1 积分=0.1 元）直接扣已是 10 倍毛利**；对外报价可直接用积分面值：**25~50 积分/百条 → 0.25~0.5 积分/条（面值 0.025~0.05 元/条）**，定价留安全余量可定 **50~100 积分/百条（面值 5~10 元/百条）**。
- 包月模式按每月增减员总量折算：500 条/月 → 扣费 125~250 积分（面值 12.5~25 元），可报 50~100 元/月功能费。
- 两点报价保护：① 编排开销与文件数相关而与条数弱相关，**文件多、每文件条数少的客户单价更高**（可设按文件 2~5 积分/文件 + 按条 0.25~0.5 积分/条 双因子）；② 新供应商格式首次解析含试错（修复率升），首月可上浮。
- 需真机校准后再冻结报价：跑一次真实任务记录 `usage_breakdown`（缓存命中率、真实输出 token、agent 轮数），把 §2 的编排行替换为实测值。

## 5. 校准方法（上线前执行一次）

1. 用本 zip 5 文件 + 标准模板走一遍完整 skill 管线（M1 渲染 → M3 抽取 → M4 校验修复 → 填充 → cp 交付）。
2. 从 `chat_records.usage_breakdown` 取各轮 prompt/completion/cached tokens，按 `calculate_credit_cost` 复算积分。
3. 把实测值回填本文档 §2 表格，冻结报价基准；后续每季复核一次单价表。

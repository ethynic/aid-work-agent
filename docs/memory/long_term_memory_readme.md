# 长期记忆系统

> 让智能体"记住"每个用户的偏好、习惯和重要信息，提供个性化服务。

## 概述

长期记忆系统在用户日常对话中自动提取值得记住的信息，持久化为 Markdown 文件。每次用户发消息时，相关记忆会被注入到系统提示词中，使智能体具备跨会话的个性化能力。

**核心能力**：
- 自动从每日对话中提取用户偏好、习惯、业务知识等
- 支持用户主动要求"记住"特定事项
- 回复风格个性化（如用户设定"拟人风格"后全局生效）
- 记忆按优先级注入上下文，超限时自动截断

## 工作方式

记忆写入有三种途径：

| 途径 | 触发方式 | 写入内容 |
|------|---------|---------|
| 每日自动总结 | 凌晨 2:00 定时任务 | LLM 分析当天对话，提取偏好/习惯/业务知识等 |
| 用户主动要求 | 对话中说"帮我记住..." | 原文写入"用户明确要求记住的事项"分类 |
| API 手动编辑 | `PUT /api/v1/memory/long-term` | 用户自行编辑完整记忆文件 |

### 自动总结流程

```
APScheduler 每日 02:00 触发
  → 查询当天有活跃会话的用户列表（最多 50 人）
    → 逐个用户：
      1. 从数据库收集当天对话（用户问题 + 助手回答）
      2. 读取用户现有记忆文件
      3. 调用 LLM 提取值得记忆的信息
      4. 增量合并到记忆文件（检测冲突，相同前缀的条目会被替换）
```

### 对话注入流程

```
用户发送消息
  → Agent 构建 system_prompt 时调用 _load_long_term_memory()
    → 读取用户记忆文件
    → 按优先级排序分类，截断到 max_inject_tokens（默认 2000）
    → 以 [用户记忆] 标记注入 system_prompt
```

注入优先级（从高到低）：
1. 用户明确要求记住的事项
2. 语言偏好
3. 工作习惯
4. 常用联系人
5. 个人介绍
6. 其他分类

## 记忆文件格式

文件路径：`storage/memory/{tenant_id}/memory_{user_id}.md`

```markdown
# 用户记忆

> 最后更新: 2026-05-26 02:00
> 更新来源: 系统自动

## 用户明确要求记住的事项

- 回复风格：human-like
- 合同审批金额超过 50 万需要走特批流程

## 工作习惯

- 每天上午查看邮件，下午处理订单
- 常用工具：Excel、企业微信

## 常用联系人

- 张明（采购部经理，内线 8023）
- 李薇（财务部，负责报销审批）

## 个人介绍

- 职位：外贸业务主管
- 部门：海外业务部
```

**冲突合并规则**：以冒号分隔的 key-value 条目（如"姓名：张三"），相同 key 的旧条目会被新条目替换；无 key 的条目直接追加。

## 回复风格

用户可以通过对话设置回复风格，该设置存储在长期记忆中，优先级最高。

**设置方式**：
- "帮我记住回复风格是拟人"
- "记住用 human-like 风格回复"
- "记一下用正式风格回答"

**优先级**（从高到低）：
1. 用户长期记忆中的 reply_style
2. 子智能体配置的 reply_style
3. 全局默认 reply_style（config.yaml）

## 配置

在 `configs/config.yaml` 中：

```yaml
memory:
  long_term:
    enabled: true               # 总开关
    storage_dir: "storage/memory"   # 记忆文件存储目录
    summary_cron: "0 2 * * *"       # 自动总结执行时间（Cron）
    max_users_per_run: 50           # 单次总结最多处理用户数
    max_inject_tokens: 2000         # 注入上下文的最大 token 数
```

代码默认值 `enabled: false`，部署配置中显式设为 `true`。

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/memory/long-term` | 获取当前用户记忆文件 |
| PUT | `/api/v1/memory/long-term` | 更新当前用户记忆文件 |

两个接口均需要登录认证（`get_current_user`），自动按 `tenant_id` 隔离。

## 相关文件

| 文件 | 职责 |
|------|------|
| `src/memory/long_term.py` | 长期记忆文件存储层（读写、合并、注入格式化） |
| `src/memory/memory_summarizer.py` | 每日自动总结（收集对话 → LLM 提取 → 增量合并） |
| `src/memory/manager.py` | 统一记忆管理器（短期 + 中期 + 长期） |
| `src/scheduler/manager.py` | APScheduler 调度，注册和执行每日记忆总结任务 |
| `src/api/memory.py` | 长期记忆 REST API（查看/编辑） |
| `src/config/settings.py` | `LongTermMemoryConfig` 配置模型 |
| `src/core/agent.py` | 记忆注入 system_prompt、remember 意图检测、回复风格解析 |

## 多 Worker 部署注意事项

定时任务使用 Redis 分布式锁（`scheduled_task_manager:lock`），确保多个 Gunicorn Worker 中只有一个会执行记忆总结任务。锁有效期 300 秒，定时任务 `misfire_grace_time` 为 300 秒。

如果 Redis 不可用，分布式锁获取失败时仍会继续启动调度器（日志会有 warning），此时可能出现多 Worker 重复执行（幂等的 merge 操作不会导致数据损坏）。

## LLM 提取规则

自动总结时，LLM 会提取以下类型的信息：
1. 用户明确要求记住的事项
2. 用户的个人特征（职位、部门、职责）
3. 用户的偏好（回复风格、语言、格式）
4. 用户的工作行为习惯（常用工具、工作流程、时间段）
5. 用户提及的业务知识和规则
6. 用户频繁联系的同事或客户

**不会提取**：一次性任务、临时性上下文、敏感信息（密码/密钥/身份证号）。

## 限制

- 单次总结最多处理 50 个用户（`max_users_per_run`）
- 每个用户的对话内容截取前 8000 字符发送给 LLM
- 现有记忆文件截取前 3000 字符作为上下文
- 每条消息截取前 500 字符
- 注入 system_prompt 的记忆最多 2000 token
- 无手动触发记忆总结的 API（仅定时执行）

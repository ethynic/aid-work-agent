# 研学报价技能稳定性优化设计（方案 A：Prompt 规则固化）

> **关联开发计划**：[plan-travel-quote-prompt-stability.md](../../plans/plan-travel-quote-prompt-stability.md)
> **关联技能**：`src/skills/travel-quote/`
> **登记**：[docs/ideas.md](../ideas.md)

## 一、背景

同一份行程方案文本，连续两次调用 `travel-quote` 技能，输出的人均报价差距较大（实测从 1,861 元漂到 2,045 元，差额 184 元），其中：

- **用车费用**：从 79.39 元/人 漂到 121.53 元/人（差距 53%）
- **门票项目**：第二次多出"水族马尾绣"项目（118 元 × 30 = 3,540 元）

经定位，根因在于 `itinerary_parser.py` 的 prompt 对三个高方差环节的口径定义模糊，导致 LLM 即便 `temperature=0`，每次抽样仍可能落到不同分支：

1. **用车段提取**：未规定"景区内酒店↔景点当天往返"是否计入；起止点 POI 名称（如"天眼景区"vs"中国天眼科普基地"）归一不一致，落到高德 API 不同坐标点，里程漂移。
2. **可选项目判定**：行程文本中带"可选"、"自由活动"、"自理"的项目是否计入 `activities`，无规则。
3. **POI 名称归一**：`from`/`to` 用景区内具体 POI 还是城市/区县，由 LLM 自由决定。

## 二、设计目标

- **同输入 → 同输出**：对完全相同的 `itinerary_text`，多次调用 `travel-quote` 技能，用人均报价差异 ≤ 0.1 元
- **不破坏现有解析能力**：保留 LLM 提取景点/酒店/团队结构的能力
- **零结构变更**：不改 `generate.py` 主流程、不改 `vehicle.py`/`attraction.py` 等模块接口

## 三、方案设计

### 3.1 用车段（daily_routes）口径

**规则**：

1. **只提取行程中明确写明跨城/跨区的长途移动段**，触发关键词（任一即可）：
   - "乘车前往"、"前往"、"抵达"
   - "约 X 小时车程"、"约 Xkm"、"X 公里"
   - 出发/结束日的"接站"、"送站"
2. **不提取**以下段：
   - 同一天内的酒店↔景区往返（视为景区内活动）
   - 行程中只写"入住"、"自由活动"、"休息"的段
   - `from == to` 的段（已有过滤）
3. **起止点用城市/区县名**，不用景区内具体 POI：
   - ✅ "贵阳市区 → 平塘县"
   - ✅ "平塘县 → 荔波县"
   - ❌ "平塘酒店 → 天眼景区"（同一天往返，不提取）
   - ❌ "中国天眼科普基地 → 南仁东事迹馆"（景区内子场馆，不提取）

### 3.2 可选项目（activities）口径

**规则**：

- 行程文本中出现以下字样的项目，**不写入** `activities`，仅作为该景点的备注信息：
  - "可选"、"自由活动"、"自理"、"或"、"建议"、"另行付费"
- 必须明确写"含"、"已含"、"安排"、"体验"的项目，才写入 `activities`

### 3.3 景点合并口径（已有，强化）

行程文本里出现的同一景区的子场馆（如"天文体验馆"、"南仁东事迹馆"、"FAST观景台"都属于"中国天眼科普基地"）必须合并为一个景点。此项 prompt 已有规则，但 LLM 有时会拆开。强化为：**输出前自检 `daily_attractions` 中是否存在同一景区的重复条目**。

## 四、改动文件

|------|------|
| `src/skills/travel-quote/scripts/itinerary_parser.py` | 重写 prompt 第 2、7、8 条规则，加入用车段提取规则、可选项目规则、POI 归一规则 |

## 五、验证方案

使用用户提供的实际行程（贵州天眼+荔波6天5晚）作为测试样本，连续调用 3 次，验证：

1. 三次输出的 `parsed.daily_routes` 完全一致（段数、起止点、预计里程范围）
2. 三次输出的 `parsed.daily_attractions[].activities` 完全一致
3. 三次最终人均报价差额 ≤ 0.1 元

## 六、已知限制

- 方案 A 只解决"LLM 口径"方差，**无法解决**高德 API 对同一 POI 名返回不同坐标的小概率方差（实测中"天眼景区"在不同时段查询可能落在游客中心或核心区）。如果 POI 归一到城市/区县级，此项方差可忽略。
- 不引入缓存（方案 B 留待后续），每次仍走 LLM。但 prompt 规则固化后，期望方差收敛到 0。

## 七、追加优化：返回结构精简（2026-06-16）

### 7.1 背景

方案 A 上线后，输入侧方差收敛，但**输出侧**出现新问题：

> AI 对生成的报价单做的总结文字，总是和 Excel 报价单中的内容**对不上**。

经分析，根因是 skill 返回的 JSON 字段结构与 Excel 表头脱钩：

| 旧字段名 | 实际含义 | LLM 误解风险 |
|---------|---------|-------------|
| `items[].subtotal` | Excel "费用小计"列（本行人均） | "subtotal"字面像"小计"，LLM 容易当成总价 |
| `items[].teacher_subtotal` | Excel "随队老师"列（本行老师费用） | "subtotal"字面像"老师合计"，LLM 容易当成总价 |
| `items[].unit_price`/`quantity`/`frequency` | Excel "单价/数量/次数"列 | LLM 会自行计算 `unit_price × quantity × frequency`，与"费用小计"对不上 |
| `price_per_person`/`total_price` | 人均报价/总价 | 字段名英文，LLM 不能确定是否含老师 |
| `teacher_total` | 老师成本合计 | 容易被 LLM 重复计入总价 |
| `region_name` | 区域名 | 客户已知，多余 |

LLM 看到 `subtotal=79.39`、`unit_price=2381.85`、`quantity=1`、`frequency=1` 时，无法判断"79.39 是这一行的什么数"（人均？总价？含老师？），就会自己脑补一个解读，于是和 Excel 的口径对不上。

### 7.2 方案：返回结构按 Excel 表头对齐

把 `data.items` 改为 `data.rows`，字段名**直接用 Excel 中文表头**：

```json
{
  "rows": [
    {
      "成本类别": "用车",
      "项目": "38座大巴",
      "单价": 2381.85,
      "数量": 1,
      "单位": "辆",
      "次数": 1,
      "单位2": "趟",
      "费用小计": 79.39,
      "随队老师": 0,
      "备注": "..."
    }
  ],
  "合计_费用小计": 809.39,
  "合计_随队老师": 2880.00,
  "人均报价": 2223.33,
  "总价": 66699.90,
  "file_path": "..."
}
```

**核心原则**：让 LLM 看到的字段名和 Excel 表头**完全一致**，LLM 只需"复读"，不需要理解或换算。

### 7.3 改动文件

| 文件 | 改动 |
|------|------|
| `src/skills/travel-quote/scripts/generate.py` | `return` 字段重构：items→rows（中文字段），新增合计_费用小计/合计_随队老师，price_per_person/total_price→人均报价/总价，删除 region_name/teacher_total |
| `src/skills/travel-quote/SKILL.md` | 输出格式示例更新 + 字段含义对照表 + "收到结果后的操作"改为"严格按 rows 字段复述，不要自行换算" |

**计算逻辑完全不变**，`internal_data`（传给 Excel 导出的完整数据）保持原样，只改 `return` 给 LLM 的视图。

### 7.4 验证

通过单元测试（不连数据库）模拟 5 行 items 数据走 return 重构逻辑，验证：

- ✅ rows 字段名完全对应 Excel 表头（成本类别/项目/单价/数量/单位/次数/单位2/费用小计/随队老师/备注）
- ✅ 合计_费用小计 / 合计_随队老师 正确累加
- ✅ 旧英文字段全部清除

## 八、追加优化：三个修复（2026-06-16）

### 8.1 问题1：人均报价与总价÷人数不恒等

**现象**：用户实测发现 `人均报价 × 人数 ≠ 总价`，存在 0.5 元以内的取整误差。

**根因**：原计算 `quote_per_person = round(cost_per_person * (1 + profit_rate), 2)`、`quote_total = round(quote_per_person * total_people, 2)` 是"先算人均再乘人数"，两步分别 round 会累积误差。

**修复**：改为"先算总价，再回推人均"：

```python
quote_total = round(cost_per_person * (1 + profit_rate) * total_people, 2)
quote_per_person = round(quote_total / total_people, 2) if total_people > 0 else 0.0
```

**验证**：5 组测试用例（1人 / 7人 / 11人 / 30人 / 3人小数成本），全部满足 `人均报价 × 人数 == 总价`（误差 < 0.005）。

### 8.2 问题2：AI 回复对客户提及"成本"/"利润"

**现象**：AI 总结报价时出现"人均成本约 1163 元，加利润后人均报价 1337 元"等字眼，对外暴露了内部定价机制。

**根因**：

1. SKILL.md 的参数表把 `profit_rate` 描述为"利润率（默认 15%）"，LLM 看到后会把"利润率"叙事带入回复
2. SKILL.md 的"注意事项"里有"profit_rate 为 null 时使用默认 15%"
3. 没有明确的"对客户回复口径"硬约束

**修复**：

| 位置 | 改动 |
|------|------|
| SKILL.md 参数表 | `profit_rate` 描述改为"内部定价参数（外部调用方无需关注，由系统配置）" |
| SKILL.md 注意事项 | 删除"默认 15%"字样 |
| SKILL.md 新增章节「⚠️ 对客户的回复口径」 | 三条硬约束：① 只说报价，禁止提"成本/利润/利润率/加价后/加利润后" ② 不要解释定价机制 ③ 不要拆分"费用小计"，"成本类别"是模板固定列名，对客户说"用车/门票/住宿" |

### 8.3 问题3：LLM 脑补儿童票（半价推算）

**现象**：天眼景区价格表只有"成人 140"一行，LLM 看到团队含学生，**自行脑补**返回 `儿童票 70`（按 140÷2 推算）。

**根因**：`attraction.py` 的 `_llm_extract_tickets` prompt 没有明确禁止按比例推算价格，LLM 默认会"补全"缺失票种。

**修复**：在 prompt 中加入第 4-6 条硬规则：

1. **严格按价格表提取**：价格表明确写了什么票种就只返回这些，没有的票种绝对不返回、绝对不按比例推算
2. 列举三种典型禁止场景：
   - ❌ 禁止"140÷2=70"半价推算
   - ❌ 禁止"140×0.5=70"比例推算
   - ❌ 禁止"老人免票"脑补
3. 团队构成信息**只用于判断是否返回某票种**（人数为 0 则不返回），**绝不用于推算价格**
4. 给出 ✅ 正确样例：价格表只有"成人 140"一行时，无论团队构成如何，都只返回一条 adult 票

### 8.4 改动文件

| 文件 | 改动 |
|------|------|
| `src/skills/travel-quote/scripts/generate.py` | 人均报价计算改为"先总价后人均"，确保恒等 |
| `src/skills/travel-quote/SKILL.md` | 参数表 profit_rate 描述改写、注意事项删默认值、新增对客户回复口径硬约束 |
| `src/skills/travel-quote/scripts/attraction.py` | `_llm_extract_tickets` prompt 新增禁脑补规则 |

### 8.5 验证

通过单元测试（不连数据库）验证：

- ✅ 修复1：5 组人数×成本用例，`人均报价 × 人数 == 总价` 全部成立
- ✅ 修复2：SKILL.md 非禁令上下文已无"利润率/加利润/默认 15%/0.15"字样；新增对客户回复口径硬约束
- ✅ 修复3：attraction.py prompt 包含"严禁 140÷2=70"、"严禁 140×0.5"、"严禁老人免票"、"严格按价格表提取"四类标记

## 九、追加优化：行程景点约束 + 用车段防漏（2026-06-16）

### 9.1 问题4：行程中出现知识库不存在的景点

**现象**：travel-consultant 子智能体生成行程时，会脑补知识库中不存在的景点（如"黔灵山公园"、"甲秀楼"），导致后续 travel-quote 报价时这些景点匹配不上，且其本应有的项目也因为景点不在知识库而丢失。

**根因**：SUBAGENT.md 已有"信息必须来自知识库"的总原则，但缺少**可执行的硬约束**：
- 没有明确"行程景点名必须与 attraction_search 返回的 title 完全一致"
- 没有提供 ✅/❌ 反例
- 缺少输出前的自检步骤

**修复**：在 SUBAGENT.md 三处加硬约束（采用「搜索原则 + 详细行程格式 + 输出自检」组合方案）：

| 位置 | 改动 |
|------|------|
| 搜索原则 - 第二步 | 加"必须记住本次搜索返回的所有景点 title（白名单）"；`project_table` 为空时游玩项目写"—"，**不允许编造** |
| 详细行程格式 - 各列填写规则 | 加两条硬约束：① 行程安排列景点必须来自搜索结果 title ② 游玩项目列必须来自该景点 project_table；附 ✅/❌ 反例 |
| 详细行程输出步骤 - 第1步 | 加"输出前必须自检"：逐一比对景点名和项目名是否都在白名单内，未通过自检的行程**禁止输出** |

### 9.2 问题5：跨城用车段被漏提取

**现象**：贵州荔波小七孔4天3晚行程（D1 贵阳→荔波约3小时车程、D3 荔波→贵阳约3小时车程）实际报价时车费为 0。

**根因**：itinerary_parser.py 第 7 条 prompt 只说"跨城/跨区长途移动段"，但当同一天上午在市内景点（如黔灵山公园）、下午才跨城时，LLM 容易把整天的所有移动都判定为"市内活动"而漏掉跨城段。

**修复**：在 itinerary_parser.py 第 7 条 prompt 加：
- 跨城判定关键词组合（"乘车前往"+"另一城市名"、"约 X 小时车程"）
- "不要因为当天有市内活动就漏掉跨城段"的显式提醒
- 两个具体的 ✅ 必须提取示例（D1 贵阳→荔波、D3 荔波→贵阳）
- "输出前自检"步骤：扫描所有跨城关键词，每个都应在 daily_routes 中有对应段

| `src/skills/travel-quote/scripts/itinerary_parser.py` | 第7条 prompt 加跨城关键词组合、漏提场景反例、输出前自检 |

## 十、追加优化：subtotal 字段语义统一为团队人均（2026-06-16）

### 10.1 问题6：subtotal 字段口径在不同行不一致

**现象**：用户用荔波4天3晚亲子游（1成人+1儿童4岁）测试，发现工具返回的"合计_费用小计=1703.08、人均报价=1958.54、总价=3917.08"与按"单价×数量×次数"累加得到的"总价=3186.16、人均=1593.08"对不上。

**根因**：`subtotal` 字段在不同模块里含义不统一：

| 行类型 | 旧公式 | 是否为团队人均 |
|--------|--------|---------------|
| 用车 per_km | 行总价 ÷ 人数 | ✓ |
| 用车 daily | 行总价 ÷ 人数 | ✓ |
| 门票 per_person | 单价 | ❌（当只有 1 人买票、其他人免票时，未÷人数） |
| 项目 per_group | 单价 ÷ 人数 | ✓ |
| 项目 per_person | 单价 | 数学等价（数量=总人数，÷人数后=单价） |
| 酒店 | 单价/2 × 夜数 | ❌（未按"间"计费，公式不统一） |
| 餐饮 | 单价 × 餐数 | 数学等价（数量=总人数，÷人数后=单价×餐数） |
| 导游 per_trip | 单价 | ❌（按团计费未÷人数） |
| 导游 daily | 单价 × 天数 | ❌（按日计费未÷人数） |
| 其他 per_person | 单价 | 数学等价 |
| 其他 per_person_per_day | 单价 × 天数 | 数学等价 |
| 其他 per_trip | 单价 ÷ 人数 | ✓ |
| 其他 per_vehicle_per_day | 单价 × 车数 × 天数 ÷ 人数 | ✓ |

5 处实质错误（门票、酒店、导游×2、隐式口径），其他是数学等价但代码不自解释。

### 10.2 统一规则

**subtotal = 团队人均 = 该行总价 ÷ total_people**

各行总价公式：

| 行类型 | 行总价公式 |
|--------|----------|
| 用车 per_km | 整车公里总价（已是整车价） |
| 用车 daily | 日租金 × 车数 × 天数 |
| 门票 | 单价 × 该票型人数 |
| 项目 per_group | 单价（团价） |
| 项目 per_person | 单价 × 总人数 |
| 酒店 | 单价 × ceil(总人数/2) × 夜数（按"间"计费，2人一间） |
| 餐饮 | 单价 × 总人数 × 餐数 |
| 导游 per_trip | 单价（团价） |
| 导游 daily | 日薪 × 天数 |
| 其他 per_person | 单价 × 总人数 |
| 其他 per_person_per_day | 单价 × 总人数 × 天数 |
| 其他 per_trip | 单价（团价） |
| 其他 per_vehicle_per_day | 单价 × 车数 × 天数 |

恒等式：**subtotal(人均) × total_people = 行总价**

| 文件 | 改动 |

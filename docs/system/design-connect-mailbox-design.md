# 连接邮箱设计

> 状态：Phase 1 开发完成（2026-11-24），已提交到分支 `dev/connect-mailbox`，等待合并 `master`。第一版（QQ、163、自定义）确认后，按反馈增加企业邮箱和两个预留位，并确定「同一品牌的多套服务器由系统自动尝试，不让用户选」「预留位接入前不显示」。开发安排与遗留见[开发计划](../plans/plan-connect-mailbox.md)。
> 交互设计稿：[prototypes/connect-mailbox/index.html](../prototypes/connect-mailbox/index.html)，双击即可在浏览器打开。

## 1. 背景与目标

个人邮箱配置现在在「设置」弹窗的「邮箱设置」页签（`SettingsDialog.vue`），是一张 9 项的表单：邮箱地址、SMTP 服务器 / 端口 / 用户名 / 密码 / 加密、IMAP 服务器 / 端口 / 加密。普通员工不知道这些参数从哪里来，QQ 邮箱、163 邮箱这类常见邮箱也得自己查。

本次把个人邮箱配置搬到连接中心，按邮箱品牌做成简单入口：

- 个人邮箱：QQ邮箱、163邮箱点开只填账号和授权码；Outlook、iCloud 邮箱先预留位置。
- 企业邮箱：腾讯企业邮箱、网易企业邮箱点开只填地址和密码或授权码；其他企业邮箱走「自定义邮箱」，默认只填 4 项。
- 沿用现有行为：每个用户 1 个邮箱；保存前先发一封测试邮件；密码和授权码加密保存、不回显。

## 2. 范围

本期：

- 用户个人邮箱，对应表 `user_email_settings` 和接口 `/api/email-settings`。
- 品牌预设：QQ邮箱、163邮箱、腾讯企业邮箱、网易企业邮箱。

不在本期（见第 5 节待确认）：租户共用邮箱（租户设置页的「租户邮箱」卡片）、一人多个邮箱、网页授权登录（OAuth）、校验收件（IMAP）登录。Outlook、iCloud 邮箱只预留位置，参数另行调研。

## 3. 方案要点

### 3.1 入口

| 位置 | 做法 |
|---|---|
| 连接中心子菜单 | 新增「连接邮箱」，全体员工可见，排在「外部系统」之后 |
| 页面 | `/t/:tenant_id/connections/email`，独立页面，`AppHeader` 标题「连接邮箱」，内容区居中最宽 896px（与「微信 Agent」同一模式） |
| 旧入口 | 移除「设置」弹窗里的「邮箱设置」页签，弹窗只保留「基础设置」 |
| 手机端 | 不变。现有手机端侧栏不显示连接中心入口，也不显示设置入口 |

### 3.2 品牌预设

品牌卡片分两组，每组一行（宽屏四列）：

| 分组 | 卡片 | 账号形式 |
|---|---|---|
| 个人邮箱 | QQ邮箱、163邮箱、Outlook（预留）、iCloud 邮箱（预留） | 域名固定，只填前缀 |
| 企业邮箱 | 腾讯企业邮箱、网易企业邮箱、自定义邮箱 | 企业自己的域名，填完整地址 |

企业邮箱组标题下有一句提示：「公司邮箱一般使用企业自己的域名。不确定是哪家，可以看平时登录邮箱的网址。」

**域名固定的品牌**

| 品牌 | 用户填写 | 发件服务器（SMTP） | 收件服务器（IMAP） | 登录凭据 |
|---|---|---|---|---|
| QQ邮箱 | QQ 号，补全为 `@qq.com` | `smtp.qq.com` 465 SSL | `imap.qq.com` 993 SSL | 16 位授权码 |
| 163邮箱 | 账号名，补全为 `@163.com` | `smtp.163.com` 465 SSL | `imap.163.com` 993 SSL | 客户端授权密码 |

**企业邮箱品牌**（地址都是完整的企业邮箱地址；同一品牌的多套服务器按表中顺序依次尝试，成功即停）

| 品牌 | 尝试顺序 | 发件服务器（SMTP） | 收件服务器（IMAP） | 登录凭据 |
|---|---|---|---|---|
| 腾讯企业邮箱 | 1 通用 | `smtp.exmail.qq.com` 465 SSL | `imap.exmail.qq.com` 993 SSL | 邮箱密码；已开启「安全登录」的填客户端专用密码 |
| 腾讯企业邮箱 | 2 信创 | `xcsmtp.exmail.qq.com` 465 SSL | `xcimap.exmail.qq.com` 993 SSL | 同上 |
| 网易企业邮箱 | 1 付费版 · 华北 | `smtp.qiye.163.com` 465 SSL | `imap.qiye.163.com` 993 SSL | 客户端授权码 |
| 网易企业邮箱 | 2 付费版 · 华东 | `smtphz.qiye.163.com` 465 SSL | `imaphz.qiye.163.com` 993 SSL | 客户端授权码 |
| 网易企业邮箱 | 3 免费版 | `smtp.ym.163.com` 994 SSL | `imap.ym.163.com` 993 SSL | 邮箱密码 |

规则：

- **凭据是授权码或专用密码，不一定是登录密码。** QQ 邮箱、163 邮箱登录第三方客户端必须用授权码，直接填登录密码会被拒绝，所以字段写成「授权码」。网易企业邮箱付费版必须用客户端授权码，免费版没有授权码、直接用密码，所以字段写成「授权码 / 密码」。腾讯企业邮箱默认用密码，开启了「安全登录」的要在邮箱设置里生成客户端专用密码，字段写成「密码 / 客户端专用密码」。
- **个人邮箱的账号只填前缀。** 输入框右侧固定显示 `@qq.com` / `@163.com`，下方实时显示「将连接 xxx@qq.com」。直接填完整地址也可以；填了其他域名时提示改用对应的品牌或「自定义邮箱」。
- **企业邮箱填完整地址。** 地址用企业自己的域名，不限定后缀。
- **服务器参数用户不可见**，由系统带入。接口 `POST /api/email-settings` 仍接收原来的 9 项，品牌到参数的映射由前端完成，接口契约不变。
- **不让用户选服务器。** 同一个品牌有多套服务器时（腾讯企业邮箱：通用、信创；网易企业邮箱：付费版华北、付费版华东、免费版），由系统依次用用户填的地址和凭据去尝试，哪一套成功就用哪一套发测试邮件并保存。用户不知道、也不该判断自己在哪一套，界面不提供任何选择。全部失败就按「填写内容有误或邮箱没有开通权限」处理，提示里讲清楚怎么填、需要管理员开通什么。

填写和开通的步骤（放在弹窗内可展开的说明里，样式沿用 `HelpExpand`；个人邮箱的入口是「如何获取授权码？」，企业邮箱的入口是「怎么填写和开通？」）：

| 品牌 | 步骤 | 官方说明 |
|---|---|---|
| QQ邮箱 | 登录网页版 mail.qq.com → 「设置 → 账号」→ 开启「IMAP/SMTP 服务」，按提示完成短信验证 → 复制生成的 16 位授权码 | https://service.mail.qq.com/detail/0/428 |
| 163邮箱 | 登录网页版 mail.163.com → 「设置 → POP3/SMTP/IMAP」→ 开启「IMAP/SMTP 服务」，按提示完成手机验证 → 复制生成的授权密码 | http://u.163.com/cyqCpfaYf |
| 腾讯企业邮箱 | 怎么填：登录网页版 exmail.qq.com（或从企业微信进入邮箱）→ 「设置 → 收发信设置」开启「IMAP/SMTP 服务」→ 没开启「安全登录」的填邮箱密码，已开启的到「设置 → 邮箱绑定」生成客户端专用密码。怎么开通：服务勾选不了时，请公司邮箱管理员到企业微信管理端「协作 → 邮件 → 安全管理 → 客户端访问权限」开启 | https://open.work.weixin.qq.com/help2/pc/19886 |
| 网易企业邮箱 | 怎么填：登录网页版 qy.163.com → 「设置 → 账户与安全 → 客户端设置」→ 生成客户端授权码（只显示一次）；免费企业邮箱（ym.163.com）没有授权码，直接填密码。怎么开通：提示没有权限时，请公司邮箱管理员在邮箱后台为这个账号开启 IMAP、SMTP 权限 | https://office.163.com/helpCenter/mail/d/2057123645218729986.html |

**预留位置**：Outlook、iCloud 邮箱各占一张卡片，原型里用虚线边框和「预留」标记表示，不可点击。参数没有调研，本期不接入；上线时不显示这两张卡片，代码里保留位置，调研完参数再上。

### 3.3 自定义邮箱

默认只显示 4 项：邮箱地址、密码 / 授权码、发件服务器（SMTP）、收件服务器（IMAP）。

端口、加密方式、SMTP 用户名收进「高级设置」，默认折叠：SMTP 端口 465、SMTP 加密 SSL、IMAP 端口 993、IMAP 加密 SSL、SMTP 用户名默认同邮箱地址。加密方式的三个选项沿用现有表单的文字。

### 3.4 交互设计

页面有两个状态：

| 状态 | 内容 |
|---|---|
| 未连接 | 「我的邮箱」卡片：一句说明 + 个人邮箱、企业邮箱两组品牌卡片 + 一行说明（每个账号连接 1 个邮箱，连接新的会替换当前的） |
| 已连接 | 「我的邮箱」卡片：邮箱地址、品牌、连接时间、「已连接」状态，操作「重新连接」「断开连接」；下方「更换邮箱」卡片：同样两组品牌卡片 |

弹窗沿用 `BaseModal`（品牌弹窗尺寸 `md`，自定义弹窗 `lg`），开启 `accessible`，点击遮罩不关闭。

| 场景 | 表现 |
|---|---|
| 打开 | 个人邮箱弹窗：邮箱账号（带固定后缀）、授权码。企业邮箱弹窗：邮箱地址、密码或授权码。都是密码型输入，不回显；焦点落在第一个输入框 |
| 校验未通过 | 点「连接」后字段下方给出提示，焦点落到第一个有问题的字段；输入时该字段的提示即时消失 |
| 连接中 | 按钮显示「连接中…」并禁用，输入框、「取消」、关闭按钮都禁用，Esc 不关闭 |
| 连接成功 | 弹窗关闭，页面显示已连接卡片，提示「邮箱连接成功，测试邮件已发送至 xxx」 |
| 连接失败 | 弹窗顶部红色提示：原因和处理办法，按钮改为「重试」，已填内容保留。个人邮箱附「查看获取步骤」，企业邮箱附「查看填写和开通步骤」，点击后展开步骤，失败提示仍留在顶部 |
| 更换邮箱 | 已有连接时选其他邮箱，弹窗顶部提示「连接成功后将替换当前已连接的 xxx」 |
| 重新连接 | 点卡片上的「重新连接」或同品牌卡片：地址已带出，只需重新输入密码或授权码 |
| 企业邮箱的服务器 | 界面不出现服务器相关的选项。腾讯企业邮箱依次尝试通用、信创；网易企业邮箱依次尝试付费版华北、付费版华东、免费版。第一套成功的即保存 |
| 断开连接 | 先弹出确认（沿用现有页面的浏览器确认框）：「断开后，数字员工将不能再用 xxx 收发邮件」 |
| 加载中 | 页面骨架屏 |
| 加载失败 | 「邮箱信息加载失败」+「重试」按钮 |

窄屏（界面宽度小于 768）：品牌卡片按内容宽度排成三列、两列或一列；已连接卡片里地址占满一行，状态另起一行，两个按钮通栏并排；弹窗左右各留 16px，底部两个按钮平分宽度；自定义表单里两项服务器改为上下排列。

连接失败时的提示：

| 原因 | 给用户看的文案 |
|---|---|
| 授权码错误或未开启服务（QQ邮箱、163邮箱） | 授权码不正确，或未开启 IMAP/SMTP 服务。请确认填写的是授权码而不是登录密码；首次使用需要先在该邮箱设置中开启 |
| 腾讯企业邮箱：两套服务器都失败 | 连接失败：已尝试所有服务器，请检查填写内容。通常是密码不正确，或邮箱还没有开通客户端收发权限。开启了「安全登录」的邮箱要填「客户端专用密码」，不是登录密码；「收发信设置」里勾选不了服务时，需要公司邮箱管理员开启客户端访问权限 |
| 网易企业邮箱：三套服务器都失败 | 连接失败：已尝试所有服务器，请检查填写内容。通常是授权码或密码不正确，或邮箱还没有开通客户端收发权限。付费版要填「客户端授权码」，免费版填邮箱密码；权限需要公司邮箱管理员在邮箱后台为这个账号开启 |
| 自定义邮箱发送失败 | 测试邮件发送失败。请检查邮箱地址、密码 / 授权码和服务器设置是否正确 |
| 连接超时、网络异常 | 连接邮箱服务器超时，请稍后重试 |

## 5. 设计决策记录

已确认（2026-11-24）：

- 同一品牌有多套服务器时由系统自动依次尝试，界面不让用户选；全部失败按「填写内容有误或没有开通权限」提示，并说明怎么填写、需要管理员开通什么。
- 预留位（Outlook、iCloud 邮箱）接入前不显示，代码里保留位置，参数调研完再上。原型里画出来是为了确认位置和分组。

用户已指示开始开发，以下事项按「做法」一列执行，开发中如有不同意见可以调整：

| # | 事项 | 做法 |
|---|---|---|
| 1 | 品牌卡片分成「个人邮箱」「企业邮箱」两组 | 一共 7 张卡片（上线时 5 张），分组后更容易找到自己的；企业邮箱组下说明地址用公司域名 |
| 2 | 字段写「授权码」而不是「密码」（QQ、163） | QQ、163 填登录密码必然失败 |
| 3 | 每人 1 个邮箱，连接新的替换当前的 | 沿用现状。支持多个邮箱要先决定数字员工发信时用哪一个，需要单独设计 |
| 4 | 租户设置里的「租户邮箱」卡片是否一起简化 | 本次不动。它是管理员配置的全租户共用邮箱，入口在租户设置；需要的话另立条目，复用同一套品牌弹窗 |
| 5 | 旧入口「设置 → 邮箱设置」直接移除，不留跳转提示 | 前后端同版本发布，没有旧页面可访问 |
| 6 | 自定义邮箱把端口、加密方式、SMTP 用户名收进「高级设置」 | 绝大多数邮箱用默认值，展开后仍是原来的字段 |
| 7 | 连接失败的原因如何区分 | 保存接口在失败响应里增加错误类型（授权失败 / 无法连接 / 超时 / 其他），原有 `error` 文案保留。企业邮箱要连续尝试多套服务器，需要分清「这套服务器不对」和「凭据不对」 |
| 8 | 品牌图标 | 开发时先用设计稿里的示意 SVG，后续替换为品牌官方图标素材，或由设计提供 |

## 6. 实现时必须处理的现状

| 现状 | 对实现的要求 | 依据 |
|---|---|---|
| 接口 `POST /api/email-settings` 要求 9 项齐全，先发测试邮件再保存 | 品牌弹窗由前端补全其余字段；测试邮件的行为和提示文案不变 | `src/api/email_settings.py` |
| 接口一次只验证一组服务器 | 前端按品牌自带的顺序依次调用现有接口：腾讯企业邮箱「通用 → 信创」，网易企业邮箱「付费华北 → 付费华东 → 免费版」。第一个成功的即保存；全部失败按失败提示处理。顺序开发时按实测调整 | 同上 |
| 查询接口只返回 9 个字段，没有时间 | 「连接时间」需要响应里带上 `updated_at`（表里已有该列） | `src/api/email_settings.py`、`deploy/init-postgres.sql` 的 `user_email_settings` |
| 密码查询时返回 `****` | 「重新连接」只带出地址，密码或授权码留空重新输入；不把 `****` 当新密码提交 | `src/db/email_credential.py` `get_masked_by_user` |
| `user_email_settings.user_id` 唯一 | 一人一个邮箱由表结构保证，替换走现有 upsert | `deploy/init-postgres.sql` |
| 测试邮件只验证发信 | 「连接成功」的含义是发信可用；收件（IMAP）登录不在这步校验 | `src/api/email_settings.py` 保存逻辑 |

## 7. 风险与开发流程

本功能录入邮箱密码和授权码，属于敏感数据范围，按高风险走完整三智能体流程（开发 → 独立测试 → 独立 Code Review）。

测试重点：各品牌拼出的 9 项与预设一致，腾讯两套、网易三套服务器的参数各自正确，尝试顺序正确，第一套成功后不再继续尝试；替换、重新连接、断开三条路径；密码和授权码不出现在前端日志、请求日志和错误提示里；失败类型到文案的映射；旧入口移除后设置弹窗的其他功能不受影响。

## 8. 尚未验证

- 四个品牌的服务器参数和凭据获取步骤都来自官方帮助页，没有用真实账号实际连接过。开发时每个品牌至少用测试账号连一次，并对照当时的官方页面核对帮助文字。
- 企业邮箱的自动尝试：腾讯两套、网易三套服务器的尝试顺序、全部失败时的总耗时、连续登录失败会不会触发对方的风控，都需要用真实账号确认。界面没有手动选择作为退路，所以如果前端逐个尝试不可靠，要改为后端先做一次只登录不发信的探测，再发测试邮件。
- 网易免费版的 SMTP 加密端口官方只列了 994，465 是否可用没有确认。
- 腾讯企业邮箱的用户有多少开启了「安全登录」、多少企业在用信创邮箱，没有数据。界面不区分这两种情况，都由系统自动尝试；帮助文字的侧重可能需要按实际用户调整。
- Outlook、iCloud 邮箱的登录方式（多半需要应用专用密码或网页授权）没有调研，预留位能否按同样的「地址 + 密码」形式接入要调研后才能确定。

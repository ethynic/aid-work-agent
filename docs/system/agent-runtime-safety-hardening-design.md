# Agent 运行时安全加固设计

> 日期：2026-08-28
>
> 状态：独立设计基线；候选改动待从 `master` 重新提取、审查和实施
>
> 边界：仅描述行为确定、与 Task 无关的运行时安全能力

## 1. 目的

本设计保留已识别出的确定性安全能力：租户隔离、请求上下文恢复、敏感错误脱敏、知识库对象归属校验、观测成本闭环和核心代码结构守卫。它不是新的 Task、Plane 或执行账本，也不创建新的业务领域对象。

保留项不能从 `feature/task-plane-phase0-1` 整体合并。实施时必须以最新 `master` 为基线逐项提取，详见[暂停与处置报告](../research/task-plane-suspension-and-disposition-report.md)。

安全加固分支只承载本设计列出的独立候选，不负责清理已弃置 feature，也不负责删除或迁移 Task 数据库对象。候选 diff 中引用旧 Task 设计、Phase 编号或已删除文档路径的注释/docstring 必须移除，改为本安全能力自身的行为与风险说明。

## 2. 确定性能力

### 2.1 定时任务租户与用户隔离

- `scheduled_tasks` 与 `scheduled_task_logs` 明确记录 tenant/user 归属。
- list、view、pause、resume、cancel、日志查询和执行读取都在 SQL 中携带租户与用户条件。
- 调用方身份缺失、冲突或无法验证时 fail-closed。
- 管理员能力必须走现有权限体系，不通过空 tenant 或省略条件隐式扩大权限。

作用：防止猜测任务 ID、复用工具或后台执行路径造成跨租户、跨用户读写。

### 2.2 请求级上下文隔离与恢复

- Agent 和 scheduler 使用请求级 tenant/user ContextVar，不把可变身份写到共享 Agent 实例。
- execute 与 dry-run 使用同一优先级和冲突规则。
- `finally` 恢复 token；成功、异常、取消和嵌套调用后都不得泄漏上下文。
- 已验证身份、请求上下文和持久化对象之间出现租户冲突时 fail-closed，且不得调用 Agent、创建记录或重试。

作用：保证共享 Agent 并发时身份不串线。

### 2.3 敏感错误脱敏

- 在 scheduled task API 与 DB 日志边界统一处理异常文本。
- 遮蔽 password、passwd、token、secret、api key 等常见键值形式，包括 `=`、`:`、空白、引号和跨行内容。
- 未闭合引号和被截断文本按保守规则遮蔽，不把原始异常或 traceback locals 返回给用户。
- 日志保留错误类别和可操作上下文，不记录凭据值。

作用：避免第三方 SDK、数据库或工具异常把秘密带入 API 响应和日志。

### 2.4 知识库对象级租户保护

- 文档读取、更新、删除及派生操作在最终数据访问点校验 tenant。
- 不只依赖路由参数、上游查询或用户提供的对象 ID。
- 找不到对象与无权访问使用不泄漏对象存在性的响应策略。

作用：封闭通过已知/猜测对象 ID 越权操作知识库的路径。

### 2.5 Observability 成本闭环

- `obs_traces.total_cost` 从现有计费结果参数化写入。
- 处理计费完成早于 Trace INSERT 的时序，使用有界 pending 回填避免永久丢失。
- Trace 是技术诊断数据，不是业务完成证明，也不是计费权威；最终金额仍以现有 billing/chat record 链路为准。

作用：支持技术成本分析和对账，不改变日报、成果或计费模型。

### 2.6 租户值语义

- `None` 表示租户未知、缺失或尚未解析。
- 空字符串仅在现有业务明确表示公共域时使用。
- 禁止用 `value or ""` 把未知身份静默降级为公共域。

作用：避免身份解析失败被误当成更宽松的公共访问。

### 2.7 纯 helper 与结构守卫

- 可保留与领域无关、无 I/O 的 `agent_events` 纯函数拆分，但必须证明行为等价。
- `agent.py` 维持“新逻辑优先落独立模块、核心文件只做接线”的约束。
- 行数只降不升和依赖方向守卫可独立存在；不得引用已删除的 `src/task_plane`。

作用：控制核心循环继续膨胀，降低安全修复的回归面。

### 2.8 工具 effect 与幂等安全清单

- 静态登记工具是否只读、具有副作用或效果未知。
- 明确哪些工具可安全重试，哪些在超时后必须人工确认。
- 清单仅用于审查、告警和未来具体功能的输入，不自动产生业务对象，也不授权自动重试。

作用：降低邮件发送、发布、浏览器自动化等动作被盲目重放的风险。

## 3. 数据权威与既有功能边界

| 数据/能力 | 权威来源 | 本设计的边界 |
|---|---|---|
| 身份、租户、权限 | 现有 SaaS 身份与权限系统 | 只传递、校验和隔离，不创造新权限模型 |
| 定时任务状态 | `scheduled_tasks` / `scheduled_task_logs` | 加强属主条件，不把定时任务提升为通用 Task |
| 计费金额 | 现有 billing 与 `chat_records` | Trace 只保存技术观测投影 |
| 技术调用链 | `obs_traces` / `obs_spans` | 继续负责诊断；不证明业务动作成功 |
| 工作日报 | 现有日报聚合与生成链路 | 保持每日总结职责，不改为运行时台账 |
| 工作成果 | `work_outcomes` 及既有文件/复盘来源 | 保持成果展示职责，不强制关联不存在的 Task |
| 知识库对象 | 现有知识库表 | 增加租户 guard，不改变内容权威来源 |

## 4. 明确非目标

- 不定义 Task、Session、Execution、Artifact 或 AgentRelease。
- 不新增统一事件总线、outbox、执行账本或统计看板。
- 不做 Task UI、Task 识别、对话目标抽取或完成判定。
- 不把 Agent 正常返回、工具 `success=true` 或 Trace 完整视为业务成功。
- 不把 Policy Shadow 从旧实现中抽出；权限改进应从现有权限系统按独立需求重新设计。

## 5. 实施与测试门禁

每个能力必须独立提取、独立提交，并满足：

1. 相对最新 `master` 逐行 review，不整体 cherry-pick feature 提交。
2. 移除所有指向已删除 Task 设计/计划的出处注释、docstring 和 schema description；保留代码不得保留旧设计依赖。
3. 租户隔离测试覆盖同租户同用户、同租户不同用户、跨租户、身份缺失和管理员路径。
4. ContextVar 测试覆盖并发、异常、取消、嵌套调用和恢复。
5. 脱敏测试覆盖多种键名、分隔符、单双引号、跨行、未闭合引号、超长输入和无秘密文本。
6. 知识库测试覆盖读取、更新、删除和对象不存在，确认无存在性泄漏。
7. 成本测试覆盖 Trace 先写/后写两种时序、重复回填和失败降级。
8. 结构守卫只约束真实存在的通用模块，不依赖已删除 Task 目录。
9. 运行定向测试、相邻回归、配置加载和关键启动 import；测试全绿后再进入 CodeReview。

## 6. 失败策略

- 身份、租户或对象归属不确定：fail-closed。
- 观测、成本投影或诊断写入失败：不得改变既有业务执行结果，但必须有不含敏感值的降级日志。
- 外部副作用是否发生不确定：标记未知并禁止自动重试；由具体业务流程决定人工确认或后置查询。
- 安全修复与现有行为冲突：停止该项提取并重新评估，不能为赶进度引入 Task 兼容层。

# Runtime 异常退出后如何恢复

2026-11-11 · 待评审

Runtime 异常退出后，会留下上次的运行记录。国腾现场已经重启，旧执行进程也已退出，Runtime 却仍显示「待核对」，一直无法接单。[现场记录](../incidents/guoteng-runtime-disconnect-20261110.md)

## 怎么恢复

恢复判断只用本软件的进程退出证据，不用 Windows 重启状态（开机标识、开机时间）作依据。

1. 登录自启或用户打开 Runtime 时，如果发现上次异常退出，就按进程退出证据确认旧执行已退出：同登录会话内，直接终止旧记录登记的受管进程组并确认清零；跨登录会话时，用上次的退出回执，或确认原会话已无进程。
2. 旧标记或解密凭据读不出（记录为本机原子写入，读不出即外部损坏且不会自愈），归档为历史并直接恢复接单。进程台账读不出但能识别原登录会话时，按该会话是否还有进程判断：无进程即恢复，有进程就等待。
3. 确认旧执行已退出，就把旧记录留作历史，用原配对恢复心跳和接单。即使 Windows 换了登录会话，也以旧进程是否已经退出为准。
4. 旧执行还在运行时，沿用现有的停止方式，只停止能确认是上次 Runtime 留下的执行进程。正在退出或系统暂时查不到时，显示「正在确认上次的执行是否已退出」，自动再查。确认退出后直接恢复。
5. 用户主动停止执行或退出本产品时，取消本次自动启动；恢复结果晚到也不会再触发启动。

恢复接单后，上次结果不明的动作不会自动重做。

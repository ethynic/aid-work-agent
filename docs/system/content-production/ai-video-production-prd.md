## ⭐ 第 0 章 v0.4 MVP 重新定义（权威，取代之前各版 MVP 范围表述）

> **背景**：v0.1–v0.3 把产品越设计越重（工艺链状态机、批量任务扇出、审核台、发布链路对接）。v0.4 回归本质——**这不是"批量生产系统"，是一个"生成→抽卡→留用→精修"的内容工具**。
>
> **本章为 v0.4 权威定义**。若本章与文档其他章节（含 v0.2/v0.3 的功能、数据模型、分期、验收表述）冲突，**一律以本章为准**。其他章节保留作为 Phase 1+ 的演进参考。

### 0.1 产品本质（一句话）

> **选场景 → 上传素材 → 填文案 → 生成 2-4 个视频抽卡 → 满意的留下继续优化编辑 → 下载。**

这是一个**抽卡式 AI 视频工具**：每次生成多条，像抽卡一样挑满意的，不满意的扔掉重来，满意的留下继续打磨。运营拿到成片后自己上传视频号/抖音。

### 0.2 MVP 唯一闭环（四个动作）

```
① 选场景  →  ② 上传素材 + 填文案  →  ③ 生成2-4个视频（抽卡）  →  ④ 挑选/留用/精修/下载
```

| 动作 | MVP 做什么 | MVP 不做什么 |
|------|-----------|-------------|
| ① 选场景 | 内置 **1-2 个通用场景**（产品展示 / 氛围），每个场景封装好 prompt 模板 + 运镜 + 工艺参数 | 不做 7 类全场景（后续加） |
| ② 上传素材 + 填文案 | 向导内上传产品图/模特图（自动抠图），文本框填文案；素材落 file_id | 不建产品库、不抽取详情页 |
| ③ 生成抽卡 | 基于场景+素材+文案，**一次生成 2-4 条差异化视频**（运镜/光影不同），卡片式展示供挑选 | 不做"批量任务扇出/进度看板"那套重交互，就是一次抽卡 |
| ④ 留用/精修/下载 | 满意的"留用"；留用视频可**重新生成式编辑**（调运镜/换背景/改文案/prompt 重跑）；最终下载 | 不做帧级剪辑（裁剪/字幕轨）；不做审核台；不接发布链路 |

### 0.3 v0.4 相对 v0.3 的关键收敛

| 维度 | v0.3 | v0.4（本版） |
|------|------|------------|
| 产品形态 | 批量生产系统 | **抽卡式工具** |
| 场景预设 | 7 类全做 | **1-2 个通用场景**先跑通 |
| 生成交互 | 批量任务+进度看板+工艺链时间线 | **一次抽卡 2-4 条**，卡片挑选 |
| 编辑 | 无（只下载） | **重新生成式编辑**（调参重跑） |
| 审核台 | P0 完整审核工作流 | **删除**（工具不需要审核台） |
| 发布链路 | P0 接 social_* / P1 真实发布 | **删除**（MVP 到下载为止，运营手动上传） |
| 工艺链 | 10 环节状态机 + 断点续跑 + 单步重试 | **内部仍走工艺链**，但对用户隐藏为"一次抽卡"，不暴露环节时间线 |
| 数据模型 | creative_*/gen_* + gen_batch_tasks + gen_step_records | **极简**：素材(file_id) + 生成会话 + 抽卡结果卡片（见 §0.5） |

### 0.4 "重新生成式编辑"是什么

留用的视频可继续优化，但 **MVP 不集成前端剪辑器**（最重的活）。编辑 = **改参数重新生成**：

- 换运镜（push in → orbit）
- 换背景/场景氛围
- 改文案/prompt 微调
- 调时长

本质是"用新参数再抽一次卡"，复用已有生成能力，零新增重型组件。帧级剪辑（裁剪/加字幕轨/BGM 混音）留待用户明确提需求后再评估。

### 0.5 v0.4 极简数据模型（取代第 7 章 MVP 部分）

只需三件事的记录：**素材、一次抽卡会话、抽出来的卡片**。

```
gen_sessions（一次抽卡会话）
  ├ session_id, tenant_id
  ├ scene_preset_id          -- 选的场景
  ├ input_asset_ids (JSONB)  -- 上传的素材 file_id（含 asset_role）
  ├ copywriting (TEXT)       -- 填的文案
  ├ expanded_prompt (TEXT)   -- 提示词引擎扩展后的 prompt（可微调）
  ├ status                   -- generating / done
  └ created_at

gen_cards（抽出来的视频卡片）
  ├ card_id, tenant_id, session_id
  ├ variant_params (JSONB)   -- 本条的差异化参数（运镜/光影/背景）
  ├ provider_task_id         -- 厂商任务id
  ├ output_asset_id          -- 成片 file_id（含AI标识）
  ├ status                   -- generating / succeeded / failed
  ├ kept (BOOLEAN)           -- 是否被运营"留用"
  ├ parent_card_id           -- 精修溯源（从哪张卡重新生成来的）
  └ created_at
```

- **素材**不建表，复用 file_id/MediaRef，直接存 `gen_sessions.input_asset_ids`。
- **无 gen_batch_tasks / gen_step_records / video_scripts / scene_presets 独立表**：场景预设 MVP 硬编码 1-2 个（配置形式），脚本即 `expanded_prompt`，工艺链状态收进 card 的 status（对用户不可见）。
- **无 social_* 对接**：成片就是 file_id，下载即终态。
- Phase 1 若要做批量/审核/发布，再回填 v0.3 的 gen_batch_tasks/social_* 结构，不影响本极简模型。

### 0.6 v0.4 验收标准（取代 11.2）

1. **选场景**：内置 1-2 个通用场景可选（产品展示/氛围）。
2. **上传素材**：向导内上传产品图/模特图，自动抠图，落 file_id。
3. **填文案**：文本框填写文案，喂给提示词引擎生成精准 prompt，可微调。
4. **抽卡生成**：一次生成 **2-4 条差异化视频**，卡片式展示。
5. **主体一致性**：成片中产品主体无明显变形（**首尾帧模式**为主力手段，见 §0.8；前置 spike 验证变形率）。
6. **合规标识**：成片烧录醒目 AI 标识（2025.9.1 法规）。
7. **留用**：可对卡片标记"留用/丢弃"。
8. **重新生成式编辑**：留用视频可换运镜/换背景/改文案重新生成。
9. **下载**：留用视频可下载（视频号/抖音规格）。
10. **量化**：单视频生产 < 15 分钟，时长 15-30s，产品变形率 < 10%。

### 0.7 v0.4 里程碑

- **MVP（v0.4）4-6 周**：选场景+上传填文案+抽卡2-4条+留用+重新生成式编辑+下载。1-2 个场景。通义万相 API。
- **Phase 1**：更多场景预设、自建 Wan2.2、多素材批量、产品库（沉淀复用）。
- **Phase 2**：审核/发布链路（若确有需求）、帧级剪辑、数据回流。

### 0.8 防变形技术澄清（v0.4 修正，前置 spike 焦点）

> **背景**：v0.2/v0.3 写的"通义万相 + IP-Adapter 防变形"是**技术错误**。IP-Adapter 是开源模型生态（ComfyUI / Wan2.2 本地部署）的插件，**通义万相云 API 是黑盒服务，挂不了 IP-Adapter**。本节记录通义万相 API 实际可用的防变形手段（已查证官方文档）。

**IP-Adapter 是什么**：让扩散模型生成时持续"盯住"参考图、把产品视觉特征当强约束注入每一帧的插件。仅适用于本地部署的开源模型（Phase 1 自建 Wan2.2 时可用）。

**通义万相 API（MVP provider）实际可用的防变形手段**（查证万相 2.7 + 首尾帧官方文档）：

| 手段 | 机制 | 防变形效果 | API 支持 |
|------|------|-----------|---------|
| **① 首尾帧模式**（`first_frame`+`last_frame`）| 起始帧+结束帧都是产品图，模型在两帧间平滑插值，发挥空间被锚定 | ⭐⭐⭐⭐ 最强 | ✅ |
| **② 首帧模式 + 精准 prompt**（`first_frame`+详细主体描述+单一运镜）| 产品图当起点，文字严格约束 | ⭐⭐⭐ 中等 | ✅ |
| **③ `negative_prompt`** | 排除"变形、扭曲、morphing、手指畸形" | ⭐⭐ 辅助 | ✅（2.7） |
| **④ 1080P + 短时长**（2.7 支持 2-15s）| 高分辨率更稳，时长越短变形越少 | ⭐⭐ 辅助 | ✅ |

**关键限制**：
- 万相 2.7 `media` 数组**每种类型仅 1 张**（`first_frame` 最多 1、`last_frame` 最多 1），**不支持多图参考**。"传 2-4 张多角度产品图综合参考"在 API 模式做不到（那是 IP-Adapter/开源能力，Phase 1 自建可用）。
- API **无独立运镜控制参数**，运镜只能靠 prompt 文字隐式引导（"镜头从平视逐渐上升"）。
- 首尾帧模式需要运营提供**尾帧图**（产品结束状态）；只有单张产品图时退化为首帧模式，防变形降至"中等"。

**对 MVP 的影响与前置 spike**：
- **防变形主力 = 首尾帧模式**。MVP 抽卡时优先用首尾帧（运营传 2 张产品图），单图时降级首帧模式。
- **前置 spike（必做）**：用真实美妆产品图，分别测「首尾帧模式」和「首帧模式」，量化产品变形率，验证"变形率<10%"验收标准在纯 API 下是否可达。这是 MVP 唯一的真实技术不确定性。
- 若纯 API 首帧模式变形率过高 → 备选：①强制要求运营提供尾帧图；②提前引入 Phase 1 的自建 Wan2.2 + IP-Adapter（成本上升）。

### 术语表

| 术语 | 含义 |
|------|------|
| SKU | Stock Keeping Unit，最小库存/售卖单元。本系统中一个产品可含多个 SKU（如不同色号/款式）。 |
| 图生视频 | 以静态图片（产品图/模特图）+ 文字描述为输入，AI 生成动态视频。 |
| **IP-Adapter** | 开源模型生态（ComfyUI/Wan2.2 本地部署）的插件，让模型生成时持续盯住参考图防变形。**通义万相云 API 不支持**，仅 Phase 1 自建模型可用。 |
| **首尾帧模式** | 通义万相 API 的图生视频模式：传入首帧+尾帧两张产品图，模型在两帧间平滑插值。是 API 模式下防变形的最强手段。 |
| **首帧模式** | 仅传一张首帧图 + prompt 生成视频。防变形能力中等（模型仍可自由发挥）。 |
| 模特素材 | 由运营上传的真人或 AI 生成的模特图片，作为图生视频的输入图。**本系统不生成模特，只消费上传的模特素材。** |
| 视频模板 | 预定义的视频脚本结构（分镜、时长、旁白槽位、BGM、字幕样式），用于驱动脚本生成与渲染。 |
| 母版 / 变体 | 母版（master）= 一条内容的原始定义；变体（variant）= 针对某平台/某账号的适配版本。沿用社媒 #20 概念。 |
| 连接器 | 对接外部社媒平台（视频号/抖音）的适配器，封装认证、上传、发布、查询。沿用 #20 `SocialPlatformConnector`。 |
| file_id / MediaRef | 系统内传递媒体资产的唯一契约（含 file_id + download_url + 元信息）。本 PRD 将现有 `ImageRef` 扩展为支持视频的 `MediaRef`。 |
| 生成任务 | 一次 AI 图像/视频生成的异步执行单元，有独立状态机（queued→rendering→succeeded/failed）。 |
| 批量任务 | 运营发起的一次批量出片请求，扇出为 N 个生成任务（多 SKU × 单模板，或单 SKU × 多模板）。 |
| 视频生成工艺链 | 从"调 API"到"可用视频"的 8-10 环节流水线（抠图→参考图注入→prompt 补全→运镜→生成→拼接→超分补帧→转场→字幕→配音）。一个高质量视频绝非单次 API 调用。 |
| 场景预设 | 按"开箱/教程/氛围/对比/试戴/旋转/特写"等电商场景封装的出片配方 = prompt 模板 + 运镜 LoRA + ComfyUI 工作流 JSON 的组合。让用户"选场景"而非"写 prompt"。 |
| 提示词引擎 | 把用户模糊输入 + SKU 卖点 + 场景预设，自动扩展为精准、结构化 prompt（对标可灵 8 层框架 / Seedance 公式）的能力。 |
| 主体一致性 | 保证产品在视频中不变形/不漂移的技术（IP-Adapter 参考图注入 + 产品 LoRA + 多图参考 + ControlNet 约束）。电商视频的核心壁垒。 |
| AI 内容显式标识 | 2025.9.1 起硬性法规要求：AI 生成内容必须在画面醒目位置长期放置"AI 生成"标识。产品必须内置。 |

## 第 2 章 背景与目标

### 2.1 业务背景

电商运营团队（美妆工具、假睫毛等品类）面临短视频内容规模化生产压力：

- **日产能目标**：每天 5-10 条视频内容，覆盖 10-20 个 SKU。
- **现有瓶颈**：单条短视频从脚本→拍摄/生成→剪辑→平台适配需数小时，人工产能无法支撑日处理 10-20 SKU 的铺量节奏。
- **可用输入**：产品详情页介绍已具备；模特素材（真人或 AI 生成的图片）由运营自行准备并上传。
- **分发平台**：视频号、抖音（C 端为主）。

### 2.2 用户痛点

1. **出片慢**：人工单条视频耗时过长，无法匹配上新节奏。
2. **一致性差**：同一批 SKU 出片质量/风格参差，缺乏统一模板约束。
3. **平台适配累**：视频号与抖音规格不同，人工逐条改稿重复劳动。
4. **参考难复用**：看到高赞视频想参考其结构，但只能靠人工拆解，无法沉淀为可复用模板。

### 2.3 产品目标

**定性目标**：构建一个以「AI 批量出片」为核心的 C 端内容生产引擎，让非技术背景的电商运营通过可视化控制台，在分钟级完成"选品→配模板→批量生成→审核→发布准备"全流程。

**量化目标（MVP 验收口径）**：

| 指标 | MVP 目标 | 说明 |
|------|---------|------|
| 单视频平均生产耗时 | < 15 分钟（从发起任务到可下载成片） | 含异步生成等待 |
| 单 SKU 批量出片成本 | 较纯人工降低 60% 以上 | 以运营工时 + API 调用费综合计 |
| 日产能（单运营） | ≥ 10 条视频 / 10 SKU | 批量模式 |
| 成片采纳率 | ≥ 70% | 审核通过 / 总生成数 |
| 视频时长合规 | 15-30s（主力）/ ≤60s（品牌向） | 100% 符合目标赛道 |

**北极星指标**：单运营日均产出可发布视频条数。

### 2.4 非目标（明确排除）

本 PRD **不做** 以下内容，避免范围蔓延：

- ❌ **AI 模特生成**：模特素材（真人/AI 图）均由运营上传，系统不负责生成模特、不做数字人/换脸/换装。未来可评估。
- ❌ **平台爆款自动采集**：不做自动抓取抖音/视频号数据。参考素材由运营人工导入。
- ❌ **B 端阿里国际站海报设计**：划入 Phase 2，不在 MVP/Phase 1 范围。
- ❌ **自动广告投放 / 商机巡检**：属社媒 #20 的广告/巡检模块，不在本系统职责。
- ❌ **纯 AI 一键直接带货**：调研显示纯 AI 视频规模化带货 GMV 闭环尚未跑通，本系统定位为**辅助投放素材生产 + 快速试错**，不承诺"一键生成直接带货转化"。

## 第 3 章 干系人与角色

| 角色 | 职责 | 本系统中的诉求 |
|------|------|---------------|
| 电商运营人员（主用户） | 选品、配模板、发起批量任务、初步筛选 | 极简可视化流程，弱对话、强表单/看板 |
| 内容审核人 | 审核生成视频、批准/驳回 | 高效预览、批量审核、可标注修改意见 |
| 系统管理员（租户） | 账号/计费/配额管理 | 成本可控、用量可见 |

## 第 4 章 产品定位与核心价值

### 4.1 产品定位

**一个以「AI 批量出片」为核心的 C 端内容生产引擎。**

- **核心价值主张**：一键产出大量差异化短视频，把运营从重复出片中解放出来。
- **分发策略**：MVP 阶段先以"人工下载 + 手动上传"兜底分发，自动分发放 Phase 1。
- **交互形态**：运营导向的**可视化控制台**（表单/向导/看板），而非对话式。子智能体能力作为后端编排引擎存在，但对运营隐藏。

### 4.2 与社媒营销智能体 #20 的关系

两者互补，构成"生产—分发"完整链路：

```
[本系统 #47 内容生产]                [社媒 #20 内容分发]
产品库 ──→ 脚本 ──→ 生成任务 ──→ 成片素材 ──→ 母版/变体 ──→ 审核 ──→ 发布任务 ──→ 视频号/抖音
  (product/gen/creative 新建)         (social_* 复用)
```

- **本系统负责"从无到有"**：产品→脚本→视频成片。
- **#20 负责"从有到发"**：成片→平台适配→审核→发布→数据回流。
- **衔接点**：生成的视频作为 `social_media_assets` 落地，关联到 `social_content_masters`，进入 #20 的发布链路。

### 4.3 核心价值（卖点）

1. **批量化**：一次操作产出 N 条视频（多 SKU × 单模板），日处理 10-20 SKU。
2. **模板化**：沉淀爆款结构为可复用模板，保证出片一致性。
3. **低成本**：API 快速落地 + 自建模型补充，单条视频成本可控。
4. **人在环**：生成后必须经审核才可发布，质量可控、合规可追溯。
5. **工艺链壁垒（v0.2 核心）**：产品价值不在"调 API"，而在把用户模糊输入经"场景预设 + 提示词引擎 + 8-10 环节工艺链"转化为可用视频。这是区别于"会调 API 就能做"的真正壁垒。

### 4.4 诚实的产品定位边界（v0.2）

基于深度调研，明确产品能做和不能做的边界：

| 能做 | 做不到/不承诺 |
|------|--------------|
| 辅助投放素材生产，快速试错迭代 | 一键生成直接带货转化（规模化 GMV 闭环行业尚未跑通） |
| 标准化出片流程，降本提效 | 替代专业摄影师/剪辑师的创意上限 |
| 多版本 A/B 素材批量产出 | 保证每条都爆款（受平台算法、人群、时机多重影响） |
| 合规标识、主体一致性、运镜控制 | 完全消除 AI 生成的"变形/闪烁"等固有缺陷（只能 mitigate） |

## 第 5.5 章 视频生成工艺链（v0.2 核心模块）

> **核心认知**：一个能过审、能起量的电商视频，绝不是"调一次生成 API"的产物，而是 8-10 环节流水线的输出。本章定义系统的"生成工艺链"——这是产品区别于"API 套壳"的真正壁垒。完整调研依据见[深度调研报告](../../research/ai-video-production-research.md)。

### 5.5.1 工艺链全景

```
用户输入（SKU卖点 + 商品图/模特图 + 场景选择）
    ↓
[1]素材预处理（抠图/主体分离/多角度参考图）
    ↓
[2]参考图注入与产品锁定（IP-Adapter + 产品LoRA + 多图参考）
    ↓
[3]提示词引擎：场景预设 + AI补全 → 结构化精准prompt（§5.6）
    ↓
[4]运镜设计（Fun-Control / 首尾帧 / 运镜LoRA）
    ↓
[5]核心I2V生成（Wan2.2 / 通义万相API / CogVideoX）
    ↓
[6]多段生成与时长拼接（首尾帧接力，chunk间一致性约束）
    ↓
[7]超分 + 补帧（流畅度，RIFE/4x超分）
    ↓
[8]转场（FFmpeg）
    ↓
[9]字幕（SmartSub/Whisper）+ 配音（TTS）+ BGM
    ↓
[10]合规标识烧录（AI生成标识，2025.9.1法规）+ 平台规格适配
    ↓
可用视频成片
```

### 5.5.2 各环节职责与失败模式

| # | 环节 | 职责 | 关键失败模式 | 解法（内建） |
|---|------|------|-------------|-------------|
| 1 | 素材预处理 | 抠图/主体分离，生成多角度参考图 | 抠图毛边、背景残留 | SAM3/Rembg 高质量抠图 + 人工校验入口 |
| 2 | 参考图注入 | 产品锁定，保证不变形 | **产品变形 morphing**（电商第一痛点） | IP-Adapter + 产品LoRA + 多图(2-4张)参考 + 深度ControlNet约束轮廓 |
| 3 | 提示词引擎 | 模糊输入→精准prompt | prompt 抽象/堆砌运镜词→出片不可控 | 场景预设 + 可灵8层结构化框架（见§5.6） |
| 4 | 运镜设计 | 控制镜头运动 | 运镜突兀/矛盾 | **每镜头单一运镜方向** + 首尾帧模式 + 运镜LoRA |
| 5 | I2V生成 | 图→视频 | **画面闪烁 flicker** | 补帧RIFE平滑 + 限制单段运动幅度 |
| 6 | 多段拼接 | 达到目标时长 | **主体漂移/拼接处畸变** | 锁定参考帧 + 减小单段时长 + chunk间强一致性约束 |
| 7 | 超分补帧 | 提升流畅度与清晰度 | 模糊低细节 | 标准模式生成 + 后期4x超分 |
| 8 | 转场 | 段落衔接 | 跳跃感 | FFmpeg平滑转场 |
| 9 | 字幕配音BGM | 信息传递与氛围 | — | SmartSub(Whisper字幕+TTS配音) 一站式 |
| 10 | 合规+规格适配 | 过审与平台适配 | **未标识被限流**（法规） | 强制烧录"AI生成"醒目标识 + 视频号/抖音规格导出 |

### 5.5.3 工艺链的产品化原则

1. **对用户隐藏复杂度**：运营只做"选场景 + 上传商品图 + 微调"，8-10 环节由系统自动编排。
2. **关键环节可人工介入**：抠图校验、prompt 微调、运镜选择保留人工入口（人在环）。
3. **失败可定位可重试**：每个环节有独立状态，某环节失败可单独重试，不必从头来。
4. **工艺链可配置**：不同场景预设可裁剪/重排环节（如"开箱展示"不需要换背景，跳过环节3背景生成）。

### 5.5.4 工艺链与生成任务的映射

工艺链的 10 个环节映射到 `gen_tasks` 的执行步骤（见第 7 章数据模型扩展）。每个 gen_task 内部是一个有序的 step 序列，每步有状态（pending/running/succeeded/failed/skipped），支持断点续跑和单步重试。

## 第 5.6 章 场景预设与提示词引擎（v0.2 核心模块）

> **核心认知**：用户（电商运营）无法写出精准的图生视频 prompt。产品的解法 = "场景预设库（封装出片配方）+ 提示词引擎（把用户模糊输入自动扩展为结构化精准 prompt）+ 用户适度微调"。这是所有成功竞品（Creatify/Runway/万相营造）的共性范式。

### 5.6.1 场景预设库

场景预设 = 一个可复用的"出片配方"，封装了：电商视频的典型场景分类。

| 场景预设 | 描述 | 内置运镜 | 时长 | 品类适配 | 工艺链裁剪 |
|---------|------|---------|------|---------|-----------|
| 开箱展示 | 包装→开箱→产品揭示，营造期待感 | slow push in | 15-20s | 通用 | 跳过换背景 |
| 卖点口播 | 产品功能演示 + 配音讲解 | overhead pan / static | 20-30s | 工具/美妆 | 含字幕配音 |
| 场景氛围 | 产品置于使用场景，氛围感呈现 | slow orbit | 15-25s | 家居/美妆 | 含背景生成 |
| 效果对比 | 使用前后对比 | static + slow pan | 15-25s | 通用 | 双画面合成 |
| 模特试戴 | 模特佩戴展示 | orbit + medium | 15-25s | 服饰/珠宝/美妆 | 含模特素材 |
| 产品旋转 | 360°旋转展全貌 | static（主体转）| 10-15s | 通用标品 | 最简工艺 |
| 细节特写 | 微距展示纹理/工艺 | macro dolly in | 10-15s | 通用 | 含超分 |

每个场景预设内部绑定：
- **prompt 模板**（含变量槽：`{product_name}`/`{selling_points}`/`{scene}`/`{lighting}`）
- **运镜 LoRA** 或 Fun-Control 参数
- **ComfyUI 工作流 JSON**（可序列化的出片工艺蓝本，可从社区导入）
- **推荐工艺链配置**（环节裁剪）
- **负面提示词**（"变形、扭曲、模糊纹理、伪影"等通用排雷词）

### 5.6.2 提示词引擎（自动补全精准 prompt）

提示词引擎把"用户模糊输入 + SKU 卖点 + 场景预设"自动扩展为结构化、精准的 prompt。**对标可灵 8 层提示词框架**（权重从左到右递减）：

```
[1 元素参考声明] [2 镜头标签] [3 景别与主体(2-3个材质特征，禁用"漂亮的"模糊词)]
[4 动作(细化到部位/量化幅度/情绪外化)] [5 运镜(每镜头单一方向，与动作分开)]
[6 场景与光影(命名真实光源，如"苹果主题演讲光")] [7 音频] [8 风格锚点+质量后缀+负面词]
```

引擎工作流程：
1. **抽取**：从 SKU 卖点 facts 抽取产品材质特征（如"12mm、自然款、水貂毛"）。
2. **填充**：把材质特征填入第3层，把场景预设的运镜填入第5层，把场景的光影填入第6层。
3. **约束**：自动注入"单一运镜方向"、"禁用模糊形容词"等规则；自动补负面词。
4. **校验**：LLM 自检 prompt 是否符合"一个主体动作 + 一个运镜方向"铁律，不符则自动修正。
5. **透明可微调**：生成完整 prompt 草稿展示给运营，支持微调（高级用户可手改 prompt）。

### 5.6.3 反同质化机制（v0.2 关键，应对平台红线）

平台明确惩罚"同构图换皮连发"（见调研§7.2）。批量任务必须保证差异化：

| 差异化维度 | 机制 |
|-----------|------|
| 脚本角度 | 同一 SKU 生成多个脚本角度（痛点型/场景型/对比型）轮换 |
| 运镜变化 | 同一批任务内运镜随机分配（push in / orbit / pan） |
| 光影氛围 | 场景预设内的光影参数随机微调（晨光/棚拍/暖调） |
| 背景场景 | 抠图换背景，同一产品置于不同场景 |
| 时长分段 | 15-30s 内随机时长，避免完全一致 |

> **批量任务的差异化程度可配置**：运营可选"高差异"（每条明显不同，适合多账号矩阵）或"低差异"（同系列统一风格，适合单账号系列）。

### 5.6.4 场景预设的运营化

- PM 可自助新增/编辑场景预设，保存到预设库（P1）。
- 预设支持从社区 ComfyUI 工作流 JSON 导入（P1）。
- 预设效果可度量（该预设生成视频的采纳率/完播率回流，P2）。

## 第 7 章 数据模型设计

> **设计原则**（沿用现有规范）：`snake_case` 命名；主键 `<entity>_id TEXT PRIMARY KEY`；强制 `tenant_id`（多租户隔离）；`created_at`/`updated_at TIMESTAMP`；复杂结构用 `JSONB`；凭证用 `_encrypted` + `encryption_manager`；无外键约束（逻辑外键）。

### 7.1 领域分层总览

```
[创意域 creative_*]        [生成域 gen_*]              [分发域 social_* 复用]
  scene_presets(场景预设)     gen_batch_tasks             social_content_masters (复用)
  video_scripts(脚本实例)     gen_tasks(含工艺链steps)     social_content_variants (复用)
                             (input_asset_ids 绑定素材)   social_media_assets (扩展)
                             gen_step_records             social_review_records (复用)
                                                          social_publish_jobs (复用)
```

血缘链（v0.3）：**上传素材 + 手填卖点 → 场景预设+提示词引擎 → 脚本 → 生成任务(10环节工艺链) → 成片素材(含合规标识) → 母版 → 变体 → 审核 → 发布**。

> **v0.3 数据模型变化（最小可用）**：**删除 product_* 域**（products/product_skus/product_selling_points）。素材不沉淀为产品实体，而是上传后直接与 `gen_tasks.input_asset_ids` 绑定，落 file_id。卖点由向导手填，存于 `video_scripts.expanded_prompt` 的输入，不入库为结构化 facts。
> v0.2 其余变化保留：① `scene_presets`（封装 prompt模板+运镜LoRA+工作流JSON+工艺链配置）；② `gen_tasks.pipeline_steps_json`（10环节状态）；③ 素材 `asset_role`；④ `gen_step_records` 工艺链步骤记录。
> **产品域预留**：当 Phase 1 出现"沉淀产品、跨任务复用素材"需求时，再补 product/sku 表，与 gen_tasks 通过 sku_id 软关联，不影响 MVP 结构。

### 7.2 产品域 `product_*`（v0.3 推迟，MVP 不建）

MVP 不建产品库。当 Phase 1+ 出现"沉淀产品、跨任务复用素材/卖点"需求时，再补 `products` / `product_skus` / `product_selling_points` 三表，并通过 `sku_id` 与 `gen_tasks` 软关联。MVP 期间素材直接绑 `gen_tasks.input_asset_ids`，卖点手填存于脚本输入。

### 8.3.1 ComfyUI 工作流引擎（v0.2 新增，自建 provider 核心）

自建 provider（Wan2.2）通过 ComfyUI 执行 `scene_presets.workflow_json`：
- 系统通过 ComfyUI HTTP API（`/prompt` 提交 + `/history` 轮询）驱动工作流。

- 工艺链的环节状态（pipeline_steps_json）映射到工作流的节点组进度。
- 社区现成工作流（comfy.org/civitai 的电商模板）可直接导入为 scene_preset（P1）。

### 8.4 生成任务调度流程（v0.2 工艺链驱动）

```
1. ContentProductionService.create_batch_task()
   → 基于上传素材 + 手填卖点 + 场景预设，调提示词引擎生成 expanded_prompt + N 条 differentiation_seed（反同质化）
   → 建 gen_batch_tasks(mode=single_batch_multi_variant) + 扇出 N 个 gen_tasks(共享input_asset_ids, status=queued, pipeline_steps_json 初始化10环节pending)

2. 工艺链编排引擎接管 gen_task（interval job + 租约）：
   顺序执行 pipeline_steps_json 的环节（按 scene_presets.pipeline_config_json 裁剪）：
   step1 预处理(抠图) → step2 主体锁定(IP-Adapter) → step3[已由提示词引擎完成,跳过]
   → step4 运镜 → step5 I2V生成 → step6 拼接 → step7 超分补帧 → step8 转场
   → step9 字幕配音 → step10 合规标识烧录
   - 每环节完成更新 pipeline_steps_json 对应 step 状态
   - step5(I2V)若为API provider：异步提交+轮询；若为自建：ComfyUI工作流

3. 全部环节成功 → 下载注册成片 → social_media_assets(含ai_labeled) → status=succeeded
   某环节失败 → retry_wait（从失败 step 续跑，不必从头）

4. 成片 → 关联 social_content_masters → 进入审核链路
```

### 8.5 关键技术风险与对策

| 风险 | 对策 |
|------|------|
| 视频生成耗时不定（数分钟~数十分钟） | 异步任务 + 轮询，前端看板轮询状态；单任务超时熔断 |
| 厂商限流/不可用 | provider 故障转移（P1）；限并发；失败重试 |
| 生成成本失控 | 按 provider/租户限并发；接入 #42 积分计费（按生成次数/时长计费因子） |
| 成片时长不符（15-30s主力/≤60s品牌向）| 生成后校验，不符标记异常，不计费/可重试 |
| 真人模特肖像合规 | 素材上传时强制标注授权状态（F1.6），未授权不可用于生成 |
| 抖音/视频号 API 变更 | 连接器隔离，单点适配 |
| **产品变形/画面闪烁/主体漂移**（v0.2 工艺链核心风险）| IP-Adapter+产品LoRA+ControlNet 约束；补帧RIFE；锁定参考帧；内建失败模式知识库自动 mitigation |
| **同质化被平台限流**（v0.2）| 反同质化机制（运镜/光影/背景轮换），§5.6.3 |
| **未标识AI内容被限流**（v0.2 法规）| 合规标识烧录为强制环节，发布前合规自检 |
| **自建模型显存/GPU 成本**（v0.2）| Wan2.2 量化部署；CogVideoX 5GB 低显存兜底；按需启停 |

### 11.2 MVP（P0）验收标准

> **MVP 范围原则（v0.3 修正）**：最小可用。**不建产品库/SKU 表**，单次生成只需"在向导里上传素材 + 手填卖点"即可驱动；素材落 file_id（便于重试/审核取回）但不沉淀为产品实体。批量语义 = 一批素材 × 一个场景预设 → 多条差异化视频。

1. **素材上传（不建产品库）**：向导内直接上传产品图（建议 2-4 张多角度）/模特图/实拍片段，自动抠图，标注 asset_role，落 file_id，与本次生成任务绑定。
2. **卖点手填**：向导内文本框手填卖点 + 材质特征，喂给提示词引擎（不抽取、不落库）。
3. **场景预设**：内置 7 类场景预设可用（开箱/口播/氛围/对比/试戴/旋转/特写）。
4. **提示词引擎**：手填卖点 + 上传素材 + 场景预设 → 自动生成结构化精准 prompt（可灵8层），支持微调。
5. **工艺链**：10 环节流水线可编排执行（通义万相做 I2V，其余环节系统侧补齐），支持断点续跑/单步重试。
6. **主体一致性**：成片中产品主体无明显变形（IP-Adapter 生效）。
7. **图生视频**：通义万相 provider 跑通完整链路。
8. **批量（一批素材 × 一场景 → 多条差异化）**：同一批素材 + 1 场景预设 → 用反同质化生成多条差异化视频（如 3-5 条），看板展示每条工艺链进度。
9. **合规标识**：成片强制烧录醒目 AI 标识，发布前合规自检。
10. **审核台**：可预览视频（含AI标识）、批准/驳回。
11. **发布准备**：通过审核视频可按平台规格打包下载。
12. **量化达标**：单视频生产 < 15 分钟，采纳率 ≥ 70%，时长 100% 合规，产品变形率 < 10%。

> **明确从 MVP 移除（v0.3）**：产品库/SKU 管理、详情页导入抽取卖点、产品 LoRA 训练、多 SKU 批量、单 SKU × 多场景 A/B、素材版权标记、批量任务模板。这些均依赖产品库或属增量能力，放 Phase 1+。

### 11.3 MVP 关键依赖与前置

- 通义万相图生视频 API 开通与配额。
- **主体一致性方案验证**：IP-Adapter + 通义万相对接可行性（关键不确定性，需前置 spike）。
- 现有基础设施可复用性确认（file_id 体系、background_runner、social_* 发布链路）。
- 合规标识方案确认（FFmpeg 烧录 + 元数据写入规范）。
- 前端控制台开发资源。

### 11.4 后续演进方向（Phase 2+ 候选）

- **自建模型深度**：Wan2.2 + Fun-Control 全工艺链工作流，摆脱 API 限制，提升质量上限。
- B 端：阿里国际站海报/详情页平面设计（复用 media provider 的 generate_image + HTML 渲染）。
- 爆款参考增强：从人工导入升级为半自动采集（合规前提下）。
- 数据回流：已发布视频的播放/互动数据回流，反哺场景预设优化。
- 场景预设度量：各预设的采纳率/完播率回流，形成"预设效果排行榜"。
- AI 模特生成（远期）：评估数字人/换脸能力补齐模特供给。

## 附录 A：关键决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 产品定位 | 重生产（AI 批量出片为王） | 用户明确优先出片效率，分发放二期 |
| 目标用户 | 电商运营人员 | 需可视化控制台，弱对话 |
| MVP 业务线 | 先 C 端图生视频 | 视频号/抖音铺量是当前最痛 |
| 算力来源 | 混合：API 快速落地 + 自建补充 | API 先跑通，自建做差异化 |
| 模特素材 | 系统不生成，只消费上传素材 | 范围收敛，合规简单 |
| 批量模式 | **一批素材×一场景×多条差异化（P0，v0.3）** + 多SKU批量/单SKU×多场景（P1）分期 | v0.3 最小可用：去掉产品库后，批量=同素材多版本差异化 |
| 爆款参考 | 人工导入 | 避开平台采集的合规与技术复杂度 |
| 生成接入 | 新建独立 media provider 层（不复用 BaseLLMProvider） | 对话语义与生成语义不兼容 |
| 数据模型 | **v0.3：新建 creative_*/gen_*，复用 social_*；product_* 推迟到 Phase 1** | MVP 最小可用，素材直接绑任务不沉淀产品实体 |
| **产品库（v0.3）** | MVP 不建，Phase 1 补 | 用户明确要最小可用，单次生成只需喂素材 |
| **卖点录入（v0.3）** | 向导内手填文本，不抽取不落库 | 去掉产品库后最轻量录入方式 |
| **视频时长（v0.2）** | 主力 15-30s，≤60s 仅品牌向 | 调研：15-30s 完播率90%+，60s<70% |
| **AI 标识合规（v0.2）** | 强制烧录为 P0 硬需求 | 2025.9.1 法规，不标识即限流 |
| **反同质化（v0.2）** | 批量任务强制差异化 | 平台惩罚"同构图换皮连发" |
| **混合素材（v0.2）** | 支持实拍+AI混合 | 美妆品类纯AI是减分项 |
| **工艺链（v0.2）** | 10环节流水线为产品核心壁垒 | 调研：可用视频非单次API |
| **场景预设（v0.2）** | 封装 prompt+运镜+工作流JSON | 对手共性：让用户选场景非写prompt |
| **自建模型选型（v0.2）** | Wan2.2-I2V-A14B（Apache 2.0） | 开源SOTA、可商用、有运镜控制 |

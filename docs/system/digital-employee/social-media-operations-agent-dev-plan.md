# 社媒内容运营智能体与聚合平台开发计划

> 版本：v1.0  
> 日期：2026-06-29  
> 状态：待开发  
> 设计文档：[social-media-operations-agent-design.md](social-media-operations-agent-design.md)  
> 首期平台：微信公众号、微信视频号

## 1. 开发目标

交付一个可扩展的社媒运营核心，并完成：

- 微信公众号官方 API 发布与基础数据同步闭环；
- 微信视频号辅助发布与数据导入闭环；
- 周计划、内容日历、素材、母版、平台版本、审核、发布和数据看板；
- 社媒运营智能体的确定性工具；
- 可通过新增连接器扩展微博、小红书、抖音、快手、今日头条、X、Instagram，而不修改核心状态机。

## 2. 实施原则

1. 先验证真实平台权限，再实现对应能力。
2. 核心领域先行，平台连接器后接。
3. 发布执行不经过 LLM，不复用“重跑提示词”式定时任务。
4. 每个阶段完成后更新本计划状态和 `docs/ideas.md`。
5. 数据库变更同步更新 `docs/system/database_system_table.md`。
6. 实际开发前创建对应 OpenSpec change 和验收规格。
7. 未通过真实账号验证的能力不得标记完成。

## 17. 风险与检查点

| 检查点 | 失败时处理 |
|--------|-----------|
| 公众号真实权限不足 | 收缩首期能力并更新设计，不使用非官方接口补洞 |
| 视频号出现正式 API | 只扩展连接器能力，不改核心状态机 |
| APScheduler 主锁不可靠 | 保留其唤醒作用，以 DB 原子领取保证不重复 |
| 现有 RBAC 不足 | 单独设计最小权限扩展，不在业务代码硬编码角色名 |
| 文件存储不满足长期素材 | 先补统一文件服务设计，不在社媒模块自建存储 |
| 指标口径无法统一 | 保留原始指标，缩小可聚合标准指标集合 |
| 平台提交结果无法确认 | 进入 `status_unknown`，人工处理，不盲目重发 |

## 18. 完成定义

只有同时满足以下条件，首期才可标记开发完成：

1. 所有 Phase 必做项完成或有经确认的范围调整；
2. 自动化测试全部通过，未跳过关键测试；
3. 公众号和视频号分别完成真实验收；
4. 租户隔离、凭证安全、审核不可绕过、发布幂等通过验证；
5. 文档与实际实现一致；
6. `docs/ideas.md`、数据库文档和 OpenSpec 状态已同步。

# 社媒营销智能体 开发计划

> 日期：2026-07-21
> 状态：内容管理骨架已落地，广告与巡检待开发
> 设计文档：[social-media-marketing-agent-design.md](social-media-marketing-agent-design.md)

> **状态图例**：✅ 已完成　🔧 部分完成　⬜ 未开始

## 1. 开发目标

把社媒营销智能体从「内容管理骨架」推进到「内容管理 + 广告管理 + 巡检商机」三大模块完整可用，在公司自有资源上验证全链路获客与营销价值。

## 2. 实施原则

1. **共享底座先行**：连接器协议扩展、调度执行框架、AI 生成框架是三模块共同依赖，先做。
2. **优先级**：巡检商机（公司第一优先级，快速验证主动获客价值）> 广告管理（公司自投广告，价值明确）> 内容管理补齐（已有骨架，补发布执行）。共享底座阻塞项优先于一切。
3. **真实平台验证驱动**：每模块 Phase 0 实测平台真实能力，不猜测。
4. **高风险动作人在环**：发布、调价、留言、私信永远人审，工具层面不暴露直接执行接口。
5. 最大化复用既有核心（账号/凭证/调度/审核/租户隔离/文件存储/browser 工具）。
6. DB 变更同步 `init-postgres.sql` + `db_update.sql` + `database_system_table.md`；每阶段更新本计划与 `docs/ideas.md`；真实账号未验证不标记完成。

## 9. 风险与检查点

| 检查点 | 失败时处理 |
|--------|-----------|
| 公众号/腾讯广告权限不足 | 收缩首期能力，不用非官方接口补洞 |
| browser 登录态不支持持久化 | B0 必须先解决（评估扩展或独立 session 方案） |
| 知乎/小红书账号被风控 | 暂停转人工降频，复盘触发原因调护栏 |
| 平台 DOM 改版 | selectors 快照自检告警，连接器降级只读+人工 |
| 小红书 web 发布/私信不可用 | 降级雷达+评论，发布走人工 APP 辅助 |
| 视频号出现正式 API | 只扩连接器能力，不改核心状态机 |
| APScheduler 多 Worker 重复 | DB 原子领取为主，Redis 租约为辅 |
| 商机/线索质量低 | 调种子词/意向分阈值/话术，持续校准 |
| 真实账号执行风险 | 所有花钱/接触先小额低频验证 |

## 10. 完成定义

社媒营销智能体标记开发完成需同时满足：

1. 共享底座 S0–S3 + 三模块必做项完成或有经确认的范围调整；
2. 自动化测试全过，未跳过关键测试；
3. 五个里程碑（M-内容/M-广告1/M-广告2/M-巡检1/M-巡检2）真实验收均通过；
4. 租户隔离、凭证/Cookie/PII 安全、人审不可绕过、幂等与护栏通过验证；
5. 文档与实现一致；`docs/ideas.md`、DB 文档、OpenSpec 同步；
6. 产出公司自用价值报告（内容引流 + 广告提效 + 巡检获客），作为产品化决策依据。

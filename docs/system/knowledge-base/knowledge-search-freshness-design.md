# 知识库多轮检索新鲜度与结果去重设计

> 日期：2026-11-04
> 状态：设计已确认，代码已实现；待人工多轮验收
> 范围：`knowledge_base_search`；关联[原知识库能力设计](knowledge-base-enhancement-design.md)、[分类授权设计](subagent-kb-category-authorization-design.md)、[共享设计](tenant-knowledge-sharing-design.md)、[实施计划](../../plans/plan-knowledge-search-freshness.md)

## 1. 问题与目标

同一会话中的历史知识库工具结果及回答会进入后续模型上下文。模型可能沿用旧知识，忽略知识库已更新。当前 `knowledge_base_search` 返回片段级 `results` 和文档级 `documents`；后者可能包含较大的 `doc_metadata.raw_payload`。多次检索又可能把相同内容重复送入模型。

**本期决策**：只要本轮需要知识库事实，模型应调用 `knowledge_base_search`；工具**每次都实际执行现有内容检索**，再把本轮模型上下文中已经存在且与新检索结果完全相同的片段、文档信息裁掉。新内容照常返回。知识分类版本表、更新时间标记、数据库触发器和版本迁移不纳入本期；它们原先仅为跳过重复检索服务，用户决定用更简单的每次检索方案。

## 2. 产品边界

1. 仅覆盖 `knowledge_base_search`；`knowledge_file_search → read`、其他直接读库工具和技能脚本本期保持现状。
2. “需要知识库事实就调用工具”靠固定系统指令、相关数字员工提示词及人工多轮实验促使模型遵循。仅靠工具钩子无法发现模型完全没调用工具的轮次，**本期不提供百分之百强制保证**。
3. Agent 继续只传现有 `query`、`source_type`、`top_k`。服务端在上下文装配后准备去重清单，经可选 `ToolExecutionContext` 交给工具；不增加模型可见的必填调用参数。
4. 历史模型消息保持原样，以维持前缀缓存；本功能不因知识变化改写、清理或重排历史。系统原有窗口裁剪、长会话压缩照常运行。裁剪只作用于本轮新工具结果。
5. 不设置任何费用门禁，也不新建费用监控体系；人工实验时按需查看现有 trace、日志和用量记录。

## 3. 当前上下文中的知识清单

在既有压缩、历史重排和窗口裁剪完成后，**每次执行 `knowledge_base_search` 前**，从当时 `state.messages` 中识别配对的本工具调用与结果；只计入仍会随下一次模型请求发送的完整内容。同一执行中前一次工具调用刚返回的内容，也应纳入下一次调用的去重清单。新格式工具结果带一个轻量格式标识，以及片段和文档信息的内容指纹；这些标记与普通工具结果一起保存。执行钩子从当前消息整理清单，经可信可选执行上下文传给知识库工具，不让 Agent 整理历史，也不额外查询历史数据库。恢复执行时同样以恢复后的当前消息为准。

片段用 `doc_id + chunk_index` 定位（沿用当前返回的 1-based `chunk_index`），再对 `text` 和稳定的知识元数据计算确定性内容指纹；`score` 等本次检索派生字段不参与，否则不同检索词命中同一片段时会误判为内容更新。文档信息独立对模型可见的 `documents[doc_id]` 内容计算指纹，包含摘要、`doc_metadata.raw_payload`、封面等。结果中的 `knowledge_scopes` 记录本次文档的栏目与共享来源，供后续授权失效提示使用。指纹不读取向量。相同位置内容变了，指纹必须不同；片段正文未变但 `raw_payload` 变了，文档信息指纹必须不同。

清单只包含本轮上下文中**仍有完整正文**的新格式结果。旧格式结果虽有检索入参，但没有历史指纹，不能据当前数据库反推，首次新调用照常返回完整结果并留下新格式标记；以后可去重。新旧格式混存时只使用完整的新格式项。结果缺字段、JSON 解析失败或历史只剩去重标记而找不到完整正文时，忽略该条去重依据，不让对话失败；诊断日志不包含知识正文。旧会话升级后的第一次检索可能与旧历史重复一次，这是兼容代价。

## 4. 每次实际检索后的裁剪

工具每次仍按可信身份和现有授权规则确定本租户及共享知识的可检索范围，正常执行查询向量化、向量/全文搜索、融合排序与 `top_k` 截取。不得在搜索候选或排名前排除历史 chunk，否则可能漏掉同一文档的其他片段或改变排名。文档自然到期、删除和知识库新增修改由当前检索的可见性过滤反映，无额外版本查询或到期预检。

对排好序的本次命中结果，若某片段的 `doc_id + chunk_index + 内容指纹` 在当前上下文清单里完全匹配，就从本次 `results` 裁掉；正文不同则必须返回。文档信息独立比较，完全相同且当前上下文仍有原文时可从本次 `documents` 省略；`raw_payload` 等信息变化时必须返回，即使关联片段正文被裁掉。相同查询、不同查询和空结果一律走这套实际检索；本期不缓存“上次查不到”。

保留现有 `success`、`documents`、`results`、`count` 等字段；`count` 是本次实际返回的片段数，新增 `matched_count` 表示裁剪前命中数。两者不同表示部分本次命中片段的完整正文已在当前上下文中；两者都为零才是本次未命中。增加 `already_in_context_chunks`（`doc_id`、`chunk_index`、内容指纹）和 `already_in_context_documents`（`doc_id`、内容指纹），只列**本次检索重新命中、确认与当前上下文相同且因此裁剪**的内容，不返回这些内容的正文，不形成引用链。即使本次有新片段，其文档信息仍可能因相同而省略；用后一清单明确指出。

工具说明使用白话解释字段及取值，拟采用以下口径：

> `matched_count` 是本次检索命中的片段数，`count` 是去重后本次 `results` 实际返回的片段数。`already_in_context_chunks` 中列出的片段，正文和相关信息已完整出现在当前模型上下文的历史工具结果中，所以本次不重复给出。`already_in_context_documents` 中列出的文档资料（包括 `doc_metadata.raw_payload`，如有）也已完整出现在当前模型上下文中，所以本次不重复给出。两个清单只包含**本次重新检索命中并确认仍相同**的历史内容；回答时可使用本次新返回的内容和清单所指的历史内容，不能据此认定其他旧知识仍然有效。若 `matched_count > 0`、`count = 0`，表示本次找到了内容，但命中的片段都已在上下文中；此时仍须查看本次 `documents` 是否返回了更新的文档资料，并以本次资料为准。两者都为零才表示本次未命中。

字段使用清楚的 `already_in_context_*` 名称，不另加“全被裁剪”提示文字。即使两个计数相等，文档资料仍可能被独立裁剪，应查看 `already_in_context_documents`。无可信钩子清单的直接调用返回完整内容，新增计数与原 `count` 一致。

## 5. 授权、失败与旧知识

复用清单不能放宽现有栏目授权或跨租户共享范围。当前检索无法命中的历史内容不能作为“本轮确认有效”；撤权内容也不能进入 `already_in_context_*`。现有 `load_authorized_source_types()` 把读取失败和未配置授权都返回 `None`，`load_shared_ranges()` 把读取失败和无共享都返回空。本期对 `knowledge_base_search` 必须区分授权读取失败与正常空值：无法核实授权时明确报错，不以“未配置”范围检索或复用。此异常处理对该工具有/无钩子调用均适用；授权正常的无钩子调用仍完整返回。`knowledge_file_search` 本期不改。

针对授权变化，本轮工具结果用 `invalid_history_documents` 临时列出当前上下文中已确认失效的历史文档 `doc_id`，提示模型不要使用；旧格式结果可用完整配对的文档栏目与片段共享来源判断撤权，但仍不用于内容去重。只用历史已有标识，不返回撤权知识的新正文。这是**过渡提示**，不能强制隔离已在历史上下文里的旧正文。后续终极方案在装配模型上下文时保留 `assistant(tool_calls)` 与 `tool` 配对，把已撤权工具结果的模型可见正文替换为“知识访问权限已被撤销”。终极方案验收通过后，删除本期专为撤权添加的失效清单与对应提示词；普通检索后去重保留。

固定提示词说明：历史工具结果、历史回答及对话摘要中的知识库事实只代表当时的信息；本轮使用知识库事实须调用工具，并以本轮结果和 `already_in_context_*` 清单为准。新摘要把知识库事实标成历史检索信息；已有摘要和历史消息不改写。模型仍可能不遵循提示词，因此本期不能宣称已彻底消除历史知识污染。

工具调用或检索真正失败时，不把未经本轮确认的旧知识当作工具结果兜底；工具明确报错。无钩子、旧格式或历史证据不可解析时仅放弃裁剪，正常完整检索。不要为同一轮结果增加额外的版本比较、二次检索或费用门禁。

## 6. 兼容性与后续事项

- 现有工具入参、`results` 片段字段及新内容的 `documents` 信息保持兼容；只有带可信清单且确认当前上下文有完整原文的结果可裁剪。Web、渠道和恢复路径都按实际模型上下文构造清单，不把裁剪标记当作原文再次复用。
- `documents[doc_id]` 对新片段可能省略，工具说明和报价/旅游等依赖 `raw_payload` 的多轮回归必须覆盖此场景。
- `knowledge_file_search → read`、其他知识入口和授权撤销历史正文强隔离均为后续独立事项。
- 宏陶 API 原始 JSON 保存也独立处理：当前 `raw_text` 是渲染 Markdown，`raw_payload` 是整理后的业务数据，`file_type=json` 不代表已保存原始 JSON 文件。后续先决定原件与现有禁存字段的关系，再设计保存、查看与存量补抓。

## 7. 验收

人工多轮实验覆盖：同词连续问答、新问题、知识内容更新、`raw_payload` 单独更新、删除和自然到期、空结果、同一文档不同片段、新片段但旧文档信息、旧会话首次新检索、历史被压缩/裁剪、共享授权变化。检查该用知识库的轮次是否真正调用工具，并核对 `matched_count`、`count`、两个 `already_in_context_*` 清单和模型最终回答。定向代码回归覆盖无钩子直调、历史格式异常、授权读取失败及 Runner 恢复。费用和缓存命中只用现有记录观察，不设通过阈值。

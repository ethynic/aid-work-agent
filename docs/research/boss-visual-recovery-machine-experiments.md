## 最小实验入口与调用方法

```powershell
node dist/src/cli/index.js screenshot --output <PNG路径> --json
node dist/src/cli/index.js visual-diagnose --image <PNG路径> --request-id <UUID> --json
node dist/src/cli/index.js visual-diagnose --request-id <相同UUID> --retrieve-only --json
```

CLI只配置我方后台 `AID_BOSS_SERVER_URL/TOKEN`；后台持有模型凭据、提示词和费率。实际实验使用本机loopback API，挂载项目真实client router，连接一次性本机PostgreSQL数据库，真实client-binding鉴权和临时租户台账。模型HTTP使用后端配置的真实智谱通道。没有mock模型/账务，没有部署远程服务，也没有动业务租户余额；每轮结束导出必要结果并清理临时库。

第一组原图1261×888不缩放，空间为 `page_image_px`；第二组窗口图单独使用 `window_image_px`。输入为版本/request_id/standalone上下文、操作目标、PNG及尺寸/hash；不传DOM候选、关闭位置或基准矩形。输出为版本、prompt_version、页面摘要、verdict、依据、单个关闭建议或null、point/target_box及真实费用receipt。非法图/坐标拒绝，非法输出只保留诊断错误和真实费用，不执行建议。

## 提示词与结构打磨

v1要求“找最上层弹窗并给关闭动作”，模型在无主模态层时仍找可关闭广告。v2先要求判定是否阻挡当前目标：遮罩模态层可处理；角落促销/列表横幅只有明确遮挡目标或用户指定时才建议动作；不得为交出坐标而强选一个×。无阻碍时返回null，不凭截图断言具体业务写操作成功。v2在本轮一阳性、一阴性样本上符合预期；样本少且发生过超时，不能推导稳定性百分比。

保留 `point` 与 `target_box`，不只返回一个“成功”布尔值；服务端检查框在原图内、点在框内。`verdict`与建议分开，避免模型建议被误当执行结果。第一组接口只支持standalone网页图；第二组已扩窗口图与单次CLI输入，managed任务和自动恢复仍待开发。

## 第二组：Chrome打印预览的现场排障

用户在当前BOSS页面模拟浏览器级阻挡，并明确要求识别原因、按建议直接排障。初始CLI网页截图和doctor都成功，doctor甚至ready=true，但图上没有弹窗；这不等于页面真实输入可用。新增CLI窗口采图后，明确看到Chrome打印预览覆盖主页面，右下角有“打印/取消”。打印预览属于浏览器UI，不能用BOSS DOM候选定位。

提示词v3明确浏览器原生/打印/文件选择UI与网页弹层不同，建议安全取消/关闭，不建议打印、发送、购买、权限授权或直接关掉整个Chrome。后台校验输出space与原图一致，防止把窗口坐标当页面坐标。

## 实验结论：建议传给GLM的最小上下文

21轮证据、可复用提示词草稿、候选请求/响应和下一轮验证优先级统一整理在[原设计N节](../design/recruiting/boss-overlay-heal-design.md#n-实验收敛建议提示词上下文与接口候选2026-10-16)。本报告保留逐轮历史事实；当前代码仍v1/v5，N节v2/v6仅供评审，不代表新增API已可调用。

当前产品DTO未扩展：上述结构化上下文仍通过现有CLI `--goal`文本传输，长度≤1000字符。下列为根据实验证据提出的正式接口候选，不宣称已冻结/上线：

- operation：工具名、原意图、目标可读标识、expected后态。目标姓名有助于检查该卡片区域；不传全简历、整段会话或无关候选材料。
- execution：明确阶段、input_status（not_started/attempted/unknown）、attempt_index、普通重试已用次数。click_calls只作诊断，不能代替实际输入阶段；缺证据就unknown，不猜false。
- error：code、source、精简summary及必要exit/guard reason。去掉本机临时路径、冗长PowerShell堆栈和“请人工重试”等旧策略话术，保留真实错误语义；错误中的“可能无在线简历”属于假设，不能当事实。

# 微信 UIA 控件树间歇不可读真机实验

2026-11-26，北京时间。使用同一台 Windows 电脑、Runtime 1.3.1 安装的验收签名微信 CLI 0.1.6 和同一个演示群。观察会话列表 `session_list`、群聊标题 `current_chat_name_label`、消息列表 `chat_message_list`，并以 `read --domain group-history --max-pages 1 --json` 实际读正文。只记录控件和消息数量。

| 场景 | 观察结果 |
| --- | --- |
| 微信 4.2.0.13，故障中 | 微信在前台，界面可直接打开目标群。独立 UIA 读取只看到 3 个外层控件。CLI 窗口恢复返回 `CONTENT_UNAVAILABLE`，读群返回 `UI_CHANGED`。 |
| 微信自动更新到 4.2.1.10 后重新登录 | 会话列表、群聊标题和消息列表恢复。同一 CLI 连续两次读群返回 `OK`，每次读取 9 条记录，其中 5 条文字。 |
| 同一 4.2.1.10 进程，打开添加朋友窗口，输入前和显示查无用户时分别采样 | 两个采样点的微信主窗口均有 170 个可枚举节点，包含会话列表和消息列表。真实微信显示查无用户，CLI 返回 `TARGET_NOT_FOUND`、`effect=none`。 |
| 只查结果仍开着时直接再次运行 | CLI 提示先关闭已有添加朋友窗口。弹窗句柄未变，主窗 UIA 继续可读。正常关窗后读取同一个群返回 `OK`。 |
| 三轮搜索后走驱动自动关窗 | 本机视觉测试替身在结果步骤返回 `unknown`，触发生产驱动的 `finally` 关窗。每轮均回到微信前台，诊断为就绪，读群 9 条记录、5 条文字。实验结束时没有好友弹窗，主窗仍能枚举 170 个节点。 |

搜索实验使用已安装的 CLI `add --domain friend --search-only --json` 真机操作。定位与分类响应由本机回环测试服务提供，首轮按实际截图返回坐标和查无用户，后续三轮复用驱动缓存并走明示的结果未确认分支。首轮到达四个视觉步骤，后续每轮仅到达搜索结果步骤。所有查询均在真实微信窗口执行，未打开申请窗口或发送好友申请。

## 结论与尚未分离的变量

- 当前样本支持故障发生时微信的应用级 UIA 控件无法被读取。独立 UIA 客户端只看到外层控件，CLI 同期拿不到群聊内容。Windows 会通过应用的控件提供程序查询应用级元素。 [Microsoft UIA Provider 文档](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-howto-expose-serverside-uiautomation-provider)
- 本次未在 4.2.1.10 复现加好友搜索、搜索结果保留或关窗导致主窗 UIA 丢失。4.2.0.13 的退化过程及申请窗口后续阶段没有受控对照。该旧版本此前在本机读取成功，11 月 23 日另有 4.1.15.13 无法读取且更新后恢复的记录。 [历史验收](../plans/plan-weixin-agent.md)
- 两次历史恢复均同时包含终止旧进程和版本升级。下一次复现时，先记录微信版本、进程启动时间和三个控件的可见性。能在同一版本正常重新启动时，先复测控件树和群聊正文，再对照升级后的结果。

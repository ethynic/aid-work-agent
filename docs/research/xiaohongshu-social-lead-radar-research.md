## 附件实际提供了什么

附件 `xhs-lead-radar-skill-v1.0.zip` 是一个面向 WorkBuddy / Claude Code 的本地工作流：产品档案和目标客户画像 → 分层关键词 → 站内搜索和详情读取 → 将笔记作者、评论者拆成不同候选 → 规则打分与排除 → 输出线索、证据、草稿和关键词复盘。它不给出平台用户的采购确认，也不等同于能拨打电话的客户名单。

| 内容 | 附件中的证据 | 采用方式 |
|---|---|---|
| 产品画像和关键词 | `product-profile.md`、`icp-and-keywords.md`、`assets/keywords.txt`；混合场景词和采购意图词 | 转译定词方法与少量示例。目标行业、痛点、正负例按任务和租户输入；附件里的公司价格、效果数字和案例不能成为产品默认事实。 |
| 采集 | `run_radar.py` 默认直达搜索结果，`--ui-search` 才加 Windows 键鼠；`xhs_core.py` 用 Playwright/CDP 从 DOM 读笔记及评论，可额外开作者主页。Windows 宿主用独立 Chrome profile 和本机调试端口；另有接管日常 Chrome 的旧脚本。 | DOM 字段可用来设计样本和接入验收。不移植常驻 Chrome、用户日常浏览器接管、调试端口、Win32 坐标或拟人逻辑。 |
| 排序 | `scoring.py` 按意图、身份、场景、活跃度加权，排除招聘、同行、卖课等；按固定阈值出级别和开场建议。样例 CSV 3 篇笔记共 9 条候选：5 条 B、4 条 C，A 为 0。 | 借鉴信号词和可解释排序。实际阈值依人工标注校准；热度不视为采购意图，判断必须看语境，缺组织或决策证据就标未知。样例不是准确率或跑通实证。 |
| 产物与恢复 | Markdown/CSV、关键词复盘、`raw.jsonl`。`run_radar.py` 的 `_seen_notes.json` 在时间戳输出目录内，默认下一轮不共享；先标已见后读详情。评论候选继承父笔记链接，样例未给稳定评论 ID。 | 报告形态可保留。使用租户内稳定来源键和商机池；同一笔记作者与多条评论不得按一个链接合并。没有可靠评论标识就按候选展示，不宣称可靠去重或全量覆盖。 |

附件中的安装命令、采集频率、发送上限和触达话术是包作者的建议，不能视为用户授权、已验证平台规则或可直接继承的产品要求。附件没有随包提供清晰的代码许可说明；首期参考业务方法，不复制脚本或将真实样例入库、入测试夹具。

## 2026-11-16 源码核对

- 对话入口：现有 [`social-media-operations/SUBAGENT.md`](../../subagents/social-media-operations/SUBAGENT.md) 是社媒运营入口，关注内容，`skills.allowed` 为空。首期在此扩展「商机雷达」职责及明确触发词。现有 [AI 获客](../subagent/ai-lead-gen/ai-lead-gen-agent-design.md) 以企业名单、联系人和邮件发信为主，产品场景调研方法可参考，原发信流程和表不能直接接这些社媒信号。
- 业务底座：[`src/social_media/outbound`](../../src/social_media/outbound) 已有 4 张表的初始化接线（[`database.py`](../../src/db/database.py)）、租户过滤的 DAO、加密原文、意向分和状态机。源码未见小红书连接器、雷达服务、公开的商机路由和数据库会话与小红书的实际接线。`SocialPlatformConnector` 当前方法偏发布和指标；`WEB_*` 枚举存在不等于读取协议已实现。既有 `LeadRepository.upsert` 按内容 ID 优先去重、留较高历史分；接线要核对笔记/评论 ID、重复提交和评分回执一致，不能把已有 DAO 当作上线验收结果。
- 浏览器：`session.py`、`worker_main.py` 有 `storage_state` 注入与导出，`account_session_store.py` 有租户/账号维度的加密存取；它们是代码组件，不能据此断言小红书跨轮登录可用。通用 `browser_automation` 已于 2026-11-06 退出新任务工具目录（[Runner 槽隔离 Phase 1](../plans/plan-runner-execution-slot-isolation-and-alerts.md)），禁止把旧设计的 #20 当成可直接调用的现成采集能力。普通网页搜索、`web_fetch` 也只可提供可访问的候选来源，不能替代站内搜索和评论权限。

## 数据源选项（2026-11-16 核查）

| 路径 | 当前证据 | 决策 |
|---|---|---|
| 官方授权检索 | [智能体平台介绍](https://miniapp.xiaohongshu.com/doc/DC897827) 提到笔记检索和站内趋势 MCP；[账户授权范围](https://openaccount.xiaohongshu.com/docs/scope) 仅开放基础资料，笔记读取列为规划。两者是不同产品面。未找到能证明我们的系统可商用接入、全站按词搜、读取评论及保存分发线索的公开授权或接口契约。 | 优先向官方核验主体准入、笔记与评论字段、可保留证据、获客用途和数据期限；以授权文档及最小实测为准。接口用 API 或 MCP 不改变权限边界。 |
| 人工选材或授权样本导入 | 用户可按建议词人工在平台找笔记，输入有权处理的链接和必要摘录；仅有链接而正文不可获取时，请补摘录。 | 可独立验证筛选质量，与插件读取共用证据判别和归集流程。 |
| 采购授权数据或受控网页读取 | 待核供应商来源、授权链和允许用途；账号登录、公开可见、限速或有界面本身不证明自动读取获准。 | 仅在许可与真实可用性明确后作为数据源选项；遇登录/验证码/限流停止，不用私有接口、验证码绕过或附件浏览器宿主补齐能力。 |
| 聚光客资收集 | [聚光 Marketing API 指南](https://ad.xiaohongshu.com/openApiDoc?articleId=3047&categoryId=761) 说明广告投放、客资收集及授权流程。 | 属于自有投放留资，和「发现第三方自然笔记/评论中的采购需求」是两个入口。若今后需要可分别接入，不能用客资能力推断自然内容接口可用。 |

## 选型

整包转译做演示最快，但会把桌面依赖、租户配置、采集和输出绑在一个脚本上；全靠通用浏览器和模型逐页判断也难以稳定复跑。建议只转译附件的**获客方法**，采用**现有社媒智能体 + 薄 Skill + 按平台接数据 + 共用商机判别与商机池**。指定主页读取由本机插件提供，人工或获授权样本可用来校准判别质量。关键词自动检索是另一种数据入口，应单独核实能力与权限。后续接其他平台只新增数据适配与平台词表，复用一套证据、评分和跟进方式。若首个平台只支持笔记，明确交付「笔记范围」，评论不得被当成已读或无评论。

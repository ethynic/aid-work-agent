## 1. 总体技术路线

```
DWG 文件
  │  ① ODA File Converter（命令行批量，DWG→DXF，保留天正代理图形）
  ▼
DXF 文件
  │  ② ezdxf 解析：实体统计 / 坐标范围 / 图框块定位 / 图名文本提取
  ▼
图幅清单（每张图的 bbox + 图号 + 图名 + 专业）
  │  ③ ezdxf drawing add-on + matplotlib 渲染（整图 + 图幅裁切 + 局部放大三级）
  ▼
PNG 图片序列（≥4200px/图幅，白底，中文可读）
  │  ④ 多模态模型：图幅识别 → 配对 → 差异对比（结构化输出）
  ▼
疑似差异清单（差异描述 + 图幅位置 + 置信度）→ 人工复核
```

核心认知：**多模态路线的质量上限由"渲染图片的可读性"决定，渲染的上限由 CAD 解析的正确性决定**。③④ 两步的工程细节见下文。

## 2. CAD 处理关键技术

### 2.1 DWG → DXF 转换（ODA File Converter）

DWG 是闭源二进制格式，Python 生态（ezdxf）只支持 DXF。推荐用 ODA（Open Design Alliance）官方免费工具做转换，支持命令行批量：

```
ODAFileConverter.exe <输入目录> <输出目录> ACAD2018 DXF 0 1 *.dwg
```

参数依次为：目标版本、输出类型（DXF）、是否递归、是否 audit 修复。转换注意：

- 转换过程会输出 `copy process ignored DIMASSOC` 警告，可忽略（尺寸关联对象丢失不影响图形显示）
- 文件名含 `#`、空格、中文、括号时命令行易出错，建议先复制为简单文件名再转换
- **天正图纸必须保留代理图形**：天正（TArch）的墙、门窗、标注是自定义对象（DXF 中为 `ACAD_PROXY_ENTITY`），只有插件环境才能解析语义；ODA 会保留其缓存的显示图形（proxy graphics），ezdxf 渲染时可以直接画出来——实测天正建筑的墙线渲染正常。若转换时丢掉代理图形，图纸会大面积缺墙

### 2.2 DXF 解析与图幅切分

一套施工图的 DWG 通常把几十张图幅平铺在一个模型空间里（实测两套图纸各含 30+ 图幅，坐标范围达数百万绘图单位）。直接整包渲染成一张图，任何模型都无法读。**必须先切图幅**，三个手段按可靠性排序：

1. **图框块引用**：正规出图的图框是块 INSERT，块名含"图幅/图框"（如 `A2+0.5图幅`、`A1(H)图幅`），每个 INSERT 即一张图的精确 bbox。注意 ezdxf 的 INSERT 没有 `.bbox()` 方法，需用 `ezdxf.bbox.extents([insert])` 或由块定义范围 + 插入点推算
2. **大字号图名文本**：扫描全部 TEXT/MTEXT，过滤含"平面图/立面图/剖面图/楼梯/大样/门窗/说明"等关键词且字高 ≥ 250 的文本，按坐标聚类即为图幅位置。注意目录页（图纸目录）会列出全部图名造成干扰，需按坐标区分
3. **网格聚类兜底**：图框形式不规范（线条拼画）时，按实体 bbox 做网格连通域聚类。缺陷：相邻图幅紧贴或共享边线时会粘连，需辅以人工确认

切分后按图名做**跨套配对**（图号 J5↔J5、图名"三层平面图"模糊匹配），并做**专业分类**（根据图名关键词与标题栏：建筑/结构/给排水/暖通/电气）。专业分类必须前置——实测中两个文件分别为建施与结施，不做分类就无法发现"样本不可比"。

### 2.3 中文显示乱码问题（最重要的坑）

国内施工图 DXF 的文字样式普遍是 **SHX 矢量字体 + 中文大字体**组合（如 `simplex.shx + gbcbig.shx`、`txt4.shx + hztxt.shx`）。ezdxf 自带的 SHX 字形库不含中文大字体，渲染中文全部变成方块；而直接读 DXF 提取文本（`e.dxf.text`）不受影响。

**解法：渲染前把所有文字样式的字体统一替换为一个 ezdxf 能解析的中文 TrueType 字体**：

```python
import ezdxf

doc = ezdxf.readfile("drawing.dxf")
for st in doc.styles:                 # 遍历全部文字样式
    st.dxf.font = "simhei.ttf"        # 关键：必须写文件名
    if st.dxf.hasattr("bigfont"):
        st.dxf.bigfont = ""           # 清掉中文大字体依赖
```

**踩坑细节**：ezdxf 的字体解析器按**字体文件名**匹配（`simhei.ttf` → SimHei ✅），传字体族名（`"SimHei"`）会静默回退到 Arial（无中文字形 → 方块），且无任何报错。可用以下调用验证解析结果：

```python
from ezdxf.fonts import fonts
fonts.find_font_face("simhei.ttf")   # -> FontFace(family='SimHei', filename='simhei.ttf') ✅
fonts.find_font_face("SimHei")       # -> FontFace(family='Arial', ...) ❌ 静默回退
```

### 2.4 渲染实现与分辨率策略

用 ezdxf 的 matplotlib 后端渲染。推荐"一次绘制、多次裁切"模式——整包 30k 实体绘制一次约 70~240 秒，之后每个图幅裁切只是重设坐标轴，秒级出图：

```python
from ezdxf.addons.drawing import RenderContext, Frontend
from ezdxf.addons.drawing.matplotlib import MatplotlibBackend
from ezdxf.addons.drawing.config import Configuration, BackgroundPolicy

fig = plt.figure(figsize=(24, 24 * 0.75), facecolor="white")
ax = fig.add_axes([0, 0, 1, 1], facecolor="white")
ctx = RenderContext(doc)
backend = MatplotlibBackend(ax)
cfg = Configuration(background_policy=BackgroundPolicy.WHITE)
Frontend(ctx, backend, config=cfg).draw_layout(doc.modelspace(), finalize=True)

# 对每个图幅：设置裁切范围 + 按裁切宽高比调整画布，再保存
ax.set_xlim(x0, x1); ax.set_ylim(y0, y1)
ax.set_aspect("equal", adjustable="datalim")
fig.set_size_inches(24, 24 * (y1 - y0) / (x1 - x0))  # 关键：防裁切被比例自适应放大
fig.canvas.draw()
fig.savefig("sheet_J5.png", dpi=5200 / 24, facecolor="white")
```

三个细节：

- **裁切宽高比必须与画布一致**：matplotlib `equal` aspect + `datalim` 模式下，若裁切范围与画布比例不符，matplotlib 会自动扩大视野来凑比例，导致"想放大却缩小"。渲染前按裁切宽高比重设 `fig.set_size_inches` 即可
- **分辨率基准**：出图文字最小高度约 250 绘图单位（A1 图幅 84100 单位宽），要达到视觉可读（≥20px）需图幅渲染宽度 ≥4200px；实测 5200px 整图 + 4200px 局部裁切的两级策略效果最好
- **视野范围核验**：matplotlib 会因比例约束微调实际坐标范围，保存时应打印 `ax.get_xlim()/get_ylim()` 确认没有裁掉图框

### 2.5 扫描件 PDF 场景的差异（路线主战场）

本次实验两端均为矢量 DWG，以上管线直接适用。若竣工图是**纸质扫描 PDF**：

- 无矢量数据，跳过 ②③ 的解析与切分，改为 PDF 栅格化（600dpi 灰度）+ 歪斜矫正 + 图框定位（可用图框角标做配准基准）
- 渲染管线的输出对象从"DXF 图幅"换成"扫描页"，分辨率策略相同
- 因扫描件存在比例失真与噪声，多模态对比结果需叠加"比例标定 + 去噪"预处理，且尺寸类差异基本只能靠人工

## 3. 多模态模型对比方法论

### 3.1 任务分解

不要让模型"看两张大图找不同"，应拆成结构化流水线，每步只做一件事：

1. **图幅识别**：单图输入，输出结构化元数据（图号、图名、专业、比例、项目名/楼号、图幅内主要分区描述）——同时完成专业分类与跨套配对所需的信息提取
2. **配对校验**：两套图的图幅清单比对，输出配对结果与"无对应图幅"清单（本次实验即在此步发现建施/结施不匹配）
3. **差异对比**：配对成功的图幅对，按"轴网 → 布局分区 → 房间/构件名称文字 → 设备编号 → 线形线色异常"顺序逐层对比
4. **复核放大**：对疑似差异区域做局部裁切二次对比，确认或排除

### 3.2 提示词设计要点

实测有效的提示词结构（差异对比步骤）：

```
你是建筑工程图纸审查专家。下面是同一项目同一图号的两张图纸渲染图，
第一张为 A 版，第二张为 B 版。

请按以下顺序对比并输出 JSON：
1. 图纸标识：各自读出的图名/图号/比例（用于确认两张图确实同类可比）
2. 轴网：横向与竖向轴线编号序列，指出增删
3. 布局：功能分区、单元/房间构成差异
4. 文字标注：房间名、设备编号、面积数字等文字差异（给出原文）
5. 差异清单：每项含 {类别, A版描述, B版描述, 位置(轴号区域), 置信度(高/中/低)}
6. 明确声明：哪些部分"确认一致"（防止只报差异不报一致）

注意：只报告你能明确指出的差异，禁止推测；看不清的标注写"不可读"而不是猜测；
如果两图不是同类图纸，直接输出"不匹配"并说明理由。
```

设计原则：

- **先标识后对比**：强制先读图名图号，防止拿"二层平面图 vs 三层结构图"硬比
- **要求输出"确认一致"清单**：只报差异会诱导模型凑数（幻觉差异）
- **允许说"不可读"**：明确禁止猜测，把小字识别失败显式化，交给局部放大或人工
- **结构化输出**（JSON）：便于入库、去重、生成对比报告

### 3.3 分辨率与输入策略

- 多模态输入会对超大图降采样，**A1 图幅至少 4200px 宽渲染**，保证 250 单位高文字 ≥20px
- 整图 + 局部两级：整图用于布局/轴网级对比，发现疑似区域后裁切 50500×51500 绘图单位（约一个单元）4200px 二次输入
- 一次会话输入 2~4 张图为宜；图太多模型会顾此失彼（漏对比）

### 3.4 实测能力边界

| 能力 | 边界 |
|------|------|
| 图名/专业/标题栏/比例识别 | 可靠，可直接用于配对与分类 |
| 布局/轴网/核心筒级差异 | 可靠 |
| 中等文字（房间名、设备编号、面积表） | 渲染达标时可读，且能做两图数值级比对（90.45㎡ 级别） |
| 语义级差异解释 | 具备（能解释"雨篷是首层入口在二层平面的投影"） |
| 小号尺寸标注 | 临界，不可依赖；工程数值核对应走矢量数据 |
| 个体字符（轴线字母等） | 有误读风险，需复核机制 |
| 完整性 | 无法保证不漏——视觉对比本质是注意力抽样，**必须人机联审** |

## 4. 工程化落地建议

1. **双轨策略**：
   - 两端都有矢量数据（DWG/矢量 PDF）→ **CAD 实体级几何比对优先**（ezdxf 直接做图元级 diff，精确、零漏报、零 token 成本），多模态仅用于给差异生成人话解释
   - 一端是扫描件 → 多模态/OCR 路线，定位为"初筛 + 定位"，人工复核确认
2. **流水线顺序固化为**：转换 → 图幅切分 → 图幅识别（含专业分类）→ 配对校验 → 差异对比 → 复核放大 → 报告生成。其中"专业分类"不可省略，实测已证明文件混放专业是常态
3. **成本估算**：单图幅 4200~5200px 渲染约 2~10 秒（首次绘制后裁切秒级）；多模态每图幅对消耗约数千 token 视觉输入，整套 30 图幅的项目全量对比属可控成本，但应只对"配对成功且同类"的图幅做全量对比
4. **复核界面**：差异清单应附"两图并排 + 差异区域裁切图"，人工点击确认/排除，形成审计闭环
5. **竣工图归档建议**：推动项目交档时同时留存矢量电子版（或电子签章 PDF），从源头避免扫描件——这比任何识别算法的收益都大（多地"数字化审图/白图交付"政策已在推动）

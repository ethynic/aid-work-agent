## 二、十大维度详细对比

### 2.1 智能体编排能力

#### 各平台对比

| 平台 | 编排模式 | DAG/工作流 | 条件分支 | 循环 | 并行执行 | 多智能体协同 |
|------|----------|------------|----------|------|----------|-------------|
| **Dify** | 可视化工作流 + ReAct Agent | 成熟的节点式画布 | 支持 | 支持（迭代节点） | 支持（并行节点） | 支持（AgentFlow） |
| **Coze 2.0** | 可视化工作流 + Agent Plan | 拖拽式节点编辑器 | 支持 | 支持 | 支持 | 支持（Expert Agent） |
| **FastGPT** | 可视化 Flow 编排 | 图形化工作流 | 支持 | 有限支持 | 基础支持 | 不支持 |
| **智谱 GLM** | 自主编排 + 规划 | 后端驱动 | 支持 | 支持 | 支持 | 支持 |
| **百度千帆** | 工作流 + 自主规划 | AppBuilder 可视化 | 支持 | 支持 | 支持 | 支持（多Agent协同） |

#### 行业最佳实践

1. **双模式并存**：成熟平台均同时支持"可视化低代码"和"代码驱动"两种编排模式
2. **状态机架构**：采用 DAG + 状态机的混合模型，支持条件分支、循环、人工审核（Human-in-the-loop）
3. **子智能体委托**：主智能体通过任务分解委托给专业子智能体，各子智能体可独立配置工具和上下文
4. **异步执行**：长时间任务支持异步编排，通过回调/SSE 推送进度

#### 对本项目的启示

当前项目使用 `Agent` 类 + `SubagentExecutor` 的代码驱动编排模式，缺少可视化工作流编辑器。建议：
- 短期：保持代码驱动模式，完善子智能体的 DAG 编排能力
- 长期：考虑引入可视化编排层，参考 Coze Loop 的 Prompt 开发调试体验

| **Coze 2.0** | 多格式+网页爬取 | 支持 | 基础 | 有限 | 向量+关键词 | 自动同步 |

- 混合检索（BM25 + 向量）的统一接口

|------|----------|------|----------|----------|----------|----------|
| **Dify** | 社区版基础/企业版完整 | 工作空间级别 | 企业版支持 | 传输+存储加密 | 依赖部署环境 | 支持 |

- SSO/OIDC 集成（企业微信/钉钉/飞书 SSO）
- 细粒度 RBAC（操作级权限控制）

- K8s 部署清单（Helm Chart）

- 灰度发布机制

## 三、差距分析与优先级建议

基于以上调研，对比本项目的现状，按优先级排列需要补齐的基础设施能力：

### P0 - 核心差距（直接制约产品交付）

| 序号 | 能力 | 当前状态 | 建议 |
|------|------|----------|------|
| 1 | 可观测性 - 链路追踪 | 仅有 loguru 日志 | 引入 OpenTelemetry，实现 Trace/Span |
| 2 | 可观测性 - Token 监控 | 无 | 实现 Token 用量和成本实时监控 |
| 3 | Prompt 管理 | 分散在各文件 | 建立 Prompt 版本管理和评估框架 |
| 4 | 知识库增强 | 基础 RAG | 补齐混合检索（BM25+向量）和 Rerank |

### P1 - 重要差距（影响企业级交付）

| 序号 | 能力 | 当前状态 | 建议 |
|------|------|----------|------|
| 5 | 企业安全 - SSO | 无 | 集成 SSO/OIDC（企微/钉钉/飞书） |
| 6 | 企业安全 - 审计日志 | 无 | 建立完整操作审计日志 |

| 8 | MCP 协议支持 | 无 | 实现 MCP 协议的工具接入 |

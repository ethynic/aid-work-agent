# 淘宝客服智能体 — 功能域深度研究

> 调研日期: 2026-05-11 | 版本: v1.0

## 1. 商品推荐

### 1.1 核心能力

用户用口语化描述表达需求（如"适合送妈妈的生日礼物"、"夏天穿的不闷脚的运动鞋"），AI 通过 NLU 解析关键属性（适用人群、场景、季节、功能），映射到商品目录的结构化字段进行检索。

### 1.2 推荐技术架构

- **混合推荐引擎**: 协同过滤（基于相似用户行为）+ 神经网络（DeepFM/DIN 等深度兴趣网络）+ 内容匹配（属性相似度）
- **实时上下文感知**: 结合当前对话上下文、用户历史浏览/购买记录、季节/促销等时间因素动态调整
- **多轮推荐对话**: 用户不满意时追问细化需求（"您更看重透气性还是缓震？"），逐步收敛

### 1.3 具体功能点

| 功能 | 说明 |
|------|------|
| 属性模糊匹配 | 用户说"大一点"，根据品类自动映射（手机→屏幕尺寸，衣服→尺码） |
| 场景化推荐 | 识别使用场景（户外、送礼、自用），推荐适配商品 |
| 搭配推荐 | 识别主商品后自动推荐搭配件（买鞋→推荐袜/鞋垫/护理套装） |
| 库存实时校验 | 推荐前检查 SKU 库存状态，避免推荐缺货商品 |
| 价格区间过滤 | 根据用户表述的预算范围自动筛选 |
| 缺货替代推荐 | 当推荐商品缺货时，自动推荐同价位/同属性的替代品 |

### 1.4 行业数据

- 太平鸟通过 AI 尺码推荐减少退换货率
- 欧莱雅 AI 自动识别赠品订单提升运营效率
- AI 商品推荐使转化率提升 35%

## 2. 优惠活动

### 2.1 核心能力

对接淘宝开放平台营销 API，获取店铺当前生效的所有促销规则（满减、折扣、优惠券、限时特价、会员专享等），AI 能主动计算最优凑单方案。

### 2.2 优惠券分发与管理

- 不同类型的优惠券（满减券、折扣券、运费券、赠品券）通过统一工厂模式管理
- AI 识别购买意图后主动推荐可用优惠券，甚至自动领取并发送到用户账户
- VIP 等级识别：根据会员等级（新客/普通/VIP/SVIP）提供差异化优惠

### 2.3 促销场景处理

| 场景 | AI 处理方式 |
|------|-----------|
| 大促预热期 | 主动告知活动时间、预售规则、定金翻倍机制 |
| 凑单计算 | 自动计算满减阈值差距，推荐补差额商品 |
| 价保申请 | 识别降价情况自动触发价保流程 |
| 跨店优惠 | 计算跨店满减/品类券的叠加使用方案 |
| 库存紧张提醒 | 促销商品库存变化实时推送，制造紧迫感 |

### 2.4 行业数据

- 奥康鞋业大促期间 AI 客服保持 96%+ 满意度，无需增加客服人力
- AI 使促销期客服承接能力提升 3-5 倍

## 3. 产品使用指导

### 3.1 RAG 知识库架构

```
产品文档（说明书/FAQ/手册）
    → 文档解析器（PDF/Word/HTML）
    → 分块器（按步骤/按主题）
    → Embedding 向量化
    → 向量数据库存储
    → 混合检索器（向量相似度 + 关键词匹配）
    → LLM 生成自然语言指导
```

### 3.2 多模态指导

| 模态 | 说明 |
|------|------|
| 文本指导 | 基于 RAG 从说明书/FAQ 检索生成指导 |
| 图文指导 | 识别用户上传的故障照片，图像识别定位问题部位 |
| 视频教程 | 复杂操作（安装、保养、调试）推送教学视频链接 |
| AR 引导 | 部分品类（家具组装、美妆上妆、穿搭）支持 AR 实景引导 |

### 3.3 故障诊断决策树

AI 通过多轮问答逐步缩小问题范围：
1. "电源指示灯亮吗？"
2. "有异响吗？"
3. "显示什么错误码？"
4. 结合用户上传的图片/视频进行远程诊断
5. 确认质量问题后自动触发售后流程

### 3.4 功能矩阵

| 功能 | 说明 |
|------|------|
| 产品参数查询 | "这件衣服含棉量多少？" → 直接从商品详情提取 |
| 使用方法指导 | "这个怎么安装？" → 分步骤图文指导 |
| 故障排查 | "开不了机" → 决策树式排查流程 |
| 保养建议 | "真皮怎么保养？" → 按材质/品类推荐保养方案 |
| 配件兼容查询 | "这个配件适配我的型号吗？" → 型号匹配验证 |

## 4. 订单管理

### 4.1 API 深度集成

| API 接口 | 功能 | 关键字段 |
|---------|------|----------|
| `taobao.trade.fullinfo.get` | 订单详情查询 | 订单状态、金额、商品列表、收货地址、物流单号 |
| `taobao.logistics.orders.detail.get` | 物流追踪 | 物流公司、运单号、节点时间、当前位置 |
| `taobao.logistics.online.send` | 发货操作 | 物流公司选择、运单号录入 |
| 统一退款退货 API | 退款/退货处理 | 退款原因、金额、退货物流 |
| `taobao.trade.memo.update` | 订单备注 | 客服内部备注、旗帜标记 |

### 4.2 订单状态机与 AI 协同

```
待付款 → (催付/取消) → 已付款 → 待发货 → 已发货 → 已签收 → 已完成
                                    ↓          ↓
                               修改地址    物流异常处理
                               合并发货    催促发货
                               开票需求    签收确认
```

AI 在每个状态节点提供对应服务：

| 状态 | AI 服务 |
|------|--------|
| 待付款 | 智能催付（识别犹豫用户，推送限时优惠促转化） |
| 待发货 | 地址修改、合并发货、发票需求处理 |
| 已发货 | 物流异常预警（超时未更新主动提醒）、到件提醒 |
| 已签收 | 满意度回访、好评引导、复购推荐 |

### 4.3 多订单批量处理

- "我最近买的几单到哪了" → AI 查询近期所有订单并汇总物流状态
- "帮我看看上周买的那件外套到哪了" → 通过时间+商品描述模糊匹配订单

## 5. 售后服务

### 5.1 智能挽单系统

2025 年淘宝智能挽单工具数据：
- 挽回金额 8.4 亿元，年化收益超 3 亿元
- 用户发起退款时，AI 在转人工前预干预
- 分析退款原因，给出替代方案（换货、补发、部分退款、优惠券补偿）
- 店小蜜 5.0 转人工率下降 20%

### 5.2 售后场景处理矩阵

| 场景 | AI 处理流程 |
|------|-----------|
| 退款申请 | 原因分析 → 智能挽单 → 匹配最优方案 → 无法解决则转人工 |
| 退货退款 | 原因判定 → 质量问题预审 → 退货地址生成 → 物流跟踪 → 签收质检 → 退款 |
| 换货 | 原因确认 → 库存校验 → 新订单创建 → 旧件回收物流 → 新件发货 |
| 维修 | 故障诊断 → 保修期内判定 → 维修点推荐/寄修指导 → 进度跟踪 |
| 补发/重发 | 物流异常确认（丢件/破损）→ 责任判定 → 补发订单创建 |

### 5.3 售后核心指标

- 自动解决率（店小蜜 5.0 从 72% 提升到 80%+）
- 首次响应时间
- 售后处理时效
- 用户满意度评分

## 6. 客户画像

### 6.1 多维度标签体系

| 维度 | 标签示例 | 数据来源 |
|------|---------|---------|
| 基础属性 | 性别、年龄段、地域、职业 | 注册信息+购买行为推断 |
| 行为偏好 | 活跃时段、浏览偏好、咨询频次 | 平台行为日志 |
| 消费能力 | 客单价区间、价格敏感度、品牌偏好 | 历史订单分析 |
| 生命周期 | 新客/首购/复购/沉睡/流失 | RFM 模型计算 |
| 服务偏好 | 偏好自助解决/偏好人工、沟通风格 | 历史咨询记录 |

### 6.2 RFM 模型应用

- **Recency**: 最近购买距今天数 → 判断活跃度
- **Frequency**: 购买频次 → 判断忠诚度
- **Monetary**: 累计消费金额 → 判断价值等级

分层服务策略：

| 客户类型 | RFM 特征 | AI 服务策略 |
|---------|---------|-----------|
| 高价值客户 | R 近+F 高+M 高 | 优先转人工、更大优惠力度、专属服务 |
| 沉睡客户 | R 远+F 高 | 唤醒优惠推送、个性化推荐 |
| 新客 | F 低 | 耐心购买引导、详细产品介绍 |

### 6.3 情感分析与 VOC

- 对话中实时 NLP 情感分析，准确率 70%+
- 识别情绪变化趋势：满意→烦躁→愤怒，触发预警
- VOC（Voice of Customer）分析：从咨询中提取产品改进点、服务痛点

## 7. 人机协作

### 7.1 智能转接触发条件

满足任一即转接人工：

- **意图识别**: 复杂投诉、法律纠纷、大额赔偿、媒体曝光威胁
- **情感检测**: 负面情绪强度超过阈值、情绪快速恶化
- **能力边界**: AI 连续 2 轮无法理解用户意图、用户明确要求人工
- **业务规则**: 特定品类/金额/场景的强制人工审核

### 7.2 转接上下文传递

| 信息类型 | 内容 |
|---------|------|
| 对话历史 | 完整的 AI-用户对话记录 |
| 尝试方案 | AI 已尝试的解决方案及结果 |
| 客户画像 | 用户标签、消费历史、VIP 等级 |
| 订单信息 | 相关订单详情、物流状态、售后记录 |
| 情绪状态 | 当前情绪评分、情绪变化趋势 |
| 建议方案 | AI 建议的处理方案（人工可参考） |

### 7.3 AI 作为座席助手（转接后）

转接后 AI 不退出，转为人工客服辅助角色：

- **实时知识推荐**: 推荐产品知识、政策条款、历史案例
- **自动填充**: 自动生成回复草稿、填写表单、创建工单
- **话术建议**: 根据情绪和场景推荐沟通话术
- **合规检查**: 实时检查回复是否违反平台规则

### 7.4 行业数据

- 李宁: AI 解决 75% 基础咨询，转人工率从 40% 降至 20% 以下
- 奥康: 大促期间 AI+人工协同，96%+ 满意度
- AI 辅助下人工客服平均处理时长缩短 30-50%

## 8. 能力优先级与实施建议

| 优先级 | 能力域 | 理由 |
|--------|--------|------|
| **P0** | 订单管理 | 最高频需求，API 标准化程度高，实现 ROI 最大 |
| **P0** | 售后服务 | 痛点最集中，智能挽单直接产生收入 |
| **P1** | 商品推荐 | 直接影响转化率，需要商品数据深度集成 |
| **P1** | 人机协作 | 保证服务质量的底线，复杂场景兜底 |
| **P2** | 优惠活动 | 大促场景价值高，日常使用频率较低 |
| **P2** | 客户画像 | 持续优化其他能力的底层能力，需数据积累 |
| **P3** | 产品使用指导 | 低频但高价值，需要 RAG 知识库建设 |

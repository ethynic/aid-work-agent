# 抖音本地生活订单 → 门店微信群推送系统 私有化部署可行性评估

> 调研日期：2026-09-06
> 调研来源：客户提供的竞品 SaaS 演示视频（22 分钟录屏，"TkTok Sys"）+ 公开资料核实
> 业务背景：竞品为多租户 SaaS；客户不愿数据落在第三方 SaaS 上，拟委托我们开发同类系统并**部署到客户内部**。商家在抖音直播/团购卖服务、线下核销，系统需把订单与客户信息按门店路由推送到对应微信群。
> 文档性质：可行性评估（非设计文档）。接口权限以平台最终审批为准，结论有效期建议 3 个月。

---

## 1. 竞品系统还原（视频分析结论）

### 1.1 核心业务闭环

```
抖音直播间/团购页成交 → 订单（含客户手机号）同步进系统
        → 按 商品SKU/门店 映射路由到订单对应门店
        → 门店微信群机器人自动推送订单+客户信息（含预约提醒）
        → 客户到店 → 门店核销 → 核销数据回传统计
```

### 1.2 视频中观察到的功能模块

| 模块 | 视频证据 | 优先级判断 |
|------|---------|-----------|
| 数据看板 | 今日接单门店/订单数/订单金额/核销金额/核销率、金额构成环形图、今日数据对比、趋势面积图；切换商家账号后指标隔离 | P1（核心卖点） |
| 前台订单管理 | 筛选：订单状态/手机号/核销时间/下单时间/门店/核销账号；列表含订单号、下单/支付/核销时间、商品名、用户昵称、手机号、金额、核销人；行内操作按钮 | P0 |
| 门店管理 | 门店列表、门店与抖音商品/SKU 映射、门店归属账号 | P0 |
| 机器人推送配置 | 弹窗配置：关联项目/关联客户/门店名称/门店业主、触发事件、消息模板（变量占位）、选择目标微信群（多选）、预约提醒（次数/时段）、机器人选择、启停开关 | P0（系统灵魂） |
| 微信群机器人 | 个人微信 PC 客户端（绿色 UI）在门店群内自动发送订单/客户信息、每日订单汇总；可被 @ 触发回复模板 | P0 |
| 客户中心 | 客户档案（手机号去重）、客户产品/次卡（生效日期、剩余次数、有效期、业务编号）、核销记录 | P1 |
| 工作台/抢单大厅 | 抢单大厅、抢核销单、分配品项处理、客服中心、维护客户、加粉丝、客服列表 | P2（运营向，可后置） |
| 账号与权限 | 用户管理（手机号+密码、角色、门店归属、套餐时长）、角色权限配置、多商家多账号数据隔离 | P0 |
| 系统管理 | 核销设置、打印/消息通知等系统参数、操作日志 | P1 |

### 1.3 技术形态推断

- Web 后台（暗色主题 SPA）+ 服务端订单轮询/回调 + 数据库。
- **微信群机器人是"个人微信号 + PC 客户端挂机自动化"**（视频 3:20-4:13、7:15-8:00 处为个人微信 PC 原生界面，非企业微信），即非官方协议/RPA 方案，存在封号风险——这是竞品方案的软肋，也是我们的差异化机会（见 §2.2）。
- 手机号可见说明其拿到了订单联系人手机号（见 §2.1.4 隐私问题）。

## 2. 平台对接评估

### 2.1 抖音侧（数据入口，最大不确定性）

**目标数据**：团购/直播售卖的服务类商品订单、买家（昵称/手机号）、订单状态（待核销/已核销/退款）、门店 POI、商品 SKU、核销码。

**官方链路：抖音生活服务开放能力**（developer.open-douyin.com → 生活服务开放能力），两条接入路径：

| 路径 | 入口 | 适用性 | 门槛 |
|------|------|--------|------|
| **A. 商家自研应用**（推荐，匹配私有化场景） | 客户登录**抖音来客** → 店铺管理 → 服务应用授权 → 商家自研服务 → 入驻开放平台 | 只操作客户自己的店铺数据，与"部署到客户内部"天然吻合 | 客户以自己企业主体认证抖音开放平台；权限按需申请（订单、核销 permission_key=12 等）；审批周期数天~数周 |
| B. 服务商（ISV）身份 | 开放平台填「生活服务技术信息收集」问卷，平台评估开发实力/行业/客户 | 未来做多商家产品化才需要 | 参考：公司注册≥1年、注册资本≥100万、非清退名单；招募有周期性；**认证服务商需缴保证金（抖店体系品牌/产业带服务商为 10 万元级，生活服务技术服务商以平台最新规则为准）** |

**接口能力范围**（需在拿到权限后逐项确认）：门店/商品查询、订单列表与详情（增量拉取）、核销接口（线上核销 + 验券）、退款同步、OAuth 商家授权与 token 刷新。本地生活订单接口支持轮询拉取，**私有化内网部署可不暴露公网回调地址**（轮询模式），这是重要的架构减险点。

**2.1.4 关键待确认项——手机号隐私**：抖店电商订单手机号默认加密（脱敏/虚拟号）。本地生活团购订单的联系人手机号开放程度未完全公开核实；竞品能显示明文手机号，可能来自：①订单详情接口明文字段（部分本地生活类目保留）；②客户到店扫码核销时授权补录；③商家在来客后台人工查看后录入。**必须在 PoC 第一周用客户真实店铺验证**，若拿不到明文手机号，推送模板需改为"虚拟号/尾号+到店补录"，直接影响产品价值，需提前向客户对齐预期。

**不推荐**：爬虫/RPA 抓来客后台（违反平台协议、稳定性差）；飞鸽电商客服接口与本场景无关（前期调研 `douyin-shop-pigeon-agent-customer-service-research.md` 结论不适用此处）。

### 2.2 微信侧（消息出口，第二风险点）

| 方案 | 形态 | 优点 | 缺点 | 建议 |
|------|------|------|------|------|
| A. 个人微信机器人（竞品同款） | 每门店 1 个个人微信号挂机（Windows + PC 微信 RPA/协议），拉进门店顾客群 | 客户群已在个人微信生态、迁移成本为零、体验与竞品一致 | **非官方，封号风险**；需稳定 Windows 挂机节点；团队已有 `docs/research/weixin-cli/`、`wechat-desktop-rpa-technical-research.md` 探针积累可复用 | 作为"对齐竞品"的选项，向客户明示封号风险并由客户决策 |
| B. 企业微信官方 API | 企微自建应用 + 客户联系/客户群 API + 群机器人 webhook | **官方合规、稳定不封号**；API 能力完整（建群、发群消息、会话存档） | 顾客需被拉入企微外部群（与个人微信群形态不同）；门店需开通企业微信 | **主推方案**；客户门店若已用企微则几乎无迁移成本 |
| C. 混合 | 推送走企微；存量个人微信群由机器人只读播报过渡 | 平滑迁移 | 两套链路并存维护 | 二期可选 |

推送引擎与通道解耦（模板变量 → 路由（订单→门店→群）→ 通道适配器），方案 A/B 可切换，降低决策耦合。

### 2.3 可选对接（按需）

短信（预约提醒兜底，需签名/模板报备）；云打印（核销小票，飞鹅/易联云）；高德/腾讯地图 POI（门店定位展示）。均非 P0。

## 3. 功能模块开发清单与工作量

### 3.1 一期 MVP（P0，目标跑通"订单→群推送→核销统计"闭环）

| 模块 | 内容 | 估算（人日） |
|------|------|------------|
| 账号权限 | 登录、RBAC（角色-权限-门店数据域）、操作日志 | 10-15 |
| 抖音订单同步 | OAuth 授权管理、token 刷新、增量拉取、状态机（待核销/已核销/退款）、幂等去重、对账报表 | 15-20 |
| 主数据 | 门店管理、抖音商品 SKU→门店→微信群路由映射、员工管理 | 8-12 |
| 客户中心 | 客户档案（手机号去重合并）、到店补录 | 6-10 |
| 订单中心 | 列表/详情/筛选/导出、核销操作（调抖音核销接口）、退款同步 | 12-15 |
| 推送引擎 | 事件订阅（新订单/核销/预约提醒）、模板变量渲染、路由、发送队列+重试、发送记录、免打扰时段 | 10-15 |
| 群机器人通道 | 企微官方通道（自建应用/群 webhook）；个人微信挂机通道（可选，复用 weixin-cli 资产，Windows 节点） | 10-18 |
| 数据看板 | 核心指标卡、趋势图、门店/商品维度、核销率 | 8-12 |
| 部署交付 | 内网 Docker Compose 一键部署、备份、监控告警、操作手册 | 5-8 |

一期合计约 **84-125 人日**：建议配置 后端 2 人 × 2.5~3 月 + 前端 1 人 × 2 月 + 测试兼职，折 **8~10 人月**；另有日历时间依赖：抖音权限审批 1~4 周（与开发并行）。

### 3.2 二期（P1/P2）

客户资产/次卡（生效日期、剩余次数、有效期预警）、核销率与金额构成深度分析、抢单大厅/客服工作台、预约提醒策略中心、企微会话存档质检、多商家 SaaS 化（如客户未来转售）。约 **3~5 人月**。

## 5. 私有化部署架构建议

- **形态**：客户内网 Docker Compose（web / api / worker / postgres / redis）+ 可选 Windows 挂机节点。纯轮询拉取抖音订单，**无需公网入站**，规避内网暴露面。
- **网络**：仅要求出网访问抖音开放平台与微信服务端点；挂机节点需可达微信客户端服务器。
- **数据安全**（呼应项目安全原则）：手机号等 PII 落库加密（复用项目 Fernet 方案）、界面脱敏展示 + 权限控制明文、操作审计、定期备份。
- **升级**：镜像版本化 + 迁移脚本，约定客户内网升级窗口。

## 6. 风险清单

| 风险 | 等级 | 对策 |
|------|------|------|
| 抖音生活服务接口权限审批不确定（自研应用可申请范围以平台审核为准） | 高 | 第 1 周即以客户主体提单申请；同步准备"来客后台人工导出 Excel 导入"降级链路保证交付 |
| 订单手机号可能为脱敏/虚拟号 | 高 | PoC 第一周真店验证；模板降级为尾号+到店补录 |
| 个人微信机器人封号 | 高（若选方案A） | 主推企微；方案A 仅在客户知情接受后提供，机器人号与主号隔离、低频发送 |
| 内网环境运维边界不清 | 中 | 合同明确：我方交付部署包+手册，客户 IT 负责主机/网络/备份执行 |
| 抖音接口限流/字段变更 | 中 | 增量拉取+退避重试+对账兜底；字段映射配置化 |

## 7. 待确认问题（需客户/平台答复）

1. 客户抖音店铺数量、类目（是否本地生活"服务类"团购）、是否已有来客 POI 认领与企微。
2. 手机号明文是否为硬性需求？接受虚拟号+到店补录的底线在哪？
3. 门店微信群现有规模与成员构成（决定企微迁移成本与方案 A/B 取舍）。
4. 是否需要保留"抢单大厅"等运营工作台，还是一期只要推送+看板。
5. 客户服务器资源与出网白名单申请流程。

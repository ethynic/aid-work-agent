# 微信桌面版搜一搜 RPA 自动化 — POC 计划

> 日期：2026-07-24
> 关联：[微信公众号文章搜索「不依赖微信 App」可行性调研](./wechat-article-search-without-app-feasibility.md)
> 目的：在正式投入「几千个协会」批量自动化前，用半天 POC 验证唯一关键路径——**通用桌面 RPA（影刀）能否自动化微信桌面版搜一搜，并稳定读取结果列表中的手机号**。
> 背景：搜一搜无 App 外通道；模拟器被微信封杀（封号率约 27%）；企业级不能用真机。唯一剩余路径是「桌面官方客户端 + 通用 RPA」。但微信 4.0+ 破坏 UI 树，所有 UIA 工具退化到图像/OCR——所以必须先 POC，不能押宝。

---

## 唯一判据（成功 / 失败）

对 3 个测试协会跑完整流程（搜一搜 → 输入 → 读结果 → 提手机号）：

- ✅ **通过**：≥ 2/3 能从结果里稳定提取出手机号，误抓率可接受（< 20%）→ 路 通，进入正式设计（铺几千家 + agent→影刀 API 集成）。
- ❌ **不通过**：结果面板读不出文本，或命中率 ≤ 1/3、误抓太高 → 路 不通，回退人机协同 / 云手机 / 重新评估是否真需要搜一搜。

**测试协会**（专挑搜狗查不到秘书长手机的，构成最干净的对比）：
1. 中国黄金协会 — 陈玉千
2. 中国饭店协会 — 宋小溪
3. 中国医疗器械行业协会 — 徐珊

---

## 环境准备（30 分钟）

1. Windows 10/11 机器一台。
2. 装**微信桌面版**（当前版即可；若控件抓取全失败，可另装 3.9.x 旧版对比，但 POC 先用当前版）。
3. **专用微信号**登录（不用业务主号；官方客户端不封模拟器，但自动化操作仍有风控可能，专用号稳妥）。
4. 装**影刀 RPA**（yingdao.com 个人免费版够 POC），装「桌面自动化」插件，确认 **OCR / 图像识别可用**（POC 核心依赖）。

---

## POC 步骤（半天）

### Step 1 — 手动摸清 UI 路径（5 分钟）
- 微信桌面版顶部搜索框 → 点开 → 输入「中国黄金协会 陈玉千」→ 回车 → 切「文章」或综合结果。
- 记录：搜索框怎么定位（Ctrl+F 快捷键？点放大镜？）、结果面板结构、手机号通常出现在哪（摘要里）。

### Step 2 — 影刀录制基本流程（30 分钟）
- 新建流程 → 用「录制」功能录一遍：打开微信 → 点搜索框 → 输入 → 回车 → 等结果加载 →（切文章 tab）。
- 关键词设成**变量**（参数化），便于循环跑多个协会。

### Step 3 — 核心验证：读结果（1-2 小时，POC 重点）
按优先级试三种读法，记录哪种可行 + 准确率：
- **A 控件抓取**：影刀「指定元素」抓结果列表项——大概率失败（微信 4.0 UI 树缺失），但要先确认。
- **B OCR 抓取（主力）**：对结果面板截图 → 影刀 OCR 识别文本 → 正则 `1[3-9]\d{9}` 抠手机号。
- **C 图像 + 坐标兜底**：A/B 都不行就坐标框选结果区域 + OCR。

### Step 4 — 跑 3 个测试协会（1 小时）
- 参数化跑 3 个关键词，每个走完整流程，统计：能否提取手机号、命中几条、误抓率。
- 每次搜索间隔 5-10 秒拟人，避免风控。

### Step 5 — 出结论
- 命中 ≥ 2/3 且误抓可接受 → **路通**：进入正式设计（铺几千家 + agent 调影刀 API 集成）。
- 否则 → **路不通**：评估图像/OCR 加固，或回退其他方案。

---

## 注意事项 / 坑

- **微信版本**：4.0+ UI 树缺失是已知问题（[微信 4.1.5 UI 树"消失"](https://zhuanlan.zhihu.com/p/1979934377757655640)）；旧版 3.9.x 控件可抓但搜一搜功能/安全需权衡。POC 先当前版 + OCR，控件全失败再考虑降版。
- **频率**：搜一搜别连发，间隔 5-10 秒，避免风控。
- **OCR 准确率**：手机号数字 OCR 易错（8↔0、漏位）——必须正则校验 + 人工抽检。
- **专用号**：全程专用号，不用业务号。
- **顺带量化增量**：POC 拿到的手机号与搜狗结果对比，量化「搜一搜到底强多少」（顺便回答此前一直缺的样本问题）。

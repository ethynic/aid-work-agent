# 摘要生成模型性价比实测报告

> 实验日期：2026-09-11；GLM-5.3-Flash 与 deepseek-flash（DeepSeek-V4.1-Flash）于 2026-09-14 按同口径补测。用真实知识库文档实测 deepseek-v4-flash 与 qwen3.8-flash 的摘要生成 token 消耗与成本，验证"仅凭单价表无法对比"的前提（不同模型 tokenizer 不同，同一文档的 prompt tokens 差约 9%）。
>
> 复现脚本：[scripts/benchmark_summary_models.py](../../scripts/benchmark_summary_models.py)。补测原始数据：GLM 见 tmp/bench_results_glm.json，deepseek-flash 见 tmp/bench_results_dsv41.json。

## 1. 实验设计

- **文档样本**：生产库 `documents` 表取 5 篇（id 24/25/2224/2238/2271），覆盖 pdf/docx/xlsx 三种类型、1012~5424 字符正文，含政策文件、产品说明、行程、企业名单、操作手册。
- **提示词**：与 `KnowledgeBaseService.generate_summary` 完全一致（正文截断 5000 字符，要求不超过 300 字中文摘要），temperature=0.3。
- **思考开关**：关思考参数与 `chat_lite` 同源（deepseek `thinking.type=disabled`，qwen `enable_thinking=False`）；开思考为模型默认（deepseek `enable_thinking=True`、qwen `enable_thinking=True`）。
- **与生产 lite 通道的差异（有意为之）**：max_tokens 统一 2048（生产为 500，思考开启时会被 reasoning 烧穿导致 content 为空，无法公平对比）；直连 Provider 不走 gateway（不落计费、不触发 failover）。
- **计价公式**：`成本 = (prompt - cached) × input单价 + cached × cached单价 + completion × output单价`（元/百万 token）。

| deepseek-v4-flash | 2.0 | 8.0 | 0.04 | 旧模型名，已被官方退役 |
| deepseek-flash | 2.0 | 8.0 | 0.04 | 即 DeepSeek-V4.1-Flash，与旧 v4-flash 同价；错峰（工作日 UTC 01-04、06-10 时段）半价未计入 |

## 2. 结果汇总（5 篇文档合计）

注：deepseek-flash 两组 10 次调用**全部命中隐式前缀缓存**（提示词与 9-11 相同，缓存跨天有效），上表为含缓存实测；无缓存折算后关思考 4.93 元/千次（与 v4-flash 的 4.92 持平）、开思考 11.69 元/千次（reasoning tokens 4,637 多于 v4-flash 的 3,655）。

要点：

- **关思考时 qwen3.8-flash 比 deepseek-v4-flash 便宜 58%**（单价差 2.5 倍，因 qwen prompt tokens 多约 9%、completion 略多，实际差距略小于单价差）。
- **开思考时 qwen3.8-flash 便宜 65%**：deepseek 思考 token 明显更多（3,655 vs 2,466），且输出单价是 qwen 的约 3 倍。
- **思考开启成本翻倍**：deepseek +84%，qwen +52%，全部来自 reasoning completion tokens。
- **速度上 deepseek 全面占优**：关思考 1.20s vs 2.62s（快 2.2 倍），开思考 3.93s vs 9.31s（快 2.4 倍）。
- **摘要长度相近**：各组合平均 151~186 字符，均在 300 字限制内，finish_reason 全部为 stop。
- **GLM 关思考成本与 qwen 基本持平**（2.08 vs 2.09 元/千次），但关思考下更快（2.16s vs 2.62s）；GLM prompt tokens 更贴近 deepseek（10,878 vs 10,539，仅差 3%）。开思考成本 +107%（4.31 元/千次），且出现摘要超限（doc 24 输出 312 字符，超出 300 字限制），再次印证摘要场景不应开思考。
- **deepseek-flash（V4.1-Flash）与旧 v4-flash 行为几乎一致**：关思考 prompt tokens 完全相同（10,539）、completion 445 vs 443，无缓存折算成本持平（4.93 vs 4.92 元/千次）。
- **deepseek 隐式缓存跨天有效且全量命中**：与 9-11 完全相同的提示词在 3 天后 10 次调用全部命中（9,727/9,728 tokens 按 0.04 元/百万计价），关思考成本降至无缓存的约 23%（1.11 vs 4.93 元/千次）——生产同前缀批量场景（摘要回填、富集）下 deepseek 的缓存优势比单价表体现的更大。

### 3.1 三家缓存机制实测对比（2026-09-14 补充）

| 维度 | deepseek-flash | qwen3.8-flash | GLM-5.3-Flash |
|------|---------------|---------------|---------------|
| 缓存类型 | 隐式（磁盘），自动 | 隐式（自动）+ 显式（cache_control 标记） | 仅显式 Context Cache API |
| 最小命中门槛 | 无（674 token 的 doc 2224 也命中 512） | **1024 token**（不足则永不可能命中） | -- |
| 缓存生效速度 | 即时（下一请求即可命中） | **异步，需数秒~数十秒**（实测 +30s 命中 1,664 tokens，+90s 命中 1,024） | -- |
| 持久性 | 跨天有效（实测 3 天后 100% 命中） | 不确定，定期清理，best-effort | -- |
| 命中折扣 | 0.04 / 2.0 = 2%（无门槛 + 长持久，折扣力度最大） | 0.16 / 0.8 = 20% | cached 单价 0.8 = input 单价，**命中也不打折** |

9-11 实验 qwen 全部 0 命中的原因（已复测澄清）：① doc 2224 仅 726 tokens 低于 1024 门槛，永远不可能命中；② 其余 4 篇关思考→开思考的重复调用仅间隔约 10 秒，缓存尚未构建完成，实测间隔 30 秒后即可命中。生产批量任务（摘要回填等）走 qwen 时，重复同前缀调用间隔拉开数十秒即可享受 20% 缓存价。GLM-5.3-Flash 无缓存折扣，0 命中对成本无影响。

**生产实证（2026-09-14 查生产库 chat_records.cached_input_tokens）**：主链路 wecom_kf（deepseek-v4-flash 多轮 agent 循环）近 3 天 37 次调用、prompt 329 万 tokens、cached 281 万，**命中率 85%**，与实验 92% 吻合——多轮循环 + 共享前缀场景 deepseek 缓存已在生产规模化兑现；qwen lite 类调用（background_llm 0%、knowledge_embedding 7%）基本吃不到缓存，与实验一致。夜间定时批量（02:00 记忆总结、02:30 工作成果复盘）近 3 天仅 9-12 凌晨产生 5 次 qwen 调用（prompt 7,891、cached 0）——此类任务每条 prompt 唯一（按会话/按文档生成），缓存天然难命中，维持 qwen lite 是当前成本最优（qwen 2.09 < deepseek 错峰无缓存 2.47 元/千次）。

注：deepseek 在 doc 2271（开思考）命中了 2,688 个隐式缓存 tokens（同前缀第二次调用），已按 0.04 元/百万计价——生产同前缀高频调用（如批量摘要回填）时 deepseek 的缓存优势会比本表更明显。

## 4. GLM-5.3-Flash 缺口与运维风险（已解除）

- 2026-09-11 实验时，本地 `.env`、生产容器（aid-agent-api）、测试容器（aid-agent-api2）三处的智谱 key 调用 GLM-5.3-Flash 均返回 `429 code=1113 余额不足或无可用资源包,请充值`。
- **2026-09-14 已充值恢复**：三处使用同一把 key（尾号 T1N7nb），本地实测与生产容器内直接调用均成功，生产 failover 链路（deepseek → qwen → zhipu）最后一跳恢复可用。
- GLM 单价与 qwen3.8-flash 接近（input 0.8 vs 0.8，output 2.8 vs 2.7），但 cached_input 单价 0.8 是 qwen（0.16）的 5 倍，且为唯一多模态通道。

## 5. 结论

1. **现网 lite 配置（`LITE_MODEL_CODE=qwen/qwen3.8-flash`，关思考）即成本最优解**：摘要场景每千次 2.09 元，比 deepseek 关思考（4.92 元）省 58%，比开思考的任何组合省 34%~65%。
2. **deepseek 适合对延迟敏感、成本不敏感的主链路**（快 2.2~2.4 倍）；批量后台任务（摘要回填、 富集、分类）继续走 qwen lite 通道。
3. **摘要场景无必要开启思考**：成本 +52%~84%、耗时 +2~3 倍，摘要长度与完成率无可见收益（未做人工质量评估，如需可后续补质量盲评）。
4. **GLM-5.3-Flash 补测结论（2026-09-14）**：关思考成本与 qwen lite 几乎持平（2.08 vs 2.09 元/千次），关思考时延反而更低（2.16s vs 2.62s），可作为 lite 通道的等价备选；但 cached_input 单价是 qwen 的 5 倍，同前缀批量场景（如摘要回填）下 qwen 的缓存成本优势更明显，现网 lite 配置维持不变。
5. **deepseek-flash（DeepSeek-V4.1-Flash）补测结论（2026-09-14）**：与旧 v4-flash 行为和价格一致，摘要场景表现不变。官方已将旧名 `deepseek-v4-flash` 退役（请求由 V4.1-Flash 接管、按 flash 价计费），现网配置无需立即改名，但建议择机将 `DEEPSEEK_MODEL_CODE`（及 `SummaryLLMConfig.model` 等配置文件项）切换为官方名 `deepseek-flash`，避免旧名未来被彻底移除时 failover 最后一跳失效。

## 附：实验局限

- 样本仅 5 篇文档、单次调用无重复，token 数存在随机波动（temperature=0.3）。
- 未评估摘要质量差异，成本结论不构成质量结论。
- prompt tokens 因 tokenizer 不同天然存在约 9% 差异（qwen 偏多），对比以实测成本为准而非单价。

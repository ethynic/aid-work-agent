# 登录辅助与页面实时帧设计（login assist / page stream，2026-08-31）

> 状态：✅ CDP 页面帧实验完成（真机数据见 §3），方案定型待开发
> 背景：扫码登录流程真机验证时发现「智能体截图转发二维码」人肉中转延迟过大（出码→用户看到
> 中间隔了整个对话回合，码已过期）。改为：runtime 推页面实时帧 → 云端登录辅助页 → 用户自己
> 看画面扫码，整个循环自动化、无人工中转。

## 1. 已真机验证的流程环节（2026-08-31 全部通过）

| 环节 | 结论 |
|---|---|
| 进入招聘侧 | 登录页点击「我要招聘」标签（821,492） |
| 切二维码登录 | 点登录卡左上角 `DIV.btn-sign-switch.ewm-switch`（523,370,40x40），CDP 点击有效 |
| 二维码载体 | `IMG`（659,512,200x200），captureFullpage 可完整截取 |
| 过期检测 | QR 区域出现「请重新刷新二维码」+「点击刷新」按钮文本即过期 |
| 过期恢复 | 动态定位「点击刷新」CDP 点击 → 新码（约 1-2 分钟有效期） |
| 登录成功检测 | URL 跳离 `web/user` → `web/chat/recommend`（招聘者主页） |
| 登录后弹窗 | 复用 overlay heal（inspect → dismiss），已真机验证 |

## 2. 产品流程（无人工中转）

```
用户：「登录 BOSS」
→ agent 触发登录辅助 → runtime 检测登录态：未登录则进扫码页（我要招聘 → ewm-switch）
→ runtime 启动页面帧推送（CDP jpeg，1fps，变化检测）
→ 云端登录辅助页（Web，租户/用户隔离 + 链接有效期）实时呈现页面帧
→ 用户经 Web 链接（企微消息可带链接）在手机/PC 打开画面，用 BOSS APP 扫画面中的码
→ runtime 监听：过期自动点刷新（画面自动更新，用户无需操作）/ 扫码成功跳转
→ 登录成功：自动关登录后弹窗（overlay heal）→ 回调云端 → agent 汇报「登录完成」
```

## 3. CDP 页面帧实验数据（真机，2026-08-31，Chrome 151）

| 指标 | 裁剪模式（登录框区域 420x460） | 整页模式（1278x1304） |
|---|---|---|
| 单帧耗时 | 36-50ms | 42-43ms |
| 单帧体积（JPEG q70） | **14KB** | 48KB |
| 变化检测（md5 比对） | 静止页 20 帧仅推 1 帧 | 同左 |
| 1fps 带宽 | 峰值 ~0.11Mbps，静止页≈0 | 峰值 ~0.38Mbps |

实验实现：raw CDP WebSocket（Node 22 全局 WebSocket，零新增依赖）+ `Page.captureScreenshot
{format:'jpeg', quality, clip}` + md5 变化检测 + 本地 MJPEG 服务（multipart/x-mixed-replace，
浏览器 `<img src>` 直接播放，零前端依赖）。探针：`.tmp/probe-frame-stream.mjs`。

**结论**：1-2fps 设计余量巨大（单帧 40ms 可支撑 10fps+）；裁剪模式（登录框区域）单帧 14KB
几乎零成本；CDP 页面帧优于桌面帧流——画面只含 BOSS 页面（隐私面小）、无锁屏/遮挡限制、
无 GPU/WGC 依赖。桌面级帧流（WGC/GDI）保留给真正需要看桌面全局的人工接管场景（原 R1）。

## 5. 边界与风险

- CDP 页面帧只覆盖网页内容；BOSS 若弹原生系统对话框（罕见）不在画面内——届时再评估桌面流
- 登录辅助页链接必须短期有效 + 租户隔离（页面暴露 BOSS 登录二维码，等同临时登录凭证）
- 二维码有效期约 1-2 分钟，刷新循环必须自动化（真机已验证刷新点击）

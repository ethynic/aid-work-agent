## 2. 错误 1：DeepSeek 400（占比 99.9%）

### 现象

`log_error` 从 16:12 起每分钟固定 1 组 4 条（deepseek provider → failover → gateway → health assessment），16:48 前后另混入 1 条空态摘要失败。报错原文：

```
[Failover] Provider [deepseek] 不可重试错误: DeepSeek API请求失败:
{"error":{"message":"The supported API model names are deepseek-flash, deepseek-v4-pro,
but you passed qwen-flash. ...","type":"invalid_request_error"}}
```

请求实际打到 `api.deepseek.com`（DeepSeek 官方 API），但携带的模型名是 `qwen-flash`。

### 根因（用户已确认并修复）

`.env` 配置错误：`LLM_PROVIDER` 当时配了含 deepseek 的 provider 链，而 `LITE_MODEL_CODE=qwen-flash`（纯模型名走当前主 provider，见 `configs/config.yaml` llm.lite_model 注释）→ qwen 系模型名被发往 DeepSeek API，必 400。

健康研判（`system_health.assessment`，每 60s 一次 `chat_lite`）是唯一分钟级常驻 lite 调用方，因此按分钟稳定刷屏；16:48:53 平台管理员登录后打开数字员工空态（sales-assistant）触发了同一 lite 链路的空态摘要，同因失败。

修复后 `.env`（17:04 mtime）：`LLM_PROVIDER=qwen`（单 provider，无 failover）+ `QWEN_MODEL_CODE=deepseek-v4.1-flash` / `LITE_MODEL_CODE=deepseek-v4.1-flash`（百炼兼容端点，该模型名在百炼平台就叫这个名字，见 master 提交 e7600110）。

## 3. 错误 3：RunnerError EXECUTION_FAILED（17:30:30）

### 现象

- 17:30:22 企微客服回调，客户「孙晨」发文本「在吗」（租户 tenant_569f4e5acf4d，客服账号 wkCeSLDgAAiSDq7_J1EIdTtofwkg2R6g，数字员工 sales-assistant）。
- Runner 执行 4 秒后失败：`runner_agent.process_message_sync` 抛 `RunnerError: EXECUTION_FAILED`（channel_routes.py:3173 -> channels/session.py:1123 -> core/session_queue.py:698）。
- 渠道侧发送了 22 字符兜底回复（"回复发送成功"）。
- 追踪库：trace `tr_runner_c78aee34862c46ad976f53be141788be` status=failed / error_message=EXECUTION_INTERRUPTED；唯一 span 为 llm_call（iteration 1），output=`{"error_code": "RuntimeError", "success": false}`。

### 根因判断

**17:30 与 20:38 两次失败同根因，且实证：`sales-assistant` 子智能体定义配置了 `llm_provider=deepseek`（JSONB：`{"provider": "deepseek", "model_codes": {"deepseek": "deepseek-v4-flash"}}`）。**

Runner 装配按子智能体定义覆盖网关（`src/services/agent_runner/runtime/profile.py:56` -> `LLMGateway(provider_name='deepseek')`），而聊易 .env 未配 `DEEPSEEK_API_KEYS`（客户只用 qwen/百炼）-> worker 抛 `RuntimeError: LLM网关未配置 provider=deepseek 的 Key，无法调用 chat`（worker-2 日志实证）-> EXECUTION_FAILED，渠道侧发兜底回复。

trace error_message=EXECUTION_INTERRUPTED 与实际 EXECUTION_FAILED 口径不一致，为次要疑点（span 层已记 RuntimeError）。

来源：管理后台创建定义时人工选择 deepseek（前端 `TenantAgentCustomizeDialog.vue` LLM_PROVIDERS 首项即 deepseek，且保存时无「该 provider 是否有 Key」校验）。租户级覆盖表 `tenant_agent_instances` 无同类配置（已核对为空）。

### 处置（2026-11-17 20:44）

```sql
UPDATE subagent_definitions SET llm_provider = NULL, updated_at = NOW()
WHERE agent_id = 'sales-assistant';
```

置 NULL 回落平台默认网关（qwen/百炼）；updated_at 同步刷新以触发 runner 资源缓存签名重建（resource_cache 按 def_updated 签名轮询）。

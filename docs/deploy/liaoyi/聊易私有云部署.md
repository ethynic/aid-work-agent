## 11. Runner 容量与资源复检（2026-11-16 完成）

worker 扩容 4 slot（`AGENT_RUNNER_WORKER_SLOTS=4` × 1.5g，SLOT_CONCURRENCY=5）后全量复检 PG 连接与 cgroup，修复三处：

| 项 | 变更 | 原因 |
|------|------|------|
| PG max_connections | 40 -> 100（postgres compose command，重建 aid-postgres 生效） | 8 容器连接池理论上限 ~91 > 40，空闲已 37/40；ThreadedConnectionPool 无收缩逻辑，负载脉冲必然打穿 |
| 连接池压配 | .env 追加 `DB_POOL_MIN=1` / `DB_POOL_MAX=10` / `LOGS_DB_POOL_MAX=2` | api/background/runner-api 各 max 15 -> 10；worker 池不受此 env 影响（`worker.py` 按 `slot_concurrency + 2` 刻意定容 min=2/max=7，4×7=28 在 100 内） |
| Redis | command 加 `--maxmemory 300mb --maxmemory-policy allkeys-lru` | 原无 maxmemory，写满触发 cgroup OOM kill；缓存有 DB 兜底可逐出 |
| worker TMPDIR tmpfs | 2g -> 1g（agent-runner compose） | 4 worker tmpfs 全打满理论 ~6g 真实 RAM，7.3G 裸机兜不起；tmpfs 页受 worker 1.5g cgroup 封顶但属系统级压力 |

复检结果：10 容器全 healthy；max_connections=100、redis maxmemory 300mb/allkeys-lru、worker tmpfs 1.0G、各容器池 min=1/max=10（worker min=2/max=7）均已生效。**追改（同日）**：worker 内存 1.5g -> 2g、`HEAVY_TOOLS_MODE` local -> remote（对齐 agent2 验收口径，重工具远程派发到 aid-heavy-tools:8093；健康端点 `/internal/heavy-tools/health` 实测 worker 内可达，容器内 localhost 亦通）。内存上限合计 ~16.7G > 物理 7.3G+swap 4G，超额较此前扩大，4 worker 并发重负载会进 swap（swappiness=10 兜底），重负载水位需持续观察。

备份：服务器侧 `.env.bak_20261116`、三个 compose 的 `*.bak_20261116`。仓库 `deploy/liaoyi/` 已回写服务器实际 compose（含历史漂移：heavy-tools 服务定义、runner-api 1g）。服务器版 compose 含 `aid-heavy-tools` 服务（HEAVY_TOOLS_MODE=local 下闲置运行，仅占上限不占实际内存，可按需 `docker stop`）。

### 2026-11-18 补录 deepseek-v4.1-flash 价目行（LLM 计费曾为 0）

- **现象**：trace `tr_runner_2f6d4b579c2f4811813b287e053fbb2d`（15:00，sales-assistant，307,142 tokens）在 `chat_records.id=48` 只计 0.01 积分；`usage_breakdown` 中 llm 组 `deepseek-v4.1-flash` 为 `credit 0.0, detail {}`，0.01 全部来自 embedding。
- **根因**：`token_cost_prices` 无 `deepseek-v4.1-flash` 行 → runner 主流路径 `freeze_price()` 仅对 `skill-call:` 边界启用兜底模型，普通边界得到空 `price={}` → `calculate_llm_credit_cost_with_breakdown(price_snapshot={})` 直接返回 `(0.0, {})`，**不触发兜底模型**（兜底只在 `calculate_credit_cost_with_breakdown` 与 skill-call 边界生效）。即 11-17 裁决时「兜底按 deepseek-flash 3/9 计」的前提实际不成立。
- **处置**：生产库补录价目行（从 `deepseek-flash` 复制，口径 3 / 0.1 / 9 元每百万）：

  ```sql
  INSERT INTO token_cost_prices (model_name, input_price_per_m, cached_input_price_per_m, output_price_per_m, is_multimodal)
  SELECT 'deepseek-v4.1-flash', input_price_per_m, cached_input_price_per_m, output_price_per_m, is_multimodal
  FROM token_cost_prices WHERE model_name='deepseek-flash'
  ON CONFLICT (model_name) DO NOTHING;
  ```

- **验证**：worker 容器内复算该 trace 用量 → `credit_cost=0.41`，`price_model=deepseek-v4.1-flash`（走本行，非兜底），`usage_factor=1`。价目查询无缓存，新会话立即生效；冻结中的旧会话 `price_snapshot` 已为空，不回填。
- **历史数据未回填**：14:02 ~ 15:00 的 5 条 `chat_records` 仍为 0.01，如需对账可单独重算。
- **未修代码缺口**：`calculate_llm_credit_cost_with_breakdown` 空 `price_snapshot` 无兜底，与 `calculate_credit_cost_with_breakdown` 口径不一致（全环境通用缺陷，其他环境主模型均有价目行未暴露）。

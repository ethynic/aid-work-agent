## 1. 背景与目标

聊易客户私有云已购创蓝253（253.com）短信服务，用于验证码短信（登录验证码 / 忘记密码 / 短信验证码技能）。需在现有 `src/sms/` 多通道架构下新增一个通道实现类，通过 `SMS_CHANNEL` 配置切换。

客户侧连通性已验证：服务器（47.104.107.85）直连 `https://smssh.253.com` 可达（2026-11-16 实测 0.12s）。

## 3. API 规格（从 SmsExample.java 提炼）

- 端点：`POST https://smssh.253.com/sms/v2/batch-send`
- 认证在 HTTP Header（非 body）：

| Header | 值 |
|--------|------|
| `Content-Type` | `application/json` |
| `AppID` | 客户 APP_ID |
| `Nonce` | 随机串（UUID 去连字符） |
| `CurTime` | Unix 秒级时间戳（字符串） |
| `CheckSum` | `SHA1(APP_SECRET + Nonce + CurTime)` 十六进制小写 |

- Body（JSON）：

```json
{
  "productType": "verify",
  "phoneNumbers": "13800138000",
  "templateCode": "1022923760",
  "templateParam": "[{\"param1\":\"123456\"}]"
}
```

注意：`templateParam` 是**字符串化的 JSON 数组**（不是嵌套 JSON），多参数手机号可用逗号分隔批量（示例 `batch-send` 命名即批量；首期按单号码实现即可）。

- 响应：HTTP 200 + JSON body（`code`/`msg` 字段；成功判定以响应 JSON 为准，联调时以真实响应为准，**不要凭训练知识猜字段**——响应字段需真实调一次确认后再固化成功判定）。

## 4. 现有架构（必须复用，勿自建第二套发送出口）

```
src/sms/
├── base.py      # SmsSender 抽象基类：channel_name / send(mobile, template_id, template_params) / is_available()
├── manager.py   # SmsManager：注册表 + get_sender(SMS_CHANNEL 配置选择通道)；123-125 行集中注册
│                #   sms_manager.register(ZhuTongSmsSender())
│                #   sms_manager.register(AliyunSmsSender())
│                #   sms_manager.register(TencentSmsSender())
├── aliyun.py / tencent.py / zhutong.py   # 三个现有通道实现（参考 zhutong.py 的结构最接近）
└── __init__.py
```

- **调用方**统一走 `sms_manager.send(mobile, template_params={...})`（`src/sms/manager.py:90`），通道类只负责发信，**不自行计费**（计费在调用方，见 §6）。
- 配置：`src/config/settings.py` `SmsConfig`（~499 行起）+ `os.getenv` 注入段（~1231 行起）。现有键：`SMS_CHANNEL` / `SMS_USERNAME` / `SMS_PASSWORD` / `SMS_SIGNATURE` / `SMS_TEMPLATE_YZM` / 各通道专有键（`aliyun_template_yzm`、`tencent_*`）。
- bypass 机制：`settings.sms.qb_sms_code`（env `QBSMSCODE`，settings.py:1240）——无可用通道时跳过真实发信直接返回成功 + 校验侧放行。**聊易私有云当前临时启用了随机 QBSMSCODE，本通道上线并验收后必须从 .env 移除**。
- 通道 `send()` 返回 `{"code": 200, ...}` 表示成功（调用方按此判定，见 base.py 注释）；不可用配置返回非 200 + msg。

## 6. 计费与审计（必读，按 `.claude/rules/billing_audit.md`）

- 通道类**不自计费**——计费在调用方。新增/改动短信调用点时按 §3.8 扫描全部 `sms_manager.send` 调用方核对；
- 技能入口（`sms_cli.py`）已是标准模式（AID_* fail-closed 身份 + 余额预检 + `_record_sms_billing` 落账，source_type=sms_verification），无需改动；
- 平台认证验证码（`send_sms_code`）是用户裁决豁免点（见 billing_audit §5.2），禁止其他发送点复用该函数；
- bypass / 私有云分流必须在调用方显式注释，防止把「跳过发信」误当「已计费」；
- PR 描述附「已按 billing_audit.md §3 核对」自检结论。
- 聊易私有云 `USAGE_FACTOR=1`（客户自购短信，费用自担），短信按条固定成本计费口径不变。

**API 事实核对（官方文档 + 实测）**：

- 官方文档 [短信发送](https://doc.chuanglan.com/docs/4KGLSB1T76BPH1NW)（更新 2026-10-24）与 [API 调用说明](https://doc.chuanglan.com/docs/I58861JUE7A3QRU4)：`CheckSum = SHA1(AppSecret + Nonce + CurTime)` 十六进制小写；`Nonce` 为 32 位随机串。
- 成功响应：`{"msg":"success","code":"000000","data":{"failNum":"0","successNum":"1","msgId":"..."},"requestId":"..."}` —— **成功码 `000000`**（归一化为 `code=200`，`biz_id=msgId`）。
- 业务失败同样 HTTP 200，靠 body `code` 判定（实测缺省 AppID 返回 `120301`，与文档一致）。
- 实测另发现 **IP 白名单**（`190403`），已登记为部署前置（§7 第 0 步）。
- 模板变量按传参顺序映射 `param1..paramN`，同一号码一个对象；无变量模板不传 `templateParam`。

**计费核对（billing_audit.md §3.8）**：通道类不自计费；`sms_manager.send` 调用方共两处——`send_sms_code`（平台认证验证码，§5.2 用户裁决豁免，未改动）与 `sms-verification` 技能 `sms_cli.py`（AID_* fail-closed + 余额预检 + `_record_sms_billing` 落账，未改动）。私有云 `USAGE_FACTOR=1` 不改变按条计费口径。

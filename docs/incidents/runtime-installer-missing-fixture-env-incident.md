# Runtime安装向导点击安装后直接退出

日期：2026-10-14。修复与交付记录见[干净安装计划Phase6](../plans/plan-runtime-clean-install.md)。

## 已确认事实

用户反馈安装进度没有结束，窗口直接关闭。主控在本地运行原始r12/UI0.0.8安装器，使用正常Windows用户环境、没有fixture环境变量、没有静默参数；自动点击真实安装按钮，约8秒后进程退出2，无完成页面，也未登记安装。安装器SHA256为`d2b50a6ac05e86127d9acd48980eb9bbc8de66d5ffbd24c90d8690ad2403cd97`。客户电脑没有独立退出码证据，因此本地同形故障可解释客户现象，不将它冒称已直接读取客户机事实。

## 根因

`runtimeReadFixture`用`ReadEnvStr`读取可选`AIDWORK_RUNTIME_INSTALL_FIXTURE`。正常机器不存在该变量时，NSIS设置Errors标志；代码没有清掉预期的缺失状态。即使进程检测和停止脚本成功，`runtimeCheckBeforeInstall`仍把该标志当成guard/UAC调用失败，将R9覆盖为2后直接Quit，没有显示失败原因。

最小原生NSIS验证证明：相同读取语句，无变量时退出2，有变量时退出0。先前真实安装器的十次连续安装和r12定向安装都使用严格nonce fixture；环境中变量始终存在，所以没有覆盖正常客户环境。实际确认/取消则使用编译后的最小hook，不能替代完整非fixture向导。此前已披露交互向导缺口，但将客户可用性建立在fixture条件上仍不足。

## 修复与验证要求

只在读取可选变量后立即ClearErrors，保留随后真实脚本/UAC错误及非零结果检查；非法fixture仍通过R0/R9明确拒绝。服务端API、Runtime运行逻辑、旧进程作用域不变。独立CR已通过；r13/UI0.0.9已实际完成正常环境非静默完整向导、出现完成页面并退出0，正常登记版本0.0.9。独立回归包括没有测试变量的macro旧/新错误标志、完整guard及真实PS失败仍拒绝；旧最小完整guard的stub对照未复现整包退出，不能将其冒称客户全链路，仅以真实r12/r13整包对照为完整复现与修复证据。

## 排障与剩余范围

r12没有持久化安装阶段日志；Windows崩溃日志无法解释主动Quit，本次靠实际向导和进程退出码定位。补全安装诊断日志属于后续明确范围，不能将本次单点修复描述为已有持久日志。现场UAC、客户电脑及业务验证保持独立边界。本轮不提交、不部署服务端。

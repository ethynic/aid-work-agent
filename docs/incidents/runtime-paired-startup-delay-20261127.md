# Windows Runtime 已配对设备重开缓慢

2026-11-27，北京时间。Runtime 1.4.0 验收版沿用已有 agent2 配对。本次用户打开客户端后，连接卡片长期显示「正在读取本机连接信息」，插件区域显示尚未提供管理能力。稍后查看同一实例的界面，已连接企业服务并列出了插件。

## 阻塞点

`RuntimeHost.open()` 在返回管理握手之前等待 `LegacyExecution.initialize()`。插件仓库初始化串行检查已安装插件，对归档重新验签和解包，逐文件比对已安装内容，再执行 `version` 和 `doctor`。同一开机过程在 `LegacyExecution.start()` 中又全量刷新一轮，然后才进入心跳和接单。前端在拿到管理握手前同时缺少设备状态与插件能力，因此显示截图中的两个占位提示。

这次最慢段位于第一次本地插件检查。实际安装目录用同一版本运行只读逐插件复测，合计约 6 秒，其中归档验签与文件比对约 2.9 秒，插件诊断约 3.1 秒。BOSS 招聘约 0.9 秒、浏览器约 1.2 秒、企业微信约 1.5 秒、微信约 2.4 秒。现场两次微信窗口诊断各不足 1 秒，旧执行核对在其后完成。当前日志无法把第一次检查的约 90 秒分到某个插件、磁盘访问或进程启动，也没有足够证据认定安全软件扫描造成延迟。

## 真机逐阶段复测

正常排空并退出验收客户端后，使用安装目录中的同一 Node Host 和已配对身份。通过本地 IPC 逐阶段采样，再用 Host 报告的 `online` 确认 agent2 实际连接。临时计时从 Node Host 启动计时，未改写安装目录文件。首次体验样本 15.656 秒在线，第一轮 7.079 秒，第二轮 6.587 秒。

再次启动复现慢样本，共 77.149 秒在线。第一轮插件检查 62.930 秒，第二轮 9.352 秒。最慢的是扫描并逐文件比对 BOSS 招聘与浏览器的已安装文件，两项累计 52.078 秒。第一轮分项如下。

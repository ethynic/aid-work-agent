# 企微客服 95003 新客户回复全失败（未验证企业累计接待 100 客户上限）事故复盘

> 2026-11-05 排查定案。现象：2026-11-05 15:27-15:58，租户 `tenant_29304e2196e8`（宏陶）客服账号上多个客户的 AI 回复发送失败，主日志报 `errcode=95003, errmsg=send msg quota limit` 共 13 次。

## 1. 结论速览

| 项 | 结论 |
|----|------|
| 根因 | **宏陶企业微信未完成企业验证**（未缴 300 元认证费，租户 11-05 口头确认）。未验证企业微信客服**累计只能接待 100 个客户咨询**，接待满 100 个后，所有**新客户**咨询无法回复（95003），**已接待老客户**继续会话不受影响 |
| 撞线时刻 | 2026-11-05 15:26:30 接待第 100 个客户；15:27:08 起第 101-110 号新客户全部失败 |
| 官方口径 | 错误码查询工具 https://developer.work.weixin.qq.com/devtool/query?e=95003 ：「发送客服消息可接待客户咨询数限制」，排查方法：**企业未验证** |
| 影响面 | 11-05 15:26 之后进来的约 10 个新客户**未收到任何 AI 回复**（含 Dawn.k、苏卫涛15369230666），需宏陶人工跟进 |
| 系统侧责任 | 无缺陷。`WeComKfReplyBudget(total=5)`（`src/channels/wecom_kf/budget.py`）按「单次咨询 5 条」的平台限制设计，行为正常；发送链路对老客户始终正常 |

## 3. 排查过程与证据链

**第一步：排除企业级配额**。同一客服账号 `wkMsuPRQAAWNdUgexIMQleVx70sfA-0g` 上，失败（15:27-15:58）与成功（15:52、16:05）交错出现 -> 配额不是按企业/账号计。

**第二步：排除 48h 客户级频控**。受影响客户 Dawn.k、苏卫涛都是当天 `auto_register` 新建的首次接触客户，**第一条回复**就 95003（我方系统从未向其发送过任何消息）；且 Dawn.k 15:27、15:37 两次发新消息后再试仍失败 -> 客户重发不重置配额。10-27/28 另一企业也偶发过 1-2 次 95003，同为孤例。

**第三步：官方口径**。用户在错误码查询工具查询 95003 -> 「发送客服消息可接待客户咨询数限制；排查方法：企业未验证」。

**第四步：数据实锤**。按客户首次咨询时间排序（`channel_messages` 按 `split_part(session_id,'_',6)` 去重），累计独立客户 110 个：

| 累计排名 | 首次咨询时间 | 客户 | 结果 |
|---------|------------|------|------|
| 第 99 个 | 11-05 15:23:50 | wmMsuPRQAAa93... | 正常 |
| **第 100 个** | **11-05 15:26:30** | wmMsuPRQAAXz8... | **正常（配额内最后一个）** |
| 第 101 个 | 11-05 15:27:08 | Dawn.k | 95003 |
| 第 102 个 | 11-05 15:27:13 | 苏卫涛 | 95003 |
| 第 103-110 个 | 11-05 15:27:19-15:58:09 | 8 个新客户 | 全部 95003 |

13 次报错与第 101-110 号新客户的进入时间一一对应。辅助证据：该租户 10 月单月新增 76 个客户均正常 -> 非月度配额；9/15 启用以来累计正好在 11-05 撞线 100 -> 累计口径。

## 4. 机制说明

微信客服对**未验证企业**限制「可接待客户咨询数」（本例实测 100 个，累计口径、非月度、非 48h 滚动）：

- 计数对象：通过该企业客服发起咨询的**独立客户**；
- 撞线表现：新客户的咨询无法被接待，API 回复报 95003；已接待客户的后续会话不受影响；
- 客户重发消息**不重置**配额；
- 根解：完成**企业验证**（企微管理后台自助提交主体资料，300 元/次认证费）后配额大幅提升。

## 6. 排查方法备忘

- 判定是否单客户问题：同一 `open_kfid` 上失败与成功是否交错（交错 -> 客户级，整段失败 -> 企业级）
- 累计接待客户数统计（生产库）：

  ```sql
  SELECT count(*) FROM (
    SELECT split_part(session_id, '_', 6) uid
    FROM channel_messages
    WHERE tenant_id = '{tid}' AND session_id LIKE '%wecom_kf%' AND role = 'user'
    GROUP BY 1
  ) t;
  ```

  注意 session_id 格式为 `tenant_{tid}_wecom_kf_{open_kfid}_{external_userid}_{subagent}`，第 6 段才是 external_userid
- 客户首触时间排名：对上式的 `min(created_at)` 做 `row_number() OVER (ORDER BY mc)`，与 95003 首次报错时间对齐即可确认门槛值
- 微信错误码详情可凭 errmsg 里的提示到 https://developer.work.weixin.qq.com/devtool/query 查询（API错误码/hint 均可查）

## 7. 遗留问题

- **发送失败仍落 assistant 历史**：95003 失败时 `channel_messages` 仍写入 assistant 消息记录，客户实际没收到，但下轮上下文里 AI「以为自己已回复过」——上下文与真实投递脱节，是否修复待用户裁决

# 发版强杀残留 Redis 锁致后台调度器全部永久罢工（宏陶商城同步停摆 44h）事故复盘

> 2026-10-26 排查定案。现象：宏陶瓷砖（`tenant_29304e2196e8`）商城产品同步配置为每天定时一次，页面上「最近同步」停留在 2026/10/21 16:17:11，之后再未同步；客户 10/23（周三）发过正式版后怀疑发版导致。

## 1. 结论速览

| 项 | 结论 |
|----|------|
| 用户感知 | 商城产品每日定时同步自 10/21 16:17 后停摆；新代码的「删除无用字段」逻辑因同步从未执行而未生效 |
| 根因 | **10/21 20:54 发版窗口内旧 background 容器被 docker 强杀（7s 宽限期内优雅停机未走完），4 个调度器的 Redis 单副本锁未释放**；20:55 新容器启动时锁仍在 TTL 内，调度器启动入口**一次性抢锁失败即永久放弃**（无重试），此后 44+ 小时全部调度器死亡且不自愈 |
| 影响面 | 不止宏陶同步：`hongtao_shop`、`wechat_mp`、`tencent_docs` 导入、主定时任务管理器（ScheduledTaskManager）4 个调度器同时罢工；billing 调度器无 Redis 锁不受影响 |
| 数据影响 | 无数据损坏；宏陶同步为幂等全量对账，恢复后自动补齐（删字段逻辑随首次同步生效） |

## 3. 证据链

1. **数据库** `bs_content_sync_runs`（module='hongtao_shop'）：10/13~10/21 每天 16:16±1min success（run #6~#14），与页面「最近同步 2026/10/21 16:17:11」吻合；10/21 20:55 之后**连 queued 记录都没有**——30min 到期源 tick 根本没跑。源配置正常（`enabled=t, sync_interval_hours=24`）。
2. **应用日志** `/var/www/agent/log/agent/aid-work-agent_20261021.log`：20:53~20:55 两次重启完整过程；20:55:17 四条「已在其他副本运行」即死亡时刻，此后 44h 无任何 hongtao 调度器日志。
3. **Redis 现状**：`--scan --pattern '*hongtao*'` 为空——幽灵锁早已过期，证明「锁不存在但调度器仍不动」＝启动入口一次性放弃、无重试路径。
4. **代码**：`src/tenant_custom/hongtao_shop/scheduler.py` `start()` 抢锁失败 `return False`；驱动循环内 `_ensure_driver_lock()` 本身有 30s 失锁重试——**死在启动门槛，不在循环**。`src/wechat_mp/scheduler.py`、`src/services/tencent_docs/import_scheduler.py`、`src/scheduler/manager.py` 同构。

## 4. 根因链条

1. **触发条件**：发版窗口内容器 76 秒内两次重启，第二次被 docker 强杀（gunicorn 优雅停机串行停 5 个调度器，10s 宽限期走不完）→ 锁泄漏。强杀在任何部署中都可能发生，不是异常操作。
2. **放大点（核心缺陷）**：调度器 `start()` 把「抢锁失败」当作「已有健康副本在跑」处理，一次性放弃且永不重试。锁 TTL 仅 300s，而判据无法区分「健康副本持锁」与「强杀残留幽灵锁」。
3. **无告警**：调度器静默死亡只留一条 INFO 日志，无任何失败级日志或监控项，44 小时无人感知（客户从页面「最近同步」发现）。

## 5. 修复方案（2026-10-26）

| 项 | 内容 |
|----|------|
| 三个 asyncio 调度器（hongtao_shop / wechat_mp / tencent_docs） | `start()` 抢锁失败不再放弃——仍启动驱动任务，复用循环内已有的 `_ensure_driver_lock()` 30s 重试路径，幽灵锁 TTL 过期后自动接管（单副本语义不变：无锁者只空轮询不干活） |
| 主定时任务管理器（manager.py） | 抢锁失败后台起 30s 间隔重试线程，拿到锁后再执行既有启动路径（调用方仅 background_runner 一处，锁过期后无竞争者，无需续期） |
| 效果预期 | 任意发版强杀后，调度器最迟 ~5 分钟（锁 TTL）内自愈接管，当日定时任务自动补跑（tick 按新鲜度判定到期） |

## 6. 排查方法备忘

- 生产 243：`ssh -p 10167 ubuntu@129.211.65.243`；background 容器 `aid-agent-background`，调度器日志 grep `hongtao_shop 调度器`（loguru `bind(module="hongtao_shop")`）。

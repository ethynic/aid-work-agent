## Phase 1 插件业务设计与跨端接口登记

- BOSS 确定对外业务命令、内部 CLI 组合、进度和结果格式、继续筛选及识别、评分、入库和计费接口。核实本地与云端批次上限及续筛回执限制。[BOSS CLI 设计](../design/recruiting/boss-cli-1.0.0-design.md)
- 企微确定对外业务命令、本地库读和桌面操作的边界、配置专用入口、可并行声明及云端服务授权。[WeCom CLI 设计](../design/wecom/wecom-cli-1.0.0-design.md)
- 开发前登记协议版本、字段、唯一写入者、生产端与消费端样例、切换与回退组合。共同检查点覆盖受信声明、任务授权、接单去重、进度、结果、诊断、取消和续接。

## Phase 2 服务端与 Runtime 通用作业链路

- 服务端统一受理 Agent 和后台直调作业，固定 `invocation_id`、设备、插件版本和授权。Agent 来源关联原 `tool_call_id`。按结果编号去重并确认，接回进度与终态供 Runner 查询和展示。
- Runtime 按已验签插件自身的声明安装、发现、发布、调度和调用。移除按插件名、标识或工具清单识别业务的路径。Agent 与后台跨插件共用串行队列，明确标记可并行的作业直接执行。可选 `session_id`、`runner_id` 有则原样回传，缺省时照常运行。
- Runtime 实现受管执行、进度转发、原回执持久保存与补传、问题编号及脱敏诊断、指定作业取消和续接转交。验证断网、回包丢失、迟到回执、原授权和同编号参数冲突。

## Phase 3 BOSS CLI 与 WeCom CLI 迁移

- 两个插件直接实现新版声明及作业接口。插件持久接单，处理重复派发，执行完整业务并报告过程结果和最终汇总。插件处理单项失败、业务超时、部分完成和用户触发续接。
- 分别验证实际业务入口与云端消费链路。覆盖批次中途失败、已尝试动作结果未知、插件异常退出、继续筛选和受支持续接。桌面或应用不可用由插件报告，符合条件的后台作业继续执行。

## Phase 4 设备连接、进程监督与状态依赖整改

- Main、Host 和安装器沿自身目录租约、安装记录及已登记的受管进程识别实例、交接升级和检查停稳。已知旧实例经管理入口或已绑定进程证据停止，缺失证据时保留相应未确认事实。原设备连接独立恢复，实际冲突只限制相关执行资格。
- 配对和服务端准入沿可信设备身份、原作业与实际执行状态，移除机器指纹依赖。保留有效设备凭据、原作业和待补传回执。失败配对退出活动入口，普通恢复沿原身份。
- 先接通并验证替代路径，再移除启动项 GUID、会话编号、重启见证、全机进程扫描、通用锁屏、按浏览器或工具放行及旧桌面锁等依赖。已支持的同机入口确实共用物理输入时，确认由同一队列或明确的输入互斥承接。插件接管实际窗口、账号、浏览器、登录或本地库等业务检查。
- 用隔离夹具让启动项与会话查询、指纹、全机枚举和电源日志不可用，验证首次安装、重启、升级、连接修复与原身份上线。核对已登记受管进程与无关 Node 或浏览器进程的隔离，同目录双启动、设备替换和真正共用输入时的互斥。通过替代路径验证后退役对应旧判断。[依赖审查](../research/runtime-platform-dependency-review-20261111.md)

## Phase 5 集成验证、实包验收与统一发行

- 用已有测试发行授权的新插件走签名导入、工具发现、派发和回执全链路。用受控命令验证多用户、跨插件、Agent 与后台串行排队，以及显式并行作业直接执行。单个 Agent 会话按结果逐次调用。运行中取消仅影响目标，实际停稳后释放串行资格。仍在运行的长作业正常完成。
- 验证插件进度与心跳独立，回执丢失按原编号补传，服务端只归档一次。重启后未领取的有效作业正常接单，已中断的业务由用户决定继续。验证可选关联字段缺省、原 Runner 查询和按问题编号定位脱敏日志。
- 用 Windows 实包覆盖登录、同一会话睡眠唤醒和跨会话恢复。首次 Host 启动失败且条件恢复时，核对原设备在最多 5 次启动恢复内恢复连续心跳并领取任务。确认启动回执丢失时可查到已启动，持续失败时核对总尝试数为 5、每次可诊断、第 5 次后显示错误。核对这些路径均无新配对请求。
- 按项目高风险流程进行开发、自测、独立测试与独立 Code Review。构建三个 1.0.0 安装或插件发行包。验证既有作业收尾及原回执交付、升级保留有效配对身份、新版首次接单、旧组合的升级提示与成套回退。实际发行及部署按项目授权执行，结果写回上方进度表。

2026-11-03逐条确认更新：需要日报或Agent成功回复的会话自动记录所有参与者消息；成功读取及发送结果沿原Runtime通路通知服务器异步保存，Agent不保存、不读取业务消息表。首录为当天全部＋零点前最近100条背景；CLI默认100条/页，前端最多查看最近1000条。一个日报计划管理多个会话。附件本轮只定元信息协议及展示，明确提示Agent暂不支持原件读取、依据文本回复。

最后确认：记录/日报持续保留，沿现有租户删除规则；日报使用内部固定模板、所选智能体模型和计划特殊要求；生成后复用现有定时任务通知发送日期工作台链接，一个计划一条终态通知。定稿评审结论见第4节。

本计划只安排本轮实施。用户暂缓内容已独立登记到[后续实施计划](plan-wecom-conversation-followups.md)，不作为本轮任务或验收前置；既有Runner和已交付客户端能力保持。

## 3. 实施顺序与完成标准

### L1：服务器异步日志与业务解耦

1. 删除wecom_flow中Agent工具流程对归档的同步依赖。保留纯写入函数：记录范围筛选、唯一键UPSERT、本人来源可选标注，不再以日志成功控制Runner。
2. 在原Runtime结果认证/校验且持久化后追加局部WeCom后台回调：记录范围内成功读取保存返回消息；成功发送（含原对账后来确认）消费可选observed_chat。Agent不回复的已读消息同样保存。
3. 回调只使用服务器已接受的原调用/结果归属；片段缺失、组装/提交后台失败、写入失败都不改变原ACK或Agent结果。复用轻量后台机制，不建事件表/总线/队列/扫描补账，失败允许丢失。
4. 从需要日报或Agent成功回复的原会话自动登记范围。首次登记提交一次普通只读补录任务的接点，完整读取函数在L2/L3接通；不在HTTP日志回调等待分页，不要求Agent调度保存。日志短事务沿现有连接池/超时，异常脱敏，不吞原业务错误、不占Runner checkpoint锁。
5. 删除marker/proof、业务游标恢复、采集生命周期、handling及API/Skill/Web调用。保留真实数据和旧未用列，不为本次删耦合重建数据库。

完成：读取/成功发送结果→原ACK/Agent照常完成→服务器异步保存；重复结果不重入消息；没有片段/OCR回退/后台失败不改变原结论；无人工记录开关，不由日志控制监控。首次补录的受理接点在本阶段、完整贯通在L3验收，允许失败后由日期读取补充。

### L2：贯通发送核验片段与单会话按日期分页

0. 发送核验保持原基线/方向/正文/时间/唯一命中规则；复用原查询已取得的同一快照，分别提供普通消息投影和核验判定。在原结果data加可选observed_chat（session/source_generation/messages/confirmed_message_id?/truncated），经现有Runtime通路上报。不得为日志增加读库、UI或核验轮询；原结果优先，片段超预算或失败可省略。片段不是完整问答，不附监控cursor。
1. `wecom_read_session`新增可选date/timezone/include_context，CLI参数同源；首次include_context缺省false，true取该日零点前最近100条，与当日消息共同分页，每页总数默认100、预算不足可更少并续页。首录和日报使用true，背景按原时间区分；旧无日期调用保持增量行为，不增加第四工具或背景状态。
2. 日期转换使用IANA时区与半开UTC范围；单聊/群聊用同一查询；按send_time/message_id keyset续页，首轮固定源消息上界和snapshot_at，续页/恢复不得重新取截止时间。
3. cursor区分日期范围与原增量，绑定include_context/背景起点；续页参数省略继承原值。复用原history查询但补真正续页，不复用监控cursor、不创建服务端分页表。
4. 按实际整页大小调整返回数；云端保留完整有界页，分组分析；单条/类型无法读取时返回带原ID/类型/原因的占位并推进该条，不沿failed+retry卡同一条；因页预算未返回的正常消息不推进。不用800字截断装作完整。
5. 同步生产者/消费者参数schema、可选结果字段与插件元数据；普通归一消息结构复用；旧插件无片段照常发送，旧无日期/附件/增量cursor回归，缺新能力不全局限制旧客户端。
6. 只统一并保留附件元信息协议：原设备/账号/会话/来源代次/消息ID及已有kind/status/name/mime_type/size_bytes/width/height。不读取原件、不传文件字节、不补缩略图或新资源服务。

完成：成功回执能带确认出站及核验窗口内其他消息；超预算/无DB片段不影响发送，旧消费端忽略新字段；跨午夜边界、同秒多条、空日、多页各正常；无重复漏页；日期历史不产生自动回复候选、不污染原增量进度。

### L3：补读、日报局部适配与原计划通知

1. 普通Runner受理→服务器RuntimeExecution中仅本业务启用的小型适配→原LocalToolAdapter。日期分页函数复用于首次只读补录和日报：补录不调用模型，各页结果沿原上报异步保存；日报再通过原模型端口分析、程序保存报告。无模型只读分支也是本阶段待开发接点，不能冒充现有Runner已支持；不另外构造工作流引擎或提示词+proof状态协议。
2. 稳定请求只含目标/日期/时区/来源设备/智能体身份；分页和分组产物属于本次执行，沿原invocation/checkpoint/资源及计费保存。
3. 程序顺序遍历日期页，每页实际CLI结果用于日报分析并由原回调尽力补日志。短内容直接总结，超过上下文时才分组；排空后按最新读取时点UPSERT当天报告。日志表为空或不可写不能阻断分析。
4. 读取失败、模型失败、取消、报告保存失败沿原Runner报告真实结果，保留旧成功日报；局部不支持内容可保存清楚标注的部分报告。
5. 任务状态只查询Runner；程序保存读取范围/固定首轮snapshot_at/生成时间；报告新鲜度比较不使用末页或保存时间。重复完成沿原事实及普通唯一键/新鲜度条件处理，不新增generation owner/proof协议。
6. Agent代理会话时引导创建日报，首次确定时间/范围，明确拒绝则不安排；复用同用户/智能体/来源设备与账号的合适计划，一个计划逐会话执行、每会话每天展示最新一份。不同来源使用对应计划并说明归属，不按群建计划。某会话失败继续其他会话；早上执行通常读前一天，临时总结今天注明截至时间。
7. 日报采用固定内部总结模板，复用所选智能体模型和需要的业务资料；特殊要求来自计划，旧硬编码main不得覆盖用户选择。按已定五块保存原summary JSONB及来源引用，不另建日报智能体、跨会话总报告或汇总表。
8. 在原定时任务终态通知里加性补充服务端构造的日报日期链接、简短完成/缺失说明；一个计划只一条终态通知，全部失败沿原失败通知。复用原通知规则、路由、投递重试及权限，不新增发送任务/事件类型；普通任务无新增数据时保持行为，通知失败不影响已存报告。

完成：首次午夜前100条＋当天补录不调用总结模型；日报实际跨原工具/模型端口，多会话共用计划并发送一条日期链接通知。普通任务和通知保持原行为，原用量/工具事实不被日志影响；共用接口按契约登记，不扩展恢复框架。

### L4：前端和业务Skill精简

- 同一页面左侧会话列表、右侧时间线，进入最底部最新消息，向上每批默认100条，最多查看最近1000条；区分各方姓名/平台/本人或Agent代发，系统事件单独呈现。
- 附件/图片只显示元数据和类型占位，本轮不提供原件下载、预览或放大按钮。Agent说明和错误明确“暂不支持读取附件内容，依据文本回复，必要时请用户补充文字”，不因附件阻断整次文本服务。
- 日报独立工作台页面，按日期切换；按当日概览、咨询分类、已处理、待人工、值得关注分块，注明来源/覆盖范围/缺口，保留生成与重算；任务状态取原Runner。
- 删除关注开关、持续采集管理、处理状态编辑及begin/fail/save/set-handling等命令。Agent不查询业务消息表、不手工操作业务库状态；保留请求响应归属、纯日期计算和操作幂等。
- 历史数据持续保留，停止代理/取消日报不删除；沿项目已有租户删除规则，不开发保留期配置或清理任务。

完成：进入页面不启动任务；已存消息可离线浏览，1000条只限制前端、不截断日报；附件显示元数据且文本回复可继续；日志故障不冒充监控失败。

### L5：独立验证及CodeReview

按实际风险采用项目高风险开发流程：开发→独立测试+独立CR→主控整合。只测真实受影响链路，不为未实现功能或所有历史版本扩测试。

| 必须验证的用户流程 | 目的 |
|---|---|
| 成功读取/发送结果→原ACK/Agent结果→异步日志 | Agent不保存或查询bs消息；确认出站与各方原消息按原ID保存 |
| 重复ACK、可选片段缺失/超预算、界面核验回退、后台写失败/退出丢处理 | 原发送结论与ACK不变，消息去重，不触发重发/额外读库 |
| 正常与恢复读取、同文同秒不同ID、单/群/系统/附件索引 | 去重和原始事实正确，不因缺头像/姓名卡住 |
| 日范围多页＋同秒页尾＋当天新消息＋空日 | 日期分页有界、无重漏；不碰监控cursor |
| 首录当天＋零点前100条、默认100条分页、续页省略背景参数、当日为空 | 时间边界/范围保持，背景不算当天消息、不伪装非空日 |
| 日志表为空/写失败＋本次CLI读取成功 | 仍能分析并保存日报；没有隐性bs消息依赖 |
| 较长通知/多条普通消息经过真实工具输出边界 | 模型收到完整页或明确缺口，不能静默少看 |
| 一个计划包含多个会话、其中一个读取失败 | 逐会话报告、其他会话继续，失败不伪装空日 |
| 首次补录任务、计划设备账号和所选智能体配置 | 补录不阻塞ACK/不调用总结模型，来源和用户选择不被默认main覆盖 |

## P0：监控配置首次启动发送

### P0.1：CLI 标题点击前重置焦点

- 在共用标题复制流程里，先点击同一企微主窗口双点标定中的输入框坐标，再单击群标题或双击单聊标题。前置点击只退出标题编辑态，原有标题复制和目标核验仍先于清空、粘贴或发送。
- 用真实群聊复现已有标题编辑框的情况，验证点击输入区后再单击能复制正确标题；同时覆盖正常群聊、单聊双击、标定和选择等共用调用，以及目标不符时不清空草稿、不输入、不发送。验收后再联测 P0.2。[CLI 设计](../design/wecom/wecom-cli-design.md)

### P0.2：监控配置首次启动发送

- 在现有监控配置增加默认关闭的「首次执行时立即发送以下消息」选项。开启后需填写固定正文。首次启动成功时冻结正文和当次全部监控会话，为每个会话安排一次发送。
- 优先验证经现有 Runtime 通道直接调用设备企微 CLI，复用同设备的执行互斥和回执。发送由配置触发，不依赖入站消息或 Runner。先在共同契约登记首次启动、设备绑定、调用身份、恢复和旧端兼容，再进入实现。
- 首次启动发送沿用现有企微文本发送工具的计费规则，验收时核对实际发送回执与原积分记录。Portal 单价属于 P3/P4 的定时发送范围。
- 验收覆盖默认关闭、开启且正文为空、群聊和单聊无新消息时仍收到原文、重复启动和重启不重复发送、单个会话失败后其他会话和监控继续、回执可查。P0 独立验证和 CodeReview 通过后，按项目授权要求做真机验收；通过后才开始定时发送开发。

P0 开发自测：隔离 PostgreSQL 下企微服务、直发调用与迁移格式等 440 项通过；前端工作台 17 项及构建通过；CLI 构建及含 Windows PowerShell 标题核对在内的 55 项通过。首次发送直接复用现有工具，原 CLI 在坐标缓存缺失时仍按原流程标定坐标。真实群聊的异常焦点、实际 Runtime/CLI 配套与发送回执留待真机验收。

P0 评审修复：首次发布、绑定发送和普通回答取得占用共用 PostgreSQL 设备组事务锁。旧快照派发与启动发布交错的 3 项定向用例修复前均失败，修复后全部通过，覆盖有权和失权两个普通回答分支。隔离 PostgreSQL 相关回归 443 项通过。

## P1：冻结定时发送的共同契约

- 核对现有 Scheduler 计划推进和企微设备协调。用生产与消费样例明确专属计划标记、记录去重键、队列顺序和设备占用释放点。记录多进程、并发暂停和重启时的原子边界。
- 对照 [Runner / Desktop / Runtime 集成契约](../system/runner-desktop-runtime-integration-contract.md)，登记唯一写入者、受信本地调用内部绑定及版本，核对 `/started` 首次成功和重复提交的行为。验证绑定设备切换账号时不会向错误会话发送，旧 Runtime 能否通过现有 Provider 接口执行要用实际发行组合验证。
- 核对原调用成功、迟到回执、缺 `receipt_id`、对账确认和设备释放证据的路由。明确计费的唯一写入者、冻结单价与原发送记录的幂等关联。涉及已有共享接口的扩展，按共同契约完成检查点后才实施。

## P2：计划与设备队列

- 增加企微专用计划管理与逐会话执行记录。覆盖创建后暂停、手动启用、暂停、编辑、恢复和软删除。普通定时任务入口与名额沿同一排除规则处理专属计划。
- 复用 Scheduler 推进一次性、每日、每周计划。用隔离数据库验证到期入队与计划推进、重复调度、跨重启恢复及 10 分钟边界。计划时间使用北京时间，状态以服务器时间核定。
- 让定时发送与监控共享设备派发。验证已有工作先释放、到期项按确定顺序插入、执行器只取队首、多会话失败不拖住后续，以及不同设备相互独立。

## P3：直发、对账与计费

- 经现有 Runtime 调用绑定设备的企微 CLI，验证服务端不创建 Runner 或调用模型。`/started` 在启动 CLI 前判定暂停、过期、身份绑定和余额；首次放行锁定单价和开始时间。验证并发暂停及重复 `/started` 不改变已经取得的授权。
- 复用发送回执和只读对账。验证明确失败直接结束，回执丢失不重发，设备释放后队列继续，后来确认成功只更新原记录。
- 接入默认 0.5 积分和 Portal 配置价。覆盖余额不足、改价前后授权、成功回执与对账重复到达、计费事务失败后补账，以及普通文本发送和旧客户端计费回归。

## P4：页面

- 「定时消息发送」与「监控配置」同级。复用企微会话目录与现有表单、列表组件。覆盖群聊和单聊多选、固定文本、北京时间计划、手动启用和暂停后编辑。历史列表按计划时间和会话展示，诊断编号可复制，软删除后配置退出管理列表。
- Portal 展示平台单价设置。前后端分别校验平台管理员权限，验证非平台管理员直接调用接口也不能修改单价。
- 运行前端构建并验证受影响页面的交互和窄屏状态。

## P5：交付门槛

- 本任务涉及调度并发、设备鉴权、租户边界、数据库迁移与计费，按项目高风险流程执行开发、自测、独立测试和独立 CodeReview。Python 使用项目 `scripts/dev_test.sh`，数据库验证使用隔离 PostgreSQL。
- 关键联测场景：设备正执行监控时定时消息到点、暂停与授权同时发生、单次计划错过窗口、多目标仅部分成功、设备切号或离线、重启前后只生成一条记录、回执丢失后队列继续、对账与成功回执只扣一次。
- 发布验证覆盖实际交付的 Runtime＋CLI 组合和服务端单独升级后的既有企微与 BOSS 路径。部署及真机验证按项目授权要求执行，计划表记录实际验收状态。

## P0：监控配置首次启动发送

### P0.1：CLI 标题点击前重置焦点

- 在共用标题复制流程里，先点击同一企微主窗口双点标定中的输入框坐标，再单击群标题或双击单聊标题。前置点击只退出标题编辑态，原有标题复制和目标核验仍先于清空、粘贴或发送。
- 用真实群聊复现已有标题编辑框的情况，验证点击输入区后再单击能复制正确标题；同时覆盖正常群聊、单聊双击、标定和选择等共用调用，以及目标不符时不清空草稿、不输入、不发送。验收后再联测 P0.2。[CLI 设计](../design/wecom/wecom-cli-design.md)

### P0.2：监控配置首次启动发送

- 在现有监控配置增加默认关闭的「首次执行时立即发送以下消息」选项。开启后需填写固定正文。首次启动成功时冻结正文和当次全部监控会话，为每个会话安排一次发送。
- 优先验证经现有 Runtime 通道直接调用设备企微 CLI，复用同设备的执行互斥和回执。发送由配置触发，不依赖入站消息或 Runner。先在共同契约登记首次启动、设备绑定、调用身份、恢复和旧端兼容，再进入实现。
- 首次启动发送沿用现有企微文本发送工具的计费规则，验收时核对实际发送回执与原积分记录。Portal 单价属于 P3/P4 的定时发送范围。
- 验收覆盖默认关闭、开启且正文为空、群聊和单聊无新消息时仍收到原文、重复启动和重启不重复发送、单个会话失败后其他会话和监控继续、回执可查。按项目授权补真机验收。

P0 开发自测：隔离 PostgreSQL 下企微服务、直发调用与迁移格式等 440 项通过；前端工作台 17 项及构建通过；CLI 构建及含 Windows PowerShell 标题核对在内的 55 项通过。首次发送直接复用现有工具，原 CLI 在坐标缓存缺失时仍按原流程标定坐标。真实群聊的异常焦点、实际 Runtime/CLI 配套与发送回执留待真机验收。

P0 评审修复：首次发布、绑定发送和普通回答取得占用共用 PostgreSQL 设备组事务锁。旧快照派发与启动发布交错的 3 项定向用例修复前均失败，修复后全部通过，覆盖有权和失权两个普通回答分支。隔离 PostgreSQL 相关回归 443 项通过。

## P1：冻结定时发送的共同契约

- 已逐项核对原决策、P0 合入版本、Scheduler、Runtime、CLI、调用回执与积分台账代码。交接见[定时发送 P1 编码契约](../design/wecom/wecom-scheduled-send-design.md#p1-编码契约)及[共同契约 2.21](../system/runner-desktop-runtime-integration-contract.md#企业微信定时消息发送共同检查点)。计划规定的是实现和验收条件，未将发行组合和真机行为记为已验证。

## P2：计划与设备队列

- 新增企微专用的创建、详情、列表、暂停、启用、编辑和软删除接口。按已认证租户用户读取固定设备、账号及目标；在服务端校验现有 CLI 文本限制及三种时间规则。同步新装 DDL、存量迁移及业务初始化，普通计划入口和名额识别同一专属标记。
- 接入现有 Scheduler 到期 SQL 与锁定分支，将逐会话记录和下一触发点一次写入。检查一次性任务不会被通用宽限先作废或进入 Runner。检查自同一时间点到期的多个计划排序、多目标次序、不同设备各自处理，持久记录与配置快照在进程重启后仍然可核验。
- 以隔离 PostgreSQL 验证两个 Scheduler 认领同一计划、首次发送和普通回复抢占、相邻分组独立、启停竞争、超过及正好 10 分钟和历史查询。派发排序及既有占用边界在 P2 完成，真实发送调用、开始授权和结果生命周期在 P3 接入。

## P3：直发、对账与计费

- 实现原调用绑定、定时专属 `/started` 授权、已有通道回执核定及设备释放。测试原设备掉线、切号、授权前暂停/过期、授权后暂停、重复 `/started`、迟到回执、原设备仍占用、明确终态后队列继续、无回执时不重发。首版不得用旧端不支持的字段或未验证的租约信号推断设备空闲。
- 复用现有只读对账工具，核对同租户、用户、设备、原调用和原会话的可信凭据；每次发送的终态与释放分别保存。覆盖成功回执和对账并发、同一记录重复核定、回执确认失败后继续队列。
- 冻结并实现价格和扣费时点，默认 0.50，沿现有平台认证写持久覆盖值。测试零价、价格变更、余额不足、普通路径扣费互斥、账本失败后事务回滚和同一记录补扣。保留 P0、普通企微文本和 BOSS 验收样例。

## P4：页面

- 「定时消息发送」与「监控配置」同级。复用企微会话目录与现有表单、列表组件。覆盖群聊和单聊多选、固定文本、北京时间计划、手动启用和暂停后编辑。历史列表按计划时间和会话展示，诊断编号可复制，软删除后配置退出管理列表。
- Portal 展示平台单价设置。前后端分别校验平台管理员权限，验证非平台管理员直接调用接口也不能修改单价。计划、逐目标结果与计费分别来自专属 API，组件不根据浏览器时间猜测授权是否过期。
- 运行前端构建并验证受影响页面的交互和窄屏状态。

## P5：交付门槛

- 本任务涉及调度并发、设备鉴权、租户边界、数据库迁移与计费，按项目高风险流程执行开发、自测、独立测试和独立 CodeReview。Python 在 WSL2 Docker 的当前工作区绑定容器内使用项目 `scripts/dev_test.sh`，数据库验证使用隔离 PostgreSQL。
- 关键联测场景：设备正执行监控时定时消息到点、暂停与授权同时发生、单次计划错过窗口、多目标仅部分成功、设备切号或离线、重启前后只生成一条记录、回执丢失后队列继续、对账与成功回执只扣一次。
- 发布验证覆盖实际交付的 Runtime＋CLI 组合和服务端单独升级后的既有企微与 BOSS 路径。部署及真机验证按项目授权要求执行，计划表记录实际验收状态。

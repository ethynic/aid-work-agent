## P0：监控配置首次启动发送

### P0.1：CLI 标题点击前重置焦点

- 在共用标题复制流程里，先点击同一企微主窗口双点标定中的输入框坐标，再单击群标题或双击单聊标题。前置点击只退出标题编辑态，原有标题复制和目标核验仍先于清空、粘贴或发送。
- 2026-11-23 补充：群标题在输入框点击后等待旧编辑框消失，标题单击后等待新编辑框出现，再向该编辑框显式全选和复制。回归覆盖旧框延迟退出、新框延迟出现及任一步超时。
- 2026-11-23 验证：旧驱动未通过延迟转换用例，修复后 6 个专项用例和独立 63 项相关回归通过。Windows 使用仓库驱动和原坐标实测「测试群」，前台及标题、输入点均被遮挡时各 5/5，分别包含 4 次预先存在标题编辑框的情况。仅复制标题，未发送、打包或安装。
- 用真实群聊复现已有标题编辑框的情况，验证点击输入区后再单击能复制正确标题；同时覆盖正常群聊、单聊双击、标定和选择等共用调用，以及目标不符时不清空草稿、不输入、不发送。验收后再联测 P0.2。[CLI 设计](../design/wecom/wecom-cli-design.md)

### P0.2：监控配置首次启动发送

- 在现有监控配置增加默认关闭的「首次执行时立即发送以下消息」选项。开启后需填写固定正文。首次启动成功时冻结正文和当次全部监控会话，为每个会话安排一次发送。
- 优先验证经现有 Runtime 通道直接调用设备企微 CLI，复用同设备的执行互斥和回执。发送由配置触发，不依赖入站消息或 Runner。先在共同契约登记首次启动、设备绑定、调用身份、恢复和旧端兼容，再进入实现。
- 首次启动发送沿用现有企微文本发送工具的计费规则，验收时核对实际发送回执与原积分记录。Portal 单价属于 P3/P4 的定时发送范围。
- 验收覆盖默认关闭、开启且正文为空、群聊和单聊无新消息时仍收到原文、重复启动和重启不重复发送、单个会话失败后其他会话和监控继续、回执可查。按项目授权补真机验收。

P0 开发自测：隔离 PostgreSQL 下企微服务、直发调用与迁移格式等 440 项通过；前端工作台 17 项及构建通过；CLI 构建及含 Windows PowerShell 标题核对在内的 55 项通过。首次发送直接复用现有工具，原 CLI 在坐标缓存缺失时仍按原流程标定坐标。真实群聊的异常焦点、实际 Runtime/CLI 配套与发送回执留待真机验收。

P0 评审修复：首次发布、绑定发送和普通回答取得占用共用 PostgreSQL 设备组事务锁。旧快照派发与启动发布交错的 3 项定向用例修复前均失败，修复后全部通过，覆盖有权和失权两个普通回答分支。隔离 PostgreSQL 相关回归 443 项通过。

## P1：冻结定时发送的共同契约

- 已逐项核对原决策、P0 合入版本、Scheduler、Runtime、CLI、调用回执与积分台账代码。交接见[定时发送 P1 编码契约](../design/wecom/wecom-scheduled-send-design.md#p1-编码契约)及[共同契约 2.21](../system/runner-desktop-runtime-integration-contract.md#企业微信定时消息发送共同检查点)。计划规定的是实现和验收条件，未将发行组合和真机行为记为已验证。

## P2：计划与设备队列

- 新增企微专用的创建、详情、列表、暂停、启用、编辑和软删除接口。按已认证租户用户读取固定设备、账号及目标；在服务端校验现有 CLI 文本限制及三种时间规则。同步新装 DDL、存量迁移及业务初始化，普通计划入口和名额识别同一专属标记。
- 接入现有 Scheduler 到期 SQL 与锁定分支，将逐会话记录和下一触发点一次写入。检查一次性任务不会被通用宽限先作废或进入 Runner。检查自同一时间点到期的多个计划排序、多目标次序、不同设备各自处理，持久记录与配置快照在进程重启后仍然可核验。
- 以隔离 PostgreSQL 验证两个 Scheduler 认领同一计划、首次发送和普通回复抢占、相邻分组独立、启停竞争、超过及正好 10 分钟和历史查询。派发排序及既有占用边界在 P2 完成，真实发送调用、开始授权和结果生命周期在 P3 接入。
- P2 先提供内部配置服务、到期记录和原子取候选接口。P3 在同一变更中接入真实消费者和监控让位判断。配置服务在 P2 不注册公开写路由。

P2 开发自测在 WSL2 Docker 的隔离 PostgreSQL 通过 639 项，覆盖真实 Scheduler 两轮扫描、无 Runner 提交、并发认领与暂停、重启追补、北京时间窗口、设备组占用和队首顺序。增量 SQL 可重复执行，表结构和索引与首次安装、运行期初始化一致。一次性计划成功入队后保持启用且没有下一触发点，后续由 P3 负责授权前取消、过期及执行收尾。

P2 独立测试复跑 639 项，另验证迁移重复执行、未知占用与 10 分钟边界、固定绑定及软删除历史共 3 项，均通过。独立 CR 通过。同一到期时间按配置入库时分配的自增 ID 确定创建顺序，再按配置中的目标顺序派发。P3 负责接入设备消费者及监控让位。

## P3：直发、对账与计费

- 2026-11-23 补充：每日明细按原定时发送会话和工具识别来源，兼容已出账记录。坐标重新标定继续按现有模型计费。用隔离库验证发送费显示「企业微信定时发送」、BOSS 记录显示「BOSS 工具」，金额保持原值。
- WSL2 Docker 隔离 PostgreSQL 验证明细与余额接口共 20 项。沿用真实台账写入的回归用例在旧查询上复现错标，修复后确认来源与积分金额正确。
- 实现原调用绑定、定时专属 `/started` 授权、已有通道回执核定及设备释放。测试原设备掉线、切号、授权前暂停/过期、授权后暂停、重复 `/started`、迟到回执、原设备仍占用、明确终态后队列继续、无回执时不重发。首版不得用旧端不支持的字段或未验证的租约信号推断设备空闲。
- 复用现有只读对账工具，核对同租户、用户、设备、原调用和原会话的可信凭据；每次发送的终态与释放分别保存。覆盖成功回执和对账并发、同一记录重复核定、回执确认失败后继续队列。
- 冻结并实现价格和扣费时点，默认 0.50，沿现有平台认证写持久覆盖值。测试零价、价格变更、余额不足、普通路径扣费互斥、账本失败后事务回滚和同一记录补扣。保留 P0、普通企微文本和 BOSS 验收样例。

P3 已接入企微设备组、Runtime 原领取及 `/started` 接口。先核定已占用的首启发送，定时候选有权等待占用释放，未开始的首启、监控读或回答在取得新占用前复查持久定时候选。启动授权在原调用事务冻结单价和开始时间，暂停与授权以执行行锁决定胜负。价格使用平台持久覆盖值，Portal 鉴权路由和页面随 P4 接入。

发送确认、设备释放和积分结算分别持久化。缺少原操作停止证据时，仅保持企微设备组占用。复用原来 CLI 已有的驱动结束后核验回执识别明确释放，允许同一原调用的可信迟到成功解除占用。只读对账确认只更新原执行记录并至多计费一次。发布版 Runtime 与 CLI 的实际回执组合仍待 P5 真机验收。

独测发现授权前领取失联会提前结束补发窗口。修复后扫描器与 `/started` 均能识别失效租约，取消旧凭据并保留执行记录和原 invocation。原账号复核成功后仍在窗口内可重新领取，超窗则结束本次。当次已授权时仍等待原回执或对账。

CR 发现企微运行状态、会话元数据和本地库检查的部分明确失败被误判为结果未知。已统一实时与可信迟到回执的无发送判据。明确失败释放设备供下一目标使用，超时、取消、崩溃和凭据失效继续保持结果未知。修复前 4 项真实入口回归复现，修复后 26 项直发专项及 2077 项扩展回归通过。

P3 开发自测在 WSL2 Docker 的隔离 PostgreSQL 通过 1391 项，包括 17 项定时直发专项。专项覆盖首启及监控让位、已开始工作继续、暂停与授权竞争、余额和截止、授权前失联恢复、授权后租约未知与迟到回执、只读对账以及台账失败后补账。单价迁移可重复执行，与首次安装及运行期初始化都保持两位小数。

同步 master `fa07a8da` 时按原顺序合并钉钉、企微队列和定时直发迁移，合并后的通知及企微回归通过 2213 项。最终基线包含 master `46d4bc2a`，隔离库独测通过 1400 项（12 条警告，0 跳过），迁移、编译与模块导入检查通过。独立 CR 复跑 26 项直发用例全部通过。

## P4：页面

- 「定时消息发送」与「监控配置」同级。复用企微会话目录与现有表单、列表组件。覆盖群聊和单聊多选、固定文本、北京时间计划、手动启用和暂停后编辑。历史列表按计划时间和会话展示，诊断编号可复制，软删除后配置退出管理列表。
- Portal 展示平台单价设置。前后端分别校验平台管理员权限，验证非平台管理员直接调用接口也不能修改单价。计划、逐目标结果与计费分别来自专属 API，组件不根据浏览器时间猜测授权是否过期。
- 运行前端构建并验证受影响页面的交互和窄屏状态。

定时消息发送在企微工作区使用 `/wecom-agent/scheduled`，原 `/wecom-agent/proxy` 保留监控配置。新建通过当前已选设备的企微目录重新核验会话和目录代际，在锁定设备选定状态后一次性登记并保存。编辑增加目标时沿用原设备和账号，只改正文或时间可直接保存。诊断编号优先用原调用 ID，没有调用时用执行 ID；到期未派发时会按 `execution=<编号>` 写日志。

Portal 单价在平台积分消耗报表管理。后台仅接受平台管理员提供的两位小数十进制字符串或恢复默认请求，返回有效单价、默认单价和覆盖状态。

开发自测在 WSL2 Docker 隔离 PostgreSQL 通过 2083 项，覆盖真实租户及用户隔离、设备选择和代际竞争、暂停、软删除历史、诊断日志、原普通定时入口与平台角色。前端构建和相关 66 项测试通过。全量运行这 7 个前端测试文件时，基线已存在的 Portal 嵌套路由快照另有 1 项失败。保留该快照并定向复跑通过。Edge 在桌面与 390px 的本地模拟数据上验证表单、操作、键盘弹窗、诊断复制与平台单价，美西浏览器时区仍显示北京时间。

独立测试复跑隔离库 2083 项（12 条警告，0 跳过），主应用 OpenAPI 核对和前端构建通过。前端目标测试过滤基线已有的 Portal 嵌套路由快照后通过 66 项，跳过 1 项。CR 在隔离库复跑 API 与直发 32 项通过，对执行记录补齐六种可达失败的简短原因后，开发、独测与 CR 各自定向复跑共享目录和定时任务 API 64 项通过（8 条警告，0 跳过）。执行记录可显示原因和诊断编号，接口继续约束为执行记录字段。

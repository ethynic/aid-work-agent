## 实施与验收

按[微信 CLI 设计](../design/weixin/weixin-cli-design.md#15-环境诊断与窗口恢复)实现。新版 `weixin_probe` 的名称和请求保持兼容，响应只增加诊断字段。运行时与发布打包的原 `doctor --json` 须继续可用。

1. 核对进程不存在、正常窗口、后台窗口、最小化、关闭到托盘、无法识别窗口和多候选。检查登录就绪及常规 doctor 零窗口副作用。
2. 显式恢复复用 Win32 前台激活和 Windows Explorer 通知区 UIA。验收前台、最小化、隐藏托盘及恢复失败。恢复不会启动第二个实例。
3. 真机仅验证窗口状态与会话列表的存在性。无截图、聊天正文、登录二维码上传。

## 真机起点

微信 4.1.15.13 点击关闭后，原主窗口句柄继续存在且不可见。直接让 Win32 显示该句柄后仍没有可读会话区。运行可执行文件会额外打开登录窗口，测试实例已关闭。Windows 11 通知区隐藏面板里的 `NotifyItemIcon`（显示名称「微信」）通过 UIA Invoke 能恢复原主窗口及其会话列表。

Windows 11 26300 真机上，正式 CLI 核对并恢复了后台、最小化和托盘三种状态。连续两次只读诊断保持最小化或隐藏状态。显式恢复后核实主窗口句柄、进程身份及会话列表。常规 `doctor --json` 约 1.9 秒完成。MCP `weixin_probe` 继续接受原参数，返回窗口和登录信息，回执无聊天正文、截图、二维码或窗口句柄。

隔离签名测试包通过验签、搬迁和诊断启动检查。交互会话仍沿用现有环境判定，独立的锁屏状态检测未纳入本次验证。托盘恢复真机覆盖上述 Windows 11 通知区布局。

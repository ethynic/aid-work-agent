## 范围与验收

1. 添加企业微信会话弹窗的群聊项不显示会话级 `peer_platform` 或原始 `unknown`；保留群聊名称、类型、短稳定 ID、已添加状态及同名预览。单聊不因本任务改变平台判断。
2. 群聊内容的 CLI 消息结果每条包含 `sender_platform`；可靠微信发言人为 `wechat`。会话记录只给此类发言人显示「微信用户」标记，企微及身份未确认者均不显示平台标记；原始 `unknown` 保留在数据中供 Agent 与归档使用，不推断为已证实的企微身份。
3. 核对现有 CLI→Runtime→服务端归档→前端与日报模型输入链路，优先只改实际有问题的展示代码。用混合群、未知发送者和单聊作定向回归，不增加新的平台推断规则。

实施前代码事实：群聊目录由 CLI 返回会话级 `peer_platform=unknown`，添加弹窗直接显示该原始值；逐消息 `sender_platform` 已在本地库解析、会话记录和日报模型输入中使用。本次以回归测试固定群消息逐条携带字段，未改变 CLI schema；合成混合群测试不代表真人混合群验收通过。

## 实施记录（2026-11-05）

- 添加会话弹窗仅在单聊显示会话级平台；群聊继续显示类型和短稳定 ID，不展示 `unknown`。
- 会话记录的消息气泡及详情只在 `sender_platform=wechat` 时显示「微信用户」。未标记消息按普通发言展示；服务端保存的 `wecom` / `unknown` 仍保持原值。CLI 的 Python 本地库、TS 归一及群读/轮询原本已逐条输出该字段，因此无需新增重复布尔字段或改动 wire schema。
- 主控定向验证：前端 23 项通过、CLI Python 2 项通过、前端生产构建通过。独立验证：前端相关 28 项、CLI Python 45 项、CLI TS 42 项通过，CLI 主构建通过；只读 CodeReview 无 P0–P2。未运行真人混合群，也未在真实浏览器里检查视觉效果；不将合成库测试称作真机验收。

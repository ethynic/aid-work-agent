# 营销 App 智能外呼代理：验证与开发计划

日期：2026-09-05。状态：📋 待开发。当前交付是方案，不代表代码、真机或实际外呼已完成。

优先执行：[GLM 第一阶段实验手册](marketing-call-agent-experiment-runbook.md)。没有云图时先做 P0-A，第一批只交付 E0/E1，具体技术方案、命令契约与门禁以手册为准。

关联：[详细设计](../design/marketing-call-agent-design.md) · [可行性调研](../research/marketing-call-agent-feasibility.md)。

## 1. 项目决策

主线固定为“自选安卓专机＋GLM-5.3-Flash 截图定位＋安卓控制＋外部有线音频桥＋实时语音智能体”。不等待厂商支持，不安排平台 API/SIP 对接工作。系统名称暂记“疑似云图”，不据此推断字段或通话机制。

**先独立验证替代 App 视觉控制与普通号码真实双向电话，再适配云图。**云图录音及销售/客户关联按黑盒能力处理，不属于我们的开发、检查或验收范围；Agent 自留音轨仅作非权威参考，不能上传云图。只展示自动点击拨号或电脑上能与 AI 对话，都不能证明该项目可交付。

## 2. 开工所需材料

P0-A 只需已授权 ADB 的模拟器/安卓设备、GLM 图文 API 配置及可选替代 App；没有替代 App 时先用系统设置的只读导航页面。E2 表单实验需要支持测试表单的 App，不满足则单项 BLOCKED。E3/E4 再准备安卓真机 A、正常 SIM、内部接听端 B 和双向音频桥，手动拨普通号码即可。

P0-B 云图集成阶段才需要客户销售账号、对应 SIM/主叫身份、云图正规安装来源与版本、测试线索、反馈字段和话术。这些不阻塞 P0-A。

提供 5–10 通经授权并脱敏的代表性人工通话材料更利于话术设计；缺少时用内部人员模拟正常咨询、不方便、拒绝、听不清、要求人工、平台提示音和语音信箱。当前不需要客户提供真实个人电话号码到项目文档。

记录业务指标：4000 多通的口径、工作日与允许时段、接通率、平均/高分位时长、重拨规则、峰值线索速度、销售账号数、反馈处理耗时，以及新线索首次联系时效。缺失时使用第 6 节的显式假设。

## 3. P0：先解耦实验，再做云图集成

P0-A 建议 3–5 个工作日，材料齐全后执行；技术步骤与通过条件见[实验手册](marketing-call-agent-experiment-runbook.md)。按项目要求走代码开发、自测、独立测试与审查，不把编写本方案算作已开发。

| 顺序 | 实验 | 依赖 | 成功证据 |
|---|---|---|---|
| E0 | 环境、截图、GLM 定位绘框 | 模拟器或真机＋视觉 API | 真实图文调用与正确目标框；不点击 |
| E1 | 替代 App 单步视觉点击 | E0；无 App 时用系统设置 | 30 次导航、异常拒绝和缩放定位结果 |
| E2 | 中文表单保存回读 | E1＋支持表单的替代 App | 10 条虚构记录离开重进回读，无重复写 |
| E3 | 普通电话双向音频 | 真机/SIM/测试接听端/音频桥；不依赖 E0–E2 | 手动拨号，真实收音、发声、双讲与恢复 |
| E4 | AI 普通电话对话 | E3＋流式语音服务 | 5 通、20 轮、10 次打断及远端延迟记录 |

第一批开发范围仅 E0/E1。E2/E3/E4 按各自资源推进；没有客户 App、SIM 或声卡不影响 E0/E1 开发。缺资源标 BLOCKED；实现错误标 FAIL。独立实验通过不代表云图适配通过。

P0-B 建议另用 2–3 个工作日，在云图可用后做：人工基线 → 新线索和详情定位 → App 到系统拨号盘 → 原绑定号码呼叫 → 平台提示/客户接通识别 → 反馈保存回读 → 崩溃防重拨。复用实验底层，不复用替代 App 坐标，不检查云图录音。

P0 合计仍参考 5–8 个工作日，但云图等待时间单列，不将 P0-B 塞入没有云图的首周。线索不能消歧、真实音频不稳定、反馈无法回读或故障会重复拨号时，对应能力不进入批量开发；其余独立实验可继续。

## 4. 后续阶段与交付物

以下以 1 名后端/实时语音工程师、1 名安卓/边缘工程师为主，QA 和产品/客户销售参与为假设。排期是估算，阶段通过后才推进。

| 阶段 | 预计时间 | 开发范围 | 验收交付 |
|---|---|---|---|
| P0-A / P0-B 可行性 | 分别 3–5 / 2–3 工作日 | 替代 App 视觉实验、普通电话音频；后续云图适配 | 独立实验结果＋云图集成结果分开报告 |
| P1 单机闭环 | 7–10 工作日 | 设备锁、截图动作、发现线索、呼叫状态、受控对话、草稿/回填 | 一个账号端到端可用；失败转复核 |
| P2 可靠性 | 7–10 工作日 | 幂等账本、故障恢复、AEC/打断、人工接管、反馈恢复、监控 | 故障矩阵通过，连续运行达标 |
| P3 受控试点 | 5–10 工作日 | 限量真实线索、人工抽检、延迟/话术优化、容量复测 | 100–300 通授权试点报告及下一步容量决定 |
| P4 扩容 | 视试点 3–5 工作日 | 第二线路或备用配置、运维培训、升级回归与回滚 | 满足实际月量与时效目标 |

预计完整试点约 5–8 周；阶段允许局部并行，但 P0 音频、身份和回填门禁不能跳过。设备采购、账号准备和客户话术审核等待不计入纯开发时间。不要提前承诺上线日期。

工程拆解：

- 设备适配：截图元数据、坐标变换、动作协议、中文输入、状态观察、版本锁定。
- 媒体适配：声卡驱动、格式转换、AEC、VAD、播放取消、看门狗与本地结束语。
- 对话运行时：话术图、槽位、规则、模型适配、转写证据、人工接管。
- 业务服务：线索识别、任务账本、租约与未知恢复、重拨策略、抑制名单。
- 回填与对账：字段映射、冲突检测、保存回读、人工复核队列。
- 运营能力：权限、加密、费用统计、报警、暂停/恢复、升级回归。

每个非平凡代码阶段遵守项目三智能体流程：开发自测 → 独立测试 → 独立 CodeReview；目前纯方案文档不启动代码阶段。不自动提交，后续仅在用户明确要求提交代码时执行 fetch、冲突检查、提交和 push。

## 5. 测试与上线门禁

所有数值是拟议目标，需客户确认；以完整样本报告衡量，不能仅展示成功个案。

| 类别 | 测试方式 | 初始验收目标 |
|---|---|---|
| 身份和外部动作 | 重复姓名/虚拟号复用/列表重排/页面切换 | 样本中 0 次拨错对象、0 次重复拨号、0 次写错线索 |
| 坐标 | 原图/缩放/裁剪/不同密度/键盘/通知/旋转异常 | 支持布局安全动作成功率 ≥99%；其他布局正确暂停 |
| 业务闭环 | 内部测试后 100–300 通试点 | ≥95% 合格任务无需人工完成；同时报告被排除/暂停占比 |
| 语音 | 远端时间标注与重叠说话测试 | 回答 p95 ≤2 秒，打断停播 p95 ≤300 ms |
| 接通识别 | 真人/平台提示/忙音/语音信箱/静默 | 分类混淆矩阵公开；未知不伪报真人接通 |
| 话术 | 固定情景集＋人工审听 | 拒绝即停止，越权承诺与编造关键事实 0 次 |
| 反馈 | 原始人工标注与保存后回读 | 自动提交部分关键字段正确率 ≥98%，错误归属 0 次 |
| 稳定性 | 至少 3 个完整工作日＋故障矩阵 | 无未发现卡死；恢复不重复外部动作 |
| 隔离 | 双租户/双账号/旧 epoch 事件 | 无跨租户数据或设备动作 |

“0 次严重错误”是试点放行要求，不是统计上证明永不出错；300 次零失败对应的真实低概率风险仍需更大样本评估。发生一次拨错/写错/违规重拨立即暂停，定位修复并重测。

定义合格任务：授权范围与时段内、身份唯一、设备健康且话术支持；必须同时报告全部任务数、合格率、暂停率和自动化率，防止通过排除难例提高指标。电话接通率受线索与线路影响，不作为机器人自身成功率。

故障用例至少包括：点击拨号后进程崩溃、保存后断网、模型迟到结果、旧 TTS 在下一通返回、客户先挂机、意外来电、平台腿接通但客户未接、SIM 选择弹窗、音频设备改名/拔线、App 升级、登录失效、账号被人工操作、磁盘满和重复通知。

坐标变换做纯函数测试；状态机做乱序与重放测试；媒体用录音回放做打断/回声测试；外部 App 必须真机验收，mock 不能证明音频路由和持久化保存。

## 6. 4000 多通的容量模型

以 **4400 次拨打尝试/月、22 个工作日、每天 8 小时、有效利用率 65%** 为算例。有效利用率覆盖维护与可用空闲，单次耗时另外计入拨号、通话和截图填表等工作；试点中避免重复计算同一开销。

每条线路月有效时间：`22 × 8 × 60 × 0.65 = 6864 分钟`。平均每次占用 `t` 分钟时，最低线路数：`ceil(4400 × t / 6864)`。

| 平均占用 t | 单线路月能力 | 满足 4400 次的最低活动线路 |
|---|---|---|
| 1.5 分钟 | 4576 次 | 1，余量很小 |
| 2.5 分钟 | 2746 次 | 2 |
| 4 分钟 | 1716 次 | 3 |
| 5 分钟 | 1373 次 | 4 |

更准确模型：`t = 拨号和振铃平均耗时 + 接通率 × 接通后平均通话时长 + UI/反馈占用 + 分摊线索扫描时间`。

例如 0.4 分钟准备/振铃＋60% 接通率×3 分钟对话＋0.6 分钟表单等开销＝2.8 分钟，4400 次需 12320 分钟，最低 2 条活动线路。若每天仅允许 4 小时外呼，相同假设需 4 条。若 4400 是接通次数，60% 接通率对应约 7334 次尝试，不能套用 4400 尝试的结论。

因此先做 1 条验证线路，成熟后可能需要 2–3 条活动线路；冷备不计入活动能力。每条活动线需要平台允许的账号/SIM 绑定，不能假设同一个销售登录多机即可扩容。只有一个可用账号/SIM 且平台不允许扩展时，容量存在硬上限。

月均不是首次联系时效保障。若要求新线索 5 分钟内联系，还需测每小时峰值到达率和时长分布，用排队仿真计算 p95 等待时间，不能只用月量除工作日。线索集中到达时优先按客户确认的规则排序，超容量显式提示或交人工。

## 7. 成本估算口径

以下是内部预算公式与敏感性算例，不是供应商价格或正式报价；未对硬件进行询价，因此不提供虚构采购价。

月运行成本：

`原线路费用 + ASR计费量×单价 + TTS计费量×单价 + 文本模型tokens费用 + 视觉输入/输出tokens费用 + 边缘/服务器/存储 + 人工异常处理 + 硬件摊销`。

若按 4400 次、60% 接通、3 分钟通话，接通语音 7920 分钟。假设 ASR/对话/TTS 折算成本分别测试 0.05/0.10/0.20 元每接通分钟，对应 396/792/1584 元。只是敏感性示例，不含振铃监听、失败请求、视觉、电话线路和运维；某些服务在等待时也收费，必须以账单口径修正。

视觉成本单独算：`4400 × 每次业务截图调用数 + 每日扫描调用数×22 + 异常重试调用数`。假设每次 12–25 次视觉调用，业务部分即 52800–110000 次/月；不应因为模型名有 Flash 就忽略此项。8 小时每分钟扫描一次是 10560 次/月，若每轮 3 张图则 31680 次。输入图片尺寸和补充上下文直接影响费用与延迟，P0 记录真实 tokens 和账单。

按 16 kHz、PCM16 单声道，1 分钟约 1.92 MB；7920 分钟约 15.2 GB，双轨约 30.4 GB，尚未计入振铃与截图。生产可按授权范围采用压缩与留存策略，诊断原始 PCM 不默认永久保存。

粗略工程投入：P0 8–12 人天，设备/视觉 10–15，人机语音 10–15，业务/回填 8–12，可靠性/试点 10–15，合计约 46–69 人天；另预留约 20% 机型与 App 不确定性，约 55–83 人天。以上分工可交叉，日历 5–8 周需有两名主要工程人员且外部条件就绪。报价应以企业实际人天单价乘工时另计硬件/服务，P0 后重估。

经济性用 `节省的销售处理工时价值 − 模型线路增量费用 − 人工复核与运维 − 开发摊销` 判断，并观察有效预约/后续成交质量。自动打完不等于创造与人工相同的销售效果。

## 8. 没有云图时首个工作周

1. 第 1 天：E0，建立独立 Python 工具、ADB 截图、真实 GLM 图文调用与绘框。
2. 第 2 天：E1，替代 App 单步点击、截图回读、坐标与异常门禁；交付第一批可运行工具。
3. 第 3 天：有表单 App 做 E2；有真机/桥接配件做 E3。两者独立，缺少条件不互相阻塞。
4. 第 4 天：E3 通过后做 E4，手动拨普通号码，测 AI 对话和打断。
5. 第 5 天：复测与故障实验，输出分项 PASS/FAIL/BLOCKED、复现说明和云图待适配清单。

没有硬件时完成视觉和离线媒体逻辑，实际通话明确留待真机。模拟器电话事件、电脑麦克风对话、双手机免提演示均不能替代 E3 的有线真机验收。

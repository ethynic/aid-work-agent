## 成功标准

模型在人工多轮实验中需要知识库事实时调用 `knowledge_base_search`。工具每次实际检索，当前命中且已在模型上下文中的相同片段/文档信息不重复返回；新内容必须返回，空结果如实报告。旧会话、无钩子直接调用、Web/渠道和恢复路径继续可用。未经本轮检索确认的旧知识不作为工具结果兜底；模型是否遵循提示词以人工实验观察，不宣称强制保证。没有数据库版本表、触发器或费用门禁。

## Phase 1：结果标记与上下文清单

1. `knowledge_base_search` 的新结果增加轻量格式标识、片段内容指纹和文档信息指纹；保留现有入参与返回字段。片段用 `doc_id + chunk_index + 指纹` 判同，指纹只覆盖 `text` 与稳定知识元数据，排除 `score` 等检索派生字段；文档信息独立判同，特别覆盖 `raw_payload` 与封面变化。指纹与普通工具结果一起保存，不新增持久化通道或数据库迁移。
2. Runner 完成既有上下文装配后，在**每次本工具执行前**从当时 `state.messages` 配对调用与结果，只把仍会发送给模型且有完整正文的新格式结果整理成可信清单，经可选 `ToolExecutionContext` 交给工具。同一执行内前一次工具结果及恢复后的当前消息也按此规则处理。模型调用 schema 不变；旧格式、只剩裁剪结果或解析异常时清单为空或跳过该条。
3. 定向验证 Web/渠道历史、压缩与窗口裁剪、旧/新格式混存、恢复中的工具调用，以及缺失/非法格式时不把会话打断或误认历史内容。

## Phase 2：检索与裁剪

1. 每次工具调用沿用当前授权范围，实际执行向量/全文检索和排序；排序后按清单裁掉完全相同的片段和文档信息。不能在候选搜索前排除旧片段。`raw_payload` 变化但片段未变时返回新文档信息；同文档新片段、旧文档信息时只裁剪文档信息。
2. 增加 `matched_count`、`already_in_context_chunks` 和 `already_in_context_documents`；`count` 仍是实际返回片段数。两个清单只标识本次重新命中且当前上下文存在的相同内容，不返回重复正文。无钩子调用完整返回；空结果仍每次实际检索。
3. 区分现有本租户/共享授权读取失败与正常未配置/无共享。`knowledge_base_search` 授权无法核实时明确失败，不沿用历史或误作允许全部；正常无钩子调用仍保持完整返回。撤权失效清单只作过渡提醒，终极方案上线后删除。
4. 定向测试覆盖不同 query/`top_k`、重复/更新/删除/到期、空结果、`raw_payload` 与封面单独变化、新片段配旧文档信息、相同文档不同片段、共享范围、无钩子直调、授权失败和检索失败。测试应证明错用旧事实会失败；针对报价/旅游从历史 `raw_payload` 取值做回归。

## Phase 3：提示词与验收

1. 固定系统指令和相关数字员工指令要求使用知识库事实前调用工具，移除“仅凭历史结果仍有效即可跳过搜索”的旧口径。工具说明用白话解释 `matched_count`、`count`、`already_in_context_chunks` 和 `already_in_context_documents`：重复的 chunk 正文和文档 `raw_payload` 在当前历史上下文中，不再重复返回；只有清单中的历史内容被本次检索确认；即使 `count=0`，也先看本次 `documents` 是否有更新。新摘要标记知识库事实为历史信息，已有摘要不改写。
2. 按本项目高风险代码改动流程安排独立测试与独立 CodeReview，重点审查 Runner 上下文、工具结果兼容、租户与共享授权；只运行相关后端测试及关键启动检查。
3. 人工多轮实验按设计 §7 执行，结合现有 trace、日志和用量记录核对模型是否调用工具、是否选用了本轮有效知识。费用和缓存命中仅观察，不设任何门禁。真机部署须另获用户当场明确指示。
4. 开发后先更新本计划顶部进度，再同步 `docs/ideas.md`；开发完成后移入 `docs/ideas_finished.md`。没有明确“提交代码”授权不提交。

### 测试环境发布准备

本功能的内容指纹在每次 `knowledge_base_search` 命中后即时计算，随新格式工具结果保存；没有数据库指纹字段、初始化数据、迁移或回填步骤，因此不新增指纹发布脚本。旧会话升级后的第一次新检索完整返回结果，之后才可使用新格式历史去重。测试环境应准备可安全修改的隔离知识样本，按设计 §7 验证真实检索、更新和授权变化；代码定向回归沿用现有 `scripts/dev_test.sh`。部署到任何测试环境仍须用户当场明确指定目标，不能把“准备测试”视为部署授权。

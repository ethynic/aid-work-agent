## Phase 0 验证原包直接复用、体积和 Chat 隔离

- 复用官方原包，不再执行已取消的源码提取路线。记录对应平台的实际可执行文件、压缩体积及使用本机 Chrome 的前提。
- 验证官方 MCP 的可用分组和实际调用限制。默认 `core` 已实测拒绝 `agent_browser_chat`。开 `core,debug` 后，附件上传、批处理与 Chat 同时在目录中出现。
- 已核对现有 Runtime 对签名清单、入口、版本、就绪和结果的要求。用户确认签名包接法、必须保留上传和批处理且禁用内置 Chat，并选择隔离验收实例。 [原版实测](../research/browser-tool-rebuild-research.md#原包离线接入验证)

## Phase 1 接线原生 MCP 与第一方 Provider

- 按确认的接法复用原版二进制。用真实 `tools/list` 和 `tools/call` 检查插件对外保留同名原生工具及其 schema，供 AID 自行选择浏览器操作。
- 核对签名声明、版本与就绪诊断，验证原生 MCP 结果能转换为 Runtime 所需回执。使用原包补测中的正常结果、失败及批量部分成功做对照。
- 验证 Chat 缺席于插件公开工具列表，并通过该插件调用时被拒绝。运行浏览器执行器的环境不传上游模型网关密钥。

## Phase 2 打包并在 Windows Runtime 导入

- 把固定版本的原版执行器和确认的第一方接线组件纳入现有离线签名包。记录原包来源、许可、版本和二进制哈希。
- 通过本机隔离 Runtime 的离线插件管理路径导入测试包。验签、版本检查和就绪诊断通过后，验证该实例的 MCP 调用走插件自声明及通用宿主路径。
- 浏览器插件 `0.1.0` 固定上游 `0.43.0`，Windows x64 签名包约 12.85 MiB，解包文件约 36.21 MiB。计入 Runtime 保留的签名包后，已安装版本占约 49.06 MiB。独立验证的浏览器测试 2 项、既有打包回归 15 项及离线搬迁验包均通过。本机用仓库当前 Host 包 `0.2.28`、Node `22.23.3` 和独立目录执行实际离线导入。只有隔离实例使用浏览器测试发布根。

## Phase 3 Runtime 本机流程验收

- 用受控页面验证打开、语义快照、点击、填写、正文读取等浏览器操作。结合确认的工具范围验证批量填写和附件上传。
- Runtime 心跳声明上报 35 个原生名称。启动有界面 Chrome 后完成打开、语义快照、点击和 Markdown 正文读取。三项批处理回执为一项成功、一项失败、一项未执行，页面回读与回执一致。站点收到原样 27 字节的附件，目录外的测试文件被拒绝。Chat 直调返回 `TOOL_NOT_ALLOWED`，通过批处理调用返回 `INVALID_ARGUMENT`，随后关闭浏览器并停止隔离 Host。
- 回归覆盖批处理文件输出限制及打开新标签页的显式地址校验。普通点击、表单批填和页面等待继续通过。
- Device API 与测试网页均运行在回环地址。验收覆盖 Runtime 插件自声明、任务领取和回执。AID 生产 Agent 的工具投影与截图传递保留为独立接入项。插件 MCP 保留原生图片内容块，现有 Runtime JSON 回执未映射该内容块。

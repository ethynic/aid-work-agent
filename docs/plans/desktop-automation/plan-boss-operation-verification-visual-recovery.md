## 1. 交付与范围

2026-10-16 用户决定先开展[CLI 真机视觉实验](../../research/boss-visual-recovery-machine-experiments.md)，随后明确授权补齐实验必需的CLI采图与后台视觉API、×50真实计费，使用保存弹窗图实调GLM打磨提示词/DTO；整套恢复仍暂缓。最新实验与范围见设计P/Q节。实验补齐后所有采图/诊断均调用CLI，不另写页面控制路径；实验切片不等于Phase 1/3或整个功能完成。

权威设计：[BOSS 操作后验证与视觉异常恢复](../../design/recruiting/boss-overlay-heal-design.md)。承接 [GLM 需求](plan-boss-job-vip-entitlements.md#glm-obstacle-recovery)，遵守 [共同契约 2.1](../../system/runner-desktop-runtime-integration-contract.md)。本计划记录实施状态，不把设计写成开发完成。

目标链路：原操作 → CDP/领域后态核验 → 必要时视觉观察 → 一个有依据的恢复动作 → fresh 后态核验 → 继续任务。正常路径不调用 VL。广告、引导、安全取消和页面重设在原授权内自动执行；无定位 DOM 时允许视觉坐标，不要求旧文本/class 白名单命中。真实外发 unknown 仅只读核验，明确证据可派生确认成功，仍不明不重发。

先筛选/清除/打开详情打通，然后网页与浏览器弹层，最后接入其他操作；不借本轮扩展面试真实发送、修改批容量或未读业务。禁止新造 Runtime/本地 Agent loop、审批、恢复表/服务、通用 GUI 框架。CLI/MCP共享业务，Runner唯一编排任务/恢复/授权与任务预算；每轮派CLI做一次诊断HTTP调用，Agent后台API独占模型/提示词/厂商key与成本×20结算，Runner消费receipt后决定动作，不再直调/重复扣同次VL。

2026-10-16 用户修订已替换本计划旧调用/计费路线：新增 `POST /api/client/v1/boss/visual-diagnose`，CLI只配置我方后台URL/client-binding token，不带厂商SDK/key/baseurl。独立CLI配置后也可单次诊断，不凭建议新增业务授权。最终积分=实际token成本（元）×20、两位小数向上取整；0.01元→0.20积分、0→0，不叠×10/×100/全局倍数/旧自愈专项费，无最低1积分。

原审查中未纳入本计划的候选项与用户反馈统一见[招聘智能体、Runtime与BOSS待优化清单](boss-recruiting-optimization-backlog.md)，保留原1—32编号及已覆盖项映射；清单不扩大本轮实现范围，也不表示用户已批准所有产品政策变更。

2026-10-16 新增分流决议：页面操作正常返回但后态明确未满足时，fresh定位同一目标普通重试一次，再失败进入视觉排障；元素不可点击等直接执行错误跳过普通重试，进入视觉排障。已有内部重试算入同一预算，Runner不能再叠加；外发unknown沿用只读核验。当前仅实测既有open-detail内部重试成功，不代表通用恢复已实现。

本轮异常分支实验证据补充：直接错误必须带真实输入阶段，当前exit=2仍被映成EXECUTION_UNKNOWN，待Phase 2类型化修复；普通重试耗尽已有客服窗下两次正常返回点击、10次后验未达的真机证据。正式输入字段候选为operation/expected、execution/input_status/attempt、error/source/summary、verification/evidence和observation时点，重试时最多补两次简短历史。后续第二轮已增加standalone DTO v2结构化字段与最小Escape，见设计O节；早期仅goal序列化的记录仍保留为历史。正式恢复编排未实现。窗口图几何偏差、CLI身份核验误报均如实登记，不以关闭弹窗替代原目标完成。

## 4. Phase 2：首个正式切片——筛选、清除、打开详情

验收：首击仅收侧栏后一次重试成功；持续网页弹窗使两次后态失败后进入视觉恢复；直接不可点击零普通重试进入恢复；关闭后原目标可验证完成。加入关闭过渡帧和输入光标16像素反例，防止过早重试或无关动态阻断。正常成功路径不额外调用模型。

2. 明确CLI共享operation的执行阶段、目标、验证状态、尝试次数；一次普通重试由CLI负责，已有内部重试计入同一预算。Runner只消费事实和恢复建议，不额外再重试原页面动作。
3. 网页原图page_image_px为唯一主坐标空间，网页关闭复用现有浏览输入，业务输入复用现有Win32。正式动作校验原目标、目标区域/必要几何和时效；不用整图hash不变，不重写坐标换算；网页模式无法观察实际浏览器遮挡时，复用既有绑定窗口截图/输入兜底，各坐标空间显式区分。
4. 复用现有boss inspect/dismiss原语扩展生产消费fixture；仅声明实际交付的网页观察/动作能力。若需修改共享schema或Runtime接口，先走共同契约检查点，不创建第二套Runtime。
5. 明确后台URL/token受信配置和Runtime对boss的专属env注入，凭据不进模型或自由工具参数。复用已验证的同ID回取/冲突和费用receipt，补本次接线的producer/consumer兼容检查。

## 4. Phase 2：首个正式切片——筛选、清除、打开详情

1. 逐项复用原Executor验证：筛选徽章与实际选中条件、清除为0及选项清空、详情画布+右侧详情按钮+经历概览。canvas姓名不能当DOM成功靶点，背景列表按钮不能代替详情结构；切职等其他命令后续按第7节接入。
2. 操作正常返回后，在合理等待窗口读取后态；明确满足就成功，明确未满足才fresh定位并普通重试一次。普通重试耗尽进入统一网页排障；已有内部重试计数不得叠加。不可判定先核验，不因没读到就判失败。
3. 直接页面交互错误跳过普通重试进入同一诊断入口，附真实输入阶段和后态；若只读事实已证实原动作成功，承认成功。参数/后台网络/鉴权错误不强制调用视觉。
4. 网页截图经现有CLI薄client送后台API，消费诊断及合法单步建议；fresh核对后执行，先验证障碍消失，再验证/继续原目标。使用现有共享Executor/operation与Runner恢复路径，不创建独立恢复服务或本地Agent loop。
5. 结果保留requested/applied/skipped、实际目标、失败/unknown与部分成果；收费只消费一次API receipt，旧自愈费不与同次视觉费叠加。未改变用户筛选标准或业务发送授权。

验收：首击仅收侧栏后一次重试成功；持续网页弹窗使两次后态失败后进入视觉恢复；直接不可点击零普通重试进入恢复；关闭后原目标可验证完成。加入关闭过渡帧和输入光标16像素反例，防止过早重试或无关动态阻断。正常成功路径不额外调用模型。

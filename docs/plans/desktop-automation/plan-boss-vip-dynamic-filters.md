## 问题与需求

来源 trace：`tr_runner_11278c921c624aeda032a58fe29c79d2`（2026-10-13，agent2）。用户指定 PHP 职位并要求增加男性、25 岁以上、离职随时到岗及 3 日内活跃。实际调用只提交库中 `experience=1年以内 / educations=[本科] / salary=15-25K`，扩展条件被三维工具契约排除。探查结果把求职状态选项归入薪资行；设置薪资保底档位时，报告滚动三次仍越界。失败不能当作整项筛选成功，也不能把工具能力限制表述为页面没有该条件。

职位库是默认要求，当前对话可覆盖或增加筛选维度，仅作用于本次任务。可用标签、档位、单选/多选及范围控件由当前账号页面确定；会员与非会员不共用硬编码选项。所有请求在变更原状态前完成可表达性与参数校验；无法精确表达时明确返回原因，不能静默漏掉用户条件。

## 真机证据与设计

- 通过仓库 BOSS CLI 自动打开固定 profile 调试 Chrome，用户登录会员账号。主控独占端口 9222 及物理输入；不打招呼、不发消息、不写职位库。
- 旧 `filter-options` 真实执行仍只返回三行，薪资中包含求职状态；截图证实存在年龄、活跃度、性别、求职状态等更多筛选行。
- 页面截图/DOM bounds 为 2506×1476，主文档唯一 HTML 同节点 bounds/clientRects 比例为 2。将主页面 bounds 坐标 (1000,800) 映射为 CDP CSS (500,400)，发出 deltaY=300 的滚轮后，内容真实移动并露出经验、学历、求职状态和薪资。依据同次测量映射，不按系统 DPI 猜倍率。
- 会员面板内容真实 `overflow-y:auto` 祖先是 scrollport，三维行标签公共祖先只覆盖下部普通筛选内容，不能充当可视 clip。footer 与内容滚动区分开。
- 行归属优先使用共同结构父容器，排除其他行、背景候选人、折行与省略号诱饵；发现应覆盖可滚动面板，报告完整性。
- 保留经验、学历、薪资旧参数；新增通用精确行筛选及真实范围控件的可选参数。自然语言判断由云端模型完成，CLI 仅依据页面真实控件精确执行，并校验实际状态。年龄是真实双端滑块，不能伪造成离散档位或把“25岁以上”缩为“25–30岁”。

### 年龄与选中状态实证

原生点击轨道不能稳定得到目标值（fraction 0.2 得 23，随后 fraction 0.25 没变化），因此不采用单次坐标猜测。复用既有 Win32 窗口与落点守卫增加拖动入口后，左端从 16 拖动后读取 24，再根据 fresh 句柄与页面反馈调整，最终得到 25；右端从“不限”拖动后读取 45，再拖回右端恢复“不限”。最终页面真实显示“25—不限”，尚未据此推断全部可表达范围。

性别“男”与求职状态“离职-随时到岗”的选项元素 `class` 均从 `option` 变为 `option active`；只有页面明确状态才作为已选证据，不能以徽章数量或鼠标调用次数代替。已取证材料只保留筛选面板、几何及控件状态，不保存候选人正文或凭据。

首轮真实 CLI 年龄自动闭环暴露理想 mock 未覆盖的偏档：要求 25，四次固定步长纠正后仍为 26，返回 `EXECUTION_UNKNOWN` 并未提交。主控同一原生拖动入口从 26 调整到 fresh 轨道 fraction 0.28 后，页面精确显示 25。后续闭环以发出的目标坐标及实际 tooltip 建立观测边界，不追随输出句柄做恒定偏移；这项未通过前不标记年龄自动设置完成。窗口最大化后的 fresh bounds 为 3200×1618、CSS 比例仍为 2，所有新动作重测几何。

修正后真实 CLI `filter --age '{"min":25,"max":null}'`（run `ba9bcd64-4a28-4c13-91bc-f61d8b9addb0`）成功，2 次原生拖动后页面值精确为 25—不限，提交后徽章 `筛选·1`，耗时 62.4 秒。新 `filter-options`（run `257629fa-3678-4503-9fd3-4858ef865bea`）真实读取 13 行，薪资与求职状态分离，经验折行 10 项完整。

### 完整 MCP 真机结果

标准 MCP SDK client 消费真实 `boss-cli mcp --stdio`：`list_tools` 的筛选 schema 同时保留旧三字段并提供 filters/options_ref/age；新探查返回版本 2、完整性及当前账号 13 行。

run `2b68d2c3-1578-40bd-9432-f94d70656ca7` 的完整组合成功：经验1年以内、学历本科、薪资20–50K、性别男、活跃度3日内活跃、求职状态离职随时到岗、年龄25—不限；徽章 `筛选·7`。页面没有请求的15–25K，沿用既有保下限映射20–50K并返回明确 substitutions；不能将其报告为15–25K精确命中。耗时141.7秒，实际1次CSS wheel、2次年龄drag，所有离散行已选状态与年龄在提交前核对。

随后返回推荐页并重新打开面板，fresh DOM 独立读取显示上述6行的 `option active`、年龄 `[25,null]` 与徽章7持续保留。只读探查截图仅保存面板；偶然切到个人中心的全页临时截图已删除，不把后台保留iframe文本当作当前页面证明。

主控进一步确认：当前个人中心 `/web/chat/user-center` 的快照仍保留推荐页 `筛选·7`，正式筛选和探查 operation 原来也只依据文本前置，会误认当前页面。收尾在设置、清除及探查前用已有 `session.getUrl()` 核对真正推荐页；非推荐页返回 `WRONG_PAGE`，不发 click/clear/drag。回归必须让非推荐页 fixture 保留完整会员文本，证明门禁确实依据页面事实而非缺少文字。

最终真实错页验收：在个人中心分别执行 `filter-options`（run `a22b3829`）、`filter --clear`（run `49c20a16`）、`filter --age ...`（run `8a9a2563`），均在约66–75毫秒内返回 `WRONG_PAGE`，perf无snapshot或输入，连接关闭。随后正式 `goto recommend` 返回推荐页，既有7项未被错误清除。

验收边界：这是本机 CLI/真实 MCP 到 BOSS 页面的验收，云端生产路径由隔离 unit/owned 恢复矩阵验证；agent2 服务端及测试客户机未部署/更新，不声称已上线端云全链路。当前复杂7项约142秒，继续遵守180秒既有调用期限，未为掩盖耗时扩大超时；年龄明确16–45整数及上限不限，范围外不能猜测或静默放宽。

原 [职位匹配设计](../../design/recruiting/resume-job-matching-design.md) 明确排除了年龄/活跃度/性别，属于历史范围；本次用户明确扩大聊天条件支持范围，设计需同步修订。旧 VIP 滚动提交 `35b41d0d / 3855e20a` 不代表当前会员面板验收通过。

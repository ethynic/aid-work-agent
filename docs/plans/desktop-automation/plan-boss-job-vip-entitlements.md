## 范围与契约

用户要求：职位管理补齐会员条件；经验、学历、求职状态按实际页面多选；薪资由手填范围表达；专业暂不实现。会员可按头像附近VIP标识识别，非会员面板默认折叠高级区。非会员误配高级条件时不点击高级项；遇会员付费弹窗只安全关闭并将高级条件列为已跳过，再继续普通筛选。未知时先由Agent询问用户是否VIP，回复只是本次提示依据，不能覆盖真实付费证据或授予其他权限。

复用 `bs_recruiting_operator_jobs.job_requirements` JSONB，无表变更，所有租户校验沿用现有服务。旧 experience(str)、salary(str)、educations、keywords（评分）、notes保留可读；新字段为：

| 字段 | 语义 |
|------|------|
| experiences: string[] | 经验多选；新表单保存此字段，旧experience回填为单元素；两者同存须避免冲突 |
| job_statuses: string[] | 普通求职状态多选 |
| salary_range: {min?:number,max?:number} | 手填薪资K范围，正数/次序校验；旧salary可兼容回填；实际页面仅有档位时显式说明映射 |
| vip_filters.age: {min?:integer,max?:integer\|null} | 年龄范围，上限不限为null，精确控件范围仍校验 |
| vip_filters.activity / gender / not_viewed / not_exchanged / job_hopping: string | 页面对应单选值；空值/不限表示不设 |
| vip_filters.schools: string[] | 院校多选：985/211/双一流院校/留学/公办本科/QS 100/QS 500 |
| vip_filters.first_degree_only: boolean | 只看第一学历；依附院校条件，未选院校时不能孤立启用 |
| vip_filters.boss_keywords: string[] | 页面牛人关键词，多选；与原keywords评分字段区分 |

所有已知选项以本次用户清单与实际页面为依据；职业配置不直接证明设备会员。`boss_jobs_list`应输出完整配置和可用普通/VIP执行参数，模型先探查当前账号，再合并职位默认和聊天覆盖，不能因库配置了VIP选项即认为账号有权益。

UI分组：普通筛选（经验/学历/求职状态/手填薪资），VIP专享（年龄/活跃度/性别/近期未看/同事交换/院校+第一学历/跳槽频率/牛人关键词），评分补充（原keywords/notes）。沿用Base*与语义token、可滚动大表单和窄屏布局；后台允许保存VIP模板，但明确执行受当前BOSS账号权益限制。

## Provider与云端边界

已读[共同契约v2.0](../../system/runner-desktop-runtime-integration-contract.md)。不修改Runtime core、Device wire、binding或公共壳。BOSS Provider 0.3.2→0.3.3，新增可选membership提示/第一学历参数与探查权益投影；旧三维/filters/age继续兼容，MCP inputSchema与manifest digest同源，云端旧设备门禁保持。

会员探查输出 `membership.status = vip | non_vip | unknown` 与不含凭据的依据；检测必须绑定本次浏览器账号，不把面板“VIP专享”标题或广告当会员证据。正证据来自当前主页面头像区域徽标；没有明确非VIP证据不得把缺少徽标判为非VIP。状态重测，遇付费窗以负证据覆盖本次会员提示，后续本次调用不再尝试VIP。

执行返回 `applied_rows/age`（实际生效）与 `skipped_filters`（VIP被屏蔽及原因），不能把部分应用报为全部满足。未知且有VIP请求时，在清除/点击前返回明确需澄清的状态；仅普通条件可直接执行。会员付费窗必须结构确认安全关闭目标且fresh校验已消失；失败停止，不盲点、不点击购买，不用无限重试。写后未知仍保持unknown不重放。

探查返回不含原始身份的`account_ref`（头像/导航名称本机SHA256摘要）；使用用户会员提示时必传`membership_account_ref=同一探查的account_ref`。云端校验它与受租户/会话/设备约束的options_ref记录一致，Provider清除前核当前账号摘要，输入及确认前继续核验，回执再次绑定账号。禁止A账号探查后切换B再沿用A的会员回答；摘要不写原头像地址/姓名，缺少可核验账号结构时先恢复页面，不能猜测。原始参数一直保留于durable意图与重放，不在派发阶段偷偷注入或替换字段。

## 暂不实现：GLM多模态异常恢复

用户第6项只登记：当动作无法按预期执行且现有确定性规则无法诊断时，调用既有云端glm-5.3-flash多模态模型，附预期动作与当前截图，解释遮挡/付费/广告并给关闭候选坐标。关闭仍经已有原生输入、身份与坐标/后态校验，不把模型坐标直接当授权。广告可关闭后继续；会员专属筛选付费则关闭并回退普通项；必需付费的其他功能则告知用户并停止该功能。不能以此自动购买或绕过收费。本次不接入该模型流程，不复制现有overlay自愈，也不限制正常模型输出token代替费用预算。

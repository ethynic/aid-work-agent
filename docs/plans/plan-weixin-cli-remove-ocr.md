## 实施与验收

按[微信 CLI 设计](../design/weixin/weixin-cli-design.md#13-移除本地-ocr)执行。以[企微 W27](plan-wecom-cli-group-chat-experiment.md#w27-企微删除添加客户与-ocr-发行依赖2026-11-07)的发行清理为参考，微信采用自身可验证的原生接口。

需要替代原本本地 OCR 的聊天正文读取时，正文和截图留在本机。新增的服务端多模态调用仅用于 UI 坐标定位。

1. 为现有视觉代理用例测试已放行模型的请求，并验证 401/402、缺绑定与直调配置场景。端点与设备契约沿用现有实现。
2. 真机证明搜索结果身份、当前会话标题和发送目标证据。固定控件优先复用原生边界。需视觉标定时仅缓存稳定布局坐标，重校当前窗口，动态行和正文实时读取。
3. 证明消息正文、发送方、分页重复、未读计数、媒体占位和旧水位恢复。无法判定发送方的消息不推进水位。禁止把失败解释为空消息或未读清零。
4. 迁移后清理生产脚本、OCR 专用匹配、无生产调用的观察实现和包内 RapidOCR/Python 资源。验收分别核对 CLI、实际加载的 MCP 工具、Runtime 原调用与产物文件清单。旧签名包保留原运行兼容。

### Phase 3A 发送前标题

`weixin_message_send_v2` 在同一微信窗口和进程下读取唯一原生会话标题及输入框边界。预检与提交前按完整原生标题核对已确认观察中的会话。原生标题仅在本机观察基线记录，保留任务名称与微信显示名格式不同的既有绑定。当前基线缺少原生标题时使用许可目标名称全等核对。发送许可、观察水位和原回执语义沿用既有契约。

Windows 微信 4.1.15.13 真机通过只读预检，当次观察锚与发送预检返回的原生标题一致。独立测试覆盖别名绑定、同窗换标题零提交和私有标题字段伪造，发送相关通过 21/21，MCP 和清单 17/17。全量 222/224，同两项基线失败。未实际发送消息。

### Phase 3C 发送入口收敛

新微信插件保留 `send --domain chat` 和 `weixin_message_send`，由插件签名清单声明发送工具。移除新插件的 V2 发送工具，并保留服务端对旧设备已提交回执的现有接纳路径。微信云端自动回复及正文同步保持停用。

发送走计费多模态接口定位控件。模型只接收空白输入框区域。目标、原始草稿和提交后的消息原文均通过 UIA 核对。在同一个选中会话中，只有读到草稿清空和可连续对齐的新增精确文本时，才回执微信界面已出现提交记录。无法核对时使用既有未知回执语义。发送链路移除 OCR 引擎调用及模糊文本比对。验收覆盖本机工具发现、签名清单、Runtime 声明消费、代理输入边界及零重复提交。新版包按当前源码挑选编译文件。

微信 4.1.15.13 真机用单聊和群聊执行只读预检。两个会话的选中行、空输入框、合法焦点坐标及最新消息视口均通过 UIA 核对。正式 CLI 走回环代理时，每次只传一张 988×79 空输入框裁剪图，模型请求中无目标名称与正文。代理故意返回越界坐标，两个调用均在输入前停止。发送成功、草稿变化、未知回执及单次回车由夹具验证。

Windows 独测：发送、历史、MCP 与代理定向 53/53，Runtime 与共享核心 37/37，插件打包 16/16，五个 PowerShell 文件的语法和编码检查通过。微信 CLI 全量 218/220，两项既有失败与 Phase 4 基线一致。独立聊天搜索仍在 Phase 3B 范围。真机仅做预检。

## 本机原生证据

- 微信 4.1.15.13 的 `session_list` 可读 14 个会话行。原生会话名与对应 `session_item_` 标识匹配。样本有三条数字未读提示，分别为独立行或和预览同行，均有同一位置的红角标。另有红角标样本缺少数字提示，不能由像素推测计数。
- 当前会话暴露明确标题、`chat_input_field` 的 `ValuePattern`、`chat_message_list`、文本行和时间行。文本项原生边界横跨列表全宽，仅凭边界无法判断发送方向。已采到原生正文节点与居左气泡同时存在的窗口，需补居右样本和历史跨页核对。
- 原生搜索框可回读输入，结果面板暴露列表与分栏。实测同一个完整名称可同时出现在不同分栏，选择目标需要核对业务分栏和当前标题。

### Phase 4 历史与持续观察

1. 历史与观察复用 CLI 本机 PowerShell/Win32 驱动。同进程 UIA 消息项的原生名称和时间标签是正文与时间的唯一来源。历史逐页滚动，以同一目标会话内有序重叠证据合并。缺少可信重叠时显式停下。
2. 本机窗口位图仅用于核对 UIA 位置、识别左右气泡和定位左侧群成员昵称区域。仅有原生节点可对应时核定群成员显示名，证据不足保留未确认。昵称无法核实不改变已确认的本人或他人方向。
3. CLI 是本机消息、方向与观察证据的唯一生产者。观察沿用 `session_observer_v1` 水位、ID、断层、和原签名发送约束。输入采集不新增云端处理或上传。截图证据继续用本机 DPAPI，返回本机引用。历史保留原参数、结果字段及内联/文件语义，发言人显示名为可选补充。
4. 回归验证空窗口、相同正文重复、目标变化、方向不明、跨页重叠、观察连续性和原发送桥。真机验证单聊同时有本人和他人的消息、群聊时间及媒体条目、未核实昵称、截图无上传。验证过程只读，结果仅记录计数等脱敏证据。
5. 以企微 CLI watch 的单轮轮询为参考，微信新增独立本机 `watch`。精确绑定已打开会话，默认十秒一轮，首帧只建基线。结果仅向本机输出新增条数，失败保留原水位。
6. 按用户确认停用 `weixin.conversation.v1` 云端自动回复。Runtime 停止微信会话引擎及能力登记，服务端停止发布、分配和续租微信自动回复并拒收新旧租约的正文批次。历史、观察及含预览正文的未读命令保持本机可用。核对派发、结果与历史补传边界。部署与已安装旧版本升级独立执行。
7. 历史改由 `target_name` 直接读取手动打开的会话，旧引用缺会话身份时给出切换入口的提示。采集和轮询固定记录已选会话的 UIA 运行时标识，重名切换保留水位。停用自动回复后仍按原许可与证据契约接纳旧版已提交的发送回执。

微信 4.1.15.13 真机用 `--target-name` 各读取三页。单聊读取 24 项，确认 7 个时间标签、7 条本人消息和 8 条他人消息，另 2 条方向未确认。群聊读取 16 项，确认 3 个时间标签和 11 条他人消息，另 2 条方向未确认。两种会话各读到 2 条媒体描述。群成员昵称均未获得 UIA 核验。正式 MCP 首轮建立水位后再次请求，两种会话均返回 0 条新增。真机 `watch` 两种会话均成功建立水位，截图文件新增数为零。测试窗口无新消息，增量事件由回归夹具验证。全程代理探针收到 0 个请求，无实际发送。

独立验证：微信 CLI 232/234，失败的原生搜索夹具和 OCR 独立文本匹配与基线一致。Windows Runtime 定向 50/50，共享核心 8/8。容器单元 123/123，隔离 PostgreSQL 定向 100/100，加领取集成 10/10。回炉隔离库 91/91，包括停用后旧发送回执正常结算及重放，新许可被拒。更广用例的旧 C3 相同文本回显测试与企微定时消息 API 六项失败均在基线复现。运行包及服务器未部署，升级前旧 Runtime 可能仍尝试发出在途请求。

## 安装验证

- 下载包 `weixin-0.1.0-dev.aidplugin.zip` 的 SHA256 与交付记录一致。使用已安装 Runtime 的固定 Node 和包配套隔离公开根运行 `verify-offline.py`，签名、清单与只读入口通过。Runtime 的插件存储使用同一隔离公开根成功导入该包，重开存储后记录仍为启用。
- Runtime 1.3.1 自带信任配置下，原生验包返回「插件发布者不受信任或签名无效」。已运行 Runtime 的信任和配对资料保持原样。需要其认可的签名包，或包含对应公开根的验收 Runtime。
- 微信 4.1.15.13 已切到前台，CLI 仍未核对到已登录会话列表。以合成群名调用现有历史入口返回 `UI_CHANGED`，返回消息数为零。2026-11-23 后续复验确认该版本在已登录状态未暴露原生 UIA 控件。重启更新到 4.2.0.13 后，修复弹窗识别并用 CLI 读通真实群聊。见[窗口复验](plan-weixin-cli-window-doctor.md#微信-42013-真机复验)。

## 当天总结验证

- 通过 UIA 采集消息和标签。北京时间日期按任务受理时固定，在次日零点或任务期限截止后不接受正文。最多扫描十页，最多提交 500 条或 20,000 字符。日期不明、媒体及裁切文字排除在外。覆盖不足时显示局部总结；无法核实范围且没有可总结文字时返回明确失败。
- 专用 PostgreSQL 使用了已包含锁定依赖 `rfc8785==0.1.4` 的本地开发镜像。验签、属主隔离、旧 Runtime 不接新调用、确认后换设备拒绝、零积分及排队期间耗尽均拦截、原作业开始前拒绝正文、并发只调用模型一次，以及结果和任务记录不保存原文已验证。模型替身只接收合成文本。七种 Nginx 路由用 60 KiB 合成请求验证了上传未结束时直接转发。
- Web 用例覆盖手动输入、明确同意、旧链接、空结果和部分覆盖。Chromium 用合成接口在 1280 px 和 390 px 验证输入、授权和结果展示。
- 新版隔离包 `weixin-agent-20261123-093959-905f65-weixin` 已使用 Runtime 1.3.1 的固定 Node 验签、搬迁和导入隔离插件库。工具声明包含 `weixin_group_daily_summary`。实际已安装应用仍拒绝该隔离签名。真机已核验本机 CLI，连接中心与 Runtime 的组合待验。

最终验证状态：原生 CLI 完整 196 项、最终独立定向 19 项通过；后端 419 项完整相关回归后，修复版独立定向 80 项通过；真实 PostgreSQL 18 项回归后重跑受影响的 8 项；Web 36 项与生产构建通过。真机及 agent2 发布步骤待授权和环境就绪。

## 验收范围

依据[连接中心设计](../system/connection-center-design.md#211-微信-agent)、[微信 CLI 设计](../design/weixin/weixin-cli-design.md#14-单会话最新消息与本机副本)及[Runtime 共同契约](../system/runner-desktop-runtime-integration-contract.md#微信正文仅限本机共同检查点)。

1. 核对下载包、发布者与已安装 Runtime 的兼容性。记录签名拒绝、插件诊断及实际版本。
2. 通过本机 `read --domain group-history --target-name <群聊全名>` 核对 Windows 微信当前选中会话的标题和群聊类型后读取。原有 `chat-history` 保留单聊支持，已交付 CLI 拒绝未知的 `group-history` 域。连接中心由用户输入完整群名。
3. 手动生成有正文依据的群聊摘要，用户可区分空历史、读取失败与总结失败。当前签名同步工具的回执维持既有字段。
4. 验证正常、未登录、群名不符、单聊误选、空记录和部分历史，回归企微入口及旧 Runtime 已有能力。覆盖 Windows 微信实机及 Web 布局。

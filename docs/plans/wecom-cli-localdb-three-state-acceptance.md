# wecom-cli 本地库通道——三态验收说明（退出登录 / 同 PID 切号 / 锁屏）

> 目的：关闭 P1a 任务 1.14 与冻结点 5（登录判定规则）。本验收回答三个问题：**退出登录后系统是否还会读旧账号数据、切换账号后是否零串号、锁屏下本地库到底能不能用**。
> 关联：[开发计划](plan-wecom-cli-localdb.md)（任务 1.14）、[设计](../design/wecom/wecom-cli-localdb-design.md) §3.4/§5/§9.6、验收记录见计划「P1a 验收记录」。
> 执行人分工：**状态切换（退出/登录/锁屏）由人工操作**；命令执行与结果采集由助手按本文档逐条执行并记录。预计总时长 40–60 分钟（不含矩阵条目决定）。

## 1. 要验收的内容（三项状态 × 四类关注点）

| 状态 | 场景定义 | 关注点 |
|---|---|---|
| **A 退出登录（进程仍在）** | 在已登录客户端上退出登录（不关进程） | 登录门禁是否拒绝；**缓存密钥/解密链是否被彻底隔离**（绝不读旧账号数据） |
| **B 同 PID 切换账号** | 退出后用另一账号登录（记录主窗口 PID 是否真保持） | 身份链是否切到新账号目录；**零串号**（cursor/ref/水位/密钥四类 A 账号残留全部失效） |
| **C 锁屏（登录态）** | Win+L 锁屏，客户端保持运行 | 登录探测在锁屏下的实际表现；**本地库只读在锁屏下是否可用**（设计 §9.6 声明的验证）；UI 通道对照 |

四类关注点（每项状态都从这四个角度验证）：① 登录探测原语输出；② doctor 深检的模式结论与状态落盘；③ 三个本地库操作（read-session / unread / watch）的拒绝或放行行为；④ 密钥与水位存储的文件级状态。

## 3. 逐状态验收项（内容 / 标准 / 方法 / 自动化程度）

### 状态 A：退出登录，进程仍在

人工操作：客户端内退出登录（**不关闭进程**），确认主窗口变为登录页或托盘消失（两种形态分别记录，见 §5 已知限制）。

| 项 | 验收内容 | 验收标准（判定） | 方法 | 自动化 |
|---|---|---|---|---|
| A-1 | 登录探测原语 | `login_state ∈ {need_login, offline, unknown}`，**不得为 online**；托盘隐藏形态输出 offline/unknown 属"待确认限制"，如实记录不判失败 | 探针脚本 | 自动 |
| A-2 | doctor 深检 | `aid-wecom doctor --localdb`：步骤 2 终态（登录引导文案）、**guidance 不含"已启用"**、退出码 1（引导失败语义）、state 文件不产出 db 模式（与 P-2 基线对比） | doctor --localdb --json | 自动 |
| A-3 | read-session 拒绝 | `read-session --channel local-db --target-name X` → `NOT_LOGGED_IN`（或 IDENTITY_UNCONFIRMED），**effect=none**；关键证据：localdb.log 无 `keyscan_result`、artifacts/localdb 无解密残留、key.bin mtime 未变——**缓存密钥与解密链被门禁彻底隔离** | 命令 + 探针 + 日志 | 自动 |
| A-4 | unread / watch 拒绝 | 两命令 `--channel local-db` → NOT_LOGGED_IN；watch 额外断言：水位文件未被读写（mtime 未变）、无 UI 兜底（NOT_LOGGED_IN 不在兜底白名单） | 命令 + 文件对比 | 自动 |
| A-5 | **缓存密钥存在仍拒绝**（核心项） | 预置假密钥（P-3）后重跑 A-3/A-4：行为完全一致——证明拒绝依据是登录门禁而非密钥可得性。验收后删除假密钥 | 脚本 + 命令 | 自动 |
| A-6 | UI 通道对照 | `read-session --channel ui` → 同样 NOT_LOGGED_IN（UI 也要登录）；确认 A 态下没有通道能读出数据 | 命令 | 自动 |

**A 通过标准**：A-1～A-6 全部符合；任一"应当拒绝却读出/解密成功"= P1 失败（本轮不通过）。

### 状态 B：切换账号（退出 A → 登录 B）

人工操作：退出登录 → 用账号 B 扫码登录。**登录前记录：主窗口 PID（探针脚本）、A 的全部基线快照。**

| 项 | 验收内容 | 验收标准 | 方法 | 自动化 |
|---|---|---|---|---|
| B-1 | 身份链切换 | 探针：`account=B 的目录账号`、`identity_confirmed=true`、`window_pid` 如实记录（与 A 相同/不同都算有效数据，标注实际形态） | 探针脚本 | 自动 |
| B-2 | cursor 零串号 | 用 A 会话返回的 cursor 读取 → `CURSOR_UNSUPPORTED`（账号不匹配），**不得返回 B 账号数据** | 命令 | 自动 |
| B-3 | ref 零串号 | A 签发的账号绑定 target_ref 读取或发送 → `TARGET_REF_STALE`，发送驱动零调用 | 命令 + 日志 | 自动 |
| B-4 | 密钥隔离与重建 | keystore 中 A 的密钥：页 1 核验失败 → 清除 → 重扫 B 密钥 → 入存（binding=B）。证据：key.bin mtime 变化 + 日志 keyscan_result；**解密成功的是 B 的库**（integrity=ok 且 conversations 属 B） | doctor --localdb 或读取命令 | 自动（需矩阵条目，见 §4） |
| B-5 | watch 水位重置 | watch DB 水位文件账号切换 → 基线重建（A 的水位不继承到 B）；B 首轮为基线轮（不回放 A 时代消息） | 命令 + 文件对比 | 自动 |
| B-6 | doctor 模式结论 | 步骤 3 选 B 目录、`identity_confirmed=true`；矩阵含该版本 → mode=db；不含 → ui(compat)（如实记录，身份部分已验证） | doctor --localdb --json | 自动 |
| B-7 | 切回 A 恢复 | 退出 B → 登录 A → 探针回到 A、doctor 重新确认 A、B 密钥按 §3.4 失效处理 | 探针 + doctor | 自动 |

**B 通过标准**：B-1～B-3、B-5（零串号三项）必须全过；B-4/B-6 依赖矩阵条目（见 §4 分层），未加条目时记录实际行为即可。

### 状态 C：锁屏（登录态）

人工操作：确认客户端已登录并运行 → **先启动采集脚本**（`sleep 90 && <探针+命令> > 锁屏结果.json`，或经 SSH 会话执行）→ Win+L 锁屏 → 等待采集完成 → 解锁。

| 项 | 验收内容 | 判定 | 方法 | 自动化 |
|---|---|---|---|---|
| C-1 | 锁屏下登录探测输出 | **如实记录**（online/need_login/offline/unknown 均为有效数据点）。已知限制：托盘隐藏/跨会话窗口枚举可能判 offline——这是要确认的，不是必须通过的 | 采集脚本 | 自动（定时）+ 人工锁屏 |
| C-2 | 锁屏下身份链 | probeCurrentAccount 是否仍确认账号（文件句柄枚举跨锁屏行为） | 采集脚本 | 同上 |
| C-3 | 锁屏下本地库只读 | 分两种结果**都算验收完成**：① 可用（读出数据）→ 设计 §9.6 收益实证，登记；② 被登录门禁拦截 → 记录拦截点与原因，产出"后台场景支持"的设计决策项（不是失败） | 采集脚本 | 同上 |
| C-4 | UI 通道对照 | 锁屏下 UI 通道读取 → 失败（交互桌面缺失类错误），语义正确 | 采集脚本 | 自动 |
| C-5 | 解锁后恢复 | 解锁后探针/doctor 恢复正常（online） | 探针脚本 | 自动 |

**C 通过标准**：C-1～C-3 产出明确记录（实际行为 + 拦截点），允许"不可用"结论；C-4/C-5 必须符合预期。C 的价值是把"锁屏可用性"从理论声明变成实测结论，并为"登录判定是否需要非窗口证据源"提供决策依据。

## 5. 已知限制与注意事项（执行前必读）

1. **登录探测的窗口依赖**：login 原语靠窗口枚举判定。托盘隐藏、锁屏跨会话、无可识别主窗口都会判 offline/unknown——这正是三态验收要实测的边界，验收中出现的此类输出按"记录"处理，不算执行失败。
2. **退出登录的操作形态**：客户端内"退出登录"与直接结束进程是不同场景，本验收只测前者（结束进程属于 WECOM_NOT_FOUND 常规路径，已有覆盖）。
3. **账号 B 数据影响**：登录 B 会把 B 的消息同步落本机（含本地库文件）；建议用非生产账号，验收后如需清理按企微客户端自身机制操作，**助手绝不手工删除企微数据目录**。
4. **假密钥（A-5）**：仅写入 keystore 用于门禁验证，验收后立即清除；全程不出现在命令行参数/日志。
5. **每次状态切换后**先跑探针脚本确认状态到位，再跑验收命令——避免状态未生效导致误判。
6. **结果记录**：所有命令带 `--json`，输出与 localdb.log 相关行、文件 mtime 对比一并归档到验收记录（计划文档追加小节）。

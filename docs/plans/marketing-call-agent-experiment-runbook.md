# GLM 执行手册：无云图依赖的第一阶段实验

日期：2026-09-05；进展更新：2026-09-07。状态：E0 起步工具已实现，真机截图、模型返回、现场单步导航和系统拨出已验证；E0 严格解析及 E1 正式实现未完成，见[真机记录](../research/marketing-call-agent-experiments/device-validation-20260907.md)。本文是前置实验 P0-A 的执行依据；与旧计划冲突时，以本文的实验范围为准。

关联：[主计划](marketing-call-agent-plan.md) · [详细设计](../design/marketing-call-agent-design.md)。

## 1. 给开发 GLM 的直接任务

先实现 E0、E1、E2 的独立实验工具，证明“安卓截图 → GLM-5.3-Flash 定位 → 坐标转换 → ADB 单步动作 → 新截图回读”可用。没有云图安装包、账号、虚拟号码也必须能开始。用户可提供任意允许测试的替代 App；尚未提供时用系统设置的搜索页面做 E1。不要先开发生产业务系统。

有真机和音频配件时，另做 E3、E4：人工从手机拨普通测试号码，验证电脑与电话双向音频及 AI 对话。E3/E4 不依赖替代 App、云图或自动拨号。没有硬件时继续完成视觉工具和离线用例，将真实音频实验标为 BLOCKED，不能用电脑麦克风对话替代通过证据。

结果分开报告：视觉控制、替代 App 表单、真实电话音频、AI 电话对话。任何单项通过均不代表云图适配完成。云图录音为黑盒，不检查、不上传、不对账；Agent 音轨只作非权威参考。

## 2. 固定技术方案与代码边界

| 层 | 首版选择 | 明确约束 |
|---|---|---|
| 实验端 | Python 3.11＋独立虚拟环境 | 新建 `experiments/marketing_call_agent/`，不改生产启动、数据库或部署 |
| 安卓控制 | Android SDK Platform Tools 的 ADB；Python `subprocess.run` 参数数组 | 显式 `-s serial`，二进制截图；禁止 shell=True 和模型拼接命令 |
| 模拟器 | Android Studio 官方 AVD，首个基线 Android 14 / API 34 | 按宿主 CPU 选择镜像架构；不是最终机型承诺 |
| 图像 | Pillow 读 PNG、缩放、绘框；Pydantic 校验定位 JSON | 原始截图像素为基准，MVP 禁裁剪、禁旋转、禁填充，只支持等比缩放 |
| 视觉 | GLM-5.3-Flash，通过 httpx 调用配置的官方图文端点 | 先实测图像请求；不能静默切文本模型/别的视觉模型 |
| 动作 | ADB `input tap/swipe/keyevent`；中文输入另见 E2 | GLM 只返回页面与目标框，不直接执行工具；不靠控件树定位替代视觉 |
| 记录 | JSONL 事件＋JSON 结果＋截图 | 仅虚构测试数据进入仓库；敏感原始材料加密保存在仓库外 |
| 音频 | python-sounddevice/PortAudio 的 RawInputStream、RawOutputStream | 显式指定输入输出设备，原生采样率先检测；不可默认用电脑麦克风 |
| 语音 | 流式 ASR → 有限状态话术 → 文本 LLM → 流式 TTS | 沿主设计供应商适配；E3 不需要任何语音模型 |

GLM 在实现时记录实际安装版本并锁定依赖，不升级仓库生产依赖。Python 版本不可用时先报告并使用项目允许的兼容版本，记录偏差。实验 CLI、目录和配置以下均为**待实现契约，不是已存在命令**。

建议文件：`cli.py / adb_device.py / vision.py / geometry.py / runner.py / audio_probe.py / schemas.py / tests/ / README.md / requirements.lock`。无需为 E1 创建 Kotlin App、Appium 服务或定制 ROM。

## 3. 输入、配置和结果契约

用户提供：一台已授权 ADB 的模拟器或安卓设备；可用视觉 API 密钥；可选替代 App 包名。音频阶段再提供手机 A＋SIM、测试接听端 B、全双工音频桥。

配置样例只允许虚构数据和环境变量引用：

```yaml
device_serial: emulator-5554
target_package: com.android.settings
mode: observe
vision:
  model: glm-5.3-flash
  endpoint_env: MCA_VISION_ENDPOINT
  api_key_env: MCA_VISION_API_KEY
  max_image_edge: 1280
limits:
  max_actions: 10
  max_model_calls: 20
  action_retry: 0
  run_timeout_seconds: 120
```

每个 run 结果为 `PASS / FAIL / BLOCKED`；报告环境、测试项、总数、成功数、拒绝数、失败原因、证据路径和未证明的能力。缺设备、账号、模型权限属于 BLOCKED；定位错误或验收不通过属于 FAIL。mock 和人工代操作分别标记，不计入自动成功数。

待实现命令入口：`python -m experiments.marketing_call_agent.cli`，子命令为 `doctor`、`observe`、`run-case`、`audio-devices`、`audio-probe`、`voice-call`。每项提供 `--help`。`run-case` 默认只画框，执行必须显式传 `--execute`；音频输出与真实通话均由现场人员准备好测试端后显式启动，程序不得自行拨任意号码。

## 4. E0：环境探测与单张定位，第一项实际工作

1. 检查 Python、ADB 版本和设备清单。指定 serial；多个设备时不自动猜选。`unauthorized/offline` 时打印恢复指引并退出。
2. 用户打开替代 App 的无敏感测试页；没有替代 App 则打开系统设置。记录前台包名、系统版本、`wm size`、`wm density`、方向。
3. 用 `adb -s SERIAL exec-out screencap -p` 获取 PNG 字节；解码读取真实宽高。截图黑屏/损坏则 BLOCKED，不尝试绕过受保护窗口。
4. 把全图等比缩到长边不超过 1280，记录原图和输入图尺寸；向 GLM 请求一个可见且低风险的目标，例如“搜索入口”。
5. 要求返回 `frame_id, page, found, bbox_px, label, ambiguity`。坐标为传入图片像素，四项分别是左上/右下；找不到返回 `found=false`，禁止猜测。
6. 转回原图坐标并绘框输出。E0 绝不点击，人工对照框是否落在真实目标。

通过：一张实际设备截图完成真实 GLM 图文调用、JSON 校验和正确绘框，记录模型 ID/请求耗时。没有密钥时可开发解析器与样例测试，但 E0 真实模型部分必须标 BLOCKED。

## 5. E1：替代 App 单步点击，第一阶段最小完成目标

先用固定竖屏、全屏截图，禁止在控制宿主机窗口坐标和安卓像素坐标之间换算。设原图 `W,H`，模型图 `w,h`，框中心 `xm,ym`，则 `x=round(xm×W/w), y=round(ym×H/h)`；检查边界，不能额外乘 DPI。

执行顺序：

1. `observe` 获取目标框；保存原图、输入图、模型 JSON、变换后的框。
2. 执行前再截图，核对前台包名、方向和尺寸。用去除状态栏/时钟区域后的内容图比较页面变化；有明显变化则旧定位作废，重新定位，不放宽阈值强行点击。
3. `adb input tap x y` 只执行一次。等待并截取新页面，由 GLM 判断预期后置条件；超时最多做 2 次只读观察，不重复点击。
4. 后置条件不成立，输出 FAIL 并停止；成功后才允许下一动作。返回键也作为单独动作记录。

默认用例：系统设置首页 → 点击搜索入口 → 确认搜索输入框出现 → 返回首页。仅导航，不改 Wi-Fi、权限、账号或其他设置。如果该系统没有此入口，由 GLM 从截图选择“关于手机”等只读详情入口，并将选定目标及后置条件写入用例文件后再运行；不能在运行中随意换任务。

有用户提供的 App 时，新增配置而不改底层算法。必须先人工定义 `start_page / target_label / expected_page / allowed_packages`。用户 App 不支持某类操作时记为覆盖不足，不能把设置 App 导航当作表单能力。

验收：30 次导航循环均记录结果，至少 29 次自动完成、0 次错误点击其他功能；另做 10 次目标不存在/遮挡/旧截图/异常 JSON/越界框测试，全部不执行点击。至少 10 张页面使用原图与缩放图分别定位，映射目标均落在人工标注目标框内。拒绝执行计入拒绝率，不计入成功。

单元测试覆盖几何变换、越界、旧 frame_id、超时、设备 serial、命令参数注入。真实 GLM 定位和 ADB 点击的证据必须独立于单元测试。

## 6. E2：替代 App 表单输入与保存

E1 通过后进行。优先使用用户提供的 App 的测试表单，要求能新建、输入中文、保存、离开重进查看。若没有这样的 App，本项 BLOCKED；可开发本地 fixture 测试输入逻辑，但不得把自建页面结果记为第三方 App 通过。

用虚构文本：标题 `实验记录-运行编号`，备注 `客户希望下周二联系，仅用于自动化测试`。按截图逐步定位输入框、输入、保存，再离开重进回读。备注不能写入真实客户。

中文输入使用小型受控 Android IME 伴随组件：接收指定实验连接的文本请求并通过 InputConnection 提交。限定测试包、单次 nonce/长度与有效期，不提供任意命令广播；测试后恢复原输入法。如果用户 App 已有可验证的安全粘贴路径，可先使用并记录该路径，不能把 `adb input text` 的英文成功冒充中文支持。

验收：10 条虚构记录，中文/标点/换行按字段支持范围完整回读；0 次重复保存；保存后超时实验先读取已有结果，无法确定则停止。没有离开重进的结果截图，不算持久化通过。E2 不依赖电话与音频。

## 7. E3：普通电话双向音频，独立于 E1/E2

此项必须真机。手机 A 正常 SIM 拨打内部人员的电话 B，初版手动拨号和挂机。不要接云图、不要虚拟号、不要自动拨号；普通电话足以验证本段媒体路径。

接线：`A 耳机输出 → 电平适配/隔离 → 电脑声卡输入`；`电脑声卡输出 → 衰减/隔直/耳麦匹配 → A 麦克风输入`。使用经过验证的双向电话耦合器/配件组合，不能把普通 AUX 线当作完整电路。没有合适配件时输出采购能力清单和 BLOCKED，不能凭软件或任意接线保证通话注入。

1. `audio-devices` 枚举声卡，人工指定稳定设备标识、通道和支持的采样率。拔线后设备编号可能变化，每次启动重新匹配，不自动退回电脑麦克风。
2. `audio-probe receive`：A 拨 B，B 读 10 句固定测试短语，电脑采集；把 A/电脑置于 B 声音无法通过空气直达的位置，验证确为电话下行。
3. `audio-probe transmit`：电脑播放含本次随机测试编号的 10 句预置 WAV，B 逐句回报听到内容；A 扬声器关闭，排除电脑扬声器被 A 内置麦克风拾取的假成功。
4. `audio-probe duplex`：收发同时保持，B 在电脑播放时插话，观察串音和削波；关闭软件监听直通。先检查物理隔离和音量，再评估 AEC，禁止简单关输入掩盖问题。
5. 人工挂断后停止媒体；重复 3 通，每通约 2 分钟，其中一通插拔并重新连接配件，恢复后重新选路验证。拔线期间停止输出，不重拨。

记录接线照片（不含敏感信息）、设备型号、采样率、输入/输出设备、收发时间、电平与溢出统计、两方向测试音轨/人工评分。通过：每方向 10 句至少 9 句清晰辨认、无持续啸叫、3 通无音轨串到下一通。双讲不合格单独标 FAIL，不能因为单向通过就宣称 AI 通话可行。

实验音轨仅含授权测试人员内容；原始音轨写入加密卷或等效加密存储，不提交仓库。通过与否依据真实收发，不以云图录音为证据。

## 8. E4：AI 普通电话对话

前提 E3 双向通过。固定技术路线为流式 ASR＋有限话术状态机＋文本模型＋流式 TTS，首版不切换端到端语音架构。供应商使用项目已有可用的国内账号；在 `providers.yaml` 锁定实际 ASR/TTS 模型 ID、区域、格式和官方接口文档。缺流式权限时 BLOCKED，不用 60 秒文件 ASR 冒充实时服务。

先用同一适配器在电脑耳机做冒烟，再接 E3 的声卡。电脑耳机通过只记 `desktop_smoke`。采集/播放与网络分别运行；20 ms 逻辑帧、单调时钟、bounded queue；使用声卡原生格式采集后按服务要求重采样。每次回答含 epoch，插话立即清空本地输出并取消旧响应，迟到音频丢弃。

实验话术仅三步：“我是通话测试助手” → 问偏好“上午还是下午联系” → 复述并结束。覆盖正常回答、改口、插话、拒绝、沉默和网络中断，不做真实营销。人工确认 B 已接听后按开始键；此实验不声称已解决平台腿/客户腿接通判断。

至少 5 通、累计 20 个回答轮次、10 次打断。以 B 侧独立测试记录或人工时间标注测端到端延迟；目标回答 p95 ≤2 秒、打断停播 p95 ≤300 ms；样本小，仅作实验门禁。没有远端测量时延迟项 BLOCKED，不用首 token 替代。失败时保留实际值，不降低标准。

模型断网：本地一次结束语并停止；本阶段由人员挂机，报告 `hangup=manual`。挂机后不继续播放，下一通无前次音频。自动挂机和客户接通识别留给后续设备集成，不伪装已经完成。

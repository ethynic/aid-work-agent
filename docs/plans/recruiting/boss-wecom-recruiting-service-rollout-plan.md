# BOSS—企业微信招聘协同方案实施与验证计划

> 状态：🔧 部分完成  
> 日期：2026-08-31  
> 关联方案：[客户解决方案](../../solutions/recruiting/boss-wecom-recruiting-service-solution.md)

## 1. 成功标准

- 形成可直接交付客户的非技术解决方案；
- 明确 100 账号/10 台虚拟机为待试点验证的容量目标；
- 已验证能力与未验证能力不混写；
- 首期面试地点具备稳定可交付方式；
- 试点结束后才能给出最终单机账号密度和 IP 配置。

## 4. 待实施

### Phase 1：5—10 账号试点

- [ ] 准备 1—2 台 Windows 虚拟机；
- [ ] 每个账号建立独立工作空间和固定归属；
- [ ] 为不同虚拟机配置独立、稳定的公网出口，确认不是同一 NAT 公网 IP；
- [ ] 连续运行 1—2 周，记录登录验证、账号异常、资源和任务成功率；
- [ ] 测试同一 VM 多桌面会话/多账号工作空间的稳定承载上限；
- [ ] 根据实测确定单台承载量，未达到 10 个则增加 VM 数量。

### Phase 2：面试地点链路验收

- [ ] 输入标准面试地址，地理编码后由招聘人员确认地点名、详细地址和经纬度；
- [ ] 生成手机可打开的高德/腾讯地图导航链接；
- [ ] 通过 WeCom CLI 向内部测试联系人发送“时间 + 联系人 + 地址 + 导航链接”，核对移动端打开效果；
- [ ] 单独设计原生位置卡片 probe，只对测试白名单联系人执行；
- [ ] 若 Windows 客户端无可用入口，评估合规 API 场景；不满足个人客户聊天条件则明确放弃原生卡片。

### Phase 3：分批扩容

- [ ] 按 20—30 个账号一批扩容；
- [ ] 每批完成账号、岗位、企微人员和 VM 的绑定台账；
- [ ] 建立掉线、锁屏、登录验证、好友申请失败和消息结果不确定的人工处理流程；
- [ ] 达到约 100 个账号后完成容量与稳定性报告。

## 5. 上线门禁

- 不把“每 VM 10 个账号”写成正式 SLA，直到连续试点通过；
- 客户报价中明确云端虚拟机为 1,000 元/台/年，预计总价随试点确认的实际台数调整；
- 不把多台 VM 部署在同一共享公网出口后宣称已完成 IP 分散；
- 原生位置卡片未经白名单真机发送并在候选人侧确认，不进入正式能力清单；
- 候选人未主动提供联系方式或未同意后续沟通时，不进入企业微信添加流程；
- 所有结果不确定的写动作禁止自动重试。

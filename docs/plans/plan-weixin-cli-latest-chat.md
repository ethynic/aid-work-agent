## 实施与验收

依据[微信 CLI 设计](../design/weixin/weixin-cli-design.md#14-单会话最新消息与本机副本)和 [Runtime 共同契约](../system/runner-desktop-runtime-integration-contract.md#微信正文仅限本机共同检查点)。

1. 新入口复用现有 UIA 行采集、送达末尾与分页连续性检查。首读最多十页，续读在已核对的末尾锚点停止。覆盖重复消息、断层、无新增和视口切换。
2. 按企微时间线基本结构写入本机 DPAPI 副本，确认连续后原子更新。验证多轮读取、进程重启隔离和保存失败恢复。
3. CLI 返回本机新增消息。签名 MCP 和云端调度仅返回同步元数据，覆盖正常、失败、首次与续读。移除新版 `weixin_name_resolve`，验证共享发送定位和存量设备兼容。

## 真机校准

微信 4.1.15.13 群聊观测到 Qt 会在不同页复用原生节点 ID，滚动后重新读取时同一批消息的原生 ID 也会变化。单次分页仍核对相邻视口重叠。持久锚点核对正文、消息类型、方向、已核验昵称，以及最近时间标签的本地分钟和区段内顺序。昨天等可信相对标签按采集日期转换。重复序列或缺少足够区分信息的窗口返回断层，保留旧副本。

群聊首读 10 页、31 条。独立进程续读 1 页、零新增，随后 MCP 再读只返回状态和计数，视觉代理零请求。使用实际分页函数与合成视口验证模板重复续读、多于十页的锚点、短会话完整前缀及断层保留。

签名测试包的四项串行声明包含 `weixin_chat_latest`，验签、搬迁和启动检查通过。服务端回归 113 项通过。工具发现黄金清单仍有主分支既有的 `image_read`、`image_render` 漏登记，该项未计入通过数。

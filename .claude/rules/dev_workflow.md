# 开发流程规范：按风险选择开发、测试与 CodeReview

本文件是开发流程的唯一详细规范，供 Codex、Claude Code 和 ZCode 共用。skill 仅提供入口。按行为影响和失败后果分级，不按文件数量机械升级。

## 1. 选择流程

| 风险 | 典型任务 | 必要流程 |
|------|----------|----------|
| 低 | 纯文档、typo、局部文案或样式调整，不改变业务行为 | 主控者直接修改并做相关检查；不强制子智能体或新增测试 |
| 常规 | 边界明确的业务功能、局部 bug 修复、复用现有模式的页面开发 | 主控者开发和自测 → 一个独立验证智能体，运行相关测试并审查 diff |
| 高 | 启动链路、调度/并发、鉴权/租户隔离、敏感数据、计费、数据库迁移、核心工具装配、跨模块契约或大规模重构 | 开发 → 独立测试智能体 + 独立 CodeReview 智能体 → 主控者整合验证 |

主控者可以承担开发角色，无需为了凑数量再启动开发子智能体。高风险流程保留三个独立角色。单行改动也可能是高风险；多个文档文件不因此升级。用户明确要求三智能体或串行流程时遵从。紧急 hotfix 按实际风险选择流程，不自动豁免验证或提交授权。简要说明选定级别及原因，发现影响扩大时升级。

## 2. 开发与交接

- 按任务读取相关规则和代码，复用现有模式；配置字段变更同步检查 `src/config/settings.py` 与 `configs/config.yaml`。
- 行为变更补充能验证正确行为的测试，重点覆盖回归、边界和异常；不为纯文档或低影响样式改动编写形式化测试。
- 开发者先跑定向自测，交接仓库路径、任务范围、文件列表、预期行为、风险点、命令与真实结果。交接信息自包含，但不要求验证者接受开发者结论。
- 使用当前客户端实际提供的子智能体工具；仅将有明确边界、可以独立完成的工作委托出去。无法获得独立验证时说明验证缺口，不把自审声称为独立审查。

## 3. 独立验证与协作

常规任务的验证者同时承担测试和审查；高风险任务分别安排测试与 CodeReview。

- 测试者独立选择并运行新行为/缺陷复现测试和相关回归，检查 mock 是否掩盖真实错误。回归范围默认是受影响模块及有实际依赖关系的相邻模块，不默认运行整个 `tests/unit/`。
- 审查者阅读本任务的 diff（含新文件）及必要上下文，重点检查正确性、权限和租户边界、资源释放、并发异步、启动安全、配置一致性及测试有效性。不要将工作区其他任务的改动混入修复。
- 开发稳定后，测试与只读审查可以并行，前提是各自能独立完成且测试不会修改共享源码或相互争用测试环境。存在依赖、资源冲突或验证期间需要改代码时串行；不让多个智能体同时修改同一工作区。
- 验证者默认报告问题，由开发者统一修复；需要委托修复时明确文件所有权，暂停受影响验证。P0/P1 修复后重跑相关测试并由审查者复核；P2 按实际影响处理，nit 不扩展任务。
- 报告命令、通过/失败/跳过情况、问题位置和未验证项。环境阻塞或原有失败不能称为“全绿”；记录原因和交付影响，不擅自修理无关问题。

## 4. 验证范围与结果复用

- 后端行为修改运行定向测试；触及 import、配置、入口或调度链路时增加相关 import/配置加载检查。实际启动检查在隔离环境中执行，避免启动生产调度或写入真实业务数据。不要打印配置凭据。
- 前端源码修改运行 `cd frontend && npm run build`；交互变化验证相关行为，布局变化查看受影响页面及必要的窄屏状态。不能查看页面时明确视觉验证缺口。
- 独立测试不能只复述开发者自测结果；但审查者无需再跑同一套已通过测试，主控者也无需因角色变化重复 build。
- 可复用结果必须对应相同的受影响代码、依赖、配置和执行环境，且有可核验的命令与退出状态。修复、合并或环境变化使相关结果失效时重跑；没有有效证据才补跑，禁止无限重复验证。
- 主控者负责检查最终 diff 和验证证据。涉及会触发部署的提交/推送，仍须亲自确认最终代码的关键 import/build 检查；主控者此前对相同最终状态运行的有效结果可以复用。通过 build/import 不等于已完成生产验收。

## 5. 本机执行环境

Python 测试统一使用 `./scripts/dev_test.sh <相关测试> -p no:cacheprovider -q`。脚本检测正在运行的 `aid-agent-api` 容器，在容器内执行 pytest，否则使用宿主机 `python`。

首次验证时确认容器/宿主机、解释器和依赖可用。容器必须运行本次工作区代码，不能用旧镜像测试结果代替当前改动。宿主机缺少 `python` 或依赖时先查找项目已有虚拟环境；无法验证则如实报告。

`python -c` 类检查使用相同环境：容器内加 `docker exec aid-agent-api` 前缀，宿主机使用已确认的解释器。前端使用 `frontend/package.json` 中的现有脚本。真实浏览器和外部服务测试仅在相关且环境具备时运行，不因默认排除而声称已验证。

## 6. 提交与交付

仅用户明确要求“提交代码”后执行 Git 操作，hotfix 亦同。具体授权、fetch、分支同步、暂存和推送规则统一见 [AGENTS.md](../../AGENTS.md#git-提交规范)，不在 skill 重复维护；不写死远程分支。

总结实际改动、验证结果和剩余风险。文档登记与开发状态按 AGENTS.md 执行。没有提交授权时，完成修改与验证即可交付。
